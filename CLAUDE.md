## Definition of Done (каждая задача)

1. **Тесты обязательны.** На каждую фичу и фикс — тесты. Новый контракт закрепляй гейтом
   `*.guard.test.ts` и **проверяй его на живом нарушении**, а не только на зелёном коде.
2. **Гейты зелёные.** По ходу работы гоняй затронутые (команды ниже); **перед завершением
   фазы — полный прогон целиком**. Красное — чини, не обходи.
3. **Документация наравне с кодом.** Пройди по «Карте документации» выше и обнови **каждый**
   файл, чей жанр задет: минимум — CHANGELOG (что изменилось) и ROADMAP (статус фазы), плюс
   INVARIANTS, если появился контракт. Фича без отражения в доках — **незавершённая**.
4. **Перевод наравне с кодом.** Любой видимый текст — только через `t()` и **сразу на всех**
   языках (см. ниже). Частичный перевод не компилируется.
5. **Версия** поднята согласованно (см. «Версионирование»).

### Полный прогон

```sh
source "$HOME/.cargo/env"                       # cargo не в PATH свежей сессии
export PATH="$HOME/Library/pnpm/bin:$PATH"      # standalone pnpm

cargo fmt    --manifest-path src-tauri/Cargo.toml --all --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test   --manifest-path src-tauri/Cargo.toml
pnpm check
pnpm test:coverage
pnpm build
```

Все шесть должны быть зелёными. Гейты покрытия (≥ 90 % чистая логика, ≥ 80 % в целом)
настроены в [vitest.config.ts](vitest.config.ts) и **роняют** прогон. `pnpm build` нужен
отдельно от `pnpm check`: `check` — это только типы (`svelte-check`), а `vite build` ловит
поломки production-сборки, которые типы пропускают (`pnpm tauri build` собирает тот же бандл).

### Очистка после зелёного прогона

```sh
rm -rf src-tauri/target/release/bundle    # .app/.dmg/.msi/.exe
./scripts/clean-launchservices.sh         # macOS: снять мёртвые регистрации vterm.app
```

**Порядок важен** — сперва `rm`, потом скрипт. Каждый `tauri build` регистрирует свой
`vterm.app` в LaunchServices; после удаления бандла запись становится фантомной, и за
десятки пересборок Finder начинает резолвить `su.vcore.vterm` в мёртвый путь — приложение
молча не открывается. Скрипт идемпотентен и чистит только несуществующие пути `vterm.app`.
Это дефект машины разработчика, а не код. Инкрементальный кэш Rust (`target/debug`,
`release/deps`) **не трогаем** — он держит следующую сборку быстрой.

## i18n — ЗАКРЕПЛЕНО

- **Главное правило.** Весь видимый текст — на **всех** языках, через `t()`. Хардкод строк
  запрещён (надписи, кнопки, `title`/`aria-label`, тосты, тексты ошибок). Ключ добавляется
  **сразу во все** словари — иначе `pnpm check` падает.
- **Где живёт.** [src/lib/i18n/](src/lib/i18n/): `locales.ts` (реестр, `DEFAULT_LOCALE=en`),
  `messages.ts` (`en` — канонический набор ключей), `translate.ts` (чистые
  resolve/interpolate), `index.ts` (`t()` реактивен от `settings.language`).
- **Не переводим** доменные термины (`CPU`/`RAM`/`SSH`/`SFTP`/`IP`/`PSI`/`inodes`, имена тем).
- **Логику не завязывай на перевод:** храни канонический английский в состоянии, локализуй
  при выводе. Поиск по настройкам — двуязычный (EN+RU в одной строке).
- **Язык интерфейса меняется только через `setLocale()`** — двусторонний бинд к
  `settings.language` пишет мимо пересева промптов ИИ (гейт `settings.guard`).
- **Нативное меню** строится в Rust, метки пушатся с фронта (`set_menu_language`).
- Переменную `{#each … as t}` не называй `t` в файлах с функцией перевода.

## Версионирование

Схема `<major>.<фаза>.<фикс>`: вторая цифра — номер фазы (растёт на новой фазе, третья
сбрасывается в 0), третья — фикс внутри фазы. `major` поднимается только на публичном
рубеже — `1.0.0` был первым таким (до него вся разработка шла на `0.<фаза>.<фикс>`).
Пререлизных суффиксов нет: Tauri их не бандлит.

**Версия лежит в одном месте — [package.json](package.json)**, и правится одной командой:

```sh
pnpm version:set 1.1.0
```

[scripts/set-version.mjs](scripts/set-version.mjs) разносит её в `Cargo.toml` и `Cargo.lock`
(cargo не умеет ссылок, нужен литерал). `tauri.conf.json` ничего не хранит — там стоит
ссылка `"version": "../package.json"`, которую Tauri резолвит сам; приложение читает версию
через `getVersion()`, то есть из того же источника. CI берёт её тоже из `package.json` —
достать `.version` из `tauri.conf.json` теперь значит получить строку `"../package.json"`
и собрать файл с таким именем. Расхождение и откат к литералу ловит гейт
`version.guard.test.ts`. Руками эти файлы не правь.

## Сборка: три артефакта

Каждая фаза даёт три дистрибутива — macOS, Windows, Linux. Единый кросс-ОС файл невозможен,
кросс-компиляция Tauri между ОС нерабочая, поэтому собирает CI:
[release.yml](.github/workflows/release.yml) на раннерах GitHub по тегу `v*` (основной путь)
и [.gitlab-ci.yml](.gitlab-ci.yml) на self-hosted раннерах
(`lint → security → test → build → release`). Локально доступна сборка только под текущую ОС.
Подробности — [docs/INSTALL.md](docs/INSTALL.md).

**Тег не собирает релиз из красного дерева:** `release.yml` первой джобой вызывает
[ci.yml](.github/workflows/ci.yml) целиком, матрица стоит под `needs`. Раскладка всех
workflow — [docs/TESTS.md](docs/TESTS.md#ci-на-github); свойства цепочки поставки —
[SECURITY.md](SECURITY.md). Правя workflow, помни: экшены пинятся **по коммит-SHA** с
комментарием версии, а `${{ … }}` в `run:` не подставляется (только через `env`) — оба
правила держит гейт.

## Toolchain (нестандартный на этой машине)

- `cargo`/`rustc` через rustup, **не в PATH** свежей сессии → `source "$HOME/.cargo/env"`.
- `pnpm` — standalone в `$HOME/Library/pnpm/bin` (corepack-шим сломан под Node 25) →
  `export PATH="$HOME/Library/pnpm/bin:$PATH"`.
- pnpm гейтит нативные build-скрипты; esbuild разрешён через `allowBuilds: { esbuild: true }`
  в [pnpm-workspace.yaml](pnpm-workspace.yaml) (**не** `onlyBuiltDependencies` в package.json).
- Запуск: `pnpm tauri dev` (первая Rust-сборка ~1–2 мин).
- `tauri-driver` (E2E) — только Linux/Windows. Локально на macOS `pnpm test`, E2E гоняет CI.
