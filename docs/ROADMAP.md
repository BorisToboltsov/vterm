## Что дальше

- **⬜ Долги окон (1.3–1.4).** Одним действием переносится одна вкладка, а не группа и не
  целая область. Вкладка с работой в полёте (синхронизация, перенос файла, ответ ИИ) ждёт её
  конца: чтобы переносить и её, эта работа должна принадлежать бэкенду, а не памяти окна.
  Бросок вкладки на другое окно не работает на Linux: оконную систему там не спрашивают (GDK
  умеет ответить на X11, на Wayland ответа нет), а угадывать по положению окон нельзя; по той
  же причине там нет ни подъёма окна под указателем, ни метки над рабочим столом. Метка над
  столом — непрозрачный прямоугольник с системным шрифтом (прозрачные окна в сборке выключены),
  а не копия вкладки. Подъём окна и метка на Windows не запускались.
  Сквозного автотеста с двумя настоящими окнами нет ([ADR 0017](adr/0017-detached-windows.md),
  [ADR 0018](adr/0018-tabs-between-windows.md)).
- **⬜ Восстановление сессий и раскладки центра.** Сейчас сохраняются только доки (кто в каком
  доке, размеры, сворачивание): вкладки при перезапуске не восстанавливаются, поэтому раскладку
  центра — дерево областей — сохранять не на чем. Восстановление — отдельная версия; открытые
  вопросы — секреты (спрашивать заново), прод (не подключаться молча), вкладки контейнеров и
  вторые окна (какая вкладка в каком окне).
- **⬜ Долги сплитов (1.2).** Редакторы остаются подвкладками сессии и переезжают вместе с её
  вкладкой — самостоятельными вкладками (с меткой хоста) они становятся отдельным шагом. Сетка
  синхронного ввода — отдельный режим поверх областей: объединять их стоит, когда сплиты научатся
  раскладывать N областей сеткой одной командой ([ADR 0016](adr/0016-center-splits.md)).
- **⬜ Широкий вид остальных панелей.** Docker и k8s подстраиваются под ширину контейнера
  (`@wide:`); Git, файлы и чат ИИ в нижнем доке работают, но раскладку не меняют. Кандидаты:
  Git — граф рядом с изменениями, файлы — колонки размера/прав/даты. И перенос в нижний док того,
  что сейчас модалки из-за узкого дока: логи и inspect Docker/k8s, результаты grep, переносы.
- **⬜ Долги связности (1.5).** Маршрут k8s на живом кластере не запускался: парсеры написаны
  по схемам `discovery.k8s.io/v1` и `networking.k8s.io/v1` и проверены на собранных по ним
  объектах. Gateway API (`HTTPRoute`) в маршрут не входит — только Ingress; NetworkPolicy и
  существование IngressClass не читаются. У Docker порты остановленного контейнера не
  показываются: `docker ps` их не печатает (проверено на Docker 29), настроенный маппинг есть
  только в `inspect`; сети с `--internal` от обычных не отличаются. Граф рисует первые 40
  контейнеров, остальные — только в списке.

## Версии после 1.0

| Версия | Что сделано |
|--------|-------------|
| 1.1 | **Три дока вместо одного**: нижний док на всю ширину окна, панели-инструменты переносятся между левым, правым и нижним доками (перетаскиванием вкладки, из её меню, из ⌘K), раскладка сохраняется, ненужную панель можно скрыть; Docker и k8s подстраиваются под ширину контейнера — в широком контейнеры и поды идут таблицей с настраиваемыми колонками (ADR 0015). Исправлен шторм `kubectl` при открытии панели k8s |
| 1.2 | **Терминалы рядом (сплиты в центре)**: центр — дерево областей, у каждой своя полоса вкладок; вкладка переносится в другую область или в новую (перетаскиванием к краю, из меню вкладки, из ⌘K, `⌘D` / `⌘⇧D`) без разрыва соединения; разделители — мышью и с клавиатуры, предел размера области. «Активная вкладка» стала «областью в фокусе»: за ней идут доки (панели сессий на экране не пересобираются, док подписывает, чья панель), статус-бар и ИИ; запись и вопросы о входе — у всех вкладок на экране (ADR 0016) |
| 1.3 | **Вкладка в отдельном окне ОС**: вкладка терминала выносится в своё окно — из меню вкладки, из ⌘K или броском за пределы окна — без разрыва соединения, со scrollback, открытыми редакторами, диалогом с ИИ и состоянием панелей; у второго окна те же панели, сплиты и статус-бар. Сессией владеет бэкенд, а не компонент терминала; вывод на время передачи придерживается, сбой откатывается. Закрытие второго окна спрашивает как выход и завершает его сессии; выход перечисляет все окна. Настройки и список серверов едины для окон (ADR 0017) |
| 1.4 | **Вкладка между открытыми окнами**: вкладка возвращается в главное окно и переносится в любое другое открытое — из меню вкладки, из ⌘K или броском на окно — тем же путём, что в новое: без разрыва соединения, со scrollback и состоянием панелей. Окно под указателем выходит вперёд, вкладка идёт за указателем — над окном-целью его вкладки расступаются, над рабочим столом её показывает окно-метка — и встаёт туда, куда её бросили. Окна, принимающие вкладки, называют себя сами и различаются по вкладке, которую показывают; какое окно под указателем, бэкенд спрашивает у ОС (macOS, Windows) и не угадывает по положению окон. Окно, не принявшее вкладку, отказывается сразу и не закрывается, если у него есть свои (ADR 0018). При любом перетаскивании текст интерфейса больше не выделяется |
| 1.5 | **Связность: кто до кого достучится.** Kubernetes — во вкладке «Сеть» вид «Маршрут»: правило ingress → сервис → эндпоинты колонками; эндпоинты читаются из EndpointSlice, а не выводятся сопоставлением селектора с подами, правило без сервиса или с необъявленным портом показано отдельно, непрочитанный список не выдаётся за пустой. Docker — во вкладке «Сети и тома» у порта написано, откуда он доступен, у сети — её контейнеры; вид «Граф» рисует членство двумя колонками (сети — контейнеры), выбор узла подсвечивает всё, с чем у него общая сеть. Новых бэкенд-команд нет |

## Принцип сборки: три артефакта

Один файл, работающий на всех ОС, невозможен, а кросс-компиляция Tauri между ОС нерабочая —
поэтому каждая фаза даёт **три** дистрибутива (macOS · Windows · Linux), и собирает их CI:
[release.yml](../.github/workflows/release.yml) на раннерах GitHub по тегу `v*` и
[.gitlab-ci.yml](../.gitlab-ci.yml) на self-hosted раннерах. Локально доступна сборка только под
текущую ОС. Подробности — [INSTALL.md](INSTALL.md).
