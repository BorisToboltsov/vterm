## 🔁 Принцип сборки: два файла на каждом этапе

Один файл, работающий и на Windows, и на macOS, **невозможен** (разные форматы
исполняемых файлов). Поэтому **на каждой фазе собираются два артефакта**:

- **macOS** — `.app` (портативный бандл) + `.dmg`;
- **Windows** — `.msi` / NSIS `.exe` (+ портативный `vterm.exe`).

**Definition of Done каждой фазы** включает зелёную CI-сборку обеих ОС. Механизм —
**GitLab CI** [.gitlab-ci.yml](../.gitlab-ci.yml) (задачи `build:macos` + `build:windows`):
push в дефолтную ветку/MR/ручной запуск → артефакты пайплайна; push тега `v*` →
GitLab Release для обеих ОС.

> Локально доступна сборка только под текущую ОС (`pnpm tauri build`). Windows-файл
> на macOS не собрать — для него нужен Windows-раннер из CI.

## ✅ Фаза 17 — ИИ-агент (opt-in)

**Цель:** встроить ИИ-ассистента для работы с серверами — чат, исполнение команд с
подтверждением, генерация планов и скриптов из записей сессий. **Полностью opt-in,
выключен по умолчанию.**

**Зафиксированные решения (обсуждено 2026-06-30):**
- **Офлайн-инвариант — осознанно ослаблен:** ИИ выключен по умолчанию; **весь
  LLM-трафик идёт через Rust-бэкенд** (`reqwest`), не из WebView, поэтому CSP остаётся
  строгим, а фронт-гейт `autonomy.guard` — зелёным; разрешены **только пользовательские
  эндпоинты** (нет зашитых облаков/телеметрии) — «как SSH». Обновляются `autonomy.guard`,
  [SECURITY.md](../SECURITY.md), [INVARIANTS.md](INVARIANTS.md).
- **Провайдеры:** адаптер **OpenAI-совместимый** (`/v1/chat/completions` — Ollama/vLLM/
  LM Studio/локальный Qwen/OpenAI) **+ Anthropic** (нативный Claude) с самого начала.
  Конфиг эндпоинта: тип/baseURL/модель/ключ (keychain `vterm:ai-key`, `zeroize`); несколько
  эндпоинтов с выбором активного.
- **Исполнение:** *только предложить* / **подтверждать каждую** (дефолт) / *опц. авто* —
  авто-режим разрешён **только на не-прод** серверах под явным флагом; на проде — никогда.
- **Приватность:** перед отправкой — маскирование секретов + окно явного согласия
  «отправить N строк на `<endpoint>`» (и для локальных, и для облачных эндпоинтов).
- **Модель контекста — manual-first по уровням:** по умолчанию ИИ видит **выделение /
  последние N строк**; «приложить весь буфер», «приложить запись», «приложить метаданные»
  (ОС/hostname/ядро) — **явными переключателями**, всё через маскирование + согласие.
- **Контракт вывода — переключаемый в настройках:** v1 **Markdown-парсинг** (```bash → кнопка
  «Выполнить»; дефолт, модель-агностично, работает на слабом локальном Qwen) **и** v2 **нативный
  tool-calling** (`run_command()`, для моделей с function-calling). Выбор — в настройках ИИ.
- **MCP — отложен:** нативного tool-calling в брокере достаточно для старта; MCP добавляем
  позже ради экосистемы внешних инструментов (опционально).

## ✅ Фаза 21 — Proxy / jump host на запись сервера (v0.21.0 → v0.21.35)

Подключение к серверу **через промежуточный хост**. Настройка — **на каждой записи
сервера** (у одного может быть proxy, у другого нет). Реализованы **все три типа**:
**SSH jump host (ProxyJump)** (v0.21.0), **SOCKS5** и **HTTP CONNECT** (v0.21.1). Все
три отдают russh готовый байтовый поток, поверх которого идёт реальная SSH-сессия
(`connect_stream`), поэтому вся текущая аутентификация/SFTP не меняется.

- **Модель данных (оба стека).** `ProxyKind` (`jump`/`socks5`/`http`) + `ServerProxy`
  (`kind`, `host`, `port`, `username`, `authMethod`, `keyPath`, `hasSavedPassword`);
  поле `proxy: Option<ServerProxy>` на `ServerProfile`/`NewServerProfile`
  (`#[serde(default)]` — старые профили остаются валидными). Зеркало —
  [types.ts](../src/lib/types.ts).
- **Транспорты** ([ssh.rs](../src-tauri/src/ssh.rs), enum `Proxy`). Отдельная фаза
  `proxy` эмитится первой при любом типе.
  - **jump host:** connect + auth к бастиону (свой host-key-чек и секреты), затем
    `channel_open_direct_tcpip` → `connect_stream` по туннелю. Хендл jump-хоста хранится
    в `SshSession` (живёт весь сеанс — иначе туннель рвётся).
  - **SOCKS5** (`tokio-socks`) и **HTTP CONNECT** (`async-http-proxy`): TCP-поток к цели
    через прокси (опциональный basic-auth: username на профиле + пароль в keychain), затем
    тот же `connect_stream`. Владение потоком уходит в SSH-сессию, доп. хендл не нужен.
  - Общий помощник `authenticate` для jump/цели; `map_handshake_err` для host-key;
    `conn_timeout`/таймауты на каждый прокси.
- **Секреты прокси.** Секрет (пароль/passphrase jump-хоста или пароль SOCKS5/HTTP) — в
  **keychain** под proxy-scoped id (`{id}::proxy`, [secrets.rs](../src-tauri/src/secrets.rs)),
  вводится в **форме сервера**, сохраняется командой `save_proxy_secret`.
  `forget_secrets`/`delete_all` чистят и прокси-секреты. Ошибка `ProxyAuthRejected`
  ([error.rs](../src-tauri/src/error.rs), маркер `proxy-auth-rejected`; матчинг проверяется
  раньше общего `auth-rejected`, чей текст он содержит).
- **Экран загрузки — сгруппированные подстадии** (v0.21.2, вариант B). Прокси
  эмитит **свои подстадии** отдельными событиями: jump host →
  `proxyConnecting`/`proxyAuthenticating`/`proxyTunnel` (как полноценный SSH-connect к
  бастиону), SOCKS5/HTTP → `proxyConnecting`/`proxyHandshake` (TCP-connect и негоциация —
  раздельные `await`, для SOCKS5 через socket-вариант `tokio-socks`). Чистый маппинг —
  `phaseSteps(current, errored, proxy)` (`proxy: "jump"|"tcp"|null`) возвращает шаги с
  тегом группы `proxy`/`server`; [ConnectingOverlay](../src/lib/ConnectingOverlay.svelte)
  рисует группы с заголовками-адресами и отступом. Чек-лист **всегда вложенный** (v0.21.3):
  без прокси — одна группа «сервер» (шаги под адресом сервера), с прокси — группа прокси
  сверху. Провал замирает на конкретном подшаге (`proxy-auth-rejected` →
  `proxyAuthenticating`, [ssherror.ts](../src/lib/ssherror.ts)).
- **Форма сервера** ([ServerFormModal](../src/lib/ServerFormModal.svelte)) — секция «Proxy /
  jump host»: чекбокс включения, выбор типа, host/port; для **jump** — username + метод
  аутентификации (пароль/ключ) + файл ключа + секрет; для **SOCKS5/HTTP** — опциональные
  username + пароль (basic-auth). Валидация host/port (и username для jump).

## ✅ Фаза 22 — Синхронный ввод на несколько серверов (v0.22.0)

- **Задача.** Ввод команд одновременно на нескольких серверах из одного окна
  («broadcast» / MultiExec). Печатаешь команду один раз → уходит на все выбранные
  живые сессии.
- **Механизм — фан-аут на фронте, без нового бэкенда.** Переиспользуем **единый
  контракт терминала**: команда отправляется как N вызовов существующего
  `write_to_terminal(sessionId, bytes)` из [+page.svelte](../src/routes/+page.svelte)
  (`doBroadcast`). Бэкенд ([ssh.rs](../src-tauri/src/ssh.rs)/[pty.rs](../src-tauri/src/pty.rs)),
  CSP, офлайн-инвариант и keychain не затронуты.
- **Чистая логика** — [broadcast.ts](../src/lib/broadcast.ts): `eligibleMembers`
  (живые открытые члены группы в порядке вкладок), `prodMembers`/`groupHasProd`
  (prod-тег через `isProdServer`), `frameCommand` (команда + `\n`, null для пустой),
  `pickLayout` (сетка до порога `FOCUS_THRESHOLD=9`, дальше фокус+ростер),
  `gridColumns` (число колонок по ширине с мин. плиткой 380px и капом 4). Стор —
  [stores/broadcast.svelte.ts](../src/lib/stores/broadcast.svelte.ts) (`enabled`,
  `members`, `focusId`, `layoutMode`; toggle/add-all/clear/remove).

  CSS-классы keyed-`{#each}`, без дублирования сессий): **сетка** плиток (≤9 членов) и

## Заметки по архитектурным решениям

- **`portable-pty` — для локального терминала.** SSH-вкладки используют удалённый
  PTY канала `russh` напрямую; для **локальной shell-вкладки** («+» в списке
  вкладок) добавлен `portable-pty` (forkpty на Unix, ConPTY на Windows) —
  [pty.rs](../src-tauri/src/pty.rs). Локальный PTY переиспользует те же события
  `term://out|closed/{id}` и команды `write_to_terminal`/`resize_pty`/`disconnect`,
  что и SSH, поэтому фронтенд-виджет терминала общий.
- **`russh-keys`** в свежих версиях влит в `russh` — проверить актуальность на момент
  начала Фазы 2.
- **`keyring` vs собственное шифрование** — основным выбран `keyring` (системное
  хранилище). `chacha20poly1305` под мастер-пароль — опция для портативного файла.
- **Хранение профилей** — простой JSON-файл на стороне Rust (`serde` + `directories`),
  без `tauri-plugin-store` (это фронтовое хранилище настроек, дублирование не нужно).
- **Tailwind v4** вместо 3.x из исходного плана — интеграция одним плагином Vite,
  без `tailwind.config.js`/PostCSS.
