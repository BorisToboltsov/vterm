## Что дальше

- **v1.0.0 — первый публичный релиз.** Готово: сборка трёх ОС по тегу в GitHub Actions
  (`.dmg` / `.msi` / NSIS `.exe` / portable / `.deb` / `.rpm` / AppImage), ассеты релиза,
  ревизия документации. Осталось: прогнать тег и опубликовать черновик.
- **⬜ Фаза 16 — подпись кода и раннеры.** Единственный незакрытый пункт из ранних фаз: Apple
  Developer ID + нотаризация (macOS) и code-signing сертификат (Windows); опционально
  автообновление через `tauri-plugin-updater`. Пока не сделано — сборки неподписанные, и
  получателю нужен `open-on-mac.sh` или снятие карантина вручную ([INSTALL.md](INSTALL.md)).
  - **Сюда же — незакрытая проверка сборки.** В GitLab CI **не зарегистрирован ни один
    раннер** (теги в конфиге — плейсхолдеры), а `build:windows`/`lint:windows` стоят
    `when: manual` + `allow_failure`. Значит строка Definition of Done «зелёная CI-сборка
    всех трёх ОС» **ни разу фактически не исполнялась**, и Windows-регрессию пайплайн не
    ловит — прошлые всплывали как баг-репорты пользователя. GitHub Actions (раннеры
    хостит GitHub, регистрировать нечего) закрывает это для релиза по тегу, но сам
    workflow тоже ещё ни разу не запускался.
- **🔜 Фаза 45 — связность: маршрут k8s, сеть Docker, граф.** Спроектирована, не начата. Обе
  части ложатся в **существующие** сабтабы, новых бэкенд-команд и сабтабов не требуют.
  - **Маршрут k8s** (Ingress → Service → кто реально принимает трафик) — в сабтабе Network,
    колонками: это цепочка, а не граф. Нужны `endpointsArgs`/`parseEndpoints` + `spec.selector`
    и backend-ссылки ingress, которые парсеры сейчас отбрасывают. **Читать EndpointSlice, а не
    матчить селекторы на фронте**: совпадение лейблов ≠ приём трафика (not Ready, readiness
    gates, terminating), и нарисовать «трафик идёт сюда» точно в тот момент, когда пользователь
    смотрит на 502, — худший из возможных отказов для отладочного инструмента (тот же принцип,
    что «потолок из спека, а не из процентов»). Явно обработать: `ExternalName` без эндпоинтов,
    headless-сервисы, ingressClass без контроллера (выглядит здоровым во всех объектах и не
    роутит ничего — в данных этого не видно, значит и рисовать нельзя).
  - **Связность Docker** (публикация портов + членство в сетях) — в сабтабе сетей и томов.
    Данные почти бесплатны: строка портов уже приходит, членство — один токен `{{.Networks}}` в
    существующий формат `psArgs`. Ценность: `127.0.0.1:5432` против `0.0.0.0:5432` (читаются
    одинаково, значат противоположное), остановленный контейнер всё ещё показывает маппинг, два
    compose-проекта в разных сетях не резолвят имена друг друга, выглядя здоровыми.
    Нераспознанную строку порта рисовать **как есть** (IPv6 `[::]`, диапазоны, udp, Swarm), а не
    отбрасывать.
  - **Граф — только для Docker, тумблером.** Сети Docker — двудольный граф членства
    (сети | контейнеры), поэтому раскладка — две отсортированные колонки: детерминированно, без
    force-directed и дёрганья под трёхсекундный поллинг. Выигрыш, которого список не даёт:
    контейнер в двух сетях — узел с двумя рёбрами, а не строка, показанная дважды.
    Переиспользовать `ViewModeToggle` (сейчас хардкодит i18n-ключи `jsonlog` — обобщить),
    прецедент отрисовки — `GitGraph.svelte`. **Для k8s графа не делаем** — маршрут уже
    оптимален колонками; асимметрия намеренная. Ограничения: деградирует после ~40 контейнеров
    (кап + «и ещё N»), `host`/`none` не рисуются как колонки, сортировка по имени. Общая сеть —
    условие **необходимое, но не достаточное** (может не слушать, может использовать другой
    алиас), поэтому подписывать как «могут ли в принципе», иначе это повторяет ту же ложь, что
    матчинг селекторов.

## Принцип сборки: три артефакта

Один файл, работающий на всех ОС, невозможен, а кросс-компиляция Tauri между ОС нерабочая —
поэтому каждая фаза даёт **три** дистрибутива (macOS · Windows · Linux), и собирает их CI:
[release.yml](../.github/workflows/release.yml) на раннерах GitHub по тегу `v*` и
[.gitlab-ci.yml](../.gitlab-ci.yml) на self-hosted раннерах. Локально доступна сборка только под
текущую ОС. Подробности — [INSTALL.md](INSTALL.md).
