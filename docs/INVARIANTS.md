# Инварианты vterm

Жёсткие контракты кодовой базы — **что обязан соблюдать и чего нельзя**. Это канон:
нарушать без явного решения нельзя. Обоснования решений — в [adr/](adr/); как всё
устроено (диаграмма, слои, спека подсистем) — в [ARCHITECTURE.md](ARCHITECTURE.md);
правила процесса — в [../CLAUDE.md](../CLAUDE.md) (он подключает этот файл через
`@`-импорт, поэтому инварианты авто-загружаются в каждую сессию).

---

## Архитектурные инварианты (выработано в Фазе 6 — соблюдать)

Полные обоснования — в [docs/adr/](adr/). Краткие правила:

- **Граница фронт/бэк.** Вся логика SSH/SFTP/секретов/файлов живёт в Rust-бэкенде
  (`src-tauri/src/`). Svelte-фронтенд ходит к ней только через `invoke()` (команды
  в `lib.rs`) и каналы событий (`term://…`, `sftp://…`, `menu://…`, `install://…`). Новый
  функционал такого рода: команда в бэкенде + типизированная обёртка в
  [src/lib/api/](../src/lib/api/). Не дублируй бизнес-логику на фронте. (ADR 0001)
  - **Единый контракт терминала.** SSH-сессии ([ssh.rs](../src-tauri/src/ssh.rs)) и
    локальные shell-вкладки ([pty.rs](../src-tauri/src/pty.rs), `portable-pty`)
    используют **один** канал событий (`term://out|closed/{id}`) и **одни** команды
    (`write_to_terminal`/`resize_pty`/`disconnect`, маршрутизация по `session_id`),
    поэтому [Terminal.svelte](../src/lib/Terminal.svelte) общий для обоих (проп
    `local`). Новый вид терминала подключай к этому же контракту, а не отдельным.
    **Синхронный ввод на несколько серверов** (Фаза 22) — тоже **поверх этого
    контракта**: команда рассылается как N вызовов `write_to_terminal` из фронта
    (`doBroadcast` в [+page.svelte](../src/routes/+page.svelte)), без нового бэкенда/канала
    и **без дублирования сессий** (раскладки сетка/фокус переиспользуют уже
    смонтированные `Terminal` через рефлоу CSS). Кому/что/как — чистая логика в
    [broadcast.ts](../src/lib/broadcast.ts). **Отправка на прод-сервер** (`isProdServer`)
    требует явного подтверждения — тот же прод-контракт точного тега, что и у ИИ-агента.
    **Выбор шелла для локальной вкладки** (Фаза 26) — тоже **поверх этого контракта**:
    та же команда `open_local_terminal` с необязательным `shell` и тот же канал
    `term://…`, без нового бэкенда/канала. Какую программу спавнить — чистая логика
    [localshell.ts](../src/lib/localshell.ts) (`resolveLocalShell`): `null` = дефолт ОС
    (`CommandBuilder::new_default_prog()`), иначе явная программа (поиск по PATH).
    Детект ОС — команда `host_os` (`std::env::consts::OS`), **не** runtime-плагин, чтобы
    офлайн-CSP и «фронт без сети» остались целы.
  - **Окно подключения (connecting-оверлей).** Пока SSH-вкладка в статусе
    `Connecting…`, поверх области терминала показывается
    [ConnectingOverlay.svelte](../src/lib/ConnectingOverlay.svelte): орбита-комета вокруг
    иконки сервера + `alias` + `user@host:port` + **честный** чек-лист фаз. Фазы —
    **реальные**, из дополнительного канала `term://phase/{id}` ([ssh.rs](../src-tauri/src/ssh.rs)
    `phase_event`, payload цели `connecting`→`authenticating`→`session`, эмитится по ходу
    последовательных стадий `connect`); фронт слушает его в `Terminal.svelte` (проп `onphase`,
    только SSH), а чистый маппинг фаза→состояние-шага — в [connphase.ts](../src/lib/connphase.ts)
    (`phaseSteps`, ADR 0003). Новую **обязательную** стадию добавляй как новый `emit` в `connect` +
    запись в `PHASE_ORDER`, не плоди отдельные каналы. **Прокси-подстадии** (Фаза 21) — тоже
    реальные события, **но не в `PHASE_ORDER`**: эмитятся первыми и группируются под прокси —
    jump host `proxyConnecting`/`proxyAuthenticating`/`proxyTunnel`, SOCKS5/HTTP
    `proxyConnecting`/`proxyHandshake`. `phaseSteps(current, errored, proxy)`
    (`proxy: "jump"|"tcp"|null`) добавляет их с тегом группы `proxy` только при наличии прокси.
    Чек-лист **всегда вложенный** (v0.21.3): шаги сервера — под заголовком-адресом группы
    `server`, прокси-подшаги — под заголовком прокси выше (без прокси остаётся одна группа).
    **Фейковые подстадии рисовать нельзя** — для
    SOCKS5 честное разбиение достигается socket-вариантом `tokio-socks` (сами делаем
    `TcpStream::connect`, затем негоциацию). Анимации — только дешёвые
    `transform`/`opacity`, под глобальным `prefers-reduced-motion`-guard.
    **Тот же компонент — экран ошибки/обрыва** (проп `failed`): орбита заменяется
    статичной иконкой сервера с **красным крестом**, чек-лист **замирает на упавшей
    фазе** (`phaseSteps(phase, true)` → пройденные `done`, упавшая `error`, дальше
    `pending`), под ним — заголовок/красная деталь и **кнопки-действия через слот**
    (`children`). Старую тонкую верхнюю плашку оставляем **только для локальных
    вкладок**; для SSH — оверлей. Маппинг статуса вкладки в заголовок/деталь/упавшую
    фазу/действие — `sshErrorView` в [+page.svelte](../src/routes/+page.svelte).
    **Провал аутентификации больше не закрывает вкладку автоматически**: вкладка
    остаётся с оверлеем (`Соединение ✓ / Аутентификация ✗`), а модалка ввода секрета
    открывается **по кнопке** «Ввести пароль заново» (`reauth`), а не сразу.


- **Ошибки — типизированы.** В Rust возвращай `AppResult<T>`
  ([error.rs](../src-tauri/src/error.rs)), не `String`. Семантические случаи —
  отдельные варианты (`AuthRejected`, `HostKeyRejected`, `NoSession`,
  `UnknownServer`); прочее — `AppError::Message`. `AppError` сериализуется в строку,
  поэтому контракт с фронтом не меняется; маркеры (`auth-rejected` и т.п.) живут в
  `Display`. (ADR 0002)
- **Чистая логика — в `.ts`/свободных функциях**, не в `.svelte`/командах: её
  тестируют без DOM/сети. Фронт: [tree.ts](../src/lib/tree.ts),
  [format.ts](../src/lib/format.ts), [util.ts](../src/lib/util.ts),
  [actions/drag.ts](../src/lib/actions/drag.ts), [ssherror.ts](../src/lib/ssherror.ts)
  (статус SSH → оверлей), [virtuallist.ts](../src/lib/virtuallist.ts) (оконная
  виртуализация), [serverform.ts](../src/lib/serverform.ts) (валидаторы host/IP и порта
  формы сервера). Rust: `reprefixed`, `decode_or_default`, парсеры метрик в
  [metrics.rs](../src-tauri/src/metrics.rs). (ADR 0003)
- **Состояние UI — в runes-сторах** `src/lib/stores/*.svelte.ts` (по образцу
  [settings.svelte.ts](../src/lib/settings.svelte.ts)): `layout` (ширины/сворачивание
  панелей), `tabs` (вкладки терминалов). Не разбрасывай состояние по компонентам. (ADR 0003)
- **Компоненты декомпозированы.** `+page.svelte` — оркестратор; крупные части
  вынесены в `TopBar`, `ServerTree`, а самодостаточные модалки — в `ServerFormModal`,
  `FolderModals`, `SecretPrompt` (Фаза 18.4). `SettingsPanel` — тонкий shell, секции
  живут в `*SettingsSection.svelte` (Фаза 18.5). `api.ts` разложен по доменам в
  `src/lib/api/` с barrel-реэкспортом (Фаза 18.6). **Оверлеи всегда с явным
  `z-index`** (или через `Modal`/`ConfirmDialog`) — закреплено гейтом
  [overlay.guard.test.ts](../src/lib/overlay.guard.test.ts). Переиспользуй примитивы
  `Modal`, `ConfirmDialog`, `Icon`. **Контекстное меню (ПКМ)** — только через общий
  примитив [ContextMenu.svelte](../src/lib/ContextMenu.svelte) (Фаза 31): поверхность
  описывает меню как декларативный список `MenuItem` из [ctxmenu.ts](../src/lib/ctxmenu.ts)
  (`action`/`separator`/`submenu`, `disabled`/`danger`) и отдаёт примитиву; своего попапа
  на панель не заводи. Чистая логика (кламп к вьюпорту `clampMenuPosition`, гвард
  `isAction`) — в `.ts` с тестом. Native-меню WebView подавлено глобально
  (`suppressContextMenu`, Фаза 30), поэтому там, где своего меню нет, ПКМ не показывает
  ничего. Меню терминала — под настройкой `settings.rightClickMenu`. Иконки — из реестра
  [icons.ts](../src/lib/icons.ts)
  через `<Icon name="…" />`, **не эмодзи**. Pointer-drag — через `actions/drag.ts`.
  Подсказки — через `use:tooltip` ([actions/tooltip.ts](../src/lib/actions/tooltip.ts)),
  **не** нативный `title` (кроме заголовков-пропов и раскрытия обрезанного текста);
  у icon-only кнопок обязателен `aria-label`. Длинные описания-подсказки —
  иконкой [InfoHint](../src/lib/InfoHint.svelte) рядом с меткой (к полю) или рядом с
  заголовком секции (вводное описание всей секции), а не абзацем-текстом. (ADR 0003)
  Оформление кнопок/иконок/строк — по закреплённой **дизайн-системе** (см. [DESIGN.md](DESIGN.md)).
- **Темы и фирменный объём** (Фаза 27). Каталог тем — [themes.ts](../src/lib/themes.ts):
  палитра терминала (hex) + `ui`-палитра chrome. **Фирменные** темы (`group: "signature"`:
  Deep Well/Aurora/Glass) — **плотные** (opaque) панели; объём даёт **слой-оверлей поверх
  всего окна** ([ThemeOverlay.svelte](../src/lib/ThemeOverlay.svelte), поле `overlay`,
  `pointer-events:none`, `z-index:30` ниже модалок) — **чистый CSS-градиент** (никакой
  сети/растров/внешних ресурсов, CSP цел). Оверлей — над непрозрачным WebGL-терминалом и
  chrome одновременно, поэтому шва нет и рендерер/скорость не трогаем; терминал прозрачным
  **не** делаем (WebGL прозрачность не поддерживает). Поле `backdrop` (богатый градиент) —
  только для in-app логотипа. Цвета пресетов (вкл. фирменные) **не редактируются** — правится
  лишь `custom`. `DEFAULT_THEME_ID = "deep-well"`. **Бандл-иконка ОС статична** (Deep Well);
  под тему меняется только in-app логотип ([AppLogo.svelte](../src/lib/AppLogo.svelte)),
  без рантайм-подмены иконки дока. Первый кадр — из `vterm.chromePanel` в
  [app.html](../src/app.html), синхронно с `@theme` в app.css.
- **Заставки простоя** (Фаза 28). После простоя (**нет ввода И нет вывода PTY**)
  показывается заставка — **тем же слоевым контрактом, что и ThemeOverlay**:
  canvas ([IdleOverlay.svelte](../src/lib/IdleOverlay.svelte), `z-index:35` ниже
  модалок), под глобальным `prefers-reduced-motion`-guard (статичный кадр). Canvas
  накрывает **только область панелей терминала** (проп `targetEl` = центральный
  контейнер вкладок, измеряется каждый кадр), а не сайдбар/таб-бар/док/статус-бар; без
  вкладок — на всё окно (ambient-карточка). Цвета берутся из активной темы
  (`activeTerminalTheme`), а матрица стартует копией буфера в цвете `foreground`, чтобы
  переход был бесшовным.
  Заставка рисует **копию** буфера (глифы из `bufferText()` терминала) — **никогда не
  пишет в PTY** и **не делает сетевых вызовов** сверх уже существующего опроса метрик
  (`fetchMetrics`, только для «Карточки сервера»). Первое нажатие/клик **гасит заставку**;
  жест **глотается только если он по самой заставке** (canvas накрывает область терминала
  и держит фокус) — тогда он не уходит в терминал. Жест по другому UI (правый док
  SFTP/ИИ/**git-меню**, сайдбар, модалки) заставку тоже гасит, **но проходит** к контролу
  (иначе клики по доку при активной заставке съедались — предикат `swallowDismiss` в
  [idle.ts](../src/lib/idle.ts)). Контракт «без вывода» держится пропом `onoutput`
  у [Terminal.svelte](../src/lib/Terminal.svelte) (сброс таймера на каждый чанк вывода).
  Чистая логика — в `.ts`: детект простоя [idle.ts](../src/lib/idle.ts), сетка глифов и
  токены [idlefx.ts](../src/lib/idlefx.ts), классификация обрыва для NO SIGNAL
  [connlost.ts](../src/lib/connlost.ts) (**NO SIGNAL — только реальный неожиданный
  обрыв подключённой сессии**, не ручное закрытие и не провал коннекта). Персистентность —
  `idleEffect`/`idleTimeoutSec` в `localStorage` (settings-стор). Новые эффекты подключай
  сюда же (canvas-рендер в `IdleOverlay`, чистая часть в `.ts`), не через отдельный слой.
- **Git-панель** (Фаза 29). Третья вкладка правого дока ([GitPanel.svelte](../src/lib/GitPanel.svelte))
  — git по **текущему пути терминала** (`terminalCwd`, OSC 7), на SSH и локальных
  вкладках. **Единый контракт исполнения** (как у терминала): одна бэкенд-команда
  `git_run` (`session_id` + `cwd` + вектор аргументов) диспетчеризует транспорт по
  наличию сессии — SSH через `exec_captured` (строка `GIT_TERMINAL_PROMPT=0 git -C
  '<cwd>' …`, все поля shell-квотятся в [git.rs](../src-tauri/src/git.rs) — защита от
  инъекции), локально через `tokio::process`. Бэкенд **дамповый исполнитель**: вся
  сборка аргументов и парсинг вывода — чистая логика в [git.ts](../src/lib/git.ts)
  (`statusArgs`/`logArgs`/…, `parseStatus`/`parseLog`/`parseBranches`/`parseDiff`,
  `buildGraph` — раскладка дорожек графа, `isDestructive`), вид — в
  [gitview.ts](../src/lib/gitview.ts). Не дублируй git-логику в компонентах и не
  вводи новых per-операционных бэкенд-команд — расширяй через новые билдеры/парсеры
  в `.ts`. `GIT_TERMINAL_PROMPT=0` **обязателен** (промпт кредов без TTY → быстрая
  ошибка, не зависание). **Сетевые** операции (`fetch`/`pull`/`push`) — **только по
  явной кнопке** (часть офлайн-инварианта: remotes — серверы пользователя, трафик из
  Rust); локальный `status`/`log` авто-обновляется при смене cwd. **Прод-защита**:
  на прод-вкладке (`isProdServer`) деструктивные операции (`isDestructive`) — через
  `ConfirmDialog` (предохранитель, не граница). Диффы — унифицированные (`parseDiff`
  + [GitDiffView.svelte](../src/lib/GitDiffView.svelte)), не MergeView — но **только для
  файлов исторических коммитов** (read-only). **Изменённый файл рабочего дерева**
  открывается для правки в **существующем** [EditorTab](../src/lib/EditorTab.svelte)
  как редактируемый инлайн-diff против HEAD (CodeMirror `unifiedMergeView`): HEAD-версия
  тянется `showFileAtArgs("HEAD", path)` и кладётся в `EditorDoc.gitBase` — новый редактор
  не плодим. Тумблер «выполнять checkout в терминале» пишет команду в PTY (аудит), а не
  подменяет `git_run`. **Аудит в записи**: мутирующие `git_run` (флаг `mirror`) пишутся в
  активную запись сессии как `[git] $ … / [git] exit N` (`git::git_mirror`) **только через
  `record_output`** — в живой терминал не эмитятся (GUI чистый), чтения не пишутся.
  **Двусторонняя OSC 7**: навигация в SFTP-панели при активном «следовать за терминалом»
  шлёт `cd` в PTY (`cdTerminalTo`) — только на пользовательских переходах, чтобы не было
  петли с follow-эффектом. **Аудит-контракт остаётся**: секретов git не логирует, деструктив
  на проде — через `ConfirmDialog`.
- **Утилиты — генерация SSH-ключей** (Фаза 32). Первая «утилита» приложения; живёт в
  **панели «Утилиты»** (Фаза 33, ниже — переехала из настроек), инструмент `keys`.
  Генерация — **локальная и офлайн**: крейт `ssh-key` (тот же, что тянет
  `russh`), CSPRNG из `rand`, **без сети и без вызова внешнего `ssh-keygen`** (офлайн-
  инвариант цел). Бэкенд [keygen.rs](../src-tauri/src/keygen.rs) — **дамповый
  исполнитель**: одна команда `generate_ssh_key` пишет то, что описала **чистая логика**
  [sshkeygen.ts](../src/lib/sshkeygen.ts) (реестр алгоритмов, дефолтное имя по типу,
  сборка пути, валидация). Приватный ключ — `0600`, `~/.ssh` — `0700`; passphrase — в
  `Zeroizing`, **не логируется и не пишется в keychain** (штатный secret-prompt при
  коннекте). Коллизия без `overwrite` → типизированная `AppError::KeyExists` (маркер
  `key-exists`, как `dest-exists`) — **тихой перезаписи нет**, только явный выбор
  «перезаписать / изменить имя». UI — общий [KeyGenModal.svelte](../src/lib/KeyGenModal.svelte)
  за двумя входами (панель «Утилиты» → инструмент `keys` и шорткат в форме сервера,
  подставляющий `keyPath`); новых утилит-команд не плоди — расширяй билдеры/парсеры в `.ts`.
- **Панель «Утилиты»** (Фаза 33). Набор инструментов DevOps/SRE живёт в **отдельной
  панели-оверлее** ([UtilitiesPanel.svelte](../src/lib/UtilitiesPanel.svelte),
  `z-index:40`, как настройки), **не** в секциях настроек (инструмент нужен рядом с
  терминалом, а не в модалке настроек). Вход — кнопка `wrench` в
  [TopBar](../src/lib/TopBar.svelte) и командная палитра. Список инструментов —
  **чистый реестр** [utilities.ts](../src/lib/utilities.ts) (`id`/иконка/i18n-ключ/
  keywords, поиск `utilitiesMatching`); панель только мапит по нему и переключает
  компонент. **Каждый инструмент = чистая логика в `.ts` (с тестом) + тонкая
  UI-оболочка `Util*.svelte`** (форма/таблица без логики). Всё **офлайн**: codec/cidr/
  timeconv/cron/pwgen/jwt — без сети и без бэкенда; CSPRNG паролей —
  `crypto.getRandomValues`, словарь passphrase встроен ([wordlist.ts](../src/lib/wordlist.ts)).
  **Бэкенд — только там, где нужен файл/ОС**: known_hosts-менеджер ходит в
  `list_known_hosts`/`remove_known_host` (дамповый исполнитель над
  [store.rs](../src-tauri/src/store.rs)), парсинг/сортировка вида — чистый
  [knownhosts.ts](../src/lib/knownhosts.ts). Копирование — общий примитив
  [CopyButton.svelte](../src/lib/CopyButton.svelte). Новый инструмент добавляй так же:
  запись в реестр + `Util*.svelte` + чистый `.ts` с тестом (UI-оболочку — в exclude

- **Текст файлов — кодировка определяется и сохраняется** (Фаза 39). Читатели редактора
  (`sftp::read_text`, `localfile::read_text`) **не** предполагают UTF-8: определение и
  round-trip живут в [textenc.rs](../src-tauri/src/textenc.rs) (BOM → BOM-less UTF-16 по
  NUL-паттерну → валидный UTF-8 → `chardetng` для легаси-кодовой страницы). Только последний
  шаг — догадка; шаги 1–3 точные, поэтому всё, что открывалось раньше, round-trip'ится байт
  в байт. **Проверка «бинарности» идёт ПОСЛЕ sniff'а UTF-16** — иначе перемежающиеся NUL'ы
  UTF-16 читаются как бинарь (именно так `.ini` на Windows «не открывался»). Метка кодировки
  едет `TextFile.encoding` → `EditorDoc.encoding` → обратно в команду записи, и файл
  **пишется в исходной кодировке**: молча переписать чужой UTF-16/CP1251-конфиг в UTF-8
  нельзя — владеющая им программа перестанет его читать. Следствие: `sha256` для проверки
  конфликтов считается по **сырым байтам** (не по декодированному тексту), иначе сравнение с
  прочитанными при записи байтами разъезжается на не-UTF-8. Новый источник текста подключай
  через `textenc::decode`/`encode`, а не собственным `from_utf8`.
- **Путевая арифметика — чистая и сепаратор-осознанная** (Фаза 39). `isRoot`/`parentOf`/
  `joinPath`/`sep`/`baseName`/`isUnder` живут в [fspath.ts](../src/lib/fspath.ts), а не
  копиями внутри панелей (как было до Фазы 39 — отсюда «`..` в корне `C:\`» и путь `/`).
  Корнями считаются POSIX `/`, корень диска (`C:\`, `C:/`, `C:`) и UNC-шара
  (`\\server\share`); сравнение путей на Windows — регистронезависимое и агностичное к
  сепаратору. SFTP-панель всегда POSIX, локальная получает нативные пути — но обе ходят
  через один модуль, поэтому Windows-регрессии ловятся тестами на macOS. Не заводи `parentOf`
  «по месту» в компоненте.
  - **Навигация и файловая семантика — разные вопросы** (Фаза 39.1). `isRoot`/`parentOf`
    отвечают на **файловый** вопрос (корень диска — настоящий корень ФС), а `navParent` — на
    **навигационный** («куда ведёт `..`»), и на Windows он выше корня диска ведёт на
    синтетический уровень списка дисков `DRIVES_ROOT` (Explorer'овский «Этот компьютер»),
    иначе `D:` недостижим — строка пути панели read-only. Не растягивай `isRoot` под
    навигацию: на нём построены `trimTrailing`/`baseName`, и они тихо поедут. Синтетический
    уровень **обязан** иметь явный сентинел (`"::drives"`), а не перегружать пустую строку —
    `cwd` панели кратко пуст при монтировании. Бэкенд матчит сентинел в `localfile::list`,
    поэтому остальная навигация панели (курсор, виртуализация, клавиатура, drag-drop) не
    знает о нём вовсе. На синтетическом уровне **все мутации запрещены** — и в UI, и в самих
    функциях. Новый синтетический уровень (например, список шар UNC) добавляй так же.
  - **Перечисление дисков не должно трогать тома** (Фаза 39.1, [drives.rs](../src-tauri/src/drives.rs)).
    `GetLogicalDrives` даёт полный список букв мгновенно и **без обращения к устройствам**;
    метка тома и свободное место требуют обращения, поэтому читаются **только** для
    локальных дисков (`should_enrich`). Обращение к отвалившейся сетевой шаре блокируется на
    SMB-таймаут — панель зависнет при каждом подъёме в корень. Не заменяй это на перебор
    `A:\`…`Z:\` через `fs::metadata` (та же ловушка) и не расширяй обогащение на
    `remote`/`cdrom`. Закреплено тестом `never_probes_network_or_optical_drives`.
- **«Следовать за терминалом» — один контракт, два транспорта** (Фаза 39.3). Как у метрик
  (Фаза 38), источник cwd выбирается **по наличию локального PTY**, а не по ОС: у локальной
  вкладки есть pid оболочки → каталог читается у ОС ([proccwd.rs](../src-tauri/src/proccwd.rs)
  поверх `sysinfo`; Linux `/proc`, macOS `proc_pidinfo`, Windows PEB), у SSH-вкладки pid'а нет
  → остаётся OSC 7 / OSC 9;9 от удалённого шелла. **Нельзя** строить эту фичу только на OSC:
  стоковые шеллы молчат (zsh на macOS эмитит OSC 7 лишь при `$TERM_PROGRAM=Apple_Terminal`,
  PowerShell/`cmd.exe` — никогда), и подменять `TERM_PROGRAM`, чтобы их разговорить, тоже
  нельзя — это ложь, и она включает постороннюю машинерию сессий Apple. Оба канала работают
  **параллельно**: событие от шелла обновляет панель мгновенно, опрос — раз в секунду и только
  пока тумблер включён. Отказ чтения cwd — **штатный** `None` (Windows читает чужую память),
  панель при этом не двигается, а не прыгает в корень. Диалог с предложением вписать сниппет
  показывается **только** там, где он нужен — предикат `needsShellSetup`, не проверка ОС по месту.
  - **Обратное направление (панель → терминал)** идёт **только** на действиях пользователя и
    **только** при включённом тумблере; переход, сделанный панелью при следовании за
    терминалом, зеркалить обратно нельзя — получится петля. Команда строится чистым
    [cdterminal.ts](../src/lib/cdterminal.ts) **под реально запущенную оболочку**: POSIX-форму
    нельзя слать в `cmd.exe` (там `'` не кавычки, и без `/d` смена диска не переводит туда) и
    в PowerShell (внутренняя кавычка удваивается, нужен `-LiteralPath`). Диалект фиксируется
    на сессию в момент спавна, а не берётся из текущей настройки — вкладка живёт со своей
    оболочкой. Путь, который нельзя выразить безопасно (пустой, с переводом строки), даёт
    `null` — тогда **не шлём ничего**, а не покалеченную строку.
  - **Команда в PTY завершается CR, а не LF** (Фаза 39.5). Enter — это `\r`; `\n` проходит на
    Linux/macOS лишь потому, что readline/ZLE вешают `Ctrl+J` на `accept-line`, а PSReadLine и
    `cmd.exe` этого не делают — команда молча повиснет в промпте. Многострочный блок переводи
    **построчно** (иначе на Windows выполнится только последняя строка — тихий и частичный
    провал). Единственный источник истины — `submitLine`/`submitBlock` в
    [terminput.ts](../src/lib/terminput.ts); закреплено гейтом `terminput.guard.test.ts`.
- **Офлайн-инвариант.** Никаких runtime-обращений в сеть, кроме исходящего SSH к
  серверам пользователя (в т.ч. **через заданный им proxy** — jump host/SOCKS5/HTTP
  CONNECT, Фаза 21 — это часть пути к его же серверам) **и** — при включённом opt-in
  ИИ-ассистенте (Фаза 17) — исходящего к **пользовательскому** LLM-эндпоинту. Весь
  прокси-трафик идёт из Rust-бэкенда ([ssh.rs](../src-tauri/src/ssh.rs)), не из WebView.
  Шрифты встроены (`@fontsource`),
  внешние ссылки — только по явному клику через `tauri-plugin-opener`. **Весь
  LLM-трафик идёт из Rust-бэкенда** ([ai.rs](../src-tauri/src/ai.rs), `reqwest`), не
  из WebView, поэтому CSP остаётся строгим, а фронтенд по-прежнему не делает сетевых
  вызовов. ИИ **выключен по умолчанию**, зашитых облачных эндпоинтов нет (все —
  пользовательские). **Контекст сессии** (выделение/буфер/запись/метаданные) уходит к ИИ
  **только** после маскирования секретов ([redact.ts](../src/lib/redact.ts), маркер `‹redacted›`)
  **и** явного согласия пользователя ([AiConsentDialog.svelte](../src/lib/AiConsentDialog.svelte)) —
  в том числе на локальный эндпоинт. **Исполнение команд** ([aiexec.ts](../src/lib/aiexec.ts) +
  [AiChat.svelte](../src/lib/AiChat.svelte)): предложенные команды попадают в терминал только по
  режиму `execMode` (`suggest`/`confirm`/`dialog`/`dialogConfirm`); **диалоговые режимы никогда
  не запускаются на прод-сервере** (тег `prod`/`production`, `isProdServer`), а выполненные команды
  пишутся в запись как аудит. **Флаг сервера `noAi`** (прод-защита) полностью **блокирует контекст и исполнение** для
  такого сервера — ассистент не получает его данные и не выполняет на нём команды. Закреплено гейтом
  [autonomy.guard.test.ts](../src/lib/autonomy.guard.test.ts). (ADR 0004)
  **Прод-детект — контракт точного тега** (Фаза 20.3): `isProdServer` матчит тег,
  равный `prod`/`production` (регистронезависимо, с trim); **не расширяй** до
  substring/токен-матчинга — иначе `non-prod`/`pre-prod` (staging) ложно попадут под
  прод-защиту и потеряют диалоговое исполнение. Наследования `prod`/`noAi` через
  папки-группы нет (папка — строковая метка). Deny-list опасных команд
  (`isDangerousCommand`) и маскирование (`redact.ts`) — **не** границы безопасности,
  а предохранители (bias: over-flag/over-mask); границы — прод/noAi-гейт + consent.
  Полный аудит и остаточные риски — в [SECURITY.md](../SECURITY.md#аудит-ии-агента-фаза-20).
- **Безопасность.** CSP в `tauri.conf.json` держи строгим (никаких удалённых
  origin'ов; не возвращай `csp: null`); capabilities — минимально необходимые
  (opener только `https://`, без `dialog:default`/`fs`/`dangerous*`). Секреты —
  только в keychain, оборачивай копии в `zeroize::Zeroizing`, **никогда не логируй**.
  Host-key дефолт — не «accept». Зависимости проходят `cargo audit`/`cargo deny`/
  `pnpm audit`/Semgrep (стадия `security` в CI). Гейты:
  [tauri-security.guard.test.ts](../src/lib/tauri-security.guard.test.ts), `deny.toml`.
  Полная модель — [SECURITY.md](../SECURITY.md).
  **Следствие строгого CSP для CodeMirror (Фаза 36.4):** в `tauri build` Tauri штампует
  пер-загрузочный nonce в `style-src`, а он по спецификации отменяет `'unsafe-inline'` →
  runtime-`<style>` CodeMirror без nonce блокируется (`.sheet === null`), и **ни одно** его
  правило не применяется (раскладка/цвета/подсветка) — только в упакованной сборке (в `dev`
  страницу отдаёт Vite без CSP). Поэтому **любой** новый `EditorView` обязан включать
  `cspNonceExtension()` из [cspnonce.ts](../src/lib/cspnonce.ts) (фасет `EditorView.cspNonce` с
  style-nonce из инлайнового `<style>` в app.html). Общий style-module CodeMirror создаётся на
  **первом** view, поэтому nonce должны отдавать все (EditorTab, DiffModal, будущие). Чинить это
  дублированием стилей CodeMirror в app.css **нельзя** (симптом-патч, не покрывает цвета/подсветку —
  их классы генерируются). CSP при этом **не ослабляем** (`'unsafe-inline'` не добавляем).
  Закреплено гейтом [cspnonce.test.ts](../src/lib/cspnonce.test.ts).
