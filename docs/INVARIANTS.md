# Инварианты vterm

Канон кодовой базы — **что обязан соблюдать и чего нельзя**; нарушать без явного решения
нельзя. Пункт — это правило, причина одной фразой и гейт, который его держит. Разборы,
история и отвергнутые альтернативы — в [adr/](adr/), устройство — в
[ARCHITECTURE.md](ARCHITECTURE.md), правила процесса — в [../AGENTS.md](../AGENTS.md). Файл
подставляется в контекст **каждой** сессии, поэтому объяснение длиннее фразы уходит в ADR, а
сюда — ссылка; бюджет держит гейт `docs.guard`.

## Сквозные принципы

Разделы ниже — применение этих девяти. Частное правило, противоречащее принципу, — ошибка.

1. **Граница фронт/бэк** (ADR 0001, 0036). Логика SSH/SFTP/секретов/файлов — в Rust
   (`src-tauri/src/`); Svelte ходит к ней только через `invoke()` и каналы событий (`term://`,
   `sftp://`, `sync://`, `menu://`, `install://`, `ai://`, `window://`). Новая команда — в своём
   доменном модуле + типизированная обёртка в [src/lib/api/](../src/lib/api/); `lib.rs` только
   регистрирует её как `модуль::имя`. Команды поверх общего `AppState` и приватные мосты
   (`get_sftp`/`record_sftp`/`run_driver`) — слой-мост [commands/](../src-tauri/src/commands/) по
   доменам; новый файл моста вносится в `commands::BRIDGE` (гейт
   `the_bridge_source_lists_every_command_module`). Бизнес-логику на фронте не дублируем.
2. **Бэкенд — дамповый исполнитель, чистая логика — в `.ts`** (ADR 0003, 0005). Сборка argv,
   парсинг, валидация, раскладки, маппинги — свободные функции `.ts` с тестами (без DOM и
   сети), не `.svelte` и не команды. В Rust так же: `reprefixed`, `textenc::decode`, парсеры
   [metrics/mod.rs](../src-tauri/src/metrics/mod.rs).
3. **Один контракт — два транспорта.** Транспорт выбирается **по наличию сессии**, а не по ОС
   и не отдельной командой: SSH-сессия → `exec_captured`/`run_command`, локальный PTY →
   `tokio::process` или нативный коллектор.
4. **Расширяем билдерами, а не командами.** Новая операция драйвера — билдер/парсер в `.ts`;
   новый канал событий — только под другой **сорт** данных (`term://phase` рядом с
   `term://out`, `ai://think` рядом с `ai://out`).
5. **Честно или никак** (ADR 0009). Правдоподобная заглушка вместо неизвестного запрещена:
   неизвестное — `None`/«—»/явная пометка; «нет данных» и «здесь невозможно» — **разные**
   сообщения.
6. **Офлайн** (ADR 0004). Сеть в рантайме — только исходящий SSH к серверам пользователя (в т.ч.
   через **его** proxy) и названные исключения: opt-in ИИ — к **его** LLM-эндпоинту; «Проверка
   доступа» с локальной вкладки — рукопожатие или **его** `bash`/`nc`/`telnet`/`curl` (ADR 0012,
   0033); **его** `curl`/`openssl` в TLS-инспекторе и HTTP-клиенте (ADR 0014); проверка и
   скачивание релиза GitHub по явному действию (ADR 0031). Такой трафик идёт только из Rust:
   фронт сетевых вызовов не делает (`vterm/no-network`), CSP строгий; проксировать загрузку
   картинок или данных через Rust — то же обращение в сеть. Шрифты встроены, внешние ссылки —
   только по клику через `tauri-plugin-opener`; диагностика хоста исполняется на хосте сессии.
   Сокеты приложения — только в `ssh.rs` и `netcheck.rs` (гейт
   `app_originated_sockets_live_only_in_ssh_and_netcheck`).
7. **Границы и предохранители — не одно и то же.** Границы: прод-/`noAi`-гейт в бэкенде, окно
   согласия ИИ, keychain, CSP, capabilities, политики argv (ADR 0036). Предохранители (bias:
   over-flag/over-mask): deny-list опасных команд, `needsConfirm`/`ConfirmDialog`, маскирование
   секретов. Одно не заменяет другое.
8. **Ошибки типизированы** (ADR 0002). Rust возвращает `AppResult<T>`
   ([error.rs](../src-tauri/src/error.rs)), не `String`; семантика — свои варианты
   (`AuthRejected`, `HostKeyRejected`, `NoSession`, `UnknownServer`, `KeyExists`,
   `FileChangedOnServer`), прочее — `AppError::Message`. Сериализуется в строку, маркеры
   (`auth-rejected`, `key-exists`, `dest-exists`, `file-changed`) — в `Display`. `std::sync::Mutex`
   берётся только через `.locked()`: отравленная блокировка иначе роняла бы каждую следующую
   команду над тем же реестром (гейт `a_poisoned_lock_never_cascades`).
9. **Контракт типов — camelCase.** Rust-модели — `#[serde(rename_all = "camelCase")]`, зеркало
   в [types.ts](../src/lib/types.ts); новые поля старых структур — `#[serde(default)]`.

## Терминал и вкладки

Разборы — [ADR 0037](adr/0037-terminal-input-and-connect.md).

- **Единый контракт терминала.** SSH ([ssh.rs](../src-tauri/src/ssh.rs)) и локальный PTY
  ([pty.rs](../src-tauri/src/pty.rs)) — один канал `term://out|closed/{id}` и одни команды
  (`write_to_terminal`/`resize_pty`/`disconnect`) по `session_id`, поэтому
  [Terminal.svelte](../src/lib/Terminal.svelte) общий (проп `local`); новый вид терминала —
  сюда же. Поверх него, **без нового бэкенда и канала**: синхронный ввод (N вызовов из
  `doBroadcast`, логика — [broadcast.ts](../src/lib/broadcast.ts), на прод — с подтверждением),
  выбор шелла (та же `open_local_terminal` с `shell` из `resolveLocalShell`; ОС — команда
  `host_os`, не runtime-плагин), shell в
  контейнер/под и `port-forward` — новая вкладка хоста, команда уходит в PTY по `connected`, не
  через `container_run`/`kubectl_run`.
- **Shell контейнера кончается вместе с контейнером.** Вкладка с `Tab.attach`
  ([tabattach.ts](../src/lib/tabattach.ts)) подписана «nginx · хост», поэтому команду печатает
  `renderSessionCommand` (`exec …`/`…; exit`/`… & exit`): иначе после `exit` под именем
  контейнера остался бы шелл хоста. Её конец — не обрыв: ни автопереподключения, ни NO SIGNAL;
  argv исполняется на **каждом** `connected`. Гейт `attachtab.guard`.
- **Строка для терминала собирается под запущенную оболочку.** Панели отдают argv, строку
  собирает `renderArgv` ([termcmd.ts](../src/lib/termcmd.ts)) под оболочку вкладки, как
  `cdCommand`: POSIX-строка в `cmd.exe` разваливается. Неэкранируемый токен → `null` → не шлём
  ничего.
- **Команда в PTY завершается CR, а не LF**, многострочный блок — построчно: PSReadLine и
  `cmd.exe` не считают `\n` Enter'ом. Источник — `submitLine`/`submitBlock`
  ([terminput.ts](../src/lib/terminput.ts)), правило `vterm/submit-with-cr`.
- **Ввод в сессию идёт строго по порядку.** Два `invoke("write_to_terminal")` в полёте доходят
  до PTY в любом порядке, поэтому `writeToTerminal` ([termwrite.ts](../src/lib/termwrite.ts))
  шлёт следующую запись после ответа на предыдущую, склеивая накопленное; команду зовёт только
  он (`vterm/terminal-write`).
- **Окно подключения — честный чек-лист.** Фазы
  [ConnectingOverlay](../src/lib/ConnectingOverlay.svelte) — реальные события
  `term://phase/{id}` (`connecting`→`authenticating`→`session`), маппинг —
  [connphase.ts](../src/lib/connphase.ts); новая обязательная стадия = `emit` в `connect` +
  запись в `PHASE_ORDER`, не новый канал. Прокси-подстадии — тоже реальные события, вне
  `PHASE_ORDER` (`phaseSteps(current, errored, proxy)`), чек-лист всегда вложенный. Тот же
  компонент — экран ошибки (`failed`, маппинг — `sshErrorView`); провал аутентификации не
  закрывает вкладку (`reauth`). Верхняя плашка — только у локальных вкладок; анимации — только
  `transform`/`opacity`.
- **Вкладка закрывается ровно одним путём — `closeTabFully`** в `+page.svelte`. Под
  `sessionId` живут workspace, чат ИИ, членство в broadcast, nginx-кэш, состояние доков; сырой
  `closeTab` стора — только операция над списком, и зовёт его только `closeTabFully`
  (`vterm/owned-imports`); `tabsForServer` возвращает id и не закрывает ничего — массовое
  закрытие в сторе потянуло бы зависимость на workspaces/aichat. Новое состояние по
  `sessionId` — очистка в `closeTabFully`. Он же завершает сессию (см. «Окна»). Гейт
  `tabteardown.guard`.
- **Центр — дерево областей, терминалы — один плоский список** (ADR 0016). Раскладка — чистое
  дерево [splitlayout.ts](../src/lib/splitlayout.ts), терминал ставится по прямоугольнику
  своей области (`layoutRects`). `Terminal` рисует **один** `{#each tabsState.list}`, его
  монтирование не зависит от раскладки (ни `{#each}` по областям, ни `{#if}` на сплит, ни
  `{#key}` кроме `tab.gen`): пересозданный терминал переподключается с пустым scrollback.
  - Раскладку меняет только чистая модель: стор присваивает дереву результат функции
    `splitlayout.ts` (`$state.raw`), у `tabsState` нет сеттеров.
  - `tabsState.activeId` — производная (вкладка области в фокусе), а не поле; меняют её
    `activateTab` и `focusPane`.
  - Пустых областей нет: область появляется со вкладкой (`splitWithTab`) и исчезает с
    последней; отменённый запрос пароля не меняет ничего.
  - Открытие вкладки не прячут в аргумент необязательного вызова: `place?.(openTab(…))` без
    `place` не открывает ничего.
  - Предел — по пикселям (`PANE_LIMITS`, `canSplit`), а не по счёту.

  Гейт `centerlayout.guard`.
- **Файл показывается внутри своего соединения; область соединения делится на зоны**
  (ADR 0024). В центре — только соединения; у соединения свои виды (терминал и файлы) и своя
  раскладка зон в сторе рабочих пространств — тем же деревом, что центр
  ([sessionviews.ts](../src/lib/sessionviews.ts)).
  - Раскладку зон меняет только чистая модель; документ и его вид появляются и исчезают одним
    шагом (`addEditor`/`closeEditor`), больше никто документы не добавляет и не убирает.
  - Новый файл встаёт к файлам (`fileZone`), а не поверх терминала, в котором печатают.
  - Редакторы — один плоский список на соединение: пересозданный теряет отмену, курсор и
    прокрутку; монтирование не зависит от зон и `tab.gen`.
  - Полоса видов есть, только пока открыт файл. «На экране» — когда показан терминал: иначе
    запись на паузе, вопрос о входе ждёт; клавиатуру после подключения терминал берёт, только
    если в фокусе и его область, и он сам.
  - Несохранённые правки не закрываются без вопроса — даже у мёртвой сессии; массовое
    закрытие такое соединение оставляет.
  - В другое окно соединение уезжает со своими зонами, раскладка перестраивается (`loadViews`).
  - Прод — вокруг всего соединения: рамка обводит и его файлы.
  - Вид перетаскивают только внутри своего соединения
    ([viewdrag](../src/lib/stores/viewdrag.svelte.ts)): раскладка меняется при отпускании
    (`dropSessionView`), цель — только в области своего соединения (`data-views-of`), метка
    останавливается у её края (`confinedGhost`). Три пути: перетаскивание, меню вида, ⌘K.

  Гейт `sessionviews.guard`.
- **Синхронный ввод — способ отправки, а не вид** (ADR 0022). Участники стоят в областях
  центра, своей раскладки у группы нет. «Показать всех» — команда раскладки `tileTabs` (сетка —
  дерево сплитов, предел — `gridFit`, не поместившиеся названы); `untilePanes` возвращает
  раскладку до сетки через `loadLayout`. Участник вне экрана назван списком рядом с областями.
  Гейт `centerlayout.guard`.
- **«На экране» — показанная вкладка каждой области**, если её соединение показывает терминал
  (`onScreenSessions`, [centerview.ts](../src/lib/centerview.ts)). От этого набора — запись
  (остальные на паузе) и вопрос о входе (сперва для вкладки в фокусе); то, что следует за одной
  сессией (доки, статус-бар, контекст ИИ, заставка, заголовок окна), читает
  `tabsState.activeId`. Клавиатуру после подключения берёт только терминал области в фокусе
  (`focusOnConnect`). Пока область одна, полоса вкладок одна — над центром.
- **После перезапуска возвращается вкладка, а не сессия** (ADR 0019). Вернувшаяся вкладка ждёт
  (`Tab.waiting`; для остального — `offline`). Кто подключается сам, решает только `waitReason`
  ([tabrestore.ts](../src/lib/tabrestore.ts)): контейнер, прод и сервер с секретом не из
  keychain ждут кнопки в любом режиме; `off`/`manual` при запуске не ходят в сеть и в keychain.
  Открывает сессию контроллер [restoreflow](../src/lib/page/restoreflow.svelte.ts). Запись
  вкладки собирается по полям (`savedTab`) — ни пароля, ни вывода на диске; сохранённое дерево
  перестраивается (`loadLayout`). Слот на окно (`vterm.tabs:<метка>`); восстанавливает только
  главное окно — один раз, после каталога серверов, и не пишет слот, пока не прочитало прошлый;
  окно, закрытое с подтверждением, слот стирает. Секрет ждущей вкладке вводят на месте
  (`SecretPrompt` с `forTab`). Гейт `tabrestore.guard`.
- **Перетаскивание вкладки терминала меняет раскладку один раз — при отпускании**
  ([tabdrag](../src/lib/stores/tabdrag.svelte.ts)): до него полосы рисуют `previewTabs`, а
  область — подсветка; перенос на каждое движение слал бы терминалам `SIGWINCH` на пиксель.
  Цель решает модель (`paneZone`/`applyDrop`), бесполезная не предлагается, слот — по
  `layoutBox`. Три пути: мышь, меню вкладки, ⌘K. Общие правила перетаскивания — в «UI и
  оформление».
- **Прод — флаг профиля, а не тег.** `isProdServer` читает `ServerProfile.prod`; для `prod: null`
  (профиль до флага) — точный тег `prod`/`production` (`isLegacyProdTag`, регистронезависимо, с
  trim), иначе обновление молча сняло бы защиту. Форма пишет флаг всегда явно. Legacy-матчинг
  не расширять: `non-prod` попал бы под защиту. Наследования `prod`/`noAi` через папки нет. У
  бэкенда то же правило — `ServerProfile::is_prod`.
- **Прод виден в двух местах:** чип `prod` на вкладке и красная рамка вокруг области
  соединения — терминала с его файлами (набор — `prodTabIds` из `prodMembers`). Рамка —
  инертный оверлей (`pointer-events-none`, `z-index`) поверх контейнера, а не border/padding
  терминала (его меряет `FitAddon`), и начинается под верхним рядом полос видов. Линию сверху
  несёт только активная вкладка (2px) и вид в фокусе (1px), источник — `activeTabStrip`
  ([tabstrip.ts](../src/lib/tabstrip.ts)). Фон прод-терминала подкрашен (`settings.prodTint`,
  `mixHex`), и одна `paintedTheme` красит canvas и полоску отступа. Гейт `prodmark.guard`.

## Окна

Вкладку и область можно вынести в окно ОС и перенести в другое открытое (ADR 0017, 0018,
0023). Окно — отдельный WebView со своей памятью, поэтому всё, о чём окна договариваются,
живёт в бэкенде ([appwin.rs](../src-tauri/src/appwin.rs)). Разборы — [ADR 0038](adr/0038-windows-and-tab-drag-details.md).

- **Окно — та же страница, роль — по метке** (`main`/`win-N`,
  [appwindow.ts](../src/lib/appwindow.ts)). Передачу ведёт контроллер
  [windowflow](../src/lib/page/windowflow.svelte.ts) (`detachTab`, `handOver`, `dropOutside`,
  `tellDragOver`, `adoptFailed`); «урезанной» страницы нет. Создаёт окна только Rust (гейт
  `tauri-security.guard`).
- **Главное окно — якорь:** его закрытие — выход; только оно пишет раскладку доков,
  восстанавливает вкладки, забирает «Открыть с помощью» (`take_pending_opens`) и предупреждения
  хранилища. Второе окно появляется выносом вкладки и закрывается с последней.
- **Сессию завершает `closeTabFully`, а не компонент.** `Terminal.svelte` не зовёт `disconnect`:
  вкладка, отданная другому окну, размонтирует терминал, а сессия живёт. Бэкенд помнит
  окно-владельца, чужой `disconnect` игнорирует, сессии уничтоженного окна завершает сам; из
  реестра сессия уходит только в `end_session`. Без завершения (`closeTabFully(id, true)`)
  вкладка уходит, только если её приняло другое окно или это окно не смогло её принять. Гейт
  `a_session_ends_in_one_place_and_only_for_its_owner`.
- **Вывод терминала — только через затвор** ([outgate.rs](../src-tauri/src/outgate.rs)): эмит
  мимо него минует придержку при передаче, и байты пропадут. Гейт
  `terminal_output_goes_only_through_the_gate`.
- **Передача: придержать → снять → передать → отпустить.** `detach_begin` → снимок xterm, когда
  терминал получил все ушедшие события (сверка счёта, а не пауза) → `detach_commit` → вкладка
  убирается. Принимающее окно подписывается на вывод, пишет снимок в той же сетке и только
  потом зовёт `attach_session`. Сбой до этого — откат (`gate.resume()`). Придержанное
  ограничено `HOLD_CAP`: переполнение — откат с сообщением.
- **Пакет вкладки — только через IPC и только в памяти** (`Zeroizing`, одному окну, один раз):
  в нём пароли; `localStorage` и `BroadcastChannel` запрещены.
- **Открытое окно принимает вкладку тем же путём и от этого не закрывается** (ADR 0018). Цель —
  окно, назвавшее себя принимающим (`announce_window`) **после** подписки на
  `window://handoff`, не отдающее и не занятое другой передачей (`takes_tabs`). Откат закрывает
  окно только `if created`; окно, которому вкладка не досталась (`adoptFailed`), закрывается,
  только если других вкладок нет; не могущее принять — отказывается сразу (`decline_handoff`).
  Гейты `windowhandoff.guard`, `a_failed_handoff_never_closes_a_window_that_was_already_open`.
- **Окно под указателем спрашивают у ОС — точно или никак**
  ([winhit.rs](../src-tauri/src/winhit.rs)): прямоугольники и порядок фокуса не знают, что
  окно перекрыто, свёрнуто или на другом столе. Место указателя внутри окна — тоже от ОС
  (`contentLayoutRect`, `ScreenToClient`, `page_origin`). Где оконная система не отвечает
  (Wayland, X11 поверх Wayland — `asks_an_x_server`), цели нет: бросок открывает новое окно.
  Решает отпускание (`drag_drop`). Гейт
  `the_window_under_the_pointer_is_asked_of_the_os_never_guessed`.
- **Вкладку над чужим окном рисует это окно — и до её прибытия ничего в себе не меняет.**
  `drag_over` → `window://drag` → предпросмотр
  ([tabincoming](../src/lib/stores/tabincoming.svelte.ts), `previewIncoming`; стор знает стор
  вкладок только по типу); вкладка встаёт один раз (`placeTab`), не «открыть и переставить».
  О перетаскивании говорится по порядку и до конца: `over` по одному, `left` и отпускание ждут
  отправленного, каждый конец без прибытия — `drag_end`; место держится (`landing`) не дольше
  `LANDING_TIMEOUT_MS`. Вкладка, которую нельзя перенести, никому не показывается. Гейты
  `windowhandoff.guard`, `centerlayout.guard`.
- **Окно под указателем выходит вперёд** (`raise_window`, раз на заход — `Registry::raise`),
  поэтому при других окнах о вкладке сообщается на каждом движении, и где указатель — решает
  ответ бэкенда (`tabDrag.window`), а не границы своего окна.
- **Над рабочим столом вкладку рисует окно-метка — картинка, а не участник**
  ([dragghost.rs](../src-tauri/src/dragghost.rs)): без фокуса, прозрачно для мыши, с меткой
  `drag-ghost` вне прав и списка окон, показывается после загрузки своей страницы. На Linux
  его нет — метка остаётся у края окна с подписью. Гейт
  `the_floating_label_is_a_picture_and_never_a_window_of_the_app`.
- **Выносится только то, что можно вынести целиком** (`detachBlocker`,
  [tabhandoff.ts](../src/lib/tabhandoff.ts)): сравнение, синхронизация, ответ ИИ и сохранение
  файла держат вкладку. Новая работа «в полёте» по сессии — в `DetachState` или бэкенду.
  Состояние вкладки собирают `packTab`/`unpackTab`; новое состояние по сессии — в обе.
- **Область уходит целиком — передачей на вкладку, одной и той же** (`handOver`, ADR 0023):
  целиком или никак, решается до первой вкладки (`paneMoveBlocker`) и заново перед каждой;
  первой уходит показанная, остальные встают за ней (`paneMoveOrder`, `PaneSeat`,
  `addTabBehind`); новое окно ждут по событию `window://windows`.
- **Событие без id в имени — одному окну, и слушают его `listenHere`:** обычный `listen` слышит
  посланное другому окну.
- **Общее для окон — через бэкенд:** настройки — снимком (`window://settings`), запись
  каталога — `window://catalog` (хук в `store.rs`), «один прогон синхронизации» — замок
  `SyncBusy`. Куда скопировать файл, окна сообщают друг другу (`announce_copy_targets` →
  `window://targets`); чужой список читается, а не принимается на веру (`foreignTargets`).
- **Три точки входа:** меню вкладки, ⌘K и бросок за окно (`releasedOutside`).

## Панели-драйверы

Git, Docker, k8s, сетевые пробы и метрики — **один контракт исполнения** (ADR 0005): одна
бэкенд-команда на драйвер (`session_id` + argv), транспорт по принципу 3, argv и разбор —
чистый `.ts`, вид — `*.svelte`. Разборы — [ADR 0039](adr/0039-docks-and-drivers-in-practice.md), метрики — [ADR 0040](adr/0040-host-metrics-raw-readings.md).

- **argv драйвера проходит политику в Rust на обоих транспортах** (ADR 0036): `git::check_args`,
  `container::check_args` (`docker login` — только `docker_login`), `kube::check_args`, локально
  у проб — `netprobe::local_program_allowed`. Новая подкоманда фронта сперва вносится в
  политику и в тест `what_the_*_panel_runs_is_allowed`. Shell и `port-forward` идут в терминал,
  через драйвер — никогда.
- **Шелл-квотинг на SSH обязателен** — `git::shell_quote`, единственная реализация; пайплайн —
  одним токеном `sh -c '<pipeline>'`.
- **Локальный спавн — только через [localenv.rs](../src-tauri/src/localenv.rs) и
  [exec.rs](../src-tauri/src/exec.rs)** (`resolved_local`, `run_local`): упакованное
  macOS-приложение получает от launchd минимальный `PATH`, поэтому программа резолвится в
  абсолютный путь; шеллом не оборачиваем. ENOENT у Docker, k8s и проб — `exit 127` (честное «не
  установлен»), у git и входа в реестр — ошибка. Каждый фоновый спавн консольного CLI — через
  `localenv::no_console_window`, иначе на Windows мигает `conhost`. Гейт
  `every_local_cli_spawn_hides_the_console_window`.
- **Код выхода по SSH ждут после EOF** (`ssh::exec_on`, не дольше `EXIT_STATUS_GRACE`): OpenSSH
  шлёт его после EOF. Живые тесты `live_exec`.
- **Аудит в записи — record-only** (ADR 0041). Мутирующий вызов с флагом `mirror` пишется в
  запись `[тег] $ … / [тег] exit N` (`exec::mirror`, `sftp::sftp_mirror`), в живой терминал — нет;
  чтения и поллинг не мирроятся, секреты — никогда. Сетевые утилиты пишут итог, а не сырьё:
  `probe_run`/`netcheck_run` в запись не пишут, блок пишет `record_audit` из разобранного
  результата (`tlsAudit`/`httpAudit`/`netcheckAudit`). Гейт
  `network_utilities_never_record_raw_argv_or_output`.
- **Живой вид — снимок раз в N секунд, не поток** (`--no-stream`, `logs --tail` без `-f`);
  поллер живёт, пока панель **видима** (`visible`), возврат во вкладку — один немедленный снимок.
- **Эффект не зависит от того, что пишет сам:** инициализация и перезагрузка — под `untrack`,
  зависимости — только названное в эффекте явно; иначе панель k8s перезапускалась на
  собственном ответе — шторм процессов на хосте. Гейт `K8sPanel.test.ts`.
- **Три дока, два класса вкладок** (ADR 0015). Панели-инструменты (`PanelId`) живут только в
  левом, правом и нижнем доках; терминалы и редакторы — только в центре. Панель рисуется в
  одном месте — сниппетом `dockPanel`, сессионные — через [DockPanel](../src/lib/DockPanel.svelte).
  Гейт `docklayout.guard`.
- **Раскладка доков — чистые данные** ([docklayout.ts](../src/lib/docklayout.ts)): в стор — только
  через `loadDocks`, меняется только `movePanel`/`revealPanel` и функциями стора; каждая панель
  ровно в одном доке. В `vterm.layout` — только доки, пишет его только главное окно. Гейт
  `docklayout.guard`.
- **Центр не уже одной области, пока окно позволяет** (`CENTRE_MIN_WIDTH`): боковые доки
  рисуются по `sideDockWidths` (сохранённое не переписывается), перетаскивание упирается в
  `sideDockRoom`, окно не уже `WINDOW_MIN_WIDTH` (`minWidth`, `min_inner_size`). Гейт
  `windowmin.guard`.
- **Панель не знает, в каком она доке** (ADR 0020): получает id, `visible` и сессию; под место
  подстраивается по своему размеру (`@container`, `@wide:`); второго, «горизонтального»
  компонента нет. Гейт `docklayout.guard`.
  - Внутри контейнера нет `fixed`-элементов — ни своих, ни компонента (`Modal`/`ConfirmDialog`/
    `ContextMenu`, по цепочке импортов): в части WebView `container-type` делает элемент
    containing block для `fixed`. Гейт `panelcontainer.guard`.
  - Порог один: `--container-wide` = `WIDE_REM` в [panelwide.ts](../src/lib/panelwide.ts); JS
    читает его через `wideWhen` — для поведения и для панелей, чьи диалоги в подкомпонентах
    (Git, чат ИИ, корень файловой панели).
  - Рядом со списком — содержимое, а не диалог: `SidePane` с `DockerDetail`/`K8sDetail`/
    `DockerText`/`K8sText`; `*Modal` — тонкая обёртка-диалог. Выбранную вкладку подробностей
    держит панель (`bind:tab`).
  - Коммит рядом с историей и поиск с переносами рядом с файлами — только когда помещается:
    `wide && fitsBeside(rowWidth)`, без второго порога (ADR 0028, 0030).
  - Граница между частями — в сторе [panelsplit](../src/lib/stores/panelsplit.svelte.ts), что
    можно выставить — [panelsplit.ts](../src/lib/panelsplit.ts) (`PART_MIN`); сохранённое не
    переписывается.
- **Док без доступных панелей не рисуется;** сохранённая вкладка дока не переписывается
  (`shownPanel`); зона сброса невидимого дока — оверлей, а не полоса в раскладке.
- **Скрытая панель не предлагается нигде** (`settings.hiddenPanels`): не рисуется, не
  монтируется, её нет в ⌘K и меню переноса, `revealPanel` её не открывает, точки входа ИИ гаснут
  с панелью ИИ (`aiOn`); место в доке сохраняется. Дерево серверов не скрывается
  (`HIDEABLE_PANELS`). Пишет список `setPanelHidden`, читает — `sanitizeHiddenPanels`, каждый
  вопрос «что показывает док» передаёт список. Гейт `docklayout.guard`.
- **Перенос панели — три пути:** перетаскивание
  ([dockdrag](../src/lib/stores/dockdrag.svelte.ts)), меню вкладки, ⌘K; цель решает модель
  (`insertionIndex`/`movePanel`); принявший док показывает панель и раскрывается. Раскладка
  меняется при отпускании (`previewPanels`, место держит вкладка с `opacity-0`).
- **Панель дока не размонтируется** при смене вкладки дока и сворачивании — только
  скрывается; `{#key}` и `{#if active === …}` вокруг содержимого запрещены: пересоздание теряло
  живой SFTP-канал, каталог, scope k8s. Смонтирована — значит поллинг гейтится условием на
  `visible` (голое `void visible;` — не гейт), window-wide обработчики скрытую панель не
  слушают. Ключ сессионной панели несёт `sessionId`. Док держит смонтированными панели всех
  сессий на экране (`sessions`), видима — панель сессии в фокусе; панель строится для сессии,
  которую назвал док (`sid`), а при нескольких областях подписана (`caption`). Гейт
  `dockpanels.guard`.
- **Док ждёт сессию у любого вида вкладки:** `sessionReady` — из `dockConnection`, и у локальной
  тоже: до регистрации PTY бэкенду не на чем исполнять. Гейт `dockpanels.guard`.
- **Мёртвая сессия — одна заглушка на весь док** (`dockConnection` = `offline`): «Нет
  соединения», панели смонтированы, но `visible=false`; «Проверка…» вместо этого —
  правдоподобная заглушка.
- **Что переживает смену вкладки терминала — в сторе
  [dockstate](../src/lib/stores/dockstate.svelte.ts)** по `sessionId` (подключение и каталог
  файловой панели, scope k8s, подвкладка) и чистится в `closeTabFully`; скролл, выделение и
  модалки — не туда. Забытый context k8s не вшивается в argv.
- **Подтверждения:** `isDestructive`/`needsConfirm` → `ConfirmDialog` на **любом** сервере, на
  проде — красное предупреждение (предохранитель, принцип 7).
- **Сетевые операции — только по явной кнопке** (`fetch`/`pull`/`push`, `docker login`): трафик
  идёт с хоста сессии.

- **Возраст в строке списка — один формат** (`compactAge`, [age.ts](../src/lib/age.ts): не
  длиннее пяти знаков, без перевода; `k8sAge`/`dockerAge`/`gitAge`); фраза инструмента («3 weeks
  ago») не берётся; полная дата — в подсказке, нераспознанное — «—». Время файла и коммита, где
  есть место, — момент (`formatModified`, `commitMoment`), а не возраст.
- **Потолок нагрузки — из спека, а не из процентов:** доля — только при известном лимите
  (`resources.limits`, `HostConfig`); без лимита — число и пометка, без шкалы; сумма по стеку —
  `null`, если есть безлимитный.
- **Кто принимает трафик — читается, а не выводится** (`buildRoutes`): эндпоинты — только из
  EndpointSlice, селектор — текст, подов модель не видит; правило ingress — объявленное;
  `ExternalName` — DNS-псевдоним. Непрочитанный список — не пустой (`listFailure` → `null` → «не
  прочитаны»; «ещё не пришли» — скелет). EndpointSlice запрашиваются, только пока маршрут на
  экране. Гейты `k8sroute.guard`, `K8sPanel.test.ts`.
- **Связность Docker — возможность, а не факт** ([dockernet.ts](../src/lib/dockernet.ts)): общая
  сеть — «могут связаться»; `host`/`none` — метки, не узлы; привязки одного порта с разной
  доступностью не сливаются; нераспознанный порт — как есть; раскладка графа — функция данных.
- **Возможности хоста — по данным, а не по ОС приложения** ([hostcaps.ts](../src/lib/hostcaps.ts)
  поверх `Metrics.os` — ОС **хоста сессии**); пустая ОС — блок остаётся. Новый «недоступный
  здесь» показатель — предикатом с тестом.
- **Метрики опрашиваются на трёх уровнях:** `METRICS_SCRIPT` — на каждом тике (не раздувать),
  `DETAIL_SCRIPT` — страница, `EXTRAS_SCRIPT` — один раз при открытии оверлея,
  `fetch_pending_updates` — лениво. Дельтовые сэмплы — в `MetricsSamples`, чистятся в
  `disconnect`.
- **Зонд читает, производные считает Rust:** в `*_SCRIPT` только сырые показания, вычитание — в
  парсере; отсутствующее поле не печатается. «Использовано» RAM — колонка `free` самого хоста
  (`parse_free`, только без неоднозначности), иначе `mem_used` по правилу procps ≥ 3.3.17.
  `MemAvailable > MemTotal` — искажение: доступным считается `MemFree`; у свопа второй оценки
  нет — `None`. Гейт `probe_scripts_report_raw_readings_not_differences`.
- **Опрос идёт, только пока на него смотрят:** оверлей гасит петлю на закрытии,
  `showStatusBar=false` размонтирует `StatusBar`; поэтому вход на страницу мониторинга есть и в
  ⌘K, и в нативном меню (`menu://monitoring`).
- **Пороги и health — единые источники:** уровень значения — [thresholds.ts](../src/lib/thresholds.ts)
  (`settings.statusBarThresholds`, `null` = выкл), уровень блока —
  [monhealth.ts](../src/lib/monhealth.ts) (`worstLevel`); новый показатель = ключ порога +
  дефолт + поле настроек + строка в `*Health`. Графики — `Chart`/`Sparkline`/`StackedBar`;
  безлимитный потолок — `∞` (`fmtLimit`).
- **Пароль `docker login`** — только в keychain (`vterm:registry`), не в настройках, бэкапе и
  argv: `docker_login` подаёт его через `--password-stdin` и не мирроится. url + username —
  `settings.dockerRegistries`.

### Утилиты

- **Панель-оверлей [UtilitiesPanel](../src/lib/UtilitiesPanel.svelte)** (`z-index:40`), вход —
  `wrench` в [TopBar](../src/lib/TopBar.svelte) и ⌘K, не секция настроек. Инструмент можно
  закрепить на верхней панели, поэтому **у двух инструментов не бывает одной иконки**. Над
  инструментами — действия сессии ([sessionactions.ts](../src/lib/sessionactions.ts)). Реестр —
  [utilities.ts](../src/lib/utilities.ts).
- **Инструмент = чистая логика `.ts` с тестом + тонкая оболочка `Util*.svelte`**; копирование —
  [CopyButton](../src/lib/CopyButton.svelte).
- **Всё офлайн:** codec/cidr/timeconv/cron/pwgen/jwt — без сети и бэкенда, CSPRNG —
  `crypto.getRandomValues`, словарь passphrase встроен; бэкенд — только для файлов и ОС
  (known_hosts).
- **SSH-ключи генерируются локально** (`ssh-key` + `rand`, без внешнего `ssh-keygen`):
  [keygen.rs](../src-tauri/src/keygen.rs) — одна команда, логика — [sshkeygen.ts](../src/lib/sshkeygen.ts).
  Приватный ключ `0600`, `~/.ssh` `0700`, passphrase в `Zeroizing` и нигде не хранится,
  коллизия без `overwrite` — `KeyExists`. UI — общий `KeyGenModal`.
- **Сетевые утилиты — только поверх сессии;** локальная вкладка запускает программы
  пользователя из allowlist (ADR 0014), а не открывает сокеты сама.
- **«Проверка доступа» — единственное исключение, и оно узкое** (ADR 0012, 0032, 0033). Одна
  команда `netcheck_run`, транспорт по сессии. На SSH — скрипт `netcheckArgs`
  ([netcheck.ts](../src/lib/netcheck.ts)); порядок «Авто»: `bash /dev/tcp` под `timeout` → `nc -z`
  (с `-G`, если есть) → `telnet` под `timeout` → `curl` («открыт» — по `time_connect`, а не по
  коду выхода); пригодность каждого средства — строкой `C`, выбранное, но непригодное блокирует
  запуск — тихой подмены нет. Локально —
  рукопожатие в Rust ([netcheck.rs](../src-tauri/src/netcheck.rs): по кнопке, к введённым
  адресам, без полезной нагрузки, не больше `MAX_CHECKS`; на Windows без повторов SYN —
  `no_syn_retries`) или
  `bash`/`nc`/`telnet`/`curl` пользователя с argv только из `LocalTool::argv` — страница называет
  лишь инструмент (гейт `a_local_tool_runs_only_its_fixed_argv`). Протокол один (`H/A/C/M/D/S/R/N/E`),
  вердикт — `classifyAttempt`, без `E` прогон оборван. `0.0.0.0` и подсети вокруг — отказ; UDP
  не проверяется нигде.
  - Заявка вставляется как есть, но берётся только по действию: эвристика `recognize`
    ([netcheckpaste.ts](../src/lib/netcheckpaste.ts)) показывает, что взято; в таблицу — кнопкой
    или ⌘/Ctrl+Enter. Строка таблицы своего понятия о правиле не имеет — уходит в `parseRules`
    ([netcheckform.ts](../src/lib/netcheckform.ts)).
  - Источник выбирает сервер ([netroute.ts](../src/lib/netroute.ts)); без источника — отмеченные
    серверы, и только они; отметка не перебивает источник; ничего не отмечено — запуск держит
    причина (`unrouted`).
  - Подсеть — каждый адрес хоста, после вопроса с числом соединений; `MAX_CHECKS` (2048) — на
    сервер. `MAX_CHECKS` и `BATCH` — одни в netcheck.ts и netcheck.rs.
  - Остановка — на обеих сторонах (`cancel_id`, `sftp_cancel`): «остановлено», в записи
    `exit 130`. Гейт `a_netcheck_run_can_always_be_stopped`.
  - Правила, отметки и ответ — по хосту вкладки (стор `netcheck`), прогон живёт в сторе;
    запускают его только `startRun`/`retryRun`.

  Гейт `netcheck.guard`.

## Логи, поиск, запись сессий

- **Мастер-гейт `smartLogs.enabled`:** выключен — терминал ведёт себя **ровно как чистый
  xterm**, независимо от пер-фичевых флагов; под-фича = флаг в `SmartLogs` + дефолт + тумблер,
  читается `enabled && <feature>`. Ссылки в выводе — своя настройка.
- **Поиск принадлежит терминалу** (`@xterm/addon-search`, логика — [search.ts](../src/lib/search.ts)):
  `Cmd+F`/`Ctrl+Shift+F`, а plain `Ctrl+F` уходит в шелл; терминал создан с
  `allowProposedApi: true` (decoration-API xterm 6); невалидный regex в аддон не идёт
  (`buildMatcher` → `null`). Строка поиска не шире своей области. Гейт `termsearch.guard`.
- **Глобальные хоткеи не отнимают клавиши у шелла:** ⌘-хорды на macOS,
  `Ctrl+Shift+<key>` на Windows/Linux; plain `Ctrl+T`/`Ctrl+K` уходят в шелл. Терминал отпускает
  app-хорды (`isAppShortcut`); предикаты — [appshortcuts.ts](../src/lib/appshortcuts.ts), одни
  для терминала и окна. Хорды областей (`⌘D`/`⌘⇧D`, `⌘]`/`⌘[`) окно не трогает, если их уже
  обработал элемент в фокусе или их набрали в поле ввода. Буква хоткея — только через
  `chordLetter`: на русской раскладке `Ctrl+R` даёт «к» (`vterm/hotkey-letter`).
- **Подсветка — ANSI-SGR в потоке до `term.write`**, базовыми цветами `31…37` (берут цвета
  темы); не внутри escape-последовательностей, только в нормальном буфере; порядок правил —
  приоритет ([highlight.ts](../src/lib/highlight.ts)).
- **Ссылка из вывода открывается одним путём — `clickLink`**
  ([stores/linkopen](../src/lib/stores/linkopen.svelte.ts)), только по клику и через `openUrl`;
  что делает клик, решает `linkClick` ([termlink.ts](../src/lib/termlink.ts)) по
  `settings.terminalLinks`. Каждый xterm (и проигрыватель записей) получает
  `terminalLinkHandler`, иначе OSC 8 уходит в `confirm()`/`window.open()` xterm. OSC 8-ссылка,
  текст которой называет другой сайт (`misleadingHost`), спрашивает в любом режиме, кроме
  `off`, и «Больше не спрашивать» ей не предлагается (`canSilence`). В вопросе — хост, к
  которому подключится браузер (punycode, выделен). Открывается
  только https, http-ссылку предлагается скопировать. Гейт `termlink.guard`.
- **Файл из вывода открывается по проверенному имени и в каталоге своей команды** (ADR 0035):
  решение — `fileLinkClick` ([termfiles.ts](../src/lib/termfiles.ts)), открытие — контроллер
  [filelinkflow](../src/lib/page/filelinkflow.svelte.ts) теми же путями, что панель файлов.
  Ссылкой делает листинг каталога, а не формат `ls`; канал, сокет, устройство — не файл.
  Каталог строки — снимок при отправке (локально — бэкенд до байтов и только пока терминал
  держит сам шелл, `prompt_cwd`; по SSH — сообщённый после прошлой строки), не `localCwd`.
  `x.c:42` открывается на строке (`gotoLine`), но имя сперва читается целиком. Выделение и
  двойной клик не открывают. Шелл контейнера ссылок не даёт (`fileLinksAllowed`); SSH без
  сообщаемого каталога предлагает синхронизацию пути. Гейт `termfilelink.guard`.
- **Структурный вид парсит, только пока открыт** (`feedJson`, буфер `MAX_JSON_ENTRIES`); формат
  построчно JSON → nginx → syslog → dmesg → logfmt последним; «Clear» ставит водяной знак
  (`registerMarker`). Логика — [jsonlog.ts](../src/lib/jsonlog.ts).
- **Вставка в терминал — только `term.paste()`** (bracketed paste): прямой `writeToTerminal`
  исполнял многострочный блок построчно. Одна строка — сразу, несколько — выбор формы, исходный
  блок по умолчанию. Гейт `termpaste.guard`.
- **Поверх первой строки терминала ничего не висит:** Raw/Table, поиск, «Очистить», «Спросить
  ИИ» — в панели сессии ([sessionbar.ts](../src/lib/sessionbar.ts)); состояние держит
  `Terminal.svelte`.
- **Запись ведёт бэкенд, по сессии** ([ADR 0041](adr/0041-session-recording-and-audit.md)): `Recorder`
  ([recording.rs](../src-tauri/src/recording.rs)) внутри `SshSession`/`LocalPty`, asciicast v2 в
  `data_dir/recordings/`; чтение, удаление и мета — только внутри каталога записей
  (`is_recording_path`, граница); ввод после `password:` маскируется. У `LocalPty` файловый I/O
  записи — в своём потоке (`run_recorder`, канал `RecMsg`), не на пути слива PTY: иначе ConPTY
  на Windows вставал.
- **Пауза — экономия диска, а не пропуск:** время паузы вычитается (`paused_total`), любой
  `input` возобновляет запись первым делом. Пишутся вкладки на экране, простой — у каждой свой.
- **Автозапись прода — тем же путём, что REC** (`startSessionRecording`, идемпотентно);
  финализация на `closed` — без диалога, реконнект — новая запись.
- **Мета — в заголовке asciicast** (`title`, `description`, `server`); `with_updated_meta`
  переписывает первую строку и сохраняет `server`. Пост-стоп-диалог «Сохранить/Удалить» сам и
  есть явный выбор.
- **Аудит-факты редактора — через `annotate_recording`** (видимое `o`-событие, даже на паузе);
  новый аудит-факт — так же.

## Файлы, пути, текст

Разборы — [ADR 0042](adr/0042-files-on-the-server.md).

- **Файловые панели — один компонент** ([FileBrowser.svelte](../src/lib/FileBrowser.svelte) +
  адаптер [FileBrowserAdapter](../src/lib/filebrowser.ts)): транспорт плюс две расходящиеся
  семантики (`navParent`, мутируемость); возможности SFTP — наличием методов адаптера, где лежат
  файлы — `adapter.local`. `SftpPanel`/`LocalFilePanel` — тонкие обёртки. Третьей копии нет.
  - В узкой SFTP-панели `upload` остаётся отдельной кнопкой, остальное — под `dots`. Гейт
    `filetoolbar.guard`.
  - Таблица файлов — та же разметка, что список (`@wide:`): строка 28 px (на ней стоит
    виртуальное окно), высота шапки вычитается при прокрутке к курсору, блок действий —
    фиксированной ширины.
  - Порядок листинга — одна чистая модель ([filesort.ts](../src/lib/filesort.ts)) и один выбор
    на приложение; папки над файлами, неизвестное — в конце, равные — по имени; курсор,
    выделение и окно ходят по `shownEntries`.
  - Ответ поиска говорит, чем он не является (`GrepOutcome.truncated`/`failed`): код `grep` —
    маркером в stdout, без маркера — провал; `GREP_LIMIT` один в `sync.rs` и `sync.ts`.
    Совпадение решил `grep`, подсветка — подсказка приложения.
- **Перетаскиванием файла владеет стор, а не панель** (ADR 0026). Панель говорит, что взято
  (`beginFileDrag`), и размечает цели (`data-file-panel`, `data-drop`, `data-file-cwd`);
  указатель, цель и отпускание — в [filedrag](../src/lib/stores/filedrag.svelte.ts), бросок —
  контроллер [filedragflow](../src/lib/page/filedragflow.svelte.ts). Цель — то, что под
  указателем (`fileTargetAt`). Смысл броска — `dropMeaning`: в свою панель — перемещение с её
  вопросом (`requestMove`), на другую сессию — **всегда копия** через диалог папки. До
  отпускания ничего не происходит, кроме открытия по удержанию (`SPRING_MS`). Файлы с рабочего
  стола слушает страница, один раз на окно (место — `pagePoint`); на терминал локальной вкладки
  вписываются пути (`quotePaths`). В другое окно — эстафетой `drag_over`, сказанное берётся
  назад (`dragEnd`). Гейт `filedrag.guard`.
- **Файл выносится из приложения только обещанием** (ADR 0027): системе отдаётся имя,
  содержимое читается после броска. Страница спрашивает систему у края окна один раз
  (`drag_out_begin` в `handOver`, после `afterTelling`); пока вопрос открыт,
  `pointerup`/`pointercancel` ждут (`afterHanding`); взяла — `systemTook` и `releaseSelection`.
  Что можно — `dragOutBlocker` (зеркало `SUPPORTED`/`FOLDERS`), имя — только проверенное
  (`safe_component`). macOS: обещание исполняет задание реестра по очереди (`in_turn`,
  `KEPT_AT_ONCE`); Windows: сбой чтения потока — никогда не конец файла
  ([feed.rs](../src-tauri/src/dragout/feed.rs)), длина — от сервера в момент начала. Гейты
  `dragout.guard`, `a_file_leaves_the_app_only_as_a_checked_promise`.
- **Путевая арифметика — чистая и сепаратор-осознанная** ([fspath.ts](../src/lib/fspath.ts)):
  корни POSIX, диска и UNC; сравнение путей на Windows — регистронезависимо. `isRoot`/`parentOf`
  — файловые, `navParent` — навигационный: выше корня диска — `DRIVES_ROOT` (`"::drives"`,
  бэкенд матчит его в `localfile::list`), где запрещены все мутации. Перечисление дисков не
  трогает тома ([drives.rs](../src-tauri/src/drives.rs): `GetLogicalDrives`, метка и место —
  только локальным, `should_enrich`). Гейт `never_probes_network_or_optical_drives`.
- **Кодировка текста определяется и сохраняется** ([textenc.rs](../src-tauri/src/textenc.rs)):
  BOM → UTF-16 по NUL-паттерну → UTF-8 → `chardetng`; проверка бинарности — после UTF-16.
  Метка едет `TextFile.encoding` → `EditorDoc.encoding` → запись, файл пишется в исходной
  кодировке; `sha256` — по сырым байтам. Новый источник текста — через `textenc::decode`/`encode`.
- **`SETSTAT` — только запрошенные атрибуты:** `FileAttributes` — через `sftp::chmod_attrs` или
  с выписанными полями, никогда из шаблона: `size: Some(0)` — это truncate. Гейт
  `no_file_attributes_built_from_a_template`.
- **Каретку после вставки не считают из `.length` сырого буфера:** CRLF ложится в документ
  короче, и `state.update()` кидает до применения; позиция — из применённого изменения
  (`replaceSelection`). Правило `vterm/paste-caret`, гейт `clipboardpaste.guard`.
- **Запись текста на сервер — только через `create`** (`sftp::write_bytes`:
  CREATE|TRUNCATE|WRITE): `SftpSession::write` без `CREATE` падает на новом пути. Форма —
  sibling-temp → `set_metadata` → `remove_file` → `rename`; упавшая запись не обрезает оригинал.
- **Конфликт правки — по хэшу:** `expectedSha256` открытия сверяется перед записью →
  `FileChangedOnServer`; молча перезаписать нельзя. Лимит открытия — `settings.sftp.maxOpenMb`,
  бэкенд клампит в `[1, 64 МБ]`.
- **Права записи — по пути сохранения** (контроллер
  [editorflow](../src/lib/page/editorflow.svelte.ts)): `sftp_write_access` — предварительный
  статус, окончательный — результат записи; отказ оставляет правки и показывает рядом с
  «Сохранить» sudo и локальную копию; копия — только `create_new`, в исходной кодировке. Гейт
  `editoraccess.guard`.
- **sudo-правка:** пароль только в памяти и через stdin (`sudo -S -p ''`, `run_command_stdin`),
  успех — маркер `__VTERM_OK__`; отказ — `isPermissionError` (`permission denied` и `no such
  file`).
- **Расписка о записи отражает сервер, а не намерение** (`WriteResult`); ошибку `set_metadata`
  не глушить. Поведение сервера — живые тесты `live_sftp`.
- **Синхронизация: хэши считает бэкенд, diff — чистый TS.** `sftp_hash_tree` через SSH exec
  (`sha256sum`/`shasum`), локально — обход; обе стороны дают `HashTree`, дальше
  `diffTrees`/`apply` ([sync.ts](../src/lib/sync.ts)).
  - Нечитаемое дерево — ошибка, а не пустое (`SyncDirUnreadable`/`HashToolMissing`/
    `HashIncomplete`): пустой список с «удалять лишнее» планирует стереть всё. Непрочитанное
    ниже корня — в `skipped`.
  - Удалённая папка — своя у окна (`SyncRemotePicker`): выбор не двигает ни панель, ни терминал.
  - Синхронизацией владеет стор [syncjob](../src/lib/stores/syncjob.svelte.ts) по `sessionId`
    (чистится и останавливается в `closeTabFully`); прогон — один на приложение
    (`otherRunHolds`, между окнами — `SyncBusy`).
  - Исключения режутся при обходе только совпадающие по смыслу (`ExcludeSet`) — не больше, чем
    отфильтрует `diffTrees`.
  - Большой план не стоит квадратично: виртуальный список, прогресс на месте, итоги
    инкрементально.
  - Закрыть окно посреди работы — остановить с вопросом или увести в фон кнопкой; отмена —
    флагами `sftp_cancel` на каждую сторону.
  - Пустой план — с причиной (`emptyPlanReason`), «стереть всё на цели» — красным
    (`wipesTarget`), у неактивных кнопок — причина (`syncBlockReasons`).
  - Прогресс — существующий канал, id `sync:<путь>` (`sync_transfer_id` ↔ `syncTransferId`
    обязаны совпадать); операции без байтов шлют `emit_done`; список ведёт стор
    [syncrun](../src/lib/stores/syncrun.svelte.ts). Остановка — `state.cancels` под `runId`,
    между файлами; после неё «Применить» заблокировано.
- **Линта у legacy-режимов нет — и ложных срабатываний тоже:** линт строится на error-нодах
  Lezer; включить его для StreamLanguage-языка — заменить режим на `@codemirror/lang-*`.
  Серверный линт — команда `lint_remote`.
- **Серверные инструменты ставит менеджер сервера** (`TOOLS` + `install_command` в
  [servertools.rs](../src-tauri/src/servertools.rs), UI — `ToolInstallDialog`).
- **Свои привязки буфера обмена у терминала и редактора убирать нельзя**
  ([clipboard.ts](../src/lib/clipboard.ts)): на WKWebView без Edit-меню это единственный путь.
- **«Открыть с помощью vterm»:** `tauri-plugin-single-instance` регистрируется первым; пути — из
  argv и `RunEvent::Opened` (только macOS, под `cfg`) в `pending_opens` + `vterm://open-file`.
- **Перенос файла — задание бэкенда: окно его показывает, а не ждёт** (ADR 0025,
  [transfers.rs](../src-tauri/src/transfers.rs)). `transfer_start` возвращается сразу, дальше —
  `sftp://job` окнам, которые показывают вкладки сессий задания **на момент события**
  (`audience`, отправка одна — `send`). В окне — только строка: окно сперва слушает
  `sftp://job`, потом спрашивает `transfer_list`; позднее событие попадает в стор, только пока
  открыта сессия задания. Запускает задание только `startTransfer`
  ([transferflow.ts](../src/lib/transferflow.ts)). Конец сессии отменяет её задания
  (`end_session` → `Jobs::cancel_session`). Копия между
  серверами — через процесс (`relay_staged`), права — как у `scp`. Один файл не останавливает
  остальные, пропущенное считается. Синхронизация в реестр не входит. Гейты
  `transferjob.guard`, `a_job_is_told_only_to_the_windows_of_its_sessions`.
- **Перенос пишет во временный соседний файл и отменяем:** `upload_staged`, `download_file`,
  `relay_staged`, `localfile::copy_staged` пишут `.<имя>.vterm-tmp-*` и `rename`-ят после
  последнего байта; прямой `create(target)` запрещён. Отмена — `state.cancels`/`sftp_cancel`, не
  ошибка (в аудите `exit 130`); файлы прогона синхронизации отменяются прогоном
  (`isCancellableTransfer`).
- **Перенос не заменяет файл без согласия:** занятое имя без `replace` — `dest-exists` до
  первого байта. Занятость спрашивают у назначения, один вопрос на пачку
  (`checkUpload`/`uploadItems`, `ReplaceDialog` с очередью
  [replaceask](../src/lib/stores/replaceask.svelte.ts)); непрочитанная папка — другой вопрос. Без
  вопроса `replace` получают только согласие системного диалога (`agreed`) и план синхронизации.
- **Список после переноса обновляет стор, а не начавшая панель** (`applyJob` → `touchDir`,
  `dirRev`); листинг принимает только последний ответ (`loadSeq`).
- **Аудит SFTP — тот же record-only, тег `[sftp]`** (`sftp::sftp_mirror`): `rm`, `mv`, `cp`,
  `mkdir`, `touch`, `save` (только размер), `put`, `get`, `copy`; чтения — нет. Задание переноса —
  одной строкой (`transfers::audit_op`, имя вкладки — `audit_label`), синхронизация — одной
  записью на прогон (перечень до 50 строк). Новая мутирующая команда: `session_arc` →
  `session.sftp()` → `record_sftp`.
- **«Следовать за терминалом» — один контракт, два транспорта.** Локально — cwd процесса у ОС
  ([proccwd.rs](../src-tauri/src/proccwd.rs)), по SSH — OSC 7 / OSC 9;9; каналы параллельно, опрос
  раз в секунду и только при включённом тумблере; отказ — `None`. Только на OSC строить нельзя,
  подменять `TERM_PROGRAM` — тоже. Диалог сниппета показывает `needsShellSetup`.
  - Обратное направление (`cdTerminalTo`) — только на действиях пользователя при включённом
    тумблере (иначе петля); команда — [cdterminal.ts](../src/lib/cdterminal.ts) под оболочку,
    диалект фиксируется при спавне; невыразимый путь → `null`.
  - Переключатель и каталог дока одни (`followTerminal[sessionId]`, `dockstate.cwd`); пишут в
    каталог файловая панель и терминал — только при включённом тумблере и только при смене
    ([followcwd.ts](../src/lib/followcwd.ts)); Git не пишет.
  - Git при выключенной синхронизации следует за терминалом (`gitCwd`), неизвестный cwd — «нет
    пути»; кнопка Git включает тот же переключатель (`pathSync.enable`). Гейт `gitcwd.guard`.
  - Как включается синхронизация — ответ сервера (ADR 0034): режим в профиле
    (`ServerProfile.pathSync` — строка, не enum) или `localPathSync`, читается только
    `pathSyncMode` (неизвестное — «спрашивать», `vterm/path-sync-mode`); ответ пишет
    `set_server_path_sync`.
  - Включает синхронизацию одна функция — `start` контроллера
    [pathsyncflow](../src/lib/page/pathsyncflow.svelte.ts). Команду настройки вопрос
    показывает (`questionShowsSetup`); «Всегда» — на каждом `connected`, кроме занятого шелла
    (читается до расхода `pendingCommand`); конец сессии выключает синхронизацию; на проде при
    «всегда» — красное предупреждение. Гейт `pathsync.guard`.

## Хранение и секреты

Разборы — [ADR 0043](adr/0043-login-and-storage.md).

- **Что где живёт:** профили, папки, known_hosts — JSON в конфиг-каталоге
  ([store.rs](../src-tauri/src/store.rs)); секреты — **только** OS keychain
  ([secrets.rs](../src-tauri/src/secrets.rs)), никогда в файлах и бэкапе; настройки и layout UI —
  `localStorage`. Для e2e — `data-testid`.
- **Создание профиля подтверждается записью:** `add_server` публикует профиль в памяти только
  после записи `servers.json`; форма закрывается до ожидания keychain, сбой секрета — ошибкой
  отдельно. Гейт `servercreation.guard`.
- **Секрет proxy/jump host** — в keychain под `{id}::proxy`; чистится в
  `delete_all`/`forget_secrets`.
- **Копии секретов — в `zeroize::Zeroizing`, не логируются.** Host-key по умолчанию — не
  «accept».
- **После входа подключение уже не проваливается:** сохранение секрета и `hasSavedPassword` —
  совет (`ConnectOutcome.rememberFailed` + тост), а не условие. Гейт
  `nothing_after_login_can_fail_the_connection`.
- **`keyboard-interactive`: пароль — только в вопрос о пароле и один раз**
  ([kbdauth.rs](../src-tauri/src/kbdauth.rs), `plan`): одноразовые коды паролем не заполняются,
  после частичного успеха пароль не повторяется; остальное спрашивает окно (`term://auth/{id}`
  → `answer_auth_prompt`), ответы только в памяти; `end_session` снимает ожидающий вопрос;
  ничего пригодного — `AuthMethodsUnsupported`, а не «неверный пароль». Гейт
  `login_answers_come_only_from_the_plan`, живые тесты `live_kbdint`.
- **Сертификат хоста отклоняется при любой политике** (`host_key_fingerprint` → `None`,
  `*-cert-v01` не рекламируем): доверенных CA нет, а пин вложенного ключа пропустил бы подпись,
  срок и principals. Поддержка — явный список CA, а не «взять ключ изнутри».
- **Хардкодных абсолютных путей во фронте нет** (`vterm/no-scratch-path`); временные файлы — через
  OS temp в Rust. Windows-литералы-плейсхолдеры в настройках путей разрешены.
- **Конфиг переписывается только атомарно** (ADR 0007): `store::write_atomic` (temp → `sync_all`
  → `rename`), прямой `fs::write` в `store.rs` запрещён, ошибку `rename` не глушить; та же форма у
  `localfile::local_temp`.
- **Непрочитанный конфиг — в карантин, а не в пустоту** (`store::read_store`): нет файла /
  не парсится (→ `<имя>.corrupt-<nanos>` + `StoreWarning`) / прочитан — три случая, склеивать
  нельзя. `quarantined: None` — отдельное сообщение «данные под угрозой». Тост без TTL. Новый
  store-файл — через `read_store`/`write_atomic`.
- **Импорт бэкапа пишет каталог, собранный предпросмотром:** `read_backup` ничего не пишет; что
  станет с серверами, решает [backupimport.ts](../src/lib/backupimport.ts) (логины и пути ключей
  по значению, без серверов, что уже есть по id или по хосту, порту и логину); `import_backup`
  пишет переданный каталог после `check_catalog`, никогда — список архива; «пароль сохранён» —
  только у текущего сервера с тем же id; по умолчанию — «Добавить к моим». Гейт
  `backupimport.guard`.

## ИИ-ассистент

**Выключен по умолчанию, зашитых облачных эндпоинтов нет**; весь LLM-трафик — из Rust
([ai.rs](../src-tauri/src/ai.rs)).

- **Контекст уходит только после маскирования и согласия** ([redact.ts](../src/lib/redact.ts),
  [AiConsentDialog](../src/lib/AiConsentDialog.svelte) — и для локального эндпоинта). Точки
  входа «спросить про X» зовут один примитив `askAbout`: он кладёт запрос, `AiChat` делает из
  него чип (`SessionChat.attachment`), вопрос — свой или пресетный (`ASK_PRESETS`, на пустой
  Enter) — уходит обычной отправкой через тот же consent.
  Своего пути отправки не заводи. Гейт `autonomy.guard`.
- **В слоте терминала — одно, самое узкое:** чип, иначе выделение, иначе весь буфер (тир),
  иначе хвост; выделение не складывается с буфером. Правило — `terminalSlot`
  ([aicontext.ts](../src/lib/aicontext.ts)), по нему и `buildContext`, и подпись
  `contextSummary`.
- **Один ход на чат** (`chatBusy`): новый вопрос не стартует, пока идёт стрим, ждёт шаг диалога
  или открыт consent; `askAbout` сразу становится чипом или отклоняется (`askBlocker`), не
  паркуется; ошибка ответа гасит `dialogRunning`. Гейт `aiturn.guard`.
- **Раскладка чата по ширине — те же элементы в другом месте** (сниппеты
  `endpointControls`/`tierBoxes`/`attachToggle`/`clearButton`, каждый нарисован в одном месте).
- **Исполнение команд** ([aiexec.ts](../src/lib/aiexec.ts), `execMode`:
  `suggest`/`confirm`/`dialog`/`dialogConfirm`): диалоговые режимы **никогда** на проде,
  выполненное — в запись; `noAi` блокирует и контекст, и исполнение, новая точка входа обязана
  его уважать. Бэкенд держит то же: `ai_exec` отказывает проду и `noAi`
  (`ServerProfile::ai_exec_allowed`, ADR 0036).
- **Вендор — данные, а не транспорт:** протоколов `AiProvider` два (`openai` —
  `/chat/completions` + `Bearer`, `anthropic` — `/v1/messages` + `x-api-key`), третьего нет;
  вендор — запись в [aipresets.ts](../src/lib/aipresets.ts). Модельные id сверяй с документацией
  вендора. Эндпоинт без модели — законное состояние (`sanitizeEndpoint`), годность решает
  `activeEndpoint`.
- **Рассуждение модели — отдельный канал `ai://think/{id}`**, иначе черновик стал бы
  исполняемым блоком; поля вендоров принимаются существующими парсерами.
- **Счёт токенов** — в payload `ai://done`; половина, о которой эндпоинт промолчал, — `None` и не
  показывается.
- **История обрезается** (`trimHistory`): последнее сообщение остаётся, диалог не начинается с
  реплики ассистента.
- **Таймаут стрима — `read_timeout`, а не `timeout`;** у листинга моделей — наоборот.
- **Промпт расслоён, ядро не редактируется** (ADR 0006): только
  `buildPromptLayers`/`buildSystemPrompt` ([aicore.ts](../src/lib/aicore.ts)) в порядке ядро →
  `PERSONA_HANDOFF` → персона → `replyLanguageLine`. В ядре — контракт ```bash-блоков, значение
  `‹redacted›`, режим исполнения, неинтерактивность, прод-предупреждение; новое такое правило —
  секцией ядра с тестом. Ядро объявляет вывод терминала недоверенными данными и требует
  сообщать о попытках внедрения — секцию не убирать. Ядро английское, персона локализованная.
  Дефолтные промпты — seed-данные ([aiprompts.ts](../src/lib/aiprompts.ts), `origin`,
  `reseedBuiltinPrompts`); `replyLanguage` — отдельная настройка.
- **Deny-list** (`isDangerousCommand`) и маскирование — предохранители (принцип 7). Аудит и
  остаточные риски — [SECURITY.md](../SECURITY.md#аудит-ии-агента-фаза-20).

## Недоверенный вход

- **CSP строгий, capabilities поимённо** (ADR 0036): ни удалённых origin, ни `csp: null`,
  `script-src` без `'unsafe-inline'`; ни одного набора `*:default`, opener только `https://`, без
  `fs`/`dangerous*`. Зависимости — `cargo deny`/`cargo audit`/`pnpm audit`/Semgrep; исключение
  advisory живёт, пока ему есть что исключать; npm ставится только `--frozen-lockfile`, у каждого
  пакета. Модель — [SECURITY.md](../SECURITY.md). Гейты `tauri-security.guard`,
  `releaseassets.guard`.
- **Любой `EditorView` включает `cspNonceExtension()`** ([cspnonce.ts](../src/lib/cspnonce.ts)):
  в `tauri build` nonce в `style-src` отменяет `'unsafe-inline'`, и стили CodeMirror без nonce не
  применяются — только в упакованной сборке. Дублировать стили в app.css и ослаблять CSP
  нельзя. Гейт `cspnonce.test.ts`.
- **Markdown — недоверенный вход, защит ровно две** (ADR 0008): цель ссылки проходит `safeUrl`
  (отклонённая — текстом), любой `{@html}` с markdown висит на элементе с `use:mdLinks`
  (`vterm/md-links`); обе проверяют схему независимо. Не-markdown `{@html}` — в `EXEMPT` с
  причиной.
- **Картинки в превью — только `data:` из байтов, прочитанных нами** тем же транспортом, что
  документ ([mdimage.ts](../src/lib/mdimage.ts)); удалённый `http(s)` — никогда: `<img>` — это GET.
  `renderMarkdown` рисует `<img>` только из `opts.images` и сам перепроверяет схему. Отказ —
  плейсхолдер с alt-текстом. Статический бейдж shields.io рисуется из URL
  (`renderBadge`, инлайновый SVG с `fill`), динамический — плейсхолдер; `unescapeHtml` не
  становится общим декодером.
- **Raw-HTML в превью — санитайзер по allowlist** ([htmlsan.ts](../src/lib/htmlsan.ts)): теги и
  атрибуты по списку, каждое значение перепроверяется, `on*`/`style`/`class`/`data-*` не проходят,
  опасные теги — вместе с содержимым; ручной токенайзер с биасом на drop; opt-in и только в
  превью редактора. Новый тег — с тестом на границу, DOM-санитайзер не вводить.
- **Имя файла с сервера — недоверенный вход:** локальный путь — только через
  `localfile::safe_child`/`safe_join` (одна компонента, не `.`/`..`, на Windows без `\`, `:` и
  хвостовой точки/пробела); имя одного сервера на другом — `sftp::safe_child`; обход задания
  строит путь через `child_path`; `sync::apply` проверяет путь плана до действия. Гейт
  `local_paths_from_server_names_are_checked`.

## UI и оформление

Разборы — [ADR 0044](adr/0044-ui-drag-motion-readability.md).

- **Визуальный язык заморожен** ([DESIGN.md](DESIGN.md)): меняется только по прямой просьбе
  пользователя; новое — из существующих токенов и паттернов; если задача формально требует
  тронуть оформление — сохраняй вид и спрашивай.
- **Деструктивное — через `ConfirmDialog`:** кнопка только открывает диалог, вызов — в
  `onconfirm`. Исключение — пост-стоп-диалог записи. Изменённый файл закрывается через
  `UnsavedCloseDialog` («Сохранить» закрывает только после успешной записи). Правка черновика —
  без диалога, но с «Вернуть».
- **Фон диалога только затемняет — не закрывает** (кроме палитры ⌘K): первый клик после
  возврата в окно попадал на фон и уносил заполненную форму; окну без кнопки отмены нужен
  `showClose`. Правило `vterm/backdrop-no-close`.
- **Тосты — единственный канал неблокирующих сообщений** (`notifyError`/`notifySuccess`/
  `notifyInfo`); пустые состояния — [EmptyState](../src/lib/EmptyState.svelte), загрузка —
  [Skeleton](../src/lib/Skeleton.svelte).
- **Окно сжимается вместе с главным:** карточка `Modal` — `max-w-[95vw] max-h-[90vh]` со
  скроллом. `Modal` даёт `role="dialog"`, фокус-трап, возврат фокуса и стек (Esc закрывает
  верхнее) — не дублировать и не понижать; так же вкладки — tablist с роуминг-`tabindex`,
  дерево — `role="tree"`.
- **Буфер обмена в полях ввода — глобальный `handleClipboardShortcut`**
  ([actions/clipboardKeys.ts](../src/lib/actions/clipboardKeys.ts), чтение — `read_clipboard_text`);
  `.xterm` и CodeMirror — исключения.
- **Кольцо фокуса перечисляет элементы явно** (`:focus-visible` по списку в app.css): карточка
  `Modal` фокусируется программно, и общее правило обводило бы весь диалог.
- **Горизонтальная анимация ширины — только clip-reveal** (абсолютный контент внутри
  `relative overflow-hidden`): WebKit не переотсекает статичного ребёнка. Нижний док — тем же
  приёмом по высоте. Действия по ховеру резервируют место (`invisible` → `group-hover:visible`).
- **Отступ терминала — `px-2 pt-1` на внешней обёртке xterm**, цветом фона темы терминала; у
  элемента, который меряет `FitAddon`, паддинга нет. Гейт `termfit.guard`.
- **Виртуальный список выключает scroll anchoring** (`[overflow-anchor:none]`, строки на время
  прокрутки не принимают указатель): иначе прокрутка дёргалась на WebView2.
  Правило `vterm/virtual-scroll`.
- **Полоса вкладок не растёт за окно:** вкладки — в ограниченном горизонтальном скроллере, «+»
  сразу за последней, показанная вкладка прокручивается в вид. Гейт `taboverflow.guard`.
- **Перетаскивание — общие правила** для вкладок, видов, панелей, файлов и кнопок верхней
  панели:
  - `Esc` отменяет любое перетаскивание и дальше не идёт (`cancelOnEscape`
    в [actions/drag.ts](../src/lib/actions/drag.ts)), отпускание после отмены — не клик
    (`swallowReleaseClick`). Гейт `filedrag.guard`.
  - Пока тянут, ничего не выделяется, и механизм один: `holdSelection()` на нажатии (класс
    `dragging` на `<html>`); `removeAllRanges` постфактум нельзя; отдавший жест системе снимает
    удержание сам (`releaseSelection`). Гейт `dragselect.guard`.
  - Цель переписывается, только когда изменилась (`sameDrop`/`sameRect`/`sameTarget`): равный
    прежнему список перезапускает `animate:glide`. Гейт `dragtarget.guard`.
  - Раскладка меняется при отпускании, до него — предпросмотр; слот считается по `layoutBox`,
    а не по месту анимации (`slotIndex` — по середине соседа).
- **Состояние — в runes-сторах** `src/lib/stores/*.svelte.ts`, а не по компонентам.
- **Кнопки верхней панели — список пользователя, и трёх вещей он не может** (ADR 0029).
  `settings.topbar` — встроенные действия и `util:<id>`; модель — [topbaractions.ts](../src/lib/topbaractions.ts),
  подписи и меню — [topbarui.ts](../src/lib/topbarui.ts).
  - «Утилиты» и «Настройки» не убираются (`ANCHORS`, `canUnpin`; `sanitizeTopbar` их возвращает).
  - Убранная кнопка не уносит действие: каждое из `SESSION_ACTIONS` стоит строкой в «Утилитах»
    с причиной у неактивной кнопки; запуск — через `Record<SessionAction, …>`; у синхронного
    ввода и заметок есть ⌘K.
  - REC и синхронный ввод показываются, пока включены (`mustShow`, `shownTopbar`).
  - Строку соединения кнопки не вытесняют: лишнее — под «⋯» по пикселям (`fitTopbar`,
    `topbarRoom`); ширины кнопок — константы модели, снятые с разметки.
  - Список меняет только [stores/topbarpins](../src/lib/stores/topbarpins.svelte.ts) результатом
    модели, читается через `sanitizeTopbar`; перетаскивание
    ([topbardrag](../src/lib/stores/topbardrag.svelte.ts)) — при отпускании, место — `topbarSlot`.

  Гейт `topbar.guard`.
- **Компоненты декомпозированы:** `+page.svelte` — оркестратор; логика страницы — контроллеры
  [src/lib/page/](../src/lib/page/) (`create…Flow`, состояние страницы — геттерами), тест —
  `*.svelte.test.ts`; бэкенд — обёртки `src/lib/api/` по доменам.
- **Объект, который узнают по идентичности, — в `$state.raw`:** глубокий `$state` отдаёт прокси,
  и `===` не выполняется никогда.
- **Грамматики редактора грузятся по требованию** ([editorlangs.ts](../src/lib/editorlangs.ts),
  статически — только `lang-json`); справка — при первом показе вкладки. Гейт
  `editorlangs.test.ts`.
- **Имена в каталоге не различаются только регистром — и имена их тестов тоже:** компонент не
  называется как его модель. Гейт `filecase.guard`.
- **Переиспользуй примитивы:** `Modal`/`ConfirmDialog` — всегда с явным `z-index`
  (`vterm/overlay-z-index`); любое меню ПКМ — [ContextMenu](../src/lib/ContextMenu.svelte) с
  `MenuItem[]` ([ctxmenu.ts](../src/lib/ctxmenu.ts)), native-меню подавлено; в терминале ПКМ —
  настройка `rightClick`, а `Shift`+ПКМ всегда даёт второе действие
  ([termmouse.ts](../src/lib/termmouse.ts); гейты `rightclickmenu.guard`, `termctxfocus.guard`);
  любое поле секрета — [PasswordInput](../src/lib/PasswordInput.svelte) (не префилится, «показан»
  не персистится; `vterm/password-input`); иконки — `Icon` ([icons.ts](../src/lib/icons.ts)), не
  эмодзи; подсказки — `use:tooltip`, не `title`; icon-only кнопка — с `aria-label`; длинное
  описание — [InfoHint](../src/lib/InfoHint.svelte).
- **Семантический цвет — только из токенов темы** (`ok`/`warn`/`bad` + `accent`/`danger`/`muted`) —
  в разметке и в классах, которые отдаёт `.ts`: палитра Tailwind не обслужит все темы. `danger`
  — действие, `bad` — состояние. Правило `vterm/theme-colors`.
- **Комментарии в редакторе — не ниже AA:** `brightBlack`, поднятый к цвету текста до 4.5:1
  (`readableOn`, [colormix.ts](../src/lib/colormix.ts)); тест по всем темам.
- **Второстепенный текст читается в каждой теме:** `muted` не ниже 4.5:1 на `panel`/`panel-alt`,
  на тёмных — APCA Lc ≈ 45, всегда тусклее `text`; исключение Solarized — в тесте с причиной.
  Гейт `themes.test.ts`.
- **Движение — только через [motion.ts](../src/lib/motion.ts)** (`motion()`/`motionScale()`,
  `vterm/motion-duration`): переходы Svelte идут через WAAPI, которому CSS-guard reduced motion
  не указ. Модалки анимируют только вход.
- **Размер шрифта — из шкалы** (`text-caption`/`text-meta`/`text-xs`/…), без line-height
  companion-ов; у прописных микро-меток одно оформление. Правила `vterm/type-scale`,
  `vterm/micro-label`, гейт `typography.guard`.
- **Шрифт терминала и записей — через `activeFontFamily()`:** ручной выбор не зависит от темы.
  Гейт `fonts.guard`.
- **Темы** ([themes.ts](../src/lib/themes.ts)): фирменные (`group: "signature"`) — плотные панели
  + оверлей [ThemeOverlay](../src/lib/ThemeOverlay.svelte) (чистый CSS, `pointer-events:none`,
  `z-index:30`); терминал не прозрачен; цвета пресетов не редактируются (только `custom`);
  `DEFAULT_THEME_ID = "deep-well"`; первый кадр — `vterm.chromePanel` в app.html синхронно с
  `@theme`. Бандл-иконка ОС статична, под тему меняется только [AppLogo](../src/lib/AppLogo.svelte).
  - Бандл-иконка: один мастер [icon-source.svg](../src-tauri/icons/icon-source.svg), Windows-артефакты
    — тем же SVG со сдвинутым `viewBox`; генерация только `pnpm icons`. Гейт `appicon.guard`.
- **Заставка простоя** ([IdleOverlay](../src/lib/IdleOverlay.svelte), `z-index:35`): простой —
  нет ввода **и** вывода PTY; без вкладок заставки нет (`screensaverAllowed`); накрывает только
  область терминалов, раскладку карточки выбирает `cardTier`; первый кадр — `$effect` над
  `active`+canvas; рисует копию буфера и в PTY не пишет; метрики — `monitoredSessionId`; гасят
  только клик или клавиша (`dismissesScreensaver`), курсор не прячется, жест глотается только по
  самой заставке (`swallowDismiss`). NO SIGNAL — только реальный неожиданный обрыв
  ([connlost.ts](../src/lib/connlost.ts)). Load на графике — доля от `cpuCount`, без данных —
  `null`. Гейт `idlecard.guard`.
- **Вшитый WebView2 — только когда системного нет** (ADR 0013): системный и
  `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` побеждают всегда; распаковка атомарная, со sha256; версия
  хвоста — строго `a.b.c.d`; `.cab` — только с подписью Microsoft; без движка — окно с
  объяснением; тексты — в `webview2.rs` (до WebView `t()` нет). Гейт `webview2runtime.test.ts`.
- **Оконное обрамление: macOS нативное, Windows/Linux — своё** (ADR 0011): декорации снимает
  Rust, пока окно скрыто; заголовок, меню Файл/Справка и кнопки рисует
  [TitleBar.svelte](../src/lib/TitleBar.svelte) на общих `ContextMenu` и токенах; монтирование —
  по стору [hostenv](../src/lib/stores/hostenv.svelte.ts), не проверкой ОС по месту;
  `set-decorations` в правах WebView нет; геометрия — [windowchrome.ts](../src/lib/windowchrome.ts).
- **Выход — только через подтверждение:** любой запрос выхода → `menu://quit` главному окну,
  `QuitDialog` спрашивает всегда и перечисляет, что прервётся, во всех окнах
  (`quitRows`/`mergeQuitRows`); закрытие второго окна — тот же диалог (`window://close`).
  Системный `quit()` в меню macOS запрещён. Защиту взводит `armCloseGuard` только после
  подписки на свой вопрос. Гейты `quitguard.guard`,
  `quitting_always_goes_through_the_confirmation`.
- **i18n** — правила в [../AGENTS.md](../AGENTS.md#i18n--закреплено): весь видимый текст через
  `t()` и сразу на всех языках; язык интерфейса не биндится (`vterm/locale-binding`).

## Обновления приложения

Решение — ADR 0031, процедуры — [INSTALL.md](INSTALL.md).

- Проверка релиза и скачивание — явные действия, только Rust и HTTPS GitHub; редиректы
  ограничены хостами раздачи GitHub. Ошибка сети не означает отсутствие обновлений.
- Установка принимает только подписанное Ed25519 описание версии и совпавшие размер/SHA-256
  файла; помощник повторяет проверку после ожидания выхода. Открытый ключ встроен, закрытый не
  попадает в Git и приложение. Криптография — Rust `update_protocol::tests`.
- Формат и архитектура совпадают с текущей сборкой; portable с WebView2 сохраняет полный
  вариант, пакетные сборки обновляются установщиком. Неизвестный формат — ручная загрузка, без
  догадок.
- Помощник запускается до WebView и single-instance, подтверждает готовность и ждёт отдельного
  разрешения установки и завершения исходного процесса. Сессии не убиваются принудительно; все
  окна отвечают до выхода, несохранённые документы блокируют установку.
- При замене файлов предыдущая версия сохраняется до подтверждения запуска новой; живой процесс
  по таймауту не убивается; ошибка или прерывание оставляют резервную копию. Откат файлов не
  откатывает пользовательские данные.
- macOS-подготовка ограничена проверенным bundle vterm (карантин, ad-hoc-подпись, проверка
  codesign); системные настройки защиты не меняются. Подпись пакетов обновления не требует
  сертификатов Apple/Windows.

Гейт `updater.guard` (с живыми мутациями).
