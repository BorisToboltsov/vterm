## Сквозные принципы

Разделы ниже — применение этих девяти. Частное правило, противоречащее принципу, — ошибка.

1. **Граница фронт/бэк** (ADR 0001). Логика SSH/SFTP/секретов/файлов — в Rust
   (`src-tauri/src/`); Svelte ходит к ней только через `invoke()` и каналы событий
   (`term://`, `sftp://`, `sync://`, `menu://`, `install://`, `ai://`, `window://`). Новое — команда в **своём
   доменном модуле** (`servers.rs`/`folders.rs`/`localfile.rs`/`keygen.rs`/…) + типизированная
   обёртка в [src/lib/api/](../src/lib/api/); `lib.rs` только регистрирует её в
   `generate_handler!` как `модуль::имя` (имя команды для фронта от переезда не меняется).
   Исключение — команды поверх общего `AppState` и приватные мосты
   (`get_sftp`/`session_arc`/`record_sftp`): остаются bridge-слоем в `lib.rs`, чтобы не
   растаскивать `AppState` по чистым модулям. Бизнес-логику на фронте не дублируем.
2. **Бэкенд — дамповый исполнитель, чистая логика — в `.ts`** (ADR 0003). Сборка argv,
   парсинг вывода, валидация, раскладки, маппинги живут в свободных функциях `.ts` (тестируются
   без DOM и сети), не в `.svelte` и не в командах: [tree.ts](../src/lib/tree.ts),
   [format.ts](../src/lib/format.ts), [util.ts](../src/lib/util.ts),
   [ssherror.ts](../src/lib/ssherror.ts), [virtuallist.ts](../src/lib/virtuallist.ts),
   [serverform.ts](../src/lib/serverform.ts), [actions/drag.ts](../src/lib/actions/drag.ts) и
   далее по разделам. В Rust так же: `reprefixed`, `decode_or_default`, парсеры
   [metrics/mod.rs](../src-tauri/src/metrics/mod.rs).
3. **Один контракт — два транспорта.** Транспорт выбирается **по наличию сессии**, а не по
   ОС и не отдельной командой: есть SSH-сессия → `exec_captured`/`run_command`; есть локальный
   PTY → `tokio::process` или нативный коллектор. Так работают терминал, `git_run`,
   `container_run`, `kubectl_run`, `probe_run`, метрики, «следовать за терминалом».
4. **Расширяем билдерами, а не командами.** Новая операция драйвера = новый билдер/парсер в
   `.ts`. Per-операционных бэкенд-команд не заводим; новый канал событий — только под
   принципиально другой **сорт** данных (так `term://phase` стоит рядом с `term://out`, а
   `ai://think` — рядом с `ai://out`).
5. **Честно или никак.** Правдоподобная заглушка вместо неизвестного запрещена: фейковые
   подстадии подключения, выдуманный счёт токенов, шкала для объекта без лимита, load average
   на Windows, «данные спасены» вместо «данные под угрозой», значок битой картинки вместо
   «недостижима». Неизвестное — `None`/«—»/явная пометка. «Нет данных» и «здесь невозможно» —
   **разные** сообщения.
6. **Офлайн** (ADR 0004). Никаких runtime-обращений в сеть, кроме исходящего SSH к серверам
   пользователя (в т.ч. через **его** proxy), — при opt-in ИИ — к **его** LLM-эндпоинту,
   TCP-рукопожатия «Проверки доступа» с локальной вкладки (ADR 0012) и запуска **своих**
   `curl`/`openssl` пользователя TLS-инспектором и HTTP-клиентом там же (ADR 0014, см. «Утилиты»).
   Весь такой трафик идёт **из Rust**, не из WebView, поэтому CSP остаётся строгим, а фронт
   вообще не делает сетевых вызовов. Шрифты встроены (`@fontsource`), внешние ссылки — только
   по явному клику через `tauri-plugin-opener`. Диагностика хоста исполняется **на хосте
   сессии** (SSH/PTY), а не приложением. Проксировать загрузку картинок/данных через Rust
   нельзя — это то же обращение в сеть.
7. **Границы и предохранители — не одно и то же.** Границы: прод-/`noAi`-гейт, окно согласия
   ИИ, keychain, CSP, capabilities. Предохранители (bias: over-flag/over-mask): deny-list
   опасных команд, `needsConfirm`/`ConfirmDialog`, маскирование секретов. Предохранитель не
   заменяет границу, граница не отменяет предохранитель.
8. **Ошибки — типизированы** (ADR 0002). В Rust возвращай `AppResult<T>`
   ([error.rs](../src-tauri/src/error.rs)), не `String`. Семантика — отдельные варианты
   (`AuthRejected`, `HostKeyRejected`, `NoSession`, `UnknownServer`, `KeyExists`,
   `FileChangedOnServer`), прочее — `AppError::Message`. `AppError` сериализуется в строку
   (контракт с фронтом не меняется), маркеры (`auth-rejected`, `key-exists`, `dest-exists`,
   `file-changed`) живут в `Display`.
9. **Контракт типов — camelCase.** Rust-модели — `#[serde(rename_all = "camelCase")]`,
   зеркало в [types.ts](../src/lib/types.ts). Новые поля старых структур — `#[serde(default)]`.

## Терминал и вкладки

- **Единый контракт терминала.** SSH-сессии ([ssh.rs](../src-tauri/src/ssh.rs)) и локальные
  shell-вкладки ([pty.rs](../src-tauri/src/pty.rs), `portable-pty`) используют **один** канал
  (`term://out|closed/{id}`) и **одни** команды (`write_to_terminal`/`resize_pty`/`disconnect`,
  маршрутизация по `session_id`), поэтому [Terminal.svelte](../src/lib/Terminal.svelte) общий
  (проп `local`). Новый вид терминала подключай сюда же. Поверх этого контракта, **без нового
  бэкенда и канала**, сделаны:
  - **Синхронный ввод** — N вызовов `write_to_terminal` из `doBroadcast`
    ([+page.svelte](../src/routes/+page.svelte)), сессии не дублируются (сетка/фокус
    переиспользуют смонтированные `Terminal` через рефлоу CSS); кому/что — чистая логика
    [broadcast.ts](../src/lib/broadcast.ts). Отправка на прод — с подтверждением.
  - **Выбор шелла** — та же `open_local_terminal` с необязательным `shell`; какую программу
    спавнить решает [localshell.ts](../src/lib/localshell.ts) (`resolveLocalShell`): `null` =
    дефолт ОС (`CommandBuilder::new_default_prog()`), иначе явная программа (поиск по PATH).
    Детект ОС — команда `host_os` (`std::env::consts::OS`), **не** runtime-плагин.
  - **Shell в контейнер/под** — новая вкладка того же хоста (`onOpenContainerShell`), команда
    уходит `write_to_terminal` по статусу `connected`; **не** через `container_run`/`kubectl_run`.
    Такая вкладка несёт `Tab.attach` ([tabattach.ts](../src/lib/tabattach.ts)) и подписана
    «nginx · хост», поэтому её shell **обязан закончиться вместе с контейнером**: команду
    печатает `renderSessionCommand` (`exec …` / `…; exit` / `… & exit`), иначе после `exit`
    под именем контейнера остался бы shell хоста (принцип 5). Конец сессии такой вкладки —
    не обрыв: ни автопереподключения (вернуло бы в контейнер сразу после `exit`), ни NO SIGNAL;
    «Войти снова» — обычный реконнект, argv исполняется на **каждом** `connected`. Гейт
    `attachtab.guard`. `port-forward` — разовый `pendingCommand`, процесс живёт в PTY. Панели отдают **argv** (`execShellArgv`/
    `portForwardArgv`), а строку собирает `renderArgv` ([termcmd.ts](../src/lib/termcmd.ts)) под
    **реально запущенную** оболочку вкладки, как `cdCommand`: POSIX-строка `sh -c '… && …'` в
    `cmd.exe` разваливается (`'` там не кавычки — `>/dev/null` и `&&` разбирает сам cmd).
    Неэкранируемый токен → `null` → не шлём ничего.
- **Команда в PTY завершается CR, а не LF.** Enter — это `\r`; `\n` проходит только там, где
  readline/ZLE вешают `Ctrl+J` на `accept-line` — PSReadLine и `cmd.exe` этого не делают, и
  команда молча повиснет в промпте. Многострочный блок шлём **построчно** (иначе на Windows
  выполнится только последняя строка). Единственный источник истины — `submitLine`/`submitBlock`
  в [terminput.ts](../src/lib/terminput.ts).
- **Ввод в сессию идёт строго по порядку.** Асинхронные команды Tauri — независимые задачи на
  многопоточном runtime, поэтому два `invoke("write_to_terminal")` в полёте доходят до PTY в любом
  порядке (E2E набрал `echo vterm`, шелл выполнил `echo vtemr`; так же ломаются автонабор паролей
  и сканеры). `writeToTerminal` отправляет следующую запись только после ответа на предыдущую, а
  накопленное за это время склеивает в одну ([termwrite.ts](../src/lib/termwrite.ts)). Команду
  `write_to_terminal` зовёт **только** эта обёртка — второй прямой вызов снова гоняется с ней.
- **Окно подключения — честный чек-лист.** Пока SSH-вкладка в `Connecting…`, поверх терминала
  висит [ConnectingOverlay.svelte](../src/lib/ConnectingOverlay.svelte). Фазы **реальные**, из
  канала `term://phase/{id}` (`phase_event` в `ssh.rs`: `connecting`→`authenticating`→`session`);
  фронт слушает его в `Terminal.svelte` (проп `onphase`, только SSH), маппинг фаза→шаг — чистый
  [connphase.ts](../src/lib/connphase.ts). Новая **обязательная** стадия = новый `emit` в
  `connect` + запись в `PHASE_ORDER`, не новый канал.
  - **Прокси-подстадии** — тоже реальные события, но **не в `PHASE_ORDER`**: эмитятся первыми,
    jump host `proxyConnecting`/`proxyAuthenticating`/`proxyTunnel`, SOCKS5/HTTP
    `proxyConnecting`/`proxyHandshake`; `phaseSteps(current, errored, proxy)`
    (`proxy: "jump"|"tcp"|null`) добавляет их с тегом группы `proxy`. Честное разбиение SOCKS5
    достигается socket-вариантом `tokio-socks` (сами делаем `TcpStream::connect`, затем
    негоциацию), а не рисованием подстадий (принцип 5). Анимации оверлея — только дешёвые
    `transform`/`opacity`.
  - Чек-лист **всегда вложенный**: шаги сервера — под заголовком-адресом группы `server`,
    прокси-подшаги — под заголовком прокси выше.
  - **Тот же компонент — экран ошибки** (проп `failed`): статичная иконка с красным крестом,
    чек-лист замирает на упавшей фазе (`phaseSteps(phase, true)`), действия — через слот
    `children`; маппинг статуса в заголовок/деталь/фазу/действие — `sshErrorView` в
    `+page.svelte`. Провал аутентификации **не закрывает вкладку**: модалка секрета открывается
    по кнопке «Ввести пароль заново» (`reauth`). Тонкая верхняя плашка остаётся **только** для
    локальных вкладок.
- **Вкладка закрывается ровно одним путём.** `sessionId` — ключ не только строки в списке: под
  ним живут workspace (тексты открытых файлов), диалог с ИИ, членство в broadcast, nginx-кэш.
  Store-level `closeTab` — **только операция над списком**; полный снос — `closeTabFully` в
  `+page.svelte`, и он единственный её вызывает. Массового закрытия в сторе быть не может:
  стору пришлось бы зависеть от workspaces/aichat (инверсия слоёв) — поэтому `tabsForServer`
  **возвращает id и не закрывает ничего**, вынуждая вызывающего пройти через снос. Мёртвый
  `sessionId` в наборе broadcast — не утечка памяти, а **корректность**: рассылка бьёт в
  несуществующую сессию. Заводя новое состояние по `sessionId`, добавь его очистку в
  `closeTabFully`. Он же **завершает сессию** (`disconnect`) — см. «Окна»: компонент терминала
  этого не делает.
- **Центр — дерево областей, терминалы — один плоский список** (ADR 0016). Раскладка центра —
  чистое дерево ([splitlayout.ts](../src/lib/splitlayout.ts)): листья — области (полоса вкладок
  и вкладка, которую область показывает), узлы — сплиты пополам. Дерево превращается в
  прямоугольники (`layoutRects`), и терминал ставится по прямоугольнику своей области. Сами
  терминалы рисует **один** `{#each tabsState.list}`: монтирование `Terminal` не должно зависеть
  от раскладки — ни `{#each}` по областям, ни `{#if}` на сплит, ни `{#key}` кроме `tab.gen`.
  Пересозданный `Terminal` подключается заново (заменяя сессию) и начинает с пустого
  scrollback, и «перенести вкладку в соседнюю область» стало бы «оборвать соединение». Гейт
  `centerlayout.guard`.
  - **Раскладку меняет только чистая модель.** Стор вкладок присваивает дереву только результат
    функции `splitlayout.ts` (`$state.raw`: дерево заменяется целиком, а не правится на месте);
    у `tabsState` нет сеттеров, вне стора никто не пишет ни список вкладок, ни дерево. Вкладка,
    которой нет ни в одной области, — живая сессия, до которой не добраться.
  - **«Активная вкладка» — производная, а не поле.** `tabsState.activeId` — вкладка, которую
    показывает область в фокусе; меняют её `activateTab` и `focusPane`. Второе, записываемое
    `activeId` могло бы разойтись с деревом — доки и статус-бар следили бы не за той сессией.
  - **Пустых областей нет.** Область появляется только вместе с вкладкой (`splitWithTab`) и
    исчезает с последней; пустой бывает лишь единственная. Пустая область в фокусе значила бы
    «сессии нет» — доки и статус-бар гасли бы на время запроса пароля. Поэтому «новый терминал
    справа» открывает вкладку и **тем же тактом** выносит её в новую область, а отменённый
    запрос пароля не меняет ничего.
  - **Открытие вкладки не прячут в аргумент необязательного вызова.** `place?.(openTab(…))` не
    открывает ничего, когда `place` не передан: `?.()` не вычисляет и аргументы. Так ⌘T и
    двойной клик по серверу однажды перестали открывать вкладку — тестов у страницы нет.
  - **Предел — по пикселям, а не по счёту.** Область не рисуется меньше `PANE_LIMITS`, пока
    место есть (разделитель упирается в минимум соседей); разделить область, где две
    минимальные не поместятся, нельзя (`canSplit`) — команда недоступна, а не «делит как выйдет».
- **«На экране» — больше не одна вкладка.** Это показанная вкладка каждой области, а в сетке
  синхронного ввода — все участники: `onScreenSessions`
  ([centerview.ts](../src/lib/centerview.ts)). Всё, что раньше значило «активная вкладка, потому
  что её видно», считается от этого набора: запись идёт у вкладок на экране (остальные на
  паузе), вопрос сервера о входе показывается для вкладки на экране — сперва для той, что в
  фокусе. То, что следует за **одной** сессией (доки, статус-бар, контекст ИИ, заставка,
  заголовок окна), читает `tabsState.activeId`.
  - **Клавиатуру после подключения берёт только терминал области в фокусе** (`focusOnConnect`):
    терминал, переподключившийся в соседней области, иначе выдёргивал бы курсор из-под набора.
  - **Одна полоса вкладок, пока область одна** — над центром, как до сплитов; у каждой области
    своя полоса появляется, только когда областей больше одной. Синхронный ввод — отдельный
    режим поверх сплитов: он раскладывает участников сам и тоже показывает одну полосу со всеми
    вкладками по порядку областей.
- **Перетаскивание вкладки терминала меняет раскладку один раз — при отпускании**
  ([tabdrag](../src/lib/stores/tabdrag.svelte.ts)). Пока вкладка в воздухе, полосы рисуют
  предпросмотр порядка (`previewTabs`), а половину области, которую она займёт, показывает
  подсветка-оверлей: настоящий перенос на каждое движение мыши менял бы размер терминалов —
  по `SIGWINCH` на пиксель программам в них. Куда вкладка попадёт, решает чистая модель
  (`paneZone`/`applyDrop`); цель, которая ничего не изменит, не предлагается. Слот в полосе
  считается по `layoutBox`, как у вкладок доков. Три пути, не только мышь: перетаскивание,
  меню вкладки и команды ⌘K.
- **Прод — флаг профиля, а не тег.** `isProdServer(server)` читает `ServerProfile.prod`; теги —
  только метки поиска. `prod: null` — профиль, сохранённый до появления флага: для него (и только
  для него) действует старое правило точного тега `prod`/`production` (`isLegacyProdTag`,
  регистронезависимо, с trim), иначе обновление молча сняло бы защиту с настроенных прод-серверов.
  Форма сохраняет флаг **всегда явно**, так что наследие исчезает при первом сохранении, а явный
  флаг побеждает тег в обе стороны. Legacy-матчинг **не расширяй** до substring/токенов:
  `non-prod`/`pre-prod` ложно попали бы под защиту. Наследования `prod`/`noAi` через папки нет
  (папка — строковая метка).
- **Прод виден в двух местах сразу.** Вкладка прод-сервера несёт чип `prod`, а её окно
  терминала — красную рамку (в сетке синхронного ввода — красная граница ячейки): вкладку ищут
  глазами, а рамку видят, пока печатают. Набор вкладок — `prodTabIds` из того же
  `prodMembers`, что подтверждение рассылки. Рамка — инертный оверлей
  (`pointer-events-none`, свой `z-index`) поверх контейнера вкладки, **не** border/padding на
  терминале: элемент xterm меряет `FitAddon` (см. `termfit.guard`). Гейт `prodmark.guard`.
  - **Полоса сверху — у активной вкладки, а не у прода.** Красная линия на каждой прод-вкладке
    читалась как «эта вкладка активна». Линию несёт только активная вкладка (2px) и активная
    подвкладка панели сессии (1px): `accent`, у прод-сессии — `bad`; единственный источник —
    `activeTabStrip` ([tabstrip.ts](../src/lib/tabstrip.ts)). Когда областей несколько, активная
    — вкладка области **в фокусе**: вкладка, которую показывает другая область, подсвечена как
    выбранная, но без линии — линия отвечает на вопрос «куда уйдёт набор и за кем идут доки».
  - **Фон прод-терминала подкрашен** (`settings.prodTint`, по умолчанию включено): цвет темы с
    примесью выбранного цвета, 3–25 % ([prodtint.ts](../src/lib/prodtint.ts)). xterm берёт
    готовый цвет, поэтому смесь считается в коде (`mixHex`, [colormix.ts](../src/lib/colormix.ts)),
    и **одна** функция `paintedTheme` в `Terminal.svelte` красит и canvas, и полоску отступа —
    иначе вокруг текста осталась бы рамка нетонированного цвета. Не-hex фон темы не трогаем.

## Окна

Вкладку можно вынести в отдельное окно ОС (ADR 0017) и перенести в другое открытое, в том
числе вернуть в главное (ADR 0018). Окно — отдельный WebView со своей памятью, поэтому всё, о
чём окна должны договориться, живёт в бэкенде ([appwin.rs](../src-tauri/src/appwin.rs)), а не
в сторе.

- **Окно — та же страница, роль — по метке.** `main` — главное окно, `win-N` — окно, в которое
  вынесли вкладку ([appwindow.ts](../src/lib/appwindow.ts)). Второй, «урезанной» страницы нет:
  у вынесенной сессии те же панели, сплиты и статус-бар. Создаёт окна только Rust; у WebView
  права открывать окна нет (гейт `tauri-security.guard`).
- **Главное окно — якорь.** Его закрытие — выход из приложения; только оно сохраняет раскладку
  доков, забирает «Открыть с помощью» (`take_pending_opens`, `vterm://open-file`) и
  предупреждения хранилища. Второе окно начинает с сохранённой раскладки, но не пишет её —
  иначе следующий запуск открылся бы в раскладке случайного окна. Оно появляется только выносом
  вкладки и закрывается само вместе со своей последней вкладкой.
- **Сессию завершает `closeTabFully`, а не компонент.** `Terminal.svelte` не зовёт `disconnect`
  ни в `onDestroy`, ни где-либо ещё: вкладка, переданная другому окну, размонтирует свой
  терминал, а сессия живёт дальше. Бэкенд помнит окно-владельца каждой сессии: чужой
  `disconnect` он игнорирует, а сессии уничтоженного окна завершает сам (у закрытого WebView
  teardown не выполняется). Сессия удаляется из реестра в одном месте — `end_session`. Вкладка
  уходит без завершения сессии (`closeTabFully(id, true)`) ровно в двух случаях: её только что
  приняло другое окно, или это окно не смогло её принять.
- **Вывод терминала идёт только через затвор** ([outgate.rs](../src-tauri/src/outgate.rs)).
  `term://out` и `term://closed` шлёт затвор сессии и никто больше — SSH, локальный PTY и
  зеркало шагов ИИ пишут в него. Эмит мимо затвора минует придержку при передаче вкладки: байты
  легли бы в окно, которое вкладку уже отдаёт, после снимка, и пропали бы.
- **Передача вкладки — придержать, снять, дождаться, отпустить.** Порядок в `detachTab`
  обязателен: `detach_begin` (затвор копит вывод и сообщает, сколько событий уже ушло) → снимок
  xterm, когда терминал получил их все → `detach_commit` (бэкенд создаёт окно или предлагает
  вкладку открытому — и ждёт) → вкладка убирается из этого окна. Принимающее окно сперва
  подписывается на вывод, пишет снимок **в той же сетке**, в которой он снят, и только потом
  зовёт `attach_session` — с этого вызова придержанное идёт ему. До него всё состояние остаётся
  у исходного окна, поэтому любой сбой — откат (`gate.resume()`): вывод уходит исходному окну,
  вкладка остаётся где была.
  - **Придержанное ограничено** (`HOLD_CAP`). Переполнение — откат с сообщением, а не потеря
    байтов и не рост памяти: печатающий без остановки терминал вынести нельзя.
  - **Снимок ждёт счёт, а не паузу.** Затвор считает отправленные события, терминал —
    полученные; «подождать 100 мс» вместо сверки счёта теряет хвост вывода на медленной машине.
- **Пакет вкладки — только через IPC и только в памяти.** В нём пароль вкладки и sudo-пароли
  редакторов; бэкенд держит его в `Zeroizing`, отдаёт одному окну и один раз. `localStorage`
  и `BroadcastChannel` для него запрещены: первое — диск, у второго нет адресата.
- **Открытое окно принимает вкладку тем же путём — и от этого не закрывается** (ADR 0018).
  Цель `detach_commit` — метка окна, которое само назвало себя принимающим (`announce_window`),
  не отдающее и не занятое приёмом другой вкладки: передача хранится под меткой цели, второй
  одновременной быть не может (`takes_tabs`). Окно называет себя **только после** подписки на
  предложение (`window://handoff`) — названному раньше предложили бы вкладку, о которой оно не
  услышит. Откат закрывает окно, только если бэкенд открыл его под эту вкладку (`created`);
  фронт окна, которому вкладка не досталась (`adoptFailed`), убирает её копию и закрывается,
  только если других вкладок нет: у открытого окна свои сессии, и они умерли бы вместе с ним.
  Окно, которое не может принять вкладку, отказывается сразу (`decline_handoff`), а не
  оставляет отдающее ждать таймаута под блокировкой. Гейты `windowhandoff.guard` и
  `a_failed_handoff_never_closes_a_window_that_was_already_open`.
- **Окно под указателем спрашивают у ОС — точно или никак**
  ([winhit.rs](../src-tauri/src/winhit.rs)). Pointer-события кончаются на краю окна, поэтому
  на что брошена вкладка, отвечает бэкенд: macOS — `windowNumberAtPoint`, Windows —
  `WindowFromPoint`. Считать по прямоугольникам окон и порядку фокуса нельзя: прямоугольник не
  знает, что окно перекрыто чужим, лежит на другом рабочем столе или свёрнуто, — вкладка,
  брошенная *рядом* с окном, улетала бы в окно, которого не видно. Где ОС не отвечает (Linux),
  цели нет: бросок открывает новое окно, перенос между окнами — меню и ⌘K. Оттуда же — место
  указателя внутри окна (`contentLayoutRect`, `ScreenToClient`), а не из того, где Tauri видит
  окно на экране, и не из предположения о высоте заголовка: на macOS 26+ содержимое любого
  окна с заголовком идёт под него, «прямоугольник содержимого» равен всей рамке, и отсчёт от
  него ставил указатель на высоту заголовка ниже — вкладку приходилось наводить её меткой, а
  полоса вкладок не расступалась. Страница занимает ту часть окна, которую заголовок не
  закрывает. Решает отпускание — вопрос задаётся заново (`drag_drop`), а не читается
  с того, где вкладку рисовали последний раз (`dropOutside`). Гейт
  `the_window_under_the_pointer_is_asked_of_the_os_never_guessed`.
- **Вкладку над чужим окном рисует это окно — и до её прибытия ничего в себе не меняет.**
  Окно-цель о перетаскивании не знает ничего: указатель держит окно, из которого тащат. Оно
  говорит бэкенду (`drag_over`), тот — окну под указателем (`window://drag`), и оно показывает
  вкладку у указателя, место под неё в полосе и половину области у края — как для своей
  ([tabincoming](../src/lib/stores/tabincoming.svelte.ts)). Это предпросмотр
  (`previewIncoming`), а не перенос: стор предпросмотра знает стор вкладок только по типу,
  раскладку ему менять нечем, — настоящая перестановка на каждое движение мыши меняла бы
  размер терминалов. Вкладка встаёт один раз, когда приходит (`placeTab`): туда, где окно
  держало для неё место, а присланная командой — в область в фокусе. `placeTab` — не «открыть
  и переставить»: открытие заставило бы область в фокусе показать новую вкладку, и после
  перестановки она показывала бы соседнюю, а не ту, что была.
  - **О перетаскивании говорится по порядку и до конца.** `over` уходит по одному; возврат в
    окно (`left`) и отпускание ждут того, что ещё в пути, — иначе окно-цель получило бы место
    вкладки после известия, что она ушла. Каждый конец без прибытия вкладки обязан быть
    сказан (`drag_end`): вернулась, отменили, перенос запрещён, передача сорвалась — иначе окно
    осталось бы с вкладкой, которая не придёт. Отпущенной вкладке окно держит место
    (`landing`) до прибытия, но не дольше `LANDING_TIMEOUT_MS`.
  - **Вкладка, которую нельзя перенести, никому не показывается** (`tellDragOver` сверяется с
    `detachBlocker`); причина говорится при отпускании. Метку рисует кто-то один: над чужим
    окном — оно, над рабочим столом — окно-метка, и в своём окне она тогда гаснет.
  Гейты `windowhandoff.guard` (раздел 7) и `centerlayout.guard`.
- **Окно под указателем выходит вперёд, и где указатель — решает бэкенд, а не границы окна.**
  Пока вкладку тащат, окно приложения под указателем становится активным (`raise_window`,
  один раз на заход — `Registry::raise`): в полосу, перекрытую другим окном, не попасть, а
  неактивное окно рисует вкладку с опозданием. Поднятое окно может лечь поверх исходного, и
  тогда указатель «внутри» исходного по его границам, хотя он над другим окном. Поэтому при
  других окнах о вкладке сообщается на **каждом** движении, а не только за пределами окна, и
  ответ (`tabDrag.window`) гасит цели в своём окне; отпускание над чужим окном внутри своих
  границ — бросок на то окно (`release(…, outside)`), а не в свою область. Потеря фокуса
  исходным окном перетаскивание не обрывает: удержание выделения берётся заново на каждом
  движении. Вкладка, которую только переставляют в своей полосе, и другого окна нет, не
  спрашивает никого — иначе вызов на каждое движение мыши и окно-метка, которую никто не увидит.
- **Над рабочим столом вкладку рисует окно-метка — картинка, а не участник**
  ([dragghost.rs](../src-tauri/src/dragghost.rs), `static/ghost.*`). Страница за пределами
  своего окна не рисует ничего, поэтому между окнами метку показывает маленькое окно без рамки
  поверх всего, которое бэкенд держит у указателя. Каждое «нельзя» у него — способ сломать
  перетаскивание, которое оно лишь иллюстрирует: получив фокус, оно забрало бы клавиатуру и
  само перетаскивание у исходного окна (`focused(false)`, `focusable(false)`); доступное мыши,
  оно стало бы «окном под указателем», и до окна под ним вкладка не дошла бы
  (`set_ignore_cursor_events`, ответ `pointer_window` его исключает, смещение от указателя);
  названное как окно приложения, оно получило бы его права и попало бы в список окон для
  переноса (метка `drag-ghost`, capability на него не действует, команд оно не зовёт, вид ему
  задают `eval`-ом). Показывается только после загрузки своей страницы — до того метку рисует
  исходное окно, а не пустой прямоугольник. Подписи на нём нет: над столом вкладка говорит,
  что несут, а не что будет при отпускании. Создаётся при первом перетаскивании за окно и
  живёт скрытым до выхода. Там, где ОС не говорит, что под указателем (Linux), окна-метки нет
  — метка остаётся у края исходного окна, с подписью. Гейт
  `the_floating_label_is_a_picture_and_never_a_window_of_the_app`.
- **Выносится только то, что можно вынести целиком** — `detachBlocker`
  ([tabhandoff.ts](../src/lib/tabhandoff.ts)). Сравнение, синхронизация, перенос файла, ответ
  ИИ и сохранение файла ждут в памяти исходного окна: вкладка с такой работой остаётся и
  говорит почему. Заводя новую работу «в полёте» по сессии, добавь её в `DetachState`.
  Единственная вкладка второго окна не уходит в **новое** окно (получилось бы то же окно), но
  уходит в открытое — так она возвращается, а опустевшее окно закрывается за ней.
  Состояние вкладки собирают и раскладывают две функции — `packTab`/`unpackTab`
  ([stores/tabpacket.ts](../src/lib/stores/tabpacket.ts)); новое состояние по `sessionId`,
  которое пользователь восстанавливал бы руками, добавляется в обе.
- **Событие без id в имени — одному окну, и слушают его адресно.** Команды нативного меню —
  окну в фокусе, выход и «Открыть с помощью» — главному, прогресс переносов и сравнения — окну,
  которое их запустило (`WindowSink`). На фронте — только `listenHere`: обычный `listen`
  слышит и то, что послано другому окну, и Настройки открылись бы во всех окнах сразу.
- **Общее для окон — через бэкенд.** Настройки рассылаются снимком (`window://settings`) и
  применяются той же очисткой, что импорт бэкапа; любая запись `servers.json`/`folders.json`
  даёт `window://catalog` (хук в `store.rs`, а не строка в каждой команде) — флаги `prod` и
  `noAi` не могут разойтись между окнами. Удаление сервера закрывает его вкладки во всех окнах.
  «Один прогон синхронизации на приложение» — замок в бэкенде (`SyncBusy`), флаг в JS-сторе
  второго окна не видит.
- **Три точки входа, как у переноса между областями:** меню вкладки, ⌘K и бросок вкладки за
  пределы окна (`releasedOutside`: решает место отпускания, а не последнее движение) — на
  другое окно приложения или мимо всех, в новое. Брошенная на окно вкладка встаёт туда, куда
  её бросили — в место полосы, в область или в новую область у края; присланная из меню или
  ⌘K — в область в фокусе.

## Панели-драйверы

Git, Docker, k8s, сетевые пробы и метрики — **один контракт исполнения**: одна бэкенд-команда
на драйвер (`session_id` + argv), транспорт по принципу 3, бэкенд — дамповый исполнитель,
argv/парсинг — чистый `.ts`, вид — в `*.svelte`. Общие правила:

- **Шелл-квотинг обязателен** на SSH-ветке (`git::shell_quote` — единственная реализация) —
  защита от инъекции. Пайплайн идёт одним токеном `sh -c '<pipeline>'`.
- **Локальный спавн — только через [localenv.rs](../src-tauri/src/localenv.rs)**
  (`resolved_local`): упакованное macOS-приложение наследует от launchd минимальный `PATH`
  (`/usr/bin:/bin:/usr/sbin:/sbin`) без Docker Desktop/Homebrew, поэтому `Command::new("docker")`
  не находит бинарь **только в `tauri build`**. Реконструируем `PATH` из login-шелла (кэш) +
  известных каталогов и резолвим программу в абсолютный путь. Шеллом команду **не** оборачиваем
  (аргументы verbatim). ENOENT возвращаем как `exit 127` + stderr, **не** `Err`, чтобы
  `parseAvailability` честно сказал «не установлен». **Каждый** такой фоновый спавн
  консольного CLI проходит через `localenv::no_console_window` (на Windows `CREATE_NO_WINDOW`,
  иначе no-op): приложение — GUI-бинарь, и без флага дочерний `conhost` мигает окном на каждый
  поллинг панели (гейт `every_local_cli_spawn_hides_the_console_window`). Интерактивный
  PTY-шелл не в счёт — у него свой pty.
- **Аудит в записи — record-only.** Мутирующий вызов с флагом `mirror` пишется в активную запись
  сессии как `[тег] $ … / [тег] exit N` через `record_output` (функция `*_mirror` в модуле
  драйвера: `git::git_mirror`, `container::container_mirror`, `kube::kube_mirror`,
  `sftp::sftp_mirror`); в живой терминал **не** эмитится (GUI чистый). Чтения и поллинг не
  мирроятся. Секреты не логируются никогда.
  - **Сетевые утилиты пишут итог, а не сырьё.** `probe_run`/`netcheck_run` в запись не пишут
    ничего: в argv HTTP-клиента — значения заголовков (`Authorization`) и тело запроса, в выводе —
    тело ответа и `Set-Cookie`, у проверки доступа — нечитаемый протокол. Блок `[util] $ … /
    [util] exit N` пишет `record_audit` (`netprobe::audit_block`, вычищает управляющие символы
    ответа сервера), а строку и тело собирает фронт из **разобранного** результата
    (`tlsAudit`/`httpAudit`/`netcheckAudit`): поля сертификата, метод и URL с маской, **имена**
    заголовков, размер тела, статус и тайминги; отчёт проверки доступа — тот же, что «Скопировать
    отчёт». Провал записывается провалом (`exit ≠ 0`), а не тишиной. «Выполнить в терминале»
    аудита не требует — команда и вывод и так идут в запись. Гейт
    `network_utilities_never_record_raw_argv_or_output`.
- **Живой вид — снимок раз в N сек, не поток** (`--no-stream`, `logs --tail` без `-f`); поллер
  живёт только пока панель **видима** — проп `visible` от дока ([Dock](../src/lib/Dock.svelte) →
  [DockPanel](../src/lib/DockPanel.svelte)), а не факт монтирования (панели дока не
  размонтируются, см. ниже). Возврат во вкладку делает **один** немедленный снимок: пока панель
  была скрыта, данные не обновлялись.
- **Эффект не зависит от того, что пишет сам.** Async-функция, вызванная из `$effect`,
  отслеживается до своего первого `await`: всё, что `initAll()`/`refresh()` успели прочитать
  (запомненный scope, `scope` внутри собираемого argv), становится зависимостью эффекта. Если
  функция потом сама это пишет, эффект перезапускается на собственном результате — раньше
  эффекта, который результат запоминает. Так панель k8s сбрасывала только что выбранный context
  и зондировала заново: каждый ответ `kubectl` порождал два новых запроса — экспоненциальный
  шторм процессов **на хосте сессии**. Инициализация и перезагрузка зовутся под `untrack`;
  зависимости эффекта — только то, что названо в нём явно. Гейт — `K8sPanel.test.ts` (считает
  вызовы на одно монтирование).
- **Три дока, два класса вкладок** (ADR 0015). Панели-инструменты (`PanelId`: дерево серверов,
  файлы, Git, Docker, k8s, ИИ) живут в левом, правом и нижнем доках и переносятся **только**
  между ними; терминалы и редакторы — только в центре. Панель рисуется в одном месте — сниппетом
  `dockPanel` в `+page.svelte`, который получают все три [Dock](../src/lib/Dock.svelte);
  сессионные панели — только через [DockPanel](../src/lib/DockPanel.svelte). Бросить панель в
  центр или терминал в док нельзя: у них разный жизненный цикл (панель штатно пересоздаётся на
  смену сессии, пересоздание терминала рвёт соединение). Нижний док — на всю ширину окна, над
  статус-баром. Гейт `docklayout.guard`.
- **Раскладка доков — чистые данные и только через `loadDocks`.** Модель —
  [docklayout.ts](../src/lib/docklayout.ts): у дока порядок панелей, показанная вкладка, размер,
  сворачивание; **каждая панель ровно в одном доке**. `vterm.layout` пишет пользователь (и старая
  или новая сборка), поэтому в стор он попадает только через `loadDocks` — тот чистит прочитанное
  (дубли и незнакомые панели — прочь, потерянная панель — в свой док по умолчанию, размеры в
  пределы) и переносит ключи раскладки до 1.1. Менять раскладку — только `movePanel`/`revealPanel`
  и функциями стора ([layout.svelte.ts](../src/lib/stores/layout.svelte.ts)); прямое
  `layout.docks = …` и правка `panels` вне модели запрещены — панель, которой нет ни в одном
  доке, из интерфейса не вернуть. Сохраняются **только доки** и только главным окном (см.
  «Окна»); раскладка центра — нет (вкладки при перезапуске не восстанавливаются). Гейт
  `docklayout.guard`, property-тесты модели.
- **Панель не знает, в каком она доке.** Док передаёт панели её id и «на экране ли она» — и
  ничего больше; сторону дока панель не получает и раскладку не читает. Под место она
  подстраивается сама, по **своему фактическому размеру**: `@container` на корне панели +
  варианты `@wide:` (брейкпоинт `--container-wide` в app.css). Положение — не ориентация: правый
  док растягивается до 720 px, нижний на узком окне бывает у́же. Второй, «горизонтальный»
  компонент той же панели заводить нельзя. `@container` ставится только на элемент без
  `fixed`-потомков: в части движков containment делает его containing block для
  `position: fixed`, и модалка внутри него перестала бы накрывать окно — диалоги панели стоят
  рядом с её корнем, не внутри. Гейт `docklayout.guard`.
- **Док без доступных панелей не рисуется.** Сессионным панелям нужна сессия: без открытой
  вкладки док предлагает только дерево серверов, а пустой — не занимает места вовсе. Сохранённая
  вкладка дока при этом не переписывается (`shownPanel` — запасная только для показа). Пока
  вкладку перетаскивают, край окна невидимого дока становится зоной сброса — **оверлеем**, а не
  полосой в раскладке: полоса изменила бы размер терминала посреди перетаскивания.
- **Скрытая панель не предлагается нигде.** `settings.hiddenPanels` (в настройках, поэтому
  попадает в бэкап) — один список на всё: такую панель не рисует ни один док, она не
  монтируется и не опрашивает хост, её не предлагают ⌘K и меню переноса, а `revealPanel` её не
  открывает — индикатор или кнопка не отменяют выбор пользователя. Точки входа ИИ («спросить
  про…») гаснут вместе с панелью ИИ: флаг `aiOn` включает `!isPanelHidden("ai")`. Место панели
  в доке **сохраняется** (скрытие — фильтр в `offeredPanels`, раскладку оно не трогает),
  поэтому возвращается она туда же. Дерево серверов скрыть нельзя (`HIDEABLE_PANELS`): без
  него на экране не с чего подключаться. Пишет список только `setPanelHidden`, читает из
  хранилища — только `sanitizeHiddenPanels`; каждый, кто спрашивает «что показывает док»
  (`availablePanels`/`shownPanel`/`isPanelShown`), обязан передать список. Фоновая работа
  скрытой панели (переносы SFTP) не прерывается и остаётся управляемой там, где была, — в
  статус-баре. Гейт `docklayout.guard`.
- **Перенос панели — три пути, не только мышь**: перетаскивание вкладки (pointer-события,
  [dockdrag](../src/lib/stores/dockdrag.svelte.ts)), контекстное меню вкладки и команды в ⌘K.
  Куда панель попадёт, решает чистая модель (`insertionIndex`/`movePanel`); доки только помечают
  себя целями (`data-dock-drop`/`data-dock-tab`). Док, принявший панель, показывает её и
  раскрывается — иначе панель, брошенная в свёрнутый док, пропала бы с экрана.
  - **Раскладка меняется один раз — при отпускании.** Пока вкладка в воздухе, полосы рисуют
    только *предпросмотр* порядка (`previewPanels`): соседи расступаются, а место вкладки
    держит она сама с `opacity-0` (не `invisible`/`hidden` — пустое место обязано отвечать на
    hit-test, иначе указатель «над ничем» читается как «в конец»). Панели под полосой, активная
    вкладка и сворачивание берутся из сохранённой раскладки: предпросмотр, открывающий каждый
    док по пути указателя, показывал и прятал бы их панели.
  - **Цель считается по месту вкладки в раскладке, а не по тому, где её рисует анимация**
    (`layoutBox` в [actions/drag.ts](../src/lib/actions/drag.ts)). Сдвиг соседа — это
    `transform`: пока он едет, под указателем всё ещё он, и перестановка тут же откатывалась бы.
    Над собственным местом вкладки цель не пересчитывается. То же у вкладок терминалов:
    место — за каждой вкладкой, чью **середину** указатель прошёл (`slotIndex`), иначе обмен с
    более широкой соседкой отменяется на следующем же движении мыши. Гейт `docklayout.guard`.
- **Панель дока не размонтируется при переключении вкладок.** `Dock` монтирует панель при
  первом показе и дальше только **скрывает** её — при смене вкладки дока **и при сворачивании
  дока**; `{#key}` и `{#if active === …}` вокруг содержимого запрещены. Пересоздание рушило всё,
  что панель держала: SFTP просил «Подключить» заново для **живого** канала (`SshSession::sftp`
  кэширует его до `disconnect`), файловая панель прыгала в home, k8s забывал выбранные
  context/namespace, Docker заново опрашивал демона. Обе половины обязательны и держатся вместе
  гейтом `dockpanels.guard.test.ts`: **смонтирована** — значит поллинг гейтится `visible`
  (вкладка дока показана, док раскрыт, сессия жива), а window-wide обработчики (drop файлов в
  [FileBrowser](../src/lib/FileBrowser.svelte)) скрытую панель игнорируют. Голого `void visible;`
  мало — гейт требует условие. Сессионная панель принадлежит сессии: её ключ несёт `sessionId`,
  поэтому у другой сессии своя панель, а дерево серверов — глобальная панель — остаётся тем же
  экземпляром.
  - **Док держит панели всех сессий на экране, а показывает — сессии в фокусе.** С двумя
    терминалами рядом фокус меняется на каждый клик; пересоздание пяти панелей на клик — это
    мигание и пачка команд на хост. Поэтому `Dock` получает сессии на экране (`sessions`, по
    одной на область) и оставляет их панели смонтированными, **скрытыми**: видима (`visible`)
    только панель сессии в фокусе, остальные не опрашивают хост. Сессия, ушедшая с экрана,
    свои панели теряет, как раньше. Панель строится для сессии, которую назвал док (`sid`), а
    не для «активной вкладки» — скрытая иначе действовала бы на чужую сессию. Пока областей
    больше одной, док подписывает, чья это панель (`caption`).
- **Док ждёт сессию у любого вида вкладки.** `sessionReady` панелям Git/Docker/k8s — из
  `dockConnection` и для локальной вкладки тоже, не `true`: у неё есть честный
  `connecting`→`connected`, а до регистрации PTY бэкенду не на чем исполнять команду. Форс в
  `true` давал «Docker недоступен» на вкладке, открытой «Открыть shell» (на Windows ConPTY
  стартует медленно). Гейт `dockpanels.guard`.
- **Мёртвая сессия — одна заглушка на весь док.** Состояние сессии для дока — `dockConnection`
  ([tabs.svelte.ts](../src/lib/stores/tabs.svelte.ts)): `connecting`/`connected`/`offline`, и
  `offline` — это и разорванная, и так и не установленная сессия. Для `offline` каждая
  сессионная вкладка любого дока показывает одно «Нет соединения» (кнопки переподключения в доке
  нет — она в окне терминала; дерево серверов от сессии не зависит и остаётся), а панели
  остаются смонтированными, но считаются **скрытыми** (`visible=false`):
  поллеры стоят, по возвращении — один свежий снимок. «Проверка…» вместо «нет соединения» —
  правдоподобная заглушка (принцип 5).
- **То, что переживает смену терминальной вкладки, живёт в сторе.** Сессионная панель keyed по
  `sessionId`: при смене вкладки терминала — и при переносе панели в другой док — она
  **пере**создаётся; поэтому состояние, которое пользователь
  иначе восстанавливал бы руками, лежит в [dockstate.svelte.ts](../src/lib/stores/dockstate.svelte.ts)
  по `sessionId`: подключение и каталог файловой панели, scope k8s, активная подвкладка. Хранить
  там скролл, выделение и открытые модалки не надо — дёшево воссоздаются и устаревают. Стор keyed
  по сессии, значит чистится в `closeTabFully` (гейт `tabteardown.guard.test.ts`). Запомненный
  context, которого больше нет в kubeconfig, **не** вшивается в argv — откат на текущий.
- **Подтверждения.** `isDestructive`/`needsConfirm` (чистые предикаты) → `ConfirmDialog` на
  **любом** сервере; на прод-вкладке добавляется красное предупреждение. Это предохранитель, а
  не граница (принцип 7).
- **Сетевые операции — только по явной кнопке** (`fetch`/`pull`/`push`, `docker login`): трафик
  идёт с хоста сессии, офлайн-инвариант цел. Локальные чтения обновляются сами.

- **Возраст в строке списка — один формат на все панели.** `compactAge`
  ([age.ts](../src/lib/age.ts)): `45s`/`3h20m`/`5d4h`/`3w`/`8mo`/`2y`, не длиннее пяти знаков,
  без перевода; k8s и Docker зовут её через `k8sAge`/`dockerAge`. Готовую фразу инструмента
  (`CreatedSince` — «3 weeks ago») в строку не берём: она съедает ширину у имени. Полная дата —
  в подсказке, на языке интерфейса (`dockerDate`); нераспознанный штамп — «—» в строке и сырой
  текст в подсказке (принцип 5).
- **Потолок нагрузки берётся из спека, а не из процентов.** Доля «сколько использовано из
  доступного» считается только там, где лимит **известен**: у пода — `spec.containers[].resources.limits`,
  у контейнера — `HostConfig` через кэшируемый `inspect`. Проценты `docker stats` не годятся: у
  безлимитного контейнера они считаются от памяти хоста и неотличимы от доли лимита. Объект без
  лимита показывает голое число и пометку — шкалу ему рисовать нельзя. Сумма по стеку — `null`,
  если хоть один безлимитный (так считает и сам кластер).
- **Возможности хоста — гейт по данным, а не по ОС приложения.** «Нет данных» ≠ «здесь
  невозможно»: иначе Windows получает load average из прочерков и кнопку «Установить lm-sensors».
  Предикаты — чистый [hostcaps.ts](../src/lib/hostcaps.ts) поверх **уже существующего**
  `Metrics.os` (`uname -s` по SSH, `System::name()` локально) — ОС **хоста сессии**, а не
  `hostOs()` приложения: для SSH-вкладки с Windows на Linux-сервер верен только первый.
  Неизвестная/пустая ОС → блок **остаётся** (пустота значит «ещё не опрошено»). Новый
  «недоступный здесь» показатель — предикатом с тестом, не проверкой ОС по месту.
- **Метрики опрашиваются на трёх уровнях, и новая идёт в свой.** Лёгкий бар — `METRICS_SCRIPT`
  (один exec раз в N с); тяжёлые метрики страницы — `DETAIL_SCRIPT`; точечное и опциональное
  (GPU, Docker, SMART, OOM, статическое железо) — `EXTRAS_SCRIPT`, опрашивается **один раз при
  открытии** оверлея; очень тяжёлый подсчёт обновлений — `fetch_pending_updates`, лениво.
  Раздувать `METRICS_SCRIPT` нельзя — он платится на каждом тике. Дельтовые величины
  (per-core CPU%, ctxt/intr, per-device rate через общий `dev_rate_map`) держат пер-сессионные
  сэмплы в `MetricsSamples` и **чистятся в `disconnect`** — заводя новую, добавь очистку туда же
  (гейт читает саму структуру и требует каждое поле).
- **Зонд читает, производные считает Rust.** В `*_SCRIPT` попадают только сырые показания; любая
  величина, полученная вычитанием («использовано»), считается в парсере — там искажённый вход
  можно распознать и покрыть тестом. Разность, посчитанная на хосте, уходит отрицательной, `u64`
  её не берёт, и «использовано» **молча** становится `None` — прочерк рядом с живым «всего».
  Отсутствующее поле зонд не печатает вовсе (`MemTotal:<kB> …` с метками), а не выдаёт за ноль.
  Гейт `probe_scripts_report_raw_readings_not_differences`.
  - **«Использовано» RAM — то, что печатает `free` самого хоста.** Единого определения нет, и
    `free` сам его сменил: procps-ng 3.3.15 (OL 8) печатает всего − свободно − buff/cache, 3.3.17
    (OL 9) — всего − доступно; на одном хосте это 6.5 против 7.7 ГиБ (разница — в основном `shared`:
    лежит в buff/cache, но не освобождается). Админ сверяет статус-бар с `free -h` на этой машине,
    поэтому зонд отдаёт её `LC_ALL=C free -b` как есть, а `parse_free` читает колонку **по имени** и
    доверяет ей, только если нет неоднозначности: раскладка с `available` (в старой `buffers`/`cached`
    «used» включает кэш), по полю на колонку (busybox склеивает переросшие числа), `used ≤ total` и
    `total` **ровно** равен `MemTotal` (busybox читает `sysinfo()` — под lxcfs это другая машина).
    Это осознанная цена одного лёгкого процесса на тике `METRICS_SCRIPT`. Без `free` — свой расчёт
    `mem_used` по правилу procps ≥ 3.3.17. Проверено против настоящих `free` OL 8 и 9 на подменённом
    `/proc/meminfo`, а не по памяти: утверждение «так считает `free` на OL 9» уже однажды оказалось
    ложным.
  - **`MemAvailable` больше `MemTotal` — искажение, а не «всё свободно».** Реальная VM на OL 9.8
    отдавала 61.2 ГиБ доступных при 7.3 ГиБ всего — и при этом свопилась; так же ведут себя lxcfs
    и ballooning. Кламп в ноль — правдоподобная заглушка (принцип 5): он показывал «0 MiB
    использовано» на машине, которой не хватало памяти. procps-ng в этом случае считает доступным
    `MemFree`, так же делают `mem_used` (всего − свободно) и «Доступно» в оверлее. У свопа второй
    оценки нет: искажённое или отсутствующее «свободно» даёт `None`, а не ноль.
- **Опрос идёт только пока на него смотрят.** Оверлей мониторинга запускает петлю на открытии и
  **гасит на закрытии**; `settings.showStatusBar=false` **размонтирует** `StatusBar` (а не
  прячет) → опрос прекращается. Поэтому точки входа на страницу обязаны переживать отключение
  бара: ⌘K и пункт нативного меню (`menu://monitoring`) — помимо кнопки в баре.
- **Пороги и health — единые источники.** Классификация значение→уровень — только
  [thresholds.ts](../src/lib/thresholds.ts) (`thresholdLevel`/`thresholdClass`), пороги — в
  `settings.statusBarThresholds` по ключам `ThresholdKey` (`null` = выкл); уровень блока —
  только [monhealth.ts](../src/lib/monhealth.ts) (`worstLevel` по метрикам блока). Новый
  числовой показатель = ключ порога + дефолт + поле в настройках + строка в соответствующей
  `*Health`-функции; health «на глаз» в компоненте не считают. Графики — `Chart`/`Sparkline`/
  `StackedBar`, инлайн-SVG в оверлее не заводим. Безлимитный потолок (`fs.file-max` unlimited)
  рисуется как `∞` через `fmtLimit`/`isUnlimitedLimit`, процент и порог при этом подавляются.
- **Реестр `docker login`.** Пароль — только в keychain (`vterm:registry`, ключ = url,
  `Zeroizing`), **никогда** в settings/бэкапе и **не в argv**: отдельная команда `docker_login`
  подаёт его через `--password-stdin` (`exec_captured_stdin` по SSH / stdin-pipe локально) и
  **не мирроится** в запись. Несекретная половина (url + username) — `settings.dockerRegistries`
  (`sanitizeDockerRegistries`).

### Утилиты

- **Панель-оверлей** [UtilitiesPanel](../src/lib/UtilitiesPanel.svelte) (`z-index:40`), вход —
  кнопка `wrench` в [TopBar](../src/lib/TopBar.svelte) и ⌘K; **не** секция настроек (инструмент
  нужен рядом с терминалом). Список — чистый реестр [utilities.ts](../src/lib/utilities.ts)
  (`id`/иконка/i18n-ключ/keywords, поиск `utilitiesMatching`).
- **Каждый инструмент = чистая логика в `.ts` (с тестом) + тонкая оболочка `Util*.svelte`**
  (форма/таблица без логики; UI-оболочки — в exclude покрытия). Копирование — общий
  [CopyButton](../src/lib/CopyButton.svelte).
- **Всё офлайн**: codec/cidr/timeconv/cron/pwgen/jwt — без сети и без бэкенда; CSPRNG паролей —
  `crypto.getRandomValues`, словарь passphrase встроен ([wordlist.ts](../src/lib/wordlist.ts)).
  Бэкенд — **только** там, где нужен файл/ОС: known_hosts (`list_known_hosts`/`remove_known_host`
  над [store.rs](../src-tauri/src/store.rs)), парсинг/сортировка — чистый
  [knownhosts.ts](../src/lib/knownhosts.ts).
- **Генерация SSH-ключей — локальная и офлайн**: крейт `ssh-key` + CSPRNG `rand`, **без вызова
  внешнего `ssh-keygen`**. [keygen.rs](../src-tauri/src/keygen.rs) — дамповый исполнитель одной
  команды `generate_ssh_key`; реестр алгоритмов, дефолтные имена, сборка пути и валидация — в
  [sshkeygen.ts](../src/lib/sshkeygen.ts). Приватный ключ — `0600`, `~/.ssh` — `0700`; passphrase
  в `Zeroizing`, **не логируется и не пишется в keychain**. Коллизия без `overwrite` →
  `AppError::KeyExists`; **тихой перезаписи нет**. UI — общий
  [KeyGenModal](../src/lib/KeyGenModal.svelte) за двумя входами (панель и шорткат в форме сервера).
- **Сетевые утилиты — только поверх сессии** (см. таблицу выше). Утилита, которая ходит в сеть
  из WebView/Rust, нарушает офлайн-инвариант. Локальная вкладка запускает процессы
  пользователя из allowlist (ADR 0014), а не открывает сокеты сама.
- **«Проверка доступа» — единственное исключение, и оно узкое** (ADR 0012). Команда одна —
  `netcheck_run`, транспорт выбирается по сессии. На SSH сервер исполняет скрипт `netcheckArgs`
  ([netcheck.ts](../src/lib/netcheck.ts)): порядок средств «Авто» — `bash /dev/tcp` под `timeout` →
  `nc -z` (с `-G`, если есть: BSD `-w` не ограничивает connect) → `telnet` под `timeout` →
  `curl` (`telnet://`, на curl-minimal — `http://`; «открыт» читается по его `time_connect`, а не
  по коду выхода). Скрипт сообщает пригодность каждого средства (`C`: `ok`/`missing`/`notimeout`),
  метод можно выбрать (по хосту, `effectiveMethod`): выбранное, но непригодное средство даёт
  `M none` и блокирует запуск — **тихой подмены другим нет**. На
  локальной вкладке рукопожатие делает Rust ([netcheck.rs](../src-tauri/src/netcheck.rs)):
  только по кнопке, только к введённым адресам, без полезной нагрузки, не больше `MAX_CHECKS`
  за прогон. Исходящий адрес узнаётся подключённым UDP-сокетом, который не шлёт ни пакета.
  На Windows у сокета выключены повторы SYN (`no_syn_retries`, `SIO_TCP_INITIAL_RTO`): стек
  повторяет SYN после RST ~2 с, и под коротким таймаутом «отказ» читался бы как «таймаут —
  режет файрвол», то есть неверный диагноз.
  Обе стороны отвечают **одним** построчным протоколом (`H/A/C/M/D/S/R/N/E`, описан в
  netcheck.ts). Скрипт печатает только сырые показания (rc, метки времени, сообщение
  инструмента), вердикт выносит `classifyAttempt` — там его можно покрыть тестом. Без
  маркера `E` прогон считается оборванным, и непришедшие порты показываются «нет ответа», а
  не «ошибка». Цель `0.0.0.0` отклоняется разбором (`unspecified`): соединение с ней попадает
  на сам проверяющий хост, и «открыт» был бы ответом не про ту машину. Конструктор правила
  ([netcheckform.ts](../src/lib/netcheckform.ts)) своего понятия о валидном правиле не
  имеет — собирает строку и спрашивает `parseRules`. Правила приходят из заявок и чатов,
  поэтому `parseRules` сначала прогоняет строку через `normalizeRuleLine` (стрелки `—>`/`- >`/`➜`
  → `->`, полноширинная пунктуация, экзотические пробелы); подпись `(…)` у источника или цели —
  только заметка (`sourceLabel`/`label`), в проверку и протокол она не попадает. UDP не проверяется **нигде**: тишина
  ничего не значит. Сокеты приложения живут только в `ssh.rs` и `netcheck.rs` — новый сетевой
  примитив в другом модуле ломает гейт.

## Логи, поиск, запись сессий

- **Мастер-гейт `smartLogs.enabled`.** При выключенном флаге терминал обязан вести себя
  **ровно как чистый xterm** — независимо от пер-фичевых флагов (`search`/`highlight`/
  `jsonView`). Новая под-фича = флаг в `SmartLogs` + дефолт + тумблер в разделе «Логи и текст»;
  гейт читается как `enabled && <feature>`.
- **Поиск принадлежит терминалу.** Полнобуферный поиск — внутри
  [Terminal.svelte](../src/lib/Terminal.svelte) через `@xterm/addon-search`; хоткей —
  `Cmd+F`/`Ctrl+Shift+F` через `attachCustomKeyEventHandler`, а **plain `Ctrl+F` не
  перехватываем** — он уходит в удалённый шелл. Терминал создаётся с `allowProposedApi: true`
  (decoration-API xterm 6 ещё proposed; без флага `findNext`/`registerDecoration` кидают
  исключение). Невалидный regex **не уходит в аддон** (иначе исключение) — чистый
  `buildMatcher` возвращает `null`, и поиск показывает подсказку. Чистая логика — в
  [search.ts](../src/lib/search.ts), компонент только связывает её с буфером.
- **Глобальные хоткеи vs шелл — тем же принципом, что поиск.** Оконные действия «новая
  вкладка» и «палитра команд» — `⌘T`/`⌘K` на macOS (⌘ xterm игнорирует → событие всплывает к
  оконному обработчику) и `Ctrl+Shift+T`/`Ctrl+Shift+K` на Windows/Linux. **Плейн `Ctrl+T`/
  `Ctrl+K` не перехватываем** — они уходят в шелл (`transpose-chars`/fzf, `kill-line`); иначе
  xterm формирует управляющий код, шлёт его в PTY и делает `stopPropagation`, и оконный
  обработчик клавишу не видит. Терминал **отпускает** app-хорды (`isAppShortcut` →
  `return false` в `attachCustomKeyEventHandler`), чтобы событие всплыло к `onGlobalKey`.
  Единый источник предикатов — [appshortcuts.ts](../src/lib/appshortcuts.ts): терминал и
  оконный обработчик **обязаны** матчить одно и то же, иначе хорд, который ждёт окно, съедает
  xterm. Новый глобальный хоткей поверх сфокусированного терминала — сюда же, с формой
  `Ctrl+Shift+<key>` на Win/Linux, а не плейн-`Ctrl`. Так сделаны хорды областей: `⌘D`/`⌘⇧D`
  (новый терминал справа/снизу) и `⌘]`/`⌘[` (следующая/предыдущая область) — на Win/Linux
  `Ctrl+Shift+D`/`E` и `Ctrl+Shift+]`/`[`. Они принадлежат области терминалов: хорд, который
  уже обработал элемент в фокусе (`defaultPrevented` — редактор сам вешает `⌘D` и `⌘]`) или
  который набран в поле ввода, окно не трогает.
  - **Буква хоткея — не зависит от раскладки.** Сравнивать `e.key` с латинской буквой нельзя: на
    русской раскладке та же клавиша даёт `"к"`, и `Ctrl+R` молча уходил в reverse-search шелла.
    Буква — только через `chordLetter` (латинский `e.key`, иначе физический `e.code`: так
    Dvorak/AZERTY сохраняют свою букву), Shift — по `shiftKey`, не по регистру. Гейт
    `hotkeylayout.guard`.
- **Подсветка — ANSI-SGR в потоке, не decoration.** Правила красят вывод **вставкой
  SGR-кодов до `term.write`** (приём grc/ccze), цвет — **базовый ANSI** (`31`…`37`), поэтому
  строка автоматически рисуется цветами активной темы. Матчить **внутри** уже существующих
  escape-последовательностей нельзя (сломает их). Применяется **только к нормальному буферу**
  (`buffer.active.type === "normal"`) — full-screen TUI (vim/htop, alt-screen) не трогаем.
  Порядок правил = приоритет. Чистая логика — [highlight.ts](../src/lib/highlight.ts).
- **Ссылки из вывода — только http(s) и только по клику**, через `openUrl`
  (`tauri-plugin-opener`): офлайн-инвариант цел.
- **Структурный вид парсит только пока открыт.** `feedJson` работает лишь при включённом
  `structured` (иначе нулевой оверхед); при включении — посев из текущего scrollback +
  живой разбор, буфер ограничен `MAX_JSON_ENTRIES`. Формат определяется построчно в порядке
  JSON → nginx → syslog → dmesg → **logfmt последним** (он самый жадный; его гард требует ≥2
  пары и покрытие всей строки). «Clear» ставит **водяной знак** (`term.registerMarker`), и
  повторный вход читает буфер только после него — очищенный вывод не возвращается; маркер
  авто-инвалидируется, когда строка уходит из scrollback. Парсинг и состояние — в
  [jsonlog.ts](../src/lib/jsonlog.ts) + `Terminal.svelte`, таблица презентационна.
- **Вставка в терминал — только через `term.paste()`.** Прямой `writeToTerminal` текста из буфера
  обмена теряет bracketed paste: многострочный блок исполняется построчно, не дойдя до промпта, —
  а вставка висит на одном клике ПКМ. Гейт `termpaste.guard`.
- **Поверх первой строки терминала ничего не висит.** Переключатель Raw/Table, поиск, «Очистить» и
  «Спросить ИИ» живут в панели сессии под вкладками (`+page.svelte`, видимость — чистый
  [sessionbar.ts](../src/lib/sessionbar.ts)), а не плавают над xterm: плавающий тумблер закрывал
  заголовок nano/htop. Состояние вида держит `Terminal.svelte` (`setViewMode`/`onviewmode`),
  панель только рисует его. Пустая панель не рендерится — терминал сохраняет высоту.
- **Запись ведёт бэкенд, пер-сессия.** `Recorder` ([recording.rs](../src-tauri/src/recording.rs))
  живёт **внутри** `SshSession`/`LocalPty`: вывод пишет ридер, ввод — `write_input`. Формат —
  **asciicast v2**, файлы — `data_dir/recordings/*.cast`; команды чтения/удаления/меты
  **ограничены каталогом записей** (`is_recording_path`) — это граница, а не удобство.
  Ввод после `password:` маскируется.
  - **Файловый I/O записи — на отдельном потоке, не на пути слива PTY.** У `LocalPty` `Recorder`
    крутится в своём потоке-акторе ([pty.rs](../src-tauri/src/pty.rs) `run_recorder`), а ридер и
    `write_input` только **шлют** байты в неблокирующий канал (`RecMsg`). Синхронный
    `Recorder::output` (flush в файл на каждое событие) под общим мьютексом **прямо на ридере**
    тормозил слив ConPTY на Windows → пайп включал back-pressure → shell вставал, терминал
    замирал, и тот же мьютекс держал пути ввода и остановки. Локальный ридер **не делает
    файловый I/O**; `end_recording` шлёт `Stop` и ждёт только ограниченный флаш (не мьютекс
    поверх I/O). Новый вход записи на локальной вкладке — через канал, не инлайн под мьютексом.
- **Пауза — экономия диска, а не пропуск данных.** Пока `paused`, `output` отбрасывается, и
  для timed-режима паузная длительность **вычитается** из таймстемпов (`paused_total`), иначе в
  воспроизведении будут дыры. **Любой `input` авто-возобновляет** запись первым делом — иначе
  вывод после нажатия потеряется. Оркестрация (пишутся вкладки на экране — по одной на область,
  остальные на паузе; простой дольше `recordIdlePauseSecs` у каждой свой) — на фронте.
- **Автозапись прод-серверов идёт тем же путём, что ручной REC** (общий `startSessionRecording`,
  гард `isRecording` делает старт идемпотентным); финализация на `closed` — без диалога
  сохранения (он только для ручного стопа), реконнект = новая запись.
- **Мета живёт в заголовке asciicast** (`title` + кастомные `description`/`server`);
  `with_updated_meta` переписывает только первую строку и **сохраняет `server`** — имя сервера
  переживает переименование записи. Пост-стоп-диалог «Сохранить/Удалить» — единственное
  исключение из правила «удаление только с подтверждением»: он сам и есть явный выбор.
- **Аудит-факты редактора идут через `annotate_recording`**, не отдельным каналом: успешное
  сохранение пишет видимое `o`-событие `[vterm] правка {path} (+N −M строк)` — **даже на
  паузе** (намеренное низкочастотное событие). Новый аудит-факт подключай так же.

## Файлы, пути, текст

- **Файловые панели — один компонент через инъекцию транспорта.** Общее тело —
  [FileBrowser.svelte](../src/lib/FileBrowser.svelte), параметризованное адаптером
  [FileBrowserAdapter](../src/lib/filebrowser.ts): транспорт (SFTP-команды vs `local*`) **плюс**
  две реально расходящиеся семантики — что значит «вверх» (`navParent`) и мутируемость каталога.
  SFTP-специфика (connect/upload/download/grep/sync/transfers/OS-drop) включается **наличием**
  методов адаптера + флагами, локальная (ряды дисков) — флагом `drives`.
  [SftpPanel](../src/lib/SftpPanel.svelte) и [LocalFilePanel](../src/lib/LocalFilePanel.svelte) —
  тонкие обёртки, собирающие адаптер. Чистое (окно виртуализации, курсор после «вверх», имя при
  вставке, маркер `dest-exists`) — в `filebrowser.ts` с тестами. Третьей копии панели быть не
  должно.
- **Путевая арифметика — чистая и сепаратор-осознанная.** `isRoot`/`parentOf`/`joinPath`/`sep`/
  `baseName`/`isUnder`/`resolveRelative` живут в [fspath.ts](../src/lib/fspath.ts), не копиями в
  панелях. Корни: POSIX `/`, корень диска (`C:\`, `C:/`, `C:`), UNC-шара (`\\server\share`);
  сравнение путей на Windows — регистронезависимое и агностичное к сепаратору. SFTP всегда POSIX,
  локальная панель — нативные пути, но обе ходят через один модуль (Windows-регрессии ловятся на
  macOS).
  - **Навигация ≠ файловая семантика.** `isRoot`/`parentOf` отвечают на файловый вопрос,
    `navParent` — на навигационный: выше корня диска он ведёт на синтетический уровень
    `DRIVES_ROOT` («Этот компьютер»), иначе `D:` недостижим. Не растягивай `isRoot` под
    навигацию — на нём стоят `trimTrailing`/`baseName`. Сентинел обязан быть явным (`"::drives"`),
    не перегруженной пустой строкой (`cwd` кратко пуст при монтировании); бэкенд матчит его в
    `localfile::list`, поэтому остальная навигация о нём не знает. На синтетическом уровне **все
    мутации запрещены** — и в UI, и в самих функциях.
  - **Перечисление дисков не трогает тома** ([drives.rs](../src-tauri/src/drives.rs)):
    `GetLogicalDrives` даёт буквы мгновенно и без обращения к устройствам; метка тома и свободное
    место читаются **только** для локальных дисков (`should_enrich`) — обращение к отвалившейся
    сетевой шаре блокируется на SMB-таймаут. Перебор `A:\`…`Z:\` через `fs::metadata` — та же
    ловушка, не заменяй.
- **Кодировка текста определяется и сохраняется.** Читатели редактора (`sftp::read_text`,
  `localfile::read_text`) **не** предполагают UTF-8: определение и round-trip — в
  [textenc.rs](../src-tauri/src/textenc.rs) (BOM → BOM-less UTF-16 по NUL-паттерну → валидный
  UTF-8 → `chardetng`). Только последний шаг — догадка. **Проверка «бинарности» идёт ПОСЛЕ
  sniff'а UTF-16** (иначе перемежающиеся NUL'ы читаются как бинарь — так `.ini` «не открывался»).
  Метка едет `TextFile.encoding` → `EditorDoc.encoding` → обратно в команду записи, файл пишется
  **в исходной кодировке**: молча переписать чужой UTF-16/CP1251-конфиг в UTF-8 нельзя. Следствие:
  `sha256` для проверки конфликтов считается по **сырым байтам**. Новый источник текста подключай
  через `textenc::decode`/`encode`.
- **`SETSTAT` — только запрошенные атрибуты.** `FileAttributes` строится **исключительно** через
  `sftp::chmod_attrs` (или с полностью выписанными полями), **никогда из шаблона** — ни
  `..Default::default()`, ни конструктором-шаблоном russh-sftp: флаг атрибута поднимается на
  **каждое** `Some`, а `size: Some(0)` — это `truncate`. Уходил `ATTR_SIZE = 0` → сервер обнулял
  файл, и шаг «сохранить права» уничтожал пользовательский конфиг перед переименованием на место.
  Шаблон «новый каталог» (`size`/`uid`/`gid`/`atime`/`mtime: Some(0)`) был в russh-sftp ≤ 2.3.0
  самим `Default`; 2.4.0 сделал `Default` пустым и перенёс шаблон в отдельный конструктор — payload
  тот же, изменилось только имя, поэтому гейт держит **оба** написания (и старое: откат версии
  снова взвёл бы его).
- **Каретку после вставки не считают из `.length` сырого буфера.** CodeMirror нормализует
  переводы строк на вставке, а `<textarea>.value` по спецификации HTML приводит CRLF к LF —
  многострочный текст из Windows-приложения ложится в документ **короче** строки, из которой
  пришёл, и вычисленный `anchor` уезжает за конец: `state.update()` кидает `RangeError` **до**
  применения изменения, внутри неожиданного `.then()` → вставка проваливается молча и только не
  на macOS. Позицию бери из применённого изменения (`view.state.replaceSelection(text)`) или из
  значения, которое DOM реально сохранил.
- **Запись текста на сервер — только через `create`.** `SftpSession::write` в russh-sftp
  открывает файл флагами **`WRITE` без `CREATE`** → «No such file» на новом пути; стейджинг-temp,
  `.bak` и sudo-temp идут через `sftp::write_bytes` (`create` = CREATE|TRUNCATE|WRITE +
  `write_all` + `shutdown`). Форма записи — **sibling-temp → `set_metadata` (сохранить mode) →
  `rename` поверх цели** (перед ним `remove_file`, потому что `SSH_FXP_RENAME` у OpenSSH падает
  на существующей цели — единственное неатомарное окно, но полный контент уже в temp). Упавшая
  запись **никогда не обрезает оригинал**.
- **Конфликт правки ловится хэшем, а не временем.** `expectedSha256` — это sha256, с которым
  редактор **открыл** файл; перед записью бэкенд сверяет его с текущим и при расхождении
  возвращает `FileChangedOnServer` (маркер `file-changed`), а фронт предлагает
  переоткрыть/перезаписать. Молча перезаписать чужую правку нельзя. Лимит открытия —
  `settings.sftp.maxOpenMb` (дефолт 2 МБ), бэкенд клампит в `[1, 64 МБ]`.
- **sudo-правка: пароль только в памяти и только через stdin.** `sudo -S -p ''`
  (`run_command_stdin`) — не в argv, не в `ps`, не в history, не в keychain;
  `EditorDoc.sudoPassword` живёт в непереперсистируемом сторе. Успех проверяется маркером
  `__VTERM_OK__` (exit-статус по exec не виден). Отказ доступа ловит `isPermissionError` — и
  `permission denied`, **и** `no such file`: staged-temp создаётся в той же папке, и при
  незаписываемом каталоге часть SFTP-серверов отдаёт второе вместо первого (файл точно есть — он
  был в листинге).
- **Синхронизация: хэши считает бэкенд, diff — чистый TS.** Удалённое дерево — `sftp_hash_tree`
  через **SSH exec** `sha256sum`/`shasum` (без скачивания), локальное — обходом ФС; обе стороны
  дают `HashTree{entries: HashEntry{path, sha256}[], skipped}` с `/`-относительными путями,
  дальше — `diffTrees` в [sync.ts](../src/lib/sync.ts). Новое направление или источник хэшей
  добавляй в `diffTrees`/`apply`, не дублируй обход.
  - **Нечитаемое дерево — ошибка, а не пустое.** Пустой список планирует «залить всё», а с
    «удалять лишнее» — «стереть всё на другой стороне». Поэтому удалённый скрипт
    (`remote_hash_command`, под `sh -c`) проговаривает каждый отказ маркером — нет папки/доступа,
    нет `sha256sum`/`shasum`, строка stderr на непрочитанный объект, маркер завершения в конце —
    а `parse_hash_output` превращает их в `SyncDirUnreadable`/`HashToolMissing`/`HashIncomplete`;
    `localfile::hash_tree` так же не прощает нечитаемый корень. Непрочитанное **ниже** корня
    считается в `skipped` и показывается в окне. Exec-канал собирает только stdout: всё, что
    должно дойти, идёт через него.
  - **Удалённая папка — своя у окна.** Засевается из панели при открытии, дальше меняется только
    выбором в отдельном окне-дереве (`SyncRemotePicker`, строки — чистый
    [remotetree.ts](../src/lib/remotetree.ts)); выбор не двигает ни панель, ни каталог дока, ни
    терминал. Смена сбрасывает план.
  - **Синхронизацией владеет стор, окно — только вид.** Форма, план и сравнение/прогон в полёте
    лежат в [syncjob.svelte.ts](../src/lib/stores/syncjob.svelte.ts) по `sessionId`: «В фоне»
    закрывает окно, а панель SFTP перемонтируется при смене вкладки — компонентное состояние
    потеряло бы результат. Стор keyed по сессии → чистится в `closeTabFully` и **останавливает**
    то, что делал. Прогон — **один на приложение**: id прогресса `sync:<путь>` без сессии, два
    прогона рисовали бы полосы друг друга (`otherRunHolds` — в своём окне; между окнами — замок
    в бэкенде, `AppError::SyncBusy`).
  - **Исключения режутся при обходе, но только совпадающие по смыслу.** `sync::ExcludeSet`
    берёт шаблоны без `/` (glob по одному сегменту) и литеральные пути; путь с `*`/`?` и `/`
    остаётся фронту (`find -path` пускает `*` через `/`). Отрезать **больше**, чем отфильтрует
    `diffTrees`, нельзя: такие файлы выглядели бы «нет на этой стороне» — заливка или удаление.
    Фронтовый фильтр остаётся; отрезанное считается в `HashTree.excluded`.
  - **Большой план не стоит квадратично.** Список плана — виртуальный (`windowRange`),
    прогресс в `syncRunState` правится на месте, итоги (`done`/`weight`) ведутся инкрементально
    (`progressWeight`); пересуммировать план или копировать карту на каждое событие нельзя.
  - **Закрыть окно посреди работы — значит остановить её, с вопросом**, либо явно увести в фон
    кнопкой «В фоне» (индикатор — на кнопке синхронизации панели). Сравнение отменяется
    флагом в общей карте отмен (`sftp_cancel`, по id **на каждую сторону** — у карты один флаг на
    id); удалённый exec обрывается через `sync::until_cancelled`, локальный обход проверяет флаг
    на каждом элементе, результат опоздавшего сравнения отбрасывается. Перенос — тем же `runId`,
    что кнопка «Остановить». Молча скрыть окно, оставив работу идти, нельзя. Иначе следование за терминалом
    переносило бы сравнённый план на папку, с которой его не сравнивали.
  - **Пустой план — с причиной** (`emptyPlanReason`: обе пусты / всё исключено / только на
    стороне-цели / идентичны), пустой источник при «удалять лишнее» — красное предупреждение
    (`wipesTarget`), у неактивных кнопок — причина (`syncBlockReasons`).
- **Линт: у legacy-режимов его нет, и это осознанно.** Синтаксический линт строится на
  error-нодах `syntaxTree`, поэтому работает только для Lezer-языков; StreamLanguage-режимы
  (shell/toml/ini/…) их не дают — линта нет, **ложных срабатываний тоже**. Чтобы включить его
  для такого языка, замени режим в `langExt` на официальный `@codemirror/lang-*`; generic-линтер
  подхватит сам. Сети при этом нет — серверный линт реальными инструментами идёт отдельной
  командой `lint_remote`.
- **Серверные инструменты ставятся менеджером сервера, не нами.** Реестр — чистые `TOOLS` +
  `install_command(tool, mgr)` в [servertools.rs](../src-tauri/src/servertools.rs); UI —
  общий `ToolInstallDialog` («выполнить в терминале» или через sudo). Новый инструмент = запись
  в `TOOLS` + ветка в `install_command` + i18n-ключ, а не статичная команда в компоненте.
  Офлайн-инвариант цел: трафик идёт с сервера пользователя, sudo-пароль — только в памяти.
- **Свои привязки буфера обмена у терминала и редактора убирать нельзя.** CodeMirror —
  `contenteditable`, xterm — canvas; глобальный `handleClipboardShortcut` их намеренно **не
  трогает**, а `Cmd/Ctrl+C/X/V` привязаны внутри компонентов к нативному буферу
  ([clipboard.ts](../src/lib/clipboard.ts)). На WKWebView без Edit-меню это единственный путь:
  снимешь — копипаста исчезнет.
- **«Открыть с помощью vterm»** — `tauri-plugin-single-instance` **регистрируется первым**
  (второй запуск форвардит argv в текущее окно); пути приходят из argv (Windows/Linux) и
  `RunEvent::Opened` (**только macOS**, обязательно под `#[cfg(target_os = "macos")]` — иначе не
  собирается на Windows), оба — в очередь `pending_opens` + событие `vterm://open-file`.
- **Расписка о записи отражает сервер, а не намерение.** `WriteResult` считается из того, что
  подтвердил сервер; ошибку `set_metadata` глушить `let _ =` нельзя. Добавляя шаг в путь записи,
  спроси, что увидит пользователь, если шаг молча провалится: зелёный тост над уничтоженным
  конфигом хуже любой ошибки. Поведение **сервера** закрепляют живые тесты `live_sftp` (см.
  [TESTS.md](TESTS.md)).
- **Перенос файла пишет во временный соседний файл и отменяем.** `upload`/`download` (и файлы
  внутри скачивания папки) пишут в скрытый `.<имя>.vterm-tmp-*` рядом с целью и `rename`-ят его
  поверх **только** после последнего байта; при отмене или ошибке temp удаляется, оригинал цел.
  Права заменяемого файла переносятся на новый (скрипт остаётся исполняемым). Флаг отмены —
  общая карта `state.cancels` под id переноса, проверяется между блоками; `sftp_cancel` — один на
  всё. Прямой `create(target)` запрещён: он обрезает цель на старте, и прерванный перенос оставлял
  половину файла. Файлы прогона синхронизации (`sync:<путь>`) отменяются **прогоном**, а не
  по файлу (`isCancellableTransfer`). Отмена — не ошибка: тоста нет, в аудите `exit 130`.
- **Список после загрузки обновляет стор, а не панель, начавшая загрузку.** Док пересоздаётся
  на каждой смене вкладки терминала, и новая панель читает папку сразу — до конца загрузки, а
  «обновить по завершении» доставалось уничтоженному экземпляру. Поэтому `SftpPanel` отмечает
  пачку в [dockstate](../src/lib/stores/dockstate.svelte.ts) (`beginUpload`/`endUpload`), и
  **последняя** из идущих в папку пачек поднимает её `dirRev`: любая смонтированная панель на
  этой папке перечитывает её **один** раз на пачку, скрытая — при возврате. Листинг принимает
  только **последний** запрошенный ответ (`loadSeq` в `FileBrowser`): ответы приходят не по
  порядку, и старый вернул бы папку без загруженного файла.
- **Аудит SFTP** — тем же record-only контрактом, тег `[sftp]` (`sftp::sftp_mirror`). Мирроятся
  `rm`/`rm -r`, `mv`, `cp`, `mkdir`, `touch`, `save` (**только размер**, содержимое — нет), `put`,
  `get`. Чтения (`list`/`read_text`/`grep`/`hash_tree`) — нет. Пути квотятся `git::shell_quote`.
  Новую мутирующую команду подключай так же: `session_arc` → `session.sftp()` →
  `record_sftp(&session, &op, &res)` в `lib.rs`. SFTP — только SSH (у локальных вкладок своя
  `localfile`-панель).
  - **Синхронизация мирроится прогоном, а не файлом**: **одна** запись на прогон
    (`sync '<local>' <-> '<remote>' (N actions)` + перечень операций, кап 50 строк с хвостом
    `… and N more`; `exit 130` при остановке). Построчный миррор похоронил бы запись, которую сам
    же должен документировать. Новую массовую операцию подключай сводкой.
- **Прогресс синхронизации — существующий канал, детерминированный id.** `sync::apply` даёт
  каждому файлу id `sync:<путь>` (`sync::sync_transfer_id` ↔ `syncTransferId` в
  [sync.ts](../src/lib/sync.ts) — **обязаны совпадать**), и события `sftp://progress` сами ложатся
  на строки плана. По полю `name` связать нельзя — это базовое имя, оно коллизирует между
  каталогами. Операции без байтов (удаления) обязаны слать финальный `sftp::emit_done`, иначе
  строка висит «в очереди» над удалённым файлом. Список ведёт **свой** стор
  ([syncrun.svelte.ts](../src/lib/stores/syncrun.svelte.ts)): общий `transfers` выбрасывает
  завершённый перенос через `DONE_LINGER_MS`, и отчёт растворился бы на глазах.
  - **Остановка — существующий механизм отмены** (`state.cancels` + `sftp_cancel`, тот же, что у
    скачивания папки) под `runId`; второй заводить нельзя. Флаг проверяется **между файлами**:
    файл в полёте дописывается, потому что разрыв копирования оставит обрезанный файл поверх
    рабочего. После остановки окно **не закрывается**, «Применить» **блокируется** — план после
    частичного прогона заведомо устарел.
- **«Следовать за терминалом» — один контракт, два транспорта.** Источник cwd выбирается по
  наличию локального PTY: у локальной вкладки есть pid → каталог читается у ОС
  ([proccwd.rs](../src-tauri/src/proccwd.rs) поверх `sysinfo`: Linux `/proc`, macOS
  `proc_pidinfo`, Windows PEB), у SSH — OSC 7 / OSC 9;9 от шелла. **Только на OSC строить
  нельзя**: стоковые шеллы молчат (zsh на macOS шлёт OSC 7 лишь при
  `$TERM_PROGRAM=Apple_Terminal`, PowerShell/`cmd.exe` — никогда), а подменять `TERM_PROGRAM`
  нельзя — это ложь, включающая постороннюю машинерию Apple. Каналы работают **параллельно**:
  событие обновляет панель мгновенно, опрос — раз в секунду и только пока тумблер включён. Отказ
  чтения cwd — штатный `None` (панель не двигается, а не прыгает в корень). Диалог с предложением
  вписать сниппет показывает предикат `needsShellSetup`, не проверка ОС по месту.
  - **Обратное направление** (панель → терминал, `cdTerminalTo`) идёт **только** на действиях
    пользователя и только при включённом тумблере; переход, сделанный самой панелью при
    следовании, зеркалить нельзя — петля. Команда строится чистым
    [cdterminal.ts](../src/lib/cdterminal.ts) **под
    реально запущенную оболочку** (POSIX-форму нельзя слать в `cmd.exe` — там `'` не кавычки и
    без `/d` смена диска не переводит туда — и в PowerShell — нужен `-LiteralPath`); диалект
    фиксируется на сессию **в момент спавна**, а не берётся из текущей настройки. Путь, который
    нельзя выразить безопасно (пустой, с переводом строки), даёт `null` → **не шлём ничего**.
  - **Переключатель один на весь док, и каталог у дока один.** `followTerminal[sessionId]`
    включается из SFTP и из Git одинаково; общий каталог — `dockstate.cwd`. Пишут в него
    файловая панель (каждый успешный листинг, кроме синтетического `DRIVES_ROOT` и `"."`) и
    терминал — **только** при включённом тумблере и **только при смене** cwd (чистый
    [followcwd.ts](../src/lib/followcwd.ts)): иначе повторный прогон затёр бы папку, открытую в
    панели, если зеркальный `cd` не дошёл до занятого терминала. Git в общий каталог **не
    пишет** (`dockCwd`, без создания записи внутри `$derived`).
  - **Git при выключенной синхронизации следует за терминалом, а не за панелью** (`gitCwd`):
    файловая панель при подключении открывает home, и Git показывал «не репозиторий» по
    стартовой папке, пока пользователь работал в другой. Неизвестный cwd терминала — «нет
    пути», **не** папка панели. Поэтому локальный cwd опрашивается и пока Git на экране
    (`pollsLocalCwd`), а на SSH кнопка Git «Включить синхронизацию пути» — **тот же**
    переключатель, что в SFTP и тулбаре Git (`enablePathSync`: сниппет через тот же диалог +
    `followTerminal`): одна надпись — одно действие, и SFTP, подключённый после неё, сразу
    следует за терминалом. Отдельного «только настроить шелл» нет. Гейт `gitcwd.guard`.

## Хранение и секреты

- **Что где живёт.** Профили/папки/known_hosts — JSON в конфиг-каталоге
  ([store.rs](../src-tauri/src/store.rs)); секреты — **только** в OS keychain
  ([secrets.rs](../src-tauri/src/secrets.rs)), никогда в файлах и бэкапе; настройки и layout UI —
  `localStorage` (runes-сторы). Для e2e — `data-testid`.
- **Секрет proxy/jump host** — тоже в keychain, но под **proxy-scoped id** (`{id}::proxy`), чтобы
  не конфликтовать с секретом самой цели; чистится в `delete_all`/`forget_secrets`.
- **Копии секретов — в `zeroize::Zeroizing`, никогда не логируются.** Host-key дефолт — не
  «accept».
- **После входа подключение уже не проваливается.** Когда `ssh::connect` вернул сессию, всё
  последующее в `connect_session` (сохранение секрета в keychain, флаг `hasSavedPassword`) —
  **совет, а не условие**: сбой уходит в `ConnectOutcome.rememberFailed` и тост, сессия остаётся.
  `?` там выбрасывал аутентифицированное подключение — на Linux без Secret Service подключиться с
  «запомнить» было нельзя вовсе, а пользователь видел ошибку вместо шелла.
- **Вход по паролю — и через `keyboard-interactive`, но пароль уходит только в вопрос о
  пароле** ([kbdauth.rs](../src-tauri/src/kbdauth.rs)). Если сервер не берёт метод `password`
  (UniFi, PAM), тот же пароль даётся ответом на его **скрытый** вопрос, похожий на запрос
  пароля (`plan`), и **один раз**: тот же вопрос снова значит «неверный», вход отклоняется, а не
  переспрашивает. Одноразовые коды («Verification code», Duo «Passcode», pam_oath «One-time
  password») паролем не заполняются никогда; после частичного успеха (ключ/пароль + код)
  пароль не отправляется повторно. Остальное спрашивает окно (`term://auth/{id}` →
  `answer_auth_prompt`); ответы — только в памяти, не в keychain, записи и логах; текст
  вопросов — от сервера, показывается как текст. Ожидание ответа без таймаута, поэтому
  конец сессии (`end_session`: `disconnect` и новый `connect_session` той же сессии) **снимает**
  ожидающий вопрос. Сервер,
  не предлагающий ничего пригодного, — `AuthMethodsUnsupported` со списком его методов, не
  «неверный пароль». Гейт `login_answers_come_only_from_the_plan`, живые тесты `live_kbdint`.
- **Сертификат хоста отклоняется при любой политике** (`ssh::host_key_fingerprint` → `None`):
  доверенных CA у нас нет, а пин вложенного ключа молча пропустил бы подпись, срок и principals
  сертификата. Алгоритмы `*-cert-v01` не рекламируем (`host_key_certificates` пуст). Поддержка
  сертификатов = явный список CA + проверка сертификата, а не ветка «взять ключ изнутри».
- **Хардкодных абсолютных путей во фронте нет.** Литерал `/tmp/…` в `.svelte`/`.ts` запрещён:
  однажды отладочный блок с `/tmp/vterm-realtest.conf` уехал в main и на **каждом** запуске
  показывал тост об отсутствующем пути (на Windows `/tmp` нет вовсе) и открывал локальную вкладку
  без спроса. Временные файлы — через OS temp на стороне Rust. Windows-литералы (`C:\…`) не
  запрещены: это законные плейсхолдеры в настройках путей.
- **Конфиг переписывается только атомарно.** Store-файл перезаписывается целиком на любое
  изменение, поэтому обрыв записи оставлял обрезанный `servers.json` — а он декодируется как
  «серверов нет вовсе». Единственный путь — `store::write_atomic` (temp-сосед → `sync_all` →
  `rename`); прямой `fs::write` в `store.rs` запрещён. `sync_all` **до** `rename` обязателен: без
  него метаданные могут лечь на диск раньше данных. Ошибку `rename` глушить нельзя (на Windows
  падает, если файл держит антивирус или второй экземпляр) — альтернатива для вызывающего —
  поверить в сохранение, которого не было. Та же форма у `localfile::local_temp`: недописанный
  файл не должен быть наблюдаем по настоящему пути.
- **Непрочитанный конфиг уходит в карантин, а не в пустоту.** `store::read_store` различает три
  случая, склеивать их нельзя: **файла нет** (штатный первый запуск, тихий дефолт) · **файл не
  парсится** (переносится в `<имя>.corrupt-<nanos>`, копится `StoreWarning`) · **файл прочитан**.
  Атомарность тут не спасает — ущерб наносит **успешная** запись пустоты поверх единственной
  копии. Метка времени в имени — чтобы вторая порча не затёрла улику от первой. `quarantined: None`
  — **отдельное** сообщение («данные всё ещё под угрозой»), не смягчённая версия первого. Тост —
  **без TTL** (`notifyError(…, 0)`). Новый store-файл подключай через `read_store`/`write_atomic`.

## ИИ-ассистент

**Выключен по умолчанию, зашитых облачных эндпоинтов нет** (все — пользовательские). Весь
LLM-трафик идёт из Rust ([ai.rs](../src-tauri/src/ai.rs), `reqwest`), не из WebView.

- **Контекст уходит только после маскирования и согласия.** Выделение/буфер/запись/метаданные
  проходят [redact.ts](../src/lib/redact.ts) (маркер `‹redacted›`) и явный
  [AiConsentDialog](../src/lib/AiConsentDialog.svelte) — **в том числе** для локального
  эндпоинта. Точки входа «спросить про X» (выделение в терминале, кнопки Docker/k8s, оверлей
  метрик) зовут **один** примитив `askAbout`, который кладёт в стор *запрос*, а не отправку;
  `AiChat` превращает его в **чип над полем ввода** (`SessionChat.attachment`, по `sessionId`), и
  вопрос уходит обычной отправкой через тот же consent-диалог — свой или пресетный
  (`ASK_PRESETS` в [aiask.ts](../src/lib/aiask.ts)) на пустой Enter. Своего пути отправки не
  заводи.
- **В слоте терминала — одно, самое узкое.** Чип, иначе живое выделение, иначе весь буфер (тир),
  иначе хвост; запись и метаданные — отдельные тиры поверх. Выделение **не** складывается с
  буфером: пометив десять строк, пользователь не просил весь scrollback. Правило одно —
  `terminalSlot` в [aicontext.ts](../src/lib/aicontext.ts): по нему собирает `buildContext` и
  пишет подпись «Уйдёт: …» у скрепки (`contextSummary`), чтобы подпись не обещала не то, что
  уйдёт. Запись в подписи — только если она идёт.
- **Один ход на чат.** Пока чат занят (`chatBusy`: стрим, ждёт подтверждения шаг диалога, идёт
  шаг петли) или открыт consent-диалог, новый вопрос **не стартует**: второй стрим занимал слот
  слушателей первого (Stop до него не доставал), и ответы перемешивались. Запрос `askAbout`
  становится чипом или отклоняется тостом с причиной (`askBlocker`: ИИ не настроен / `noAi`)
  **сразу** — не паркуется в сторе, иначе сработал бы потом без спроса. `startChat` —
  страховка, `doSend` — сообщение пользователю; ошибка ответа гасит `dialogRunning`, иначе чат
  залипает занятым.
- **Исполнение команд** ([aiexec.ts](../src/lib/aiexec.ts) + [AiChat](../src/lib/AiChat.svelte)):
  предложенная команда попадает в терминал только по `execMode`
  (`suggest`/`confirm`/`dialog`/`dialogConfirm`); **диалоговые режимы никогда не запускаются на
  прод-сервере**; выполненное пишется в запись как аудит. Флаг сервера **`noAi`** полностью
  блокирует и контекст, и исполнение — новая точка входа обязана его уважать.
- **Вендор — это данные, а не транспорт.** `AiProvider` — два **реальных протокола**
  (`openai` = `/chat/completions` + `Bearer`, `anthropic` = `/v1/messages` + `x-api-key`);
  третьего заводить нельзя. Новый вендор — запись в чистом реестре
  [aipresets.ts](../src/lib/aipresets.ts) (адрес + стартовая модель + нужен ли ключ), не ветка в
  `ai.rs`. Пресет только преднастраивает форму; меню «Добавить эндпоинт» — общий `ContextMenu`.
  Модельные id устаревают быстрее кода — сверяй с документацией вендора, правдоподобную догадку
  не подставляй (у vLLM модель пустая). Эндпоинт **без модели** — законное состояние: хранится
  (`sanitizeEndpoint` его не роняет, иначе очистка поля стирала бы адрес и связь с keychain), но
  годность решает `activeEndpoint`.
- **Рассуждение модели — отдельный канал `ai://think/{id}`**, не тег на `ai://out`: иначе
  черновик модели («можно было бы `rm -rf /`») распарсился бы в исполняемый блок с кнопкой
  «Выполнить». Поля-источники у вендоров разные (`reasoning_content`/`reasoning`/`thinking_delta`)
  — принимаются все, но в **существующие** парсеры.
- **Счёт токенов** едет в payload `ai://done` (данные терминальные, не поток); половина, о
  которой эндпоинт промолчал, приходит `None` и **не показывается**.
- **История обрезается** (`trimHistory`) до отправки: последнее сообщение не выкидывается никогда,
  и обрезка **не оставляет диалог начинающимся с реплики ассистента** (Anthropic такой отвергает).
- **Таймаут стрима — `read_timeout`, а не `timeout`** (общий дедлайн обрубил бы длинный, но живой
  ответ); у нестримингового листинга моделей — наоборот.
- **Промпт расслоён, ядро не редактируется.** Собирается **только** через
  `buildPromptLayers`/`buildSystemPrompt` ([aicore.ts](../src/lib/aicore.ts)) в порядке: **ядро →
  `PERSONA_HANDOFF` → персона → `replyLanguageLine`**. В ядре — всё, на чём держится приложение
  или безопасность: контракт ```bash-блоков (на нём стоит `parseChatSegments` и кнопка
  «Выполнить»), значение `‹redacted›`, режим исполнения, неинтерактивность (`ai_exec` без TTY:
  `apt-get -y`, `sudo -n`, никаких `vim`/`less`/`top`) и прод-предупреждение. Новое правило такого
  рода — **секцией ядра с тестом**, не строкой в дефолтном промпте; секции условны (локальная
  вкладка без исполнения не получает лекцию про прод).
  - **Вывод терминала — недоверенные данные, и модель обязана это знать.** Ядро объявляет всё под
    `###`-заголовком данными, а не инструкциями, и требует сообщать о попытках внедрения:
    скомпрометированному хосту достаточно напечатать строку, читающуюся как приказ, а диалоговые
    режимы это **исполняют**. Секцию убирать нельзя.
  - **Язык ответа — последней строкой, после персоны**: пока инструкция стояла в конце ядра,
    локализованная персона оказывалась более свежей инструкцией на другом языке. Ядро
    **английское, персона локализованная** — осознанно: перевод текста, отвечающего за
    безопасность, в N локалей ослабляет защиту от инъекции незаметно; поэтому перед персоной стоит
    `PERSONA_HANDOFF`, объявляющий смену языка сменой автора. Предпросмотр в настройках рисует
    **те же слои** отдельными блоками (склейка даёт ровно отправляемую строку).
  - **Дефолтные промпты — seed-данные, а не UI-строки** ([aiprompts.ts](../src/lib/aiprompts.ts),
    не `messages.ts`): однажды пишутся в настройки и дальше принадлежат пользователю. У промпта
    есть `origin` (`builtin`/`custom`), смена языка интерфейса пересеивает **только** нетронутые
    (`reseedBuiltinPrompts`). `replyLanguage` — отдельная настройка, не следствие языка интерфейса.
- **Deny-list опасных команд** (`isDangerousCommand`) и маскирование — предохранители, не границы
  (принцип 7). Полный аудит и остаточные риски — в
  [SECURITY.md](../SECURITY.md#аудит-ии-агента-фаза-20).

## Недоверенный вход

- **CSP в `tauri.conf.json` держим строгим** (никаких удалённых origin'ов, не возвращай
  `csp: null`); capabilities —
  минимально необходимые (opener только `https://`, без `dialog:default`/`fs`/`dangerous*`).
  Зависимости проходят `cargo audit`/`cargo deny`/`pnpm audit`/Semgrep (стадия `security` в CI).
  Полная модель — [SECURITY.md](../SECURITY.md).
- **CodeMirror и nonce.** В `tauri build` Tauri штампует пер-загрузочный nonce в `style-src`, а он
  по спецификации отменяет `'unsafe-inline'` → runtime-`<style>` CodeMirror без nonce блокируется
  (`.sheet === null`), и **ни одно** его правило не применяется — только в упакованной сборке (в
  `dev` страницу отдаёт Vite без CSP). Поэтому **любой** новый `EditorView` обязан включать
  `cspNonceExtension()` из [cspnonce.ts](../src/lib/cspnonce.ts) (фасет `EditorView.cspNonce` со
  style-nonce из инлайнового `<style>` в app.html); общий style-module создаётся на
  **первом** view, поэтому nonce должны отдавать все. Чинить дублированием стилей в app.css нельзя
  (не покрывает генерируемые классы подсветки); CSP при этом **не ослабляем**.
- **Markdown — недоверенный вход, и защит ровно две.** [markdown.ts](../src/lib/markdown.ts)
  кормится ответами LLM, AI-планами, **любым `.md` по SFTP** и заметками. Экранирования
  принципиально не хватает: `[x](javascript:…)` не вставляет разметку — он становится `href`
  якоря, который мы строим сами. Поэтому: (1) цель ссылки проходит allowlist схем `safeUrl`
  (`http`/`https`/`mailto` + относительные; отклонённая рисуется **текстом**, не мёртвым
  `href="#"`), и (2) любой `{@html}` с markdown **обязан** висеть на элементе с `use:mdLinks`
  ([actions/mdlinks.ts](../src/lib/actions/mdlinks.ts)) — тот безусловно давит `preventDefault()`
  (у окна нет адресной строки, поэтому навигация WebView = неотличимый фишинг) и отдаёт http(s)
  системному браузеру. Обе половины проверяют схему **независимо**. Новый вызов `renderMarkdown`
  подключай сразу с экшеном; не-markdown `{@html}` (реестр иконок) — записью в `EXEMPT` с
  причиной.
- **Картинки в превью — только `data:` из байтов, которые прочитали мы сами.** `renderMarkdown`
  рисует `<img>` исключительно из карты `opts.images` и **сам перепроверяет** схему
  (`^data:image/…;base64,`). Что разрешено тянуть, решает чистый
  [mdimage.ts](../src/lib/mdimage.ts): файл рядом с документом — да, **тем же транспортом**,
  которым пришёл документ (`sftp_read_bytes`/`read_local_bytes`); **удалённый `http(s)` —
  никогда**. Это не про CSP, а про офлайн по смыслу: `<img>` — это GET, поэтому враждебный `.md`
  узнал бы, когда и откуда его открыли. Отказ рисуется **плейсхолдером с alt-текстом** (значок
  битой картинки утверждал бы «файл повреждён» — ложь). Растры только: SVG — документ, его
  инертность внутри `<img>` обеспечивает движок, а не мы.
  - **Статический бейдж shields.io — исключение по строгому правилу**: URL `…/badge/<label>-<message>-<colour>`
    полностью описывает картинку, поэтому она **рисуется из URL** ([badge.ts](../src/lib/badge.ts)
    `renderBadge`) без запроса. **Только** статический `/badge/…`: любой динамический эндпоинт
    (`/github/stars/…`, `/npm/v/…`, `/badge/dynamic/…`) читает значение из API — остаётся
    плейсхолдером. Цвет вне набора shields/hex — отказ, не дефолт. Вывод — **инлайновый SVG с
    `fill`, никогда HTML с `style`** (nonce в `style-src` молча убил бы цвета только в упакованной
    сборке). `unescapeHtml` разворачивает **только** три сущности `escapeHtml` и не становится
    общим декодером — иначе вернул бы двоеточие, на невосстановимости которого стоит `safeUrl`.
  - **Raw-HTML в превью — санитайзер по allowlist, а не отмена экранирования**
    ([htmlsan.ts](../src/lib/htmlsan.ts)): фиксированный список тегов, у каждого свой список
    атрибутов, **каждое значение перепроверяется** (align по словарю, размеры по цифрам, `href`
    через `safeUrl`, `src` через тот же резолвер, что картинки). Ничего исполняемого:
    `on*`/`style`/`class`/`data-*` не проходят, `<script>/<style>/<iframe>/<object>/<svg>/<form>`
    дропаются **вместе с содержимым**, `srcset`/`<source>` — тоже. Парсер — ручной токенайзер
    (чистый, без DOM) с **биасом на drop**: непарсящийся тег → экранированный текст, не
    полу-собранный элемент. Включается **opt-in** (`MarkdownOptions.html`) и **только** в превью
    редактора; ответы ИИ и заметки остаются полностью экранированными. Новый тег/атрибут — **с
    тестом на границу**; DOM-санитайзер не вводить.

## UI и оформление

- **Визуальный язык заморожен.** Дизайн-система ([DESIGN.md](DESIGN.md)) **не меняется** при
  рефакторинге, чистке, переименованиях и добавлении фич — **только** если пользователь прямо
  попросил изменить дизайн. Новый элемент обязан переиспользовать существующие токены и
  паттерны, а не вводить свои; если задача формально требует тронуть оформление, а запроса на
  это не было — сохраняй текущий вид и спрашивай.
- **Деструктивное действие — всегда через `ConfirmDialog`.** Удаление файла, папки, сервера,
  записи, правила — кнопка-иконка только **открывает** диалог (стейт с целью удаления), сам
  вызов бэкенда — в `onconfirm`; отмена и закрытие панели стейт сбрасывают. Единственное
  исключение — пост-стоп-диалог записи, который сам и есть выбор «сохранить или удалить».
  Закрытие изменённого файла — тоже выбор, а не удаление: `UnsavedCloseDialog` с тремя
  ответами «Сохранить / Не сохранять / Отмена»; «Сохранить» идёт обычным путём записи (с diff,
  если он включён) и закрывает файл **только** после успешной записи.
  Правка **черновика в поле ввода** (корзинка у строки правил «Проверки доступа») — не удаление
  данных: диалога нет, но удаление обязано быть **отменяемым** — идёт штатной командой
  редактирования (`execCommand("delete")` по выделенной строке), чтобы `⌘/Ctrl+Z` её вернул.
- **Фон диалога только затемняет — не закрывает.** Клик мимо карточки `Modal` (и панелей
  Настройки/Справка/Утилиты) ничего не делает: вернувшись из другого приложения, первый клик
  легко попадает на фон, и наполовину заполненная форма исчезала вместе с введённым. Закрытие —
  кнопки, ×, `Esc`. Окну без кнопки отмены нужен `showClose`. Исключение — палитра ⌘K
  (мимолётная, ничего не теряет). Гейт `backdrop.guard`.
- **Тосты — единственный канал неблокирующих сообщений** (`notifyError`/`notifySuccess`/
  `notifyInfo`), не инлайновые баннеры; исключение — контекстная валидация прямо в форме или на
  экране подключения. Пустые состояния — общий [EmptyState](../src/lib/EmptyState.svelte), не
  разрозненные заглушки; загрузка списков — [Skeleton](../src/lib/Skeleton.svelte), не текст
  «Loading…».
- **Окно обязано сжиматься вместе с главным.** Карточка `Modal` ограничена
  `max-w-[95vw] max-h-[90vh]` и скроллится; фиксированных размеров, способных превысить окно, не
  задавай (проп `width` — только «желаемая» ширина, вьюпорт всё равно клампит). `Modal` даёт
  `role="dialog"`/`aria-modal`, фокус-трап, автофокус, **возврат фокуса** открывшему и стек
  открытых окон (Esc закрывает **только верхнее**) — не дублируй это в новых диалогах и не понижай при рефакторинге (вкладки — tablist с
  роуминг-`tabindex`, дерево — `role="tree"`).
- **Буфер обмена в полях ввода работает везде и без разметки.** Единый глобальный
  `handleClipboardShortcut` ([actions/clipboardKeys.ts](../src/lib/actions/clipboardKeys.ts))
  висит на `document` в capture-фазе и покрывает текущие и будущие поля; чтение идёт нативно
  через бэкенд (`read_clipboard_text`), без промпта WebKit. Исключения — `.xterm` и CodeMirror:
  они владеют `⌘C`/`⌘V` сами (см. раздел про файлы), не ломай это.
- **Кольцо фокуса перечисляет элементы явно.** Правило `:focus-visible` в app.css называет
  `a`/`button`/`input`/`[role="tab"]`/`[tabindex="0"]`…, а не висит на голом `:focus-visible`:
  карточка `Modal` фокусируется программно через `tabindex="-1"`, и общее правило обводило бы
  весь диалог при каждом открытии. Терминал исключён — у него свой индикатор (курсор). Своего
  фокус-оформления в компонентах не заводи.
- **Горизонтальная анимация ширины — только clip-reveal.** Контент сворачиваемой панели
  «прикалывается» к целевой ширине и якорится к неподвижному краю через `position:absolute`
  внутри `relative` + `overflow-hidden`: абсолютный потомок отсекается каждый кадр, поэтому
  растущий контейнер **раскрывает** уже свёрстанный контент. Oversize-статичный флекс-ребёнок
  (даже с `self-end`) нельзя: WebKit при анимации ширины предка не переотсекает его, и контент
  мелькает за границей поверх терминала. Рефлоу-контент тоже нельзя — центрированные элементы
  дрейфуют не в такт с границей. Нижний док сворачивается тем же приёмом по высоте: контент
  приколот к целевой высоте и якорится к **верхнему** краю — полоса вкладок едет вместе с ним и
  остаётся свёрнутым состоянием дока, а панели под ней раскрываются, не переверстываясь. Действия
  строки по ховеру резервируют место всегда
  (`invisible` → `group-hover:visible`, **не** `hidden`) — иначе строка прыгает.
- **Отступ содержимого терминала** — `px-2 pt-1` на **внешней обёртке** xterm, и полоска
  отступа **красится в фон текущей темы терминала** (`activeTerminalTheme().background`), а не в
  `bg-panel`, иначе видна рамка чужого цвета. На элементе, в который открыт xterm (`FitAddon`
  меряет его как `parentElement`), паддинга быть **не должно**: `getComputedStyle().height` при
  `border-box` включает паддинг, сетка выходила на 4 px выше места, и спозиционированный canvas
  закрывал верхнюю линию статус-бара (на Windows при растягивании окна). Обёртка —
  `overflow-hidden`. Внутрь `.xterm` паддинг тоже не переноси. Гейт `termfit.guard`.
- **Виртуальный список выключает scroll anchoring.** Скроллер любого списка на `windowRange`
  несёт `[overflow-anchor:none]`: окно подменяет строки над видимой областью, и Chromium
  (WebView2) сам «доправлял» `scrollTop` под якорную строку — прокрутка тачпадом дёргалась
  **только на Windows** (в WebKit якорения нет). Строки на время прокрутки не принимают
  указатель — hover в Chromium обновляется только после остановки и «ехал» вместе с
  содержимым. Гейт `virtualscroll.guard`.
- **Пока что-то перетаскивают, ничего не выделяется — и механизм для этого один.** Каждое
  перетаскивание указателем (вкладки терминалов и панелей, граница колонки, разделители, сервер
  в дереве, файл в списке) на нажатии зовёт `holdSelection()`
  ([actions/drag.ts](../src/lib/actions/drag.ts)): выделение отклоняется там, где начинается
  (`selectstart`), и на время перетаскивания вся страница невыделяема (класс `dragging` на
  `<html>`). `select-none` на самом перетаскиваемом элементе не хватает: WebKit позволяет
  выделению начаться внутри невыделяемого элемента, и оно шло по всему тексту под указателем —
  вкладка, протащенная над панелью, выделяла панель. Удержание кончается само — отпусканием,
  отменой, потерей фокуса окном, — поэтому ни одно перетаскивание не может оставить приложение
  с невыделяемым текстом. (Перетаскивание вкладки терминала берёт его заново на каждом
  движении: окно теряет фокус посреди него, когда вперёд выходит окно под указателем.) Убирать выделение постфактум (`removeAllRanges`) нельзя: это признак
  перетаскивания, которое дало ему начаться. Гейт `dragselect.guard`.

- **Комментарии в редакторе — не ниже AA.** Цвет комментария — `brightBlack` палитры,

  через **WAAPI**, которым стили не управляют — никакой `!important` их не укоротит. **Модалки
  анимируют только вход**: выход означал бы, что закрытый диалог живёт в DOM ещё 120 мс вместе с

  оверлей идёт над непрозрачным терминалом и chrome сразу — шва нет, рендерер не трогаем. Поле

    примерно на 19 % мельче соседних в панели задач. Поэтому Windows-артефакты (`icon.ico`,

- **Заставки простоя** — тем же слоевым контрактом, что ThemeOverlay:
  [IdleOverlay](../src/lib/IdleOverlay.svelte), `z-index:35` ниже модалок, под

  canvas монтируется только после `active`, поэтому первый кадр рисует `$effect` над
  `active`+canvas, а карточка перерисовывается после **каждого** замера — иначе график пуст
  навсегда (Windows включает reduced motion выключателем «Эффекты анимации»). Цифры прошлой
  активации сбрасываются в «—» до первого замера. Гейт `idlecard.guard`. Простой = **нет ввода И нет вывода PTY** (проп

  сетевых вызовов сверх уже существующего опроса метрик. Чьи метрики показывает карточка,
  решает `monitoredSessionId` — тот же `isMonitorable`, что у статус-бара: локальная вкладка
  с живым баром не может получить «нет активных сессий». Гасят её **только клик или клавиша**
  (`dismissesScreensaver` в [idle.ts](../src/lib/idle.ts)); движение мыши и прокрутка — лишь
  активность, не дающая ей включиться: мышь, проехавшая по окну, и случайный свайп тачпада
  убирали заставку. По той же причине **курсор над заставкой не прячется** (`cursor:none`
  запрещён): исчезнувший указатель над окном, которое ждёт клика, выглядит поломкой. Первое нажатие/клик гасит её; жест
  глотается **только если он по самой заставке** (предикат `swallowDismiss` в
  [idle.ts](../src/lib/idle.ts)) — по доку/сайдбару/модалке он гасит заставку и **проходит** к
  контролу. Чистое — в `.ts`: детект [idle.ts](../src/lib/idle.ts), сетка глифов
  [idlefx.ts](../src/lib/idlefx.ts), классификация обрыва [connlost.ts](../src/lib/connlost.ts)
  (**NO SIGNAL — только реальный неожиданный обрыв подключённой сессии**, не ручное закрытие и не
  провал коннекта). Новый эффект — сюда же, не отдельным слоем. График карточки — доли одной оси
  0…1 (`idleSample`): load — от числа логических CPU (`Metrics.cpuCount`, считается тем же `awk`,
  что `cpustat`, без лишнего процесса на тике); без load average или без числа ядер — `null`,
  прочерк и разрыв линии, а не ноль (принцип 5).
- **Вшитый WebView2 — только когда системного нет** (ADR 0013). «Полный» portable несёт
  Fixed Version runtime в хвосте exe; `webview2::prepare` — первая строка `run()`, до окна и
  tokio. Системный runtime (и явная `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` пользователя)
  побеждает **всегда**: вшитый не обновляется. Распаковка — только атомарная (temp-папка →
  sha256 из хвоста → `rename` в `<версия>`), оборванная не выдаёт себя за готовую; версия из
  хвоста — строго `a.b.c.d`, иначе хвост не наш. `.cab` в CI вшивается только с подписью
  Microsoft. Формат хвоста описан в Rust и в `scripts/webview2-runtime.mjs` — держит их
  вместе гейт `webview2runtime.test.ts`. Нет движка ни в системе, ни в exe — окно с
  объяснением (скачать portable с WebView2 / установить runtime), а не падение при создании
  окна; «установлен» проверяется реестром **и** каталогами установки — ложное «нет»
  запретило бы рабочий запуск. Тексты окон «Подготовка…»/ошибки/«не найден» — в
  `webview2.rs` на en/ru: `t()` до WebView не существует.

  (`set_decorations(false)`) **пока окно скрыто** (`visible:false` → `show()`, без мигания рамки),
  нативное меню там **пустое**, а заголовок + меню Файл/Справка + кнопки свернуть/развернуть/закрыть
  рисует [TitleBar.svelte](../src/lib/TitleBar.svelte) — тема покрывает всю рамку, включая светлые
  темы. Монтирование бара и macOS-синк нативного меню гейтятся хостовой ОС через стор
  [hostenv](../src/lib/stores/hostenv.svelte.ts) — **не** проверкой ОС по месту; на macOS кастомный
  бар не появляется. Оконные операции идут в Tauri-API окна под минимальными `core:window:allow-*`;
  `set-decorations` в WebView-права **не** входит (декорации снимает Rust). Геометрия грип-полос
  ресайза и якорь меню — чистый [windowchrome.ts](../src/lib/windowchrome.ts). Второе окно (см.
  «Окна») создаётся сразу без декораций (`decorations(false)` в билдере) и рисует тот же
  `TitleBar`; его пункт «Файл» закрывает окно, а не приложение. Snap Layouts Windows 11
  в этом подходе теряются — принятый остаточный минус. Меню Файл/Справка переиспользует общий
  `ContextMenu`, кнопки — токены chrome (`bg-panel-alt`/`border-edge`/`hover:bg-edge`), новый примитив
  не заводим.
- **Выход — только через подтверждение.** Закрытие главного окна (крестик, Alt+F4, «Файл →
  Выход»), ⌘Q и прочие запросы ОС на выход бэкенд откладывает и шлёт главному окну
  `menu://quit`; `QuitDialog` спрашивает **всегда** и перечисляет по строкам, что будет прервано
  (`quitRows` в [quitsummary.ts](../src/lib/quitsummary.ts)) — **во всех окнах**: вторые окна
  сообщают свои строки бэкенду, главное их складывает (`mergeQuitRows`). Подтверждение —
  `quit_app`. Закрытие **второго** окна — тот же диалог с его собственным перечнем
  (`window://close` → `close_window`); его сессии завершаются вместе с ним. Системный пункт
  `quit()` в меню macOS запрещён — он завершает приложение в обход вопроса. Защиту взводит
  фронт (`armCloseGuard`, по окну) **только после** подписки на свой вопрос: взведённая защита
  без слушателя сделала бы окно незакрываемым; пока не взведена — окно закрывается как обычно.
- **Размер шрифта — из шкалы** (`text-caption`/`text-meta`/`text-xs`/`text-sm`/…), **никогда**
  произвольный `text-[Npx]`: 10px против 11px решались заново у каждой новой метки — монетка,
  которую невозможно отревьюить, потому что по отдельности верны обе. Шкала намеренно **без**
  companion-ов `--text-*--line-height` (это и позволило миграции быть чистым переименованием);
  добавить их позже — молча отменить свойство. У прописных микро-меток — одно оформление.
- **i18n** — правила в [../CLAUDE.md](../CLAUDE.md): весь видимый текст через `t()` и **сразу на
  всех** языках, логика не завязана на перевод (храни канонический английский, локализуй при
  выводе). **Язык интерфейса не биндится двусторонне**: `bind:value={settings.language}` пишет
  локаль в стор мимо `setLocale()`, а тот ещё и пересеивает неотредактированные промпты ИИ —
  переключатель тихо перестаёт работать наполовину.
