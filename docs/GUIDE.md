# Руководство пользователя vterm

Возможности vterm и как ими пользоваться. Эта же страница показывается **внутри
приложения** (Help → «Инструкция»). Установка и сборка — в [INSTALL.md](INSTALL.md);
решение проблем — в [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

---

## Возможности

### Подключение и терминал
- 🪟 Двухпанельное окно: слева — список сохранённых серверов, справа — терминал.
- 📋 Добавление сервера — кнопкой в тулбаре списка серверов (иконка «лист с +»,
  рядом с кнопкой «Новая папка»); подключение кнопкой **Connect** в центре окна
  или двойным кликом по серверу. При наведении на строку появляются значки: ✎ —
  редактировать сервер / переименовать папку, × — удалить.
- 🍎 **Нативное меню приложения**: **Settings** и **About** вынесены в системное меню.
  На macOS — в меню **vterm** (Settings с ⌘,) и **Help**; на Windows/Linux — в
  меню-баре окна (**File → Settings…**, **Help → About**).
- 🔌 **SSH-подключение** (russh) по **паролю и SSH-ключу**: выбор метода в форме,
  путь к ключу через нативный диалог, passphrase для зашифрованных ключей. Если
  путь к ключу не задан — используется дефолтный ключ из `~/.ssh/`
  (`id_ed25519` → `id_ecdsa` → `id_rsa` → …, в порядке предпочтения OpenSSH).
- 🛡️ **Proxy / jump host** (настраивается **на каждой записи сервера**): подключение
  через промежуточный хост. Доступны три типа: **SSH jump host** (как `ssh -J` — vterm
  сперва подключается и аутентифицируется на бастионе, затем через туннель к цели),
  **SOCKS5** и **HTTP CONNECT**. В форме сервера: включить «Подключаться через proxy» →
  выбрать тип, указать host/port. Для jump host — пользователь, метод аутентификации,
  ключ/пароль; для SOCKS5/HTTP — **необязательные** логин и пароль (только если прокси
  требует аутентификацию). Секрет прокси хранится **только в keychain** (под отдельным
  id). Если прокси используется, на экране ожидания появляются **отдельные подстадии
  прокси** под его адресом, а затем стадии сервера под его адресом: у jump host —
  Соединение → Аутентификация → Туннель, у SOCKS5/HTTP — Соединение → Рукопожатие. При
  ошибке чек-лист замирает точно на нужном подшаге. Без прокси экран прежний.
- 🖥️ **Живой терминал** на xterm.js: PTY, ANSI-цвета, ввод/вывод, авто-resize.
- 🗂️ **Вкладки**: несколько одновременных соединений (в т.ч. к одному серверу),
  **перетаскивание** для изменения порядка, индикатор статуса на каждой.
  **⌘T / Ctrl+T** открывает новую вкладку: на вкладке сервера — ещё одно подключение
  к **тому же серверу**, иначе (или когда ничего не открыто) — **локальную консоль**.
- ➕ **Локальный терминал**: кнопка **«+»** в списке вкладок открывает вкладку с
  shell **локальной машины** (на которой запущен vterm) — реальный PTY через
  `portable-pty` (forkpty на Unix, ConPTY на Windows). Удобно, чтобы быстро
  выполнить локальную команду, не покидая приложение.
- 📡 **Синхронный ввод на несколько серверов.** Кнопка-**broadcast** в верхней полосе
  (перед иконкой-заметкой) **добавляет активную вкладку** в группу синхронного ввода и включает режим. Режим
  **привязан к активной вкладке**: пока открыта вкладка-член группы — показывается
  broadcast-раскладка; переключишься на вкладку **не из группы** — режим сам выключается
  (обычный вид этой вкладки). Чтобы собрать группу из нескольких серверов, заходи на
  каждую вкладку и жми кнопку — либо жми **«добавить все подключённые»** в тулбаре. Вкладки,
  входящие в группу, помечены **синей точкой** рядом со статусной точкой подключения и красной
  точкой записи (точка — только индикатор и видна, пока включён режим синхронного ввода).
  Снизу — **общая командная строка**: печатаешь команду один раз, **Enter** —
  она уходит на **все живые** сессии группы. Терминалы группы показываются **сеткой**
  (до 9 серверов) или, при большом числе, — раскладкой **«фокус + список»**: крупный
  терминал — это **активная вкладка**, справа компактный список остальных (клик по строке
  делает эту вкладку активной, т.е. выводит её в фокус). Раскладку можно переключить вручную.
  Кнопки тулбара — **иконки с подсказками** (наведи, чтобы увидеть подпись): **➕** добавить все
  подключённые, **🗑** очистить всю группу, **➖** убрать активную вкладку из группы (остальные
  члены сохраняются). Отправка команды — **иконкой-самолётиком** или по **Enter**. **Отправка на prod-сервер**
  (тег `prod`/`production`) требует **подтверждения** — с показом списка prod-целей и самой
  команды. Команды видны в записи сессии, если она идёт.
  **Запись в режиме синхронного ввода — групповая:** кнопка **REC** запускает/останавливает
  запись **сразу на всех живых членах** группы (каждый сервер — свой файл), а в библиотеке
  такие записи собираются в один **свёрнутый бандл «Broadcast → N серверов»** (разворачивается
  в пофайловые записи). При остановке групповой записи приложение **предложит дать бродкасту
  имя** (как при остановке обычной записи) — оно показывается на бандле в библиотеке (можно и
  сразу **удалить** весь бандл). Каждая разосланная команда пишется **маркером** в запись каждого члена.
  При бродкасте на **prod** групповая запись включается **автоматически** (аудит). Добавишь
  сервер в группу во время записи — он тоже начнёт писаться; уберёшь — его запись финализируется.
- 🔄 Индикатор статуса (Connecting / Connected / Disconnected / Error) и
  **переподключение** при обрыве (кнопка Reconnect + опциональный авто-reconnect).
- ⏳ **Окно ожидания подключения**: пока идёт connect, в центре показывается
  анимированный оверлей (орбита-комета вокруг иконки сервера) с именем сервера,
  `user@host:port` и **чек-листом реальных фаз** соединения — Соединение →
  Аутентификация → Сессия (подсветка идёт по фактическим событиям бэкенда, а не
  по таймеру), чтобы было видно, на каком этапе подключение.
- ⛔ **Экран ошибки/обрыва** в том же стиле: при неудаче иконка сервера получает
  **красный крест**, а чек-лист **замирает на упавшем шаге** (например, «Соединение —
  отказано» с причиной от сервера) — сразу видно, где оборвалось; ниже — кнопка
  **Переподключиться**. При **провале аутентификации** вкладка остаётся с экраном
  «Аутентификация отклонена», а ввод пароля заново — по кнопке (модалка больше не
  выскакивает сама).
- ⏱️ Таймаут подключения и keepalive (настраиваются) — «мёртвое» соединение
  детектируется автоматически.
- 🔑 **Сохранение секретов в системный keychain** (macOS Keychain / Windows
  Credential Manager) — чекбокс «Сохранить» при подключении, автоподключение.
- 🛡️ **Проверка отпечатка хоста** (vterm-managed `known_hosts.json`, SHA256):
  политики strict / trust-on-first-use / accept-any.

### Список серверов и папки
- 🗂️ Профили серверов сохраняются в **JSON** в конфиг-каталоге ОС.
- 🎨 **Пиктограмма сервера.** В форме добавления/редактирования (под полем «Псевдоним») —
  **сворачиваемый** раздел выбора **иконки** из набора (~24 глифа: web, database, cache, shell,
  cloud, container, kubernetes, security, proxy, load balancer, mail, deploy и т.д.) и **цвета**
  (7 вариантов). По умолчанию раздел свёрнут, но выбранная иконка и её название видны в заголовке.
  Пиктограмма показывается **перед именем** в списке серверов, тонированная выбранным цветом —
  удобно быстро находить нужный сервер. Без выбора — нейтральный значок сервера. Значение
  хранится в профиле и попадает в бэкап.
- ➕ Модальное окно добавления/редактирования: псевдоним, host/IP, порт, логин,
  метод аутентификации и **теги**. Кнопка «Добавить сервер» (иконка «лист с +») —
  в тулбаре списка серверов, рядом с «Новая папка». **Обязательные поля** —
  псевдоним, host/IP и логин: если оставить их пустыми и нажать «Сохранить», поля
  подсветятся красной рамкой с подсказкой, а сервер не сохранится, пока их не
  заполнить. **Host / IP** дополнительно проверяется на формат — принимаются IPv4,
  IPv6 и корректные имена хостов/FQDN; некорректное значение подсвечивается. **Порт**
  должен быть целым числом 1…65535 — пустой или некорректный порт так же подсвечивается
  и блокирует сохранение.
- 📄 **Дублирование сервера.** В строке сервера (по ховеру) — иконка копирования между
  «редактировать» и «удалить»; также команда «Дублировать сервер» в палитре ⌘K. Открывается
  форма добавления с полями оригинала (алиас → « (копия)») — правишь и сохраняешь. Копия
  создаётся в той же папке. **Сохранённый пароль в копию не переносится** — он привязан к
  конкретному серверу и запрашивается при первом подключении.
- 🟢 **Индикатор подключений.** Справа в строке сервера — кружки по числу открытых вкладок
  этого сервера (внахлёст): 🟢 подключён, 🟡 подключается, 🔴 обрыв/ошибка (цвета как у точки
  на самой вкладке). Больше трёх вкладок — показываются три и бейдж `+N`. Наведёшь на строку —
  кружки уступают место кнопкам действий.
- 📂 **Иерархические папки** (любая вложенность, пустые папки сохраняются):
  создание/удаление/переименование, **перетаскивание сервера в папку мышью**
  (распределение по папкам — только так), сворачивание пиктограммой +/−;
  **поиск** по списку (alias/host/логин/папка/теги). **Выделение папки:** клик по
  строке папки подсвечивает её; пока папка выделена, кнопка «Добавить сервер» создаёт
  новый сервер **сразу в этой папке** (форма открывается с уже выбранной группой).
  **Клавиатура** (когда фокус в списке): `↑`/`↓` — двигают **рамку-курсор** по строкам
  (сервер или папка) с подсветкой рамкой; `Enter` — на сервере **подключиться**, на
  папке **свернуть/развернуть** её (по аналогии с SFTP-панелью); `Delete`/`Backspace` —
  удалить сервер/папку (с подтверждением). Пробелом ничего не выделяется; других
  комбинаций нет.

### SFTP и передача файлов
- 📁 **SFTP-менеджер файлов** (правая панель, по умолчанию свёрнута в полоску;
  разворачивается и подключается кнопкой **Connect** внутри панели): просмотр и навигация,
  создание/удаление папок, **создание пустого файла** (иконка «лист с +» рядом с
  «Новая папка»), **upload/download** через нативный диалог, **drag-and-drop**
  загрузка, индикатор прогресса. **Перемещение внутри панели**: перетащи файл или
  папку мышью на папку в списке (или на «..» — уровнем выше) — после подтверждения
  запись переедет туда. **Мультивыбор как в ОС**: клик — выбрать одну запись,
  **Ctrl/Cmd+клик** — добавить/убрать, **Shift+клик** — диапазон; перетаскивание любой
  выделенной записи переносит **всю** выборку разом. Если в цели уже есть запись с
  таким именем — она **пропускается** (ничего не перезаписывается).
  **Клавиатура** (когда фокус в списке): `↑`/`↓` — двигают только **рамку-курсор** (можно
  встать и на «..»), выделение при этом не меняется; `Home`/`End`, `PageUp`/`PageDown`;
  `Enter` или `→` — открыть файл / войти в папку, а на «..» — подняться на уровень выше (фокус
  остаётся на списке, курсор встаёт на каталог, из которого вышли); `←` — тоже вверх;
  `Space` — отметить/снять запись под курсором (отметки **сохраняются** при движении рамки);
  `Shift+↑/↓` — диапазон, `Cmd/Ctrl+A` — выделить всё, `Esc` — снять выделение; клик мышью по
  пустому месту списка тоже снимает всё выделение;
  `Backspace`/`Delete` — удалить выделенное, `F2` — переименовать; `Cmd/Ctrl+X`→`Cmd/Ctrl+V` —
  вырезать/вставить (перемещение), `Cmd/Ctrl+C`→`Cmd/Ctrl+V` — копировать/вставить (при вставке
  в **ту же** папку копия получает имя «… copy», «… copy 2»), `Cmd/Ctrl+Shift+C` — скопировать
  путь(и) как текст. Кнопка-**глаз** в тулбаре (рядом с «Обновить»)
  показывает/скрывает **скрытые файлы** (dotfiles); по умолчанию они скрыты, выбор
  запоминается в настройках. Кнопка-**терминал** включает режим «**следовать за путём
  терминала**»: наберёшь в терминале `cd /var` — панель тоже перейдёт туда (односторонне,
  свой тумблер у каждой вкладки). Работает через shell-integration (OSC 7). Т.к. многие
  шеллы (bash на Ubuntu/OEL9 по SSH) сами его не шлют, при **включении** появляется окно с
  описанием и точной командой; по подтверждению команда вписывается в терминал **только на
  текущую сессию** (на сервере ничего не сохраняется), и панель начинает следовать.
  То же есть в панели локальных файлов.

### Интерфейс, темы и настройки
- 🎨 **Темы оформления** терминала и UI (применяются в реальном времени): **One Dark
  (по умолчанию)**, Catppuccin, Dracula, Nord, Gruvbox, Solarized, Tokyo Night и ретро —
  Fallout (зелёный фосфор), Amber CRT, IBM 3270, Commodore C64; плюс **пользовательская
  тема** (свои цвета фона/текста/курсора и 16-цветной ANSI-палитры).
- ⚙ **Панель настроек** (двухпанельная): слева — **группы** (Общие, Внешний вид,
  Терминал, Подключение, Файлы и редактор, Сессии и мониторинг), справа — настройки
  выбранной группы; сверху — **поиск по всем настройкам** (с счётчиком совпадений на
  группах). Внутри: язык интерфейса, тема, шрифт (семейство/размер/интервал), курсор,
  scrollback, bell, копирование по выделению, параметры соединения, host-key-политика и
  др. Длинные коллекции (шаблоны редактора, правила подсветки) спрятаны под сворачиваемые
  блоки. Навигация по группам — мышью или стрелками `↑/↓`.
- 🌐 **Язык интерфейса** (English / Русский, переключается в **Настройки → Язык**,
  применяется мгновенно). Перевод покрывает весь UI **и нативное меню** приложения;
  добавление нового языка —
  одна запись в реестре языков плюс словарь (см. `src/lib/i18n/`). Доменные/технические
  термины (`CPU`, `RAM`, `Load average`, `Disk I/O`, `IP`, `SFTP`, `SSH`, `keychain`,
  `passphrase` и т.п.) намеренно **не переводятся**. По умолчанию язык берётся из
  **языка операционной системы** (русская ОС → русский, иначе — English); выбранный
  вручную язык сохраняется и имеет приоритет.

  > **Что такое bell.** «Bell» — реакция терминала на управляющий символ BEL
  > (ASCII `0x07`, он же `\a`). Его шлёт удалённая программа, чтобы привлечь внимание:
  > неоднозначное автодополнение по Tab, ошибка ввода в shell, уведомления из
  > `tmux`/`vim` и т.п. (проверить можно командой `printf '\a'`). В настройках
  > выбирается реакция: **None** — игнорировать, **Sound** — короткий звуковой сигнал,
  > **Visual** — кратковременная подсветка терминала акцентным цветом (когда звук
  > нежелателен). По умолчанию — None.
- 💾 **Бэкап настроек** (в панели ⚙ Settings): **Export backup…** сохраняет список
  серверов, их настройки, структуру папок и параметры приложения в один JSON-файл;
  **Import backup…** восстанавливает их (с подтверждением, т.к. заменяет текущие).
  Пароли/passphrase **не** попадают в файл — они остаются в системном keychain.
- ♻️ **Сброс настроек** (кнопка внизу панели ⚙ Settings): «Сбросить к значениям по
  умолчанию» возвращает **все** настройки приложения к дефолтным. Действие
  **необратимо**, поэтому выполняется только после подтверждения в диалоге.
- 🧭 **Верхняя полоса** — тонкая строка с **адресом активного подключения**
  (`alias · user@host:port`) слева и **быстрыми кнопками** справа. Кнопки **закреплены на
  своих местах** и не смещаются (в порядке слева направо): **синхронный ввод** (иконка-
  broadcast; добавляет активную вкладку в группу — **всегда на своём месте**, но приглушена и
  неактивна, пока нет открытой вкладки), **заметки** (иконка-документ; видна, как только есть
  **целевой сервер** — активная вкладка сервера или, на локальной вкладке, выделенный в списке),
  **мониторинг** (иконка-график), **REC** (старт/стоп записи), **библиотека записей** и
  **настройки** (шестерёнка — открывает раздел **«Сессии и мониторинг → Серверные инструменты»**).
  Синхронный ввод, мониторинг и REC работают только при открытой/«живой» сессии — **иначе
  показаны приглушёнными и неактивными**.
- 📝 **Заметки к серверу.** Кнопка-заметка всегда показывает заметки **целевого
  сервера**: если открыта и активна **вкладка сервера** — его заметки (при переключении
  вкладок цель меняется на сервер новой вкладки); на **локальной вкладке** (или без
  вкладок) — заметки **выделенного** в списке сервера. Подключаться не обязательно —
  нажмите **иконку-заметку** в верхней полосе, откроется **большое окно-редактор**.
  Заметки — в **Markdown**, с переключателем **Редактор/Просмотр**. Сохранение
  **автоматическое** (плюс кнопка «Сохранить и закрыть»). Если у сервера уже есть
  заметки, на иконке горит **точка-индикатор**. Заметки хранятся вместе с профилем и
  **попадают в бэкап**.
- 📊 **Нижний статус-бар** (как в MobaXterm): иконка ОС, hostname/пользователь,
  **график загрузки ЦП** + проценты, ОЗУ и свободное место на диске — метрики
  собираются отдельным exec-каналом раз в N секунд. При наведении на элемент —
  **всплывающая подсказка** (версия ОС, `whoami@hostname`, загрузка CPU, RAM с
  использовано/всего и процентом и т.д.). В **расширенном** режиме RAM/Swap
  показывают «использовано / всего (%)» полностью.
- 🧩 **Регулируемые и сворачиваемые панели**: ширину левой панели и SFTP можно тянуть
  мышью, каждую можно свернуть в тонкую полоску (состояние запоминается).
- 📋 **Копирование/вставка** (copy-on-select, ⌘/Ctrl-сочетания, средняя кнопка),
  **подтверждение закрытия вкладки** с активной сессией, окно **Help & About**.
  Во **всех** полях ввода (пароль, host/порт/логин в форме сервера, имена папок,
  поиск, ⌘K) работают **⌘V/Ctrl+V** (вставка), а также копирование/вырезание/
  выделение (⌘/Ctrl + C/X/A) — через единый глобальный обработчик; чтение буфера
  идёт нативно через бэкенд, поэтому WebKit не показывает запрос «Paste».

### Расширенный мониторинг
- 📈 **Страница подробного мониторинга** — дашборд: вверху блок **«Система»**
  (сгруппирован по колонкам Хост / Сеть / Здоровье / Обновления / **Оборудование** —
  модель CPU, ядра/потоки/сокеты, частота, архитектура, виртуализация, модель машины,
  материнская плата, BIOS и объём RAM; собирается один раз при открытии, без root,
  недоступное — прочерк;
  если сервер виртуальный, тип гипервизора виден **бейджем** в шапке) с **health-сводкой**
  по всем блокам (зелёный/жёлтый/красный, клик → переход к секции; уровень — по
  заданным порогам + SMART/OOM/ошибки сети), ниже — детальные
  секции с **графиками** (ЦП/load/ОЗУ/swap), **загрузкой по ядрам**, детализацией
  памяти, **полным списком файловых систем** (место + **inodes**), сетью и
  состояниями TCP, а также **таблицей датчиков температуры** (lm-sensors: CPU/ядра/
  NVMe — текущая/high/crit с цветом порога; если пакет не установлен — кнопка
  установки прямо со страницы, а если установлен, но датчиков нет — плашка «датчики
  не обнаружены»), **разбивкой CPU** (user/system/iowait/**steal**),
  **таблицей топ-процессов**, **здоровьем системы** (сбойные systemd-юниты, слушающие
  порты, conntrack, синхронизация времени), **сетью по интерфейсам** (rx/tx + ошибки/
  потери), **диском по устройствам** и **таблицей сессий** (кто/откуда), а также
  ленивым блоком **«Дополнительно»** (GPU `nvidia-smi`, Docker-контейнеры, **SMART
  дисков** и счётчик OOM-kills — подгружаются один раз при открытии).
  Открыть: **иконкой-графиком в верхней полосе** (появляется при активном подключении),
  командой **⌘K → «Мониторинг сервера»** или пунктом меню
  **Мониторинг** (⌘/Ctrl+Shift+M). **Данные тянутся только пока страница открыта.**
- 🚦 **Пороги с цветовой индикацией**: для числовых метрик (ЦП, ОЗУ, swap, диск,
  inodes, дескрипторы, load, температура) задаются «средний» и «предельный» уровни;
  превышение среднего — **жёлтый** текст, предельного — **красный**. Работает и в
  статус-баре, и на странице. Настройки → Status bar → «Пороги».
- 🧮 **Дескрипторы и inodes** — чтобы заранее видеть исчерпание ресурсов
  («невозможно создать файл»): системные FD (`/proc/sys/fs/file-nr`), `ulimit -n`,
  inodes по каждому разделу.
- 📦 **Pending updates** (apt/dnf/yum/pacman/zypper/apk) и флаг «требуется
  перезагрузка» — подгружаются **лениво**, только на странице.
- 🛑 **Полное отключение статус-бара** в настройках: бар перестаёт **опрашивать
  сервер**, при этом страница мониторинга остаётся доступной (⌘K/меню).

### Логи и текст
- 🔎 **Поиск по всему буферу терминала** — не только по видимому экрану, а по всему
  scrollback (десятки тысяч строк). Открыть: **⌘F** (macOS) / **Ctrl+Shift+F**
  (Windows/Linux). Поле поиска с **счётчиком совпадений**, тумблерами **«учитывать
  регистр / слово целиком / regex»**, навигацией **Enter / Shift+Enter** (и кнопками
  ↑/↓) и кнопкой **«копировать совпадение с контекстом»** (строка ±5). Опции
  регистр/слово/regex **запоминаются**, при ошибке в regex — подсказка. Совпадения
  подсвечиваются цветами активной темы, активное — плавно «нарастает» при переходе.
- ⌨️ **История команд по Ctrl+R** — вместо того чтобы перебирать историю по одной ↑/↓,
  нажми **Ctrl+R** в терминале: всплывает окно со **списком команд** из файла истории шелла
  сервера (`~/.zsh_history` / `~/.bash_history`) **плюс команды, которые ты набрал в этой сессии
  прямо сейчас** (появляются сразу, не дожидаясь выхода из шелла), **новые сверху**, дубликаты
  схлопнуты.
  Печатаешь — список **фильтруется вживую**; **↑/↓** двигают выбор (**PgUp/PgDn** — быстрее),
  **Enter** ставит команду **в строку ввода** (не запускает — проверишь и сам нажмёшь Enter).
  Закрыть окно: **Esc**, **крестиком** в правом верхнем углу или просто **кликнув по терминалу**
  (перенос фокуса на консоль закрывает палитру). Ctrl+R **перехватывается** приложением; если нужен родной reverse-search
  шелла — выключи тумблер **«Ctrl+R ищет по истории команд»** в настройках (раздел «Терминал»).
  История читается по тому же SSH к твоему серверу (офлайн-контракт соблюдён).
- 🎨 **Подсветка логов по правилам (regex):** настраивается в настройках («Логи и
  текст») — имя, регулярное выражение, цвет (из палитры темы), вкл/выкл, учёт
  регистра, **стили** (жирный / фон / **подсветка всей строки**) и **порядок**
  правил (↑/↓ — приоритет). Из коробки: `ERROR/FATAL` — красным жирным, `WARNING` —
  жёлтым, `SUCCESS/OK` — зелёным, IP-адреса — синим. Подсветка идёт **цветами текущей
  темы** и **только в обычном выводе** (полноэкранные программы вроде `vim`/`htop` не
  затрагиваются).
- 🔗 **Кликабельные ссылки:** `http(s)`-ссылки в выводе открываются во внешнем
  браузере по клику (через системный опенер; офлайн-инвариант сохранён).
- 🧱 **Структурный просмотр логов (мультиформатный):** переключатель **«Raw | Table»**
  (сегмент в правом-верхнем углу терминала; в табличном режиме — в тулбаре таблицы;
  **появляется только после установки соединения** — во время подключения он скрыт). В
  structured-режиме строки распознаются на лету с
  **авто-определением формата**: **JSON** (NDJSON), **logfmt** (`key=value`), **syslog**
  (`/var/log/syslog`, `journalctl`), **nginx/apache** access-логи и **dmesg** — всё в
  единую **таблицу** (Время / Уровень / Сообщение) с цветом уровня — локальный мини-аналог
  Kibana/Loki. Можно **добавлять колонки по любым полям** (пикер колонок), фильтровать
  **чипами по уровню** (error/warn/info/debug) и текстом, **разворачивать строку** (детали
  + **копирование**), а **ширину любой колонки можно менять мышью** — потяните за правый
  край заголовка (курсор-стрелка ↔; при переполнении таблица прокручивается по горизонтали).
  Таблица **автопрокручивается** в режиме `tail -f`, а **время
  приводится** к локальному виду (epoch/ISO/syslog). Кнопка **«Clear»** (с подтверждением)
  даёт чистый старт перед просмотром другого лога. Имена полей понимаются **без учёта
  регистра** — `journalctl -o json` (`MESSAGE`/`PRIORITY`/`SYSLOG_TIMESTAMP`) работает из коробки.
- ⚙️ **Раздел настроек «Логи и текст»** с **мастер-переключателем**: один чекбокс
  полностью отключает все доработки этой фазы — терминал ведёт себя как раньше
  (плюс отдельные тумблеры по фичам: поиск, подсветка, JSON-вид).

### Запись сессий
- ⏺️ **Запись сессий** в формате **asciicast v2**: кнопка **REC** в верхней полосе —
  **по сессии** (каждая вкладка пишется отдельно), красный индикатор на вкладке, старт/стоп
  также из ⌘K. Пишется весь ввод-вывод с таймингами **на бэкенде**; файлы — в каталоге
  `recordings/` приложения. В начало записи подставляется **текущая строка приглашения**
  (например `root@host:~#`), чтобы первая команда тоже шла с приглашением.
- 🎚️ **Режим записи** (Settings → «Запись сессий»): полный с таймингами (как видео),
  полный без таймингов, или **только команды** (по одной строке на Enter — без лишних
  нажатий и правок; пустые нажатия Enter не записываются). В режимах **без таймингов** команда в плеере **«печатается»** с
  постоянной скоростью, а **вывод появляется сразу целиком** (не построчно); оба таких режима
  («только команды» и «полностью без таймингов») играются **одинаково и на одной замедленной
  шкале** скоростей (см. плеер).
- 🔒 **Приватность:** ввод после промптов `password:` **маскируется** (настройка
  **Settings → «Запись сессий»**, по умолчанию вкл); SSH-пароль в запись не попадает.
- 💾 **Сохранение после остановки:** при остановке записи всплывает окно — задать **заголовок**
  и **краткое описание** и **Сохранить** либо **Удалить** запись. Заголовок и описание потом
  можно **отредактировать** карандашом в библиотеке.
- 📚 **Библиотека записей** (⌘K → «Записи» или кнопка в полосе вкладок): список с **заголовком,
  описанием и сервером** (имя сервера сохраняется даже после переименования заголовка), датой и
  размером, **поиск** (по серверу / описанию / дате), **многоуровневую сортировку** (дата/сервер/
  размер — цепочкой приоритетов) и **группировку** (когда записей много): переключатель
  **«Группировка: Нет / Сервер / Дата»** делит список на **сворачиваемые секции** с заголовком и
  счётчиком — по серверу (локальные сессии и бандлы broadcast — в отдельных секциях) или по дате
  (Сегодня / Вчера / На этой неделе / В этом месяце / Раньше). Бандлы broadcast остаются свёрнутыми
  внутри секций. **Редактирование** (карандаш), удаление **с подтверждением**,
  воспроизведение и **экспорт** в 4 формата (выбор формата — окно **поверх** библиотеки):
  **Markdown-«ранбук»** (шапка с метаданными → нумерованные команды + вывод в блоках; лучший
  для ИИ), **только команды**, **транскрипт** (чистый текст, ANSI снят) и **сырой `.cast`**.
  **Во все экспорты добавляется блок метаданных сессии:** сервер, hostname, IP, пользователь,
  версия ОС и ядра, время старта/окончания и длительность, режим записи, версия приложения
  (для удобного анализа). Чтобы скормить ИИ — снаружи; приложение остаётся **офлайн** (ИИ-вызовов внутри нет).
- ▶️ **Встроенный плеер:** открой запись из библиотеки и проиграй её как «видео» —
  **play/pause**, **перемотка** (слайдер) и **скорость**, время `M:SS`. Скорости зависят
  от записи: с реальными таймингами — `0.5/1/2/4×` (старт `1×`); без таймингов («команды +
  вывод») — **вся шкала на ступень медленнее** `0.25/0.5/1/2×` (старт `0.5×`), чтобы
  «печатание» команд читалось спокойнее. Терминал **сам следит за низом** вывода и
  **прокручивается колесом/полосой назад** по истории (без лишней внешней полосы).
  Воспроизведение в read-only терминале, офлайн.
- 🤖 **Автозапись для прод-серверов:** в форме сервера — флажок **«Автозапись сессий»**. Для
  таких серверов запись **начинается автоматически** при подключении (аудит-след каждой
  сессии) и финализируется при отключении; реконнект создаёт новую запись.
- ⏸️ **Пауза для экономии диска:** запись **не пишет фоновые потоки** (`tail -f`, `top`), когда
  вкладка не на виду. Переключение на другую вкладку **ставит запись на паузу**; простой
  активной вкладки дольше N секунд (поле **«Пауза записи при простое»** в настройках, по
  умолчанию 20с, `0` = выкл) тоже паузит — а любое нажатие в консоли мгновенно **возобновляет**.

### Редактор конфигов и продвинутый SFTP
- 📝 **Редактор конфигов** (CodeMirror) с подсветкой, diff перед сохранением,
  markdown-превью и синхронизацией папок в SFTP — **реализовано (Фаза 12)**:
  бэкенд правки файлов (12.1) — чтение/запись текста с проверкой по SHA-256 (защита от
  затирания изменённого на сервере конфига), атомарная запись с сохранением прав, гарды
  размера/бинарных файлов; **встроенный редактор** (12.2) — клик по `.yaml`/`.json`/
  `.toml`/`.sh`/`.conf`/`.md`/… в SFTP открывает под-вкладку с подсветкой (тема — в тон
  активной теме), правка и сохранение по `Ctrl/Cmd+S` прямо на сервер, индикатор
  несохранённых изменений и защита при закрытии. Подсветка для **50+ языков и форматов**:
  YAML, JSON, TOML, ini/conf, Markdown, Shell/bash, PowerShell, Python, JavaScript/TypeScript,
  Java, Dockerfile, Go, Rust, Ruby, C/C++/C#, SQL, HTML, CSS/SCSS/Less, XML, nginx, sshd_config,
  sudoers, HAProxy, BIND, systemd-юниты, Compose, Ansible, Kubernetes, GitHub Actions, Prometheus, CMake,
  diff, Protobuf, Puppet, Groovy/Gradle, Scala, Kotlin, Dart, Swift, Clojure, Haskell, Erlang,
  Elm, Lua, Perl, R, Julia, и др. **Открыть можно любой файл** — даже с незнакомым расширением
  или без расширения (откроется как обычный текст; предельный размер файла для открытия —
  настройка в разделе SFTP, по умолчанию 2 МБ). **Diff перед сохранением** (по настройке) показывает «было на
  сервере ⇄ ваши изменения», а при конфликте (файл изменили на сервере) предлагает переоткрыть
  или перезаписать. **Линт** YAML/JSON и подсветка синтаксических ошибок прямо в редакторе.
  Правки конфигов **попадают в запись сессии** (аудит). Для **Markdown** — переключатель
  «Код ⇄ Превью» (`.md` открывается сразу в красивом виде). Файлы можно открывать и **с локальной
  машины** через «Открыть с помощью vterm» (откроется вкладка локального терминала и редактор с
  файлом; `.md` — в превью). У локальной вкладки терминала справа — **панель локальной файловой
  системы** (как SFTP для удалённого сервера): обзор, навигация, создание/удаление, открытие в
  редакторе, а также кнопка-**глаз** для показа/скрытия скрытых файлов (тот же тумблер и то же
  общее предпочтение, что и в SFTP). **Синхронизация папок** (кнопка в SFTP): сравнивает локальную папку и папку на
  сервере **по SHA-256** (без скачивания), показывает dry-run превью различий и докачивает
  только изменённое — направление «залить/скачать/в обе стороны», исключения (`.git`,
  `*.tfstate`…), опционально удаление лишнего. **Поиск по содержимому** (grep по SSH) с переходом
  к найденной строке, **шаблоны** конфигов (nginx/systemd/compose/k8s/Dockerfile/bash), **иконки
  типов файлов**, правка root-конфигов **через sudo** (пароль не сохраняется) и опциональный
  `.bak` перед перезаписью. **Серверный линт по SSH** (кнопка «Линт» в редакторе): запускает
  реальный инструмент на сервере (`yamllint`/`shellcheck`/`hadolint`/`ruff`/`nginx -t`) и
  показывает кликабельные результаты с переходом к строке. **Валидаторы конфигов демонов**
  (v0.24.0) — проверка типовых конфигов их же родными командами, ставить ничего не нужно (идут в
  комплекте с сервисом): **`sshd_config`** → `sshd -t` (защита от локаута перед reload; `sshd -t`
  читает host-ключи, поэтому запускается под sudo **тем же паролем**, что и правка root-файла),
  **`sudoers`** и `sudoers.d/*` → `visudo -c`, **`haproxy.cfg`** → `haproxy -c`, **`named.conf`**
  (BIND) → `named-checkconf`, **юниты systemd** (`.service`/`.timer`/`.socket`/…) →
  `systemd-analyze verify`. Определяются по имени/каталогу (sshd_config, sudoers.d, haproxy,
  named.conf) или расширению (юниты). **Линтеры YAML-семейства** (v0.25.0) — для YAML-файлов, у
  которых есть свой специализированный валидатор: **docker-compose** (`docker-compose.yml`/
  `compose.yml`) → `docker compose config` (установка не нужна — docker уже стоит),
  **GitHub Actions** (`.github/workflows/*.yml`) → `actionlint`, **Prometheus** (`prometheus.yml`) →
  `promtool check config`, **Ansible** (плейбуки/роли) → `ansible-lint`, **Kubernetes-манифесты**
  (по содержимому — `apiVersion`+`kind`) → `kubeconform`. `Dockerfile` линтится `hadolint` (с
  Фазы 12.7). Отдельные линтеры (`ansible-lint`/`actionlint`/`kubeconform`) ставятся из раздела
  «Серверные инструменты», как остальные; проверка идёт по буферу одного файла (best-effort:
  `kubeconform` может тянуть схемы из сети на стороне сервера, `promtool` идёт в комплекте с
  Prometheus). Линт `nginx -t` появляется не только
  на `nginx.conf`, но и на **кастомных конфигах** в дереве `…/nginx/…` — файлы в `conf.d`
  (на любой глубине вложенности), `sites-available`/`sites-enabled`, `snippets` и безрасширенные
  инклюды распознаются как nginx по каталогу (одноимённые каталоги apache под этот детект не
  попадают). Конфиги, которые nginx подключает **вне** дерева `/etc/nginx/` (через `include`),
  подхватываются автоматически: приложение спрашивает у сервера список реально загружаемых файлов
  (`nginx -T`) и распознаёт их как nginx, даже если они лежат в нестандартном месте. Если конфиги
  nginx доступны только root — список берётся под sudo **тем же паролем**, что вы вводите при
  открытии root-файла (отдельного окна ввода пароля ради подсветки не появляется). **Помощь установки** этих инструментов
  (и мониторинговые `lm-sensors`/`smartmontools`/`sysstat`) — раздел «Серверные инструменты» в
  настройках: статус на сервере + установка в один клик (в терминал или через sudo), с учётом
  пакетного менеджера дистрибутива. При установке через sudo видно, **что идёт установка**:
  живая консоль с выводом в реальном времени, индикатор выполнения и в конце «✓ Установлен»;
  список инструментов после этого обновляется сам.
  **Шаблоны конфигов** (nginx/Dockerfile/compose/k8s/systemd/bash/…) редактируются в настройках —
  можно менять, добавлять свои и держать несколько на язык; в редакторе доступны в меню «Шаблоны».

### ИИ-ассистент (опционально, в разработке)

- 🤖 **Опциональный ИИ-ассистент** — **выключен по умолчанию**. Включается в
  **Настройки → ИИ-ассистент**: мастер-выключатель + один или несколько эндпоинтов
  (**локальный** OpenAI-совместимый — ваш домашний Qwen через Ollama/vLLM — или **облачный**
  Claude). API-ключ хранится в системном keychain, не в файлах.
- ⚙️ **Дополнительно (у эндпоинта).** Сворачиваемый блок «Дополнительно» в карточке эндпоинта:
  **Общий промпт модели** — преамбл, который **приклеивается перед** промптом задачи (из «Системные
  промты» / персональным промптом сервера) в каждом запросе этой модели; и **Доп. параметры (JSON)**
  — только параметры генерации `{"temperature":0.2,"top_p":0.9,"max_tokens":2048}`, которые
  подмешиваются в запрос. Слои промпта: **общий промпт модели → промпт задачи (чат/runbook/…, с
  серверным override)**. Некорректный JSON подсвечивается и не отправляется; `model`/`messages`/
  `stream`/`system` защищены от переопределения.
- 🔌 **Проверка подключения и список моделей.** В настройках эндпоинта кнопка **«Проверить
  подключение»** опрашивает сервер и показывает, какие модели на нём есть (клик по модели
  подставляет её). Поля `baseURL`/`Модель` можно заполнить и вручную. **Саму модель удобно выбирать
  прямо в чате** — селектор в шапке ИИ-панели со списком моделей сервера (кнопка ↻ обновляет список).
  Указывать конкретную модель заранее не обязательно. Если подключение не удалось, показывается
  понятная причина: **ошибка ключа** (для облачных эндпоинтов ключ надо сначала сохранить) или
  **недоступен адрес** (проверьте baseURL и что сервер запущен).
- ✍️ **Системные промты — свои для каждого случая.** В **Настройки → ИИ-ассистент → Системные
  промты** (раздел сворачивается) — четыре сворачиваемых подраздела: **чат**, **runbook**, **shell**,
  **Ansible**. В каждом можно **держать несколько промтов**, выбирать **активный** (радио), давать имя
  и сбрасывать текст к дефолту (↺). Какой чат-промт использовать на конкретном сервере — выбирается
  **в форме сервера** (поле «Промпт ИИ-чата»); если не задан, берётся активный.
- 💬 **Чат** — в правой панели рядом с файлами: у панели две **вкладки** «SFTP» и «ИИ»
  (вертикальные в свёрнутом виде, горизонтальные в развёрнутом). Открыть чат — клик по вкладке
  «ИИ» или команда палитры **⌘K → «Показать ИИ-чат»**. Ответ стримится; код-команды — в блоках.
  **Диалог у каждой вкладки свой** и сохраняется при переключении между вкладками — очищается
  кнопкой «Очистить» или при закрытии вкладки. Генерация ответа **продолжается в фоне**: если уйти
  на другую вкладку во время ответа, он всё равно допишется, и вы увидите его, вернувшись. Во время
  генерации кнопка отправки превращается в **кнопку-квадрат «Остановить»** — она прерывает запрос к
  ИИ (уже полученный текст сохраняется).
- 📎 **Контекст сессии (по желанию).** Кнопка **«Контекст»** под полем ввода прикладывает к
  вопросу то, что видит терминал. По умолчанию это **выделение** (если что-то выделено) или
  **последние строки** вывода. Стрелка ▴ рядом с кнопкой открывает меню, где для **этого чата**
  можно добавить уровни: **весь буфер**, **запись сессии**, **метаданные хоста** (ОС/hostname/ядро) —
  выбор запоминается по вкладке. В **Настройки → ИИ-ассистент** задаются лишь значения по умолчанию
  для новых чатов. Контекст не прикладывается, пока вы не нажмёте «Контекст».
- 🔒 **Приватность.** Весь трафик к ИИ идёт через бэкенд **только** на указанный вами эндпоинт
  (зашитых облаков нет); приложение остаётся офлайн, пока ИИ выключен. Перед отправкой контекста
  секреты **маскируются** (`KEY=значение`, токены `Bearer`/`Authorization`, пароли в URL,
  AWS-ключи, приватные PEM-ключи), а затем показывается **окно согласия**: «отправить N строк на
  `<эндпоинт>`» с предпросмотром уже замаскированного текста — отправка только после явного
  подтверждения (и для локальных эндпоинтов тоже).
- ▶️ **Исполнение команд.** Когда ИИ предлагает команду в блоке ```bash, под блоком появляются
  кнопки **«Копировать»** и **«Выполнить»** (команда уходит в активный терминал). Поведение
  задаётся в **Настройки → ИИ-ассистент → Исполнение команд**: **«Только предлагать»** (кнопки
  «Выполнить» нет, есть «Копировать»), **«Подтверждать каждую»** (по умолчанию — команда
  выполняется по клику) и диалоговые режимы **«Диалог с подтверждением»** / **«Диалог»**
  (агент-цикл выполнить→прочитать вывод→следующий шаг; только не-прод). **Диалог никогда не
  работает на серверах с тегом `prod`/`production`** — там остаётся ручное подтверждение.
  Выполненные ИИ команды **пишутся в запись сессии** как аудит (`[vterm] AI ran: …`). Эту настройку
  можно **переопределить для конкретного сервера** в форме сервера (поле «Исполнение команд ИИ»,
  «По умолчанию» = глобальная настройка; в ⓘ поля — краткое описание каждого режима).
- ⏸️ **Команды, требующие подтверждения.** В диалоговых режимах ассистент всё
  равно **останавливается и просит подтверждение** перед разрушительной командой. Встроенный
  список (`rm -rf`, `mkfs`, `dd of=`, `shutdown`/`reboot`, `curl | sh`, `base64 --decode`, `eval`,
  форк-бомба и т.д.) **всегда активен**. В **Настройки → ИИ-ассистент → Команды, требующие
  подтверждения** (сворачиваемый блок) можно **добавить свои подстроки** (например `terraform
  destroy`, `kubectl delete`) — совпадение без учёта регистра. Ваши паттерны **только дополняют**
  встроенный список и никогда его не ослабляют.
- 📋 **Генерация из записи (план и скрипты).** В библиотеке записей (**Сессии → Записи**) у каждой
  записи есть кнопка ✨ (видна при включённом ИИ) — меню из трёх пунктов:
  - **План-runbook** — пошаговый план (резюме, предусловия, нумерованные шаги с командами, проверки),
    открывается в отдельном окне (Markdown + «Копировать»);
  - **Скрипт shell (sh)** и **Плейбук Ansible** — генерируются из транскрипта и **открываются в
    редакторе** (подсветка + линт). На SSH-вкладке скрипт проверяется серверным линтером
    (**shellcheck**/**yamllint**) прямо по буферу.
  Во всех случаях транскрипт **маскируется** и проходит то же **окно согласия** перед отправкой.
  Скрипт открывается в редакторе активной вкладки, поэтому сначала откройте вкладку терминала.
  Тексты-инструкции всех генераторов правятся в **Настройки → ИИ-ассистент → Системные промты**.
- 🛡️ **Прод-защита.** В форме сервера есть флажок **«Запретить ИИ-ассистенту»** (рядом с
  «Автозаписью»). На сервере с этим флагом ИИ-ассистент **не получает контекст** сессии и **не
  выполняет команды** (кнопки «Контекст»/«Выполнить» отключены, авто-режим не работает); сверху
  чата показывается плашка-напоминание. Рекомендуется включать для продакшн-серверов.

## Доступность и горячие клавиши

vterm управляется с клавиатуры и предоставляет доступную семантику для скринридеров
(результат UX-ревизии Фазы 7). Модальные окна (мониторинг, библиотека записей, форма
сервера, папки, синхронизация) можно закрыть **крестиком** в правом верхнем углу, кликом
по затемнённому фону или клавишей `Esc`.

### Горячие клавиши

| Действие | Сочетание |
|----------|-----------|
| **Командная палитра** | `⌘K` / `Ctrl+K` |
| **Поиск по буферу терминала** | `⌘F` / `Ctrl+Shift+F` |
| Навигация по совпадениям поиска | `Enter` / `Shift+Enter` |
| **История команд (reverse-search)** | `Ctrl+R` |
| Копировать выделение | `⌘C` / `Ctrl+Shift+C` |
| Вставить | `⌘V` / `Ctrl+Shift+V` |
| Прерывание (SIGINT) | `Ctrl+C` |
| Масштаб шрифта консоли | жест «щипок» на тачпаде / `Ctrl+колесо` |
| Закрыть диалог / палитру | `Esc` |
| Переключение вкладок | `←` / `→` (по кругу), `Home` / `End` |
| Активировать вкладку под фокусом | `Enter` / `Space` |
| Подключиться к выбранному серверу | двойной клик по серверу |

### Командная палитра (⌘K)

`⌘K` / `Ctrl+K` открывает палитру с быстрым поиском по **серверам** (подключение),
**папкам** (добавить сервер в папку), **действиям** и **настройкам**. Навигация:
`↑` / `↓` — выбор, `Enter` — выполнить, `Esc` — закрыть.

### Доступность диалогов

Все модальные окна (форма сервера, ввод пароля **Connect**, создание/переименование
папки, диалоги подтверждения) построены на общем компоненте `Modal` и обеспечивают:

- **автофокус** первого поля при открытии;
- **фокус-трап** — `Tab` / `Shift+Tab` ходят по кругу внутри окна и не уходят на фон;
- **возврат фокуса** на элемент, открывший окно, после закрытия;
- закрытие по `Esc` и семантику `role="dialog"` / `aria-modal` / `aria-label`.

### Навигация по вкладкам терминалов

Ряд вкладок реализует ARIA-паттерн *tablist* с роуминг-фокусом: в общий порядок `Tab`
включена только активная вкладка, а `←` / `→` (с заворотом), `Home` / `End`
переключают вкладки; `Enter` / `Space` активируют вкладку под фокусом. Список серверов
слева — дерево (`role="tree"`).

### macOS: полный доступ с клавиатуры

Если в диалоге `Tab` перескакивает только между текстовыми полями и **не попадает на
кнопки**, включите системную опцию: **Системные настройки → Клавиатура → «Навигация с
помощью клавиатуры»** (Full Keyboard Access). Это ограничение macOS, а не приложения.
