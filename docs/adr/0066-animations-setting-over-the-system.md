# ADR 0066 — Анимации: настройка поверх системного «меньше движения»

**Статус:** принято (готовится). Дополняет правило движения (DESIGN «Движение», INVARIANTS «Движение —
только через motion.ts»): уважение к системной настройке остаётся поведением по умолчанию.

## Контекст

С фазы 42 каждое движение спрашивало систему: переходы Svelte — через `motion()`, счёт чисел и
сдвиг графиков мониторинга — через `motionMs(…, prefersReducedMotion())`, CSS — глобальным
`@media (prefers-reduced-motion: reduce)` в app.css. Система сказала «меньше движения» — длительность
ноль, значение встаёт сразу.

На Windows графики мониторинга шли рывками, а числа менялись в один кадр — на той же сборке, где на
macOS они досчитывали. Причина — не частота кадров (тогда числа досчитывали бы рывками, а не
вставали сразу), а ответ системы: WebView2 сообщает `prefers-reduced-motion: reduce`, когда в Windows
выключены «Эффекты анимации» (они же «Анимация элементов управления внутри окон» в параметрах
быстродействия). Их выключают не только те, кто просил покоя: виртуальная машина, удалённый рабочий
стол, «Наилучшее быстродействие». Пользователь видел приложение без движения и не знал почему —
переключатель лежал в настройках ОС, где анимации приложения никто не ищет.

Как это делают другие:

| Продукт | Что даёт |
|---|---|
| VS Code | `workbench.reduceMotion`: `auto` (как в системе) / `on` / `off` |
| Discord | «Уменьшение движения» с флажком «Синхронизировать с компьютером» |
| Windows Terminal | `disableAnimations` — своё, системный ответ не читает |
| Telegram Desktop | «Анимации интерфейса» — вкл/выкл |

## Решение

1. **Настройка «Анимации» — «Как в системе» (по умолчанию), «Всегда», «Выключены»**
   (`settings.animations`, [motion.ts](../../src/lib/ui/motion.ts) `ANIMATION_MODES`). Решение одно —
   `motionReduced(выбор, ответ системы)`: «Выключены» — всегда покой, «Всегда» — движение при любом
   ответе, «Как в системе» — как скажет система.
2. **Решение живёт на `<html>`, и спрашивает его один модуль.** Выбор — `data-animations`, решение —
   `data-motion="reduce"`. Стор настроек ставит оба при каждом изменении и при переключении системы
   (`watchMotion` слушает медиазапрос), первый кадр — скрипт в app.html из `localStorage`
   (`vterm.animations`), как масштаб интерфейса. Код спрашивает `reducedMotion()` — выбор с документа
   и ответ системы на момент вопроса; CSS пишет `:root[data-motion="reduce"]`, а не медиазапрос.
   Систему спрашивают только motion.ts и app.html — гейт `motion.guard`.
3. **Почему так, видно.** Под настройкой, когда выбор системный, а система просит покоя, — строка
   «Система просит меньше движения — анимации выключены». Главное окно пишет то же событием
   диагностики `reduced-motion` при запуске и при переключении системы: «нет анимаций на этой
   машине» находит ответ в журнале.

## Альтернативы

- **Всегда слушаться систему (как было).** Честно по отношению к доступности, но приложение
  неотличимо от сломанного там, где покой включили не ради себя, и сделать с этим внутри vterm нельзя.
- **Не слушать систему вовсе.** Отнимает у человека с вестибулярной чувствительностью то, что он
  выставил для всех программ сразу.
- **Смягчать вместо выключать** (вместо счёта — смена числа наплывом, как советует Apple HIG). Решает
  вопрос вкуса, а не «почему всё стоит»: на машине, где покой включила ВМ, оставалось бы то же
  непонятное поведение. Можно добавить позже как вид режима «Как в системе».

## Последствия

- Компонентное правило «без движения» пишется как `:global(:root[data-motion="reduce"]) .x`; три
  прежних (`LogTail`, `Terminal`, `GitPanel`) переписаны.
- `prefersReducedMotion()` стал `reducedMotion()`: он больше не «что предпочитает система», а «что
  решено». Тесты, подменяющие `matchMedia`, работают как раньше — без выбора на документе решает
  система.
- «Всегда» включает движение и там, где покой просил сам человек, — это его выбор в настройках vterm,
  по умолчанию его нет.
