# ADR 0072 — Библиотека сценариев: всё в «Моих», плейбуки рядом с рецептами

**Статус:** принято (готовится). Меняет решения 3А и 9А [ADR 0071](0071-scenarios.md) там, где они
говорят о встроенной библиотеке и о том, что библиотека — только `.sh`.

## Контекст

Владелец поработал с панелью «Сценарии» из ADR 0071 и сделал два замечания:

- встроенные рецепты нельзя изменить. Нужно слить их в «Мои», чтобы редактировать можно было любой;
- рецепты — сплошь `.sh`, а конфигурация Ansible пишется в YAML. Почему плейбуков не видно?

Почему их не было видно:

- библиотека читала только `*.sh`, файлы `.yml` в «Моих» и в папках-источниках пропускались молча;
- Ansible жил отдельно, как проект по папке. Группа «Проекты» появлялась только после булавки в
  панели файлов;
- одиночный плейбук без инвентаря и ролей не узнавался нигде;
- встроенных плейбуков не было.

Как это сделано у других:

- **AWX, Semaphore** — шаблон — это файл плейбука из репозитория плюс инвентарь; встроенного нет,
  всё — файлы пользователя.
- **Rundeck** — шаг «Ansible playbook»: файл или вставленный YAML.
- **Ansible для VS Code** — ПКМ по `.yml` → «Запустить плейбук».
- **Termius, XPipe** — только shell-сниппеты; стартовые примеры — обычные записи, их правят и удаляют.
- **JetBrains (live templates), сниппеты VS Code** — встроенное правится поверх оригинала, есть
  «Сбросить к исходному».
- **Сам vterm** — промпты ИИ (ADR 0006): засеваются один раз, дальше это текст пользователя.

Владелец взял все рекомендованные варианты по рендеру (решения 1А–7А ниже).

## Решение

**Встроенные становятся «Моими» (1А) — засев один раз.** Рецепты (`builtin/*.sh`) и примеры
плейбуков (`builtin/*.yml`) лежат в сборке и при первом чтении библиотеки записываются в папку
`scripts` обычными файлами (`seedPlan`). Дальше это файлы пользователя: правка, переименование,
удаление, бэкап. Группы «Встроенные» нет. Приложение помнит, что записало
(`settings.scenarioSeeded`: файл → отпечаток текста и язык), поэтому удалённый файл не возвращается,
а файл из новой сборки записывается один раз. Имя, которое к приходу сборки уже занято файлом
пользователя, — его файл, и приложение его не трогает. Нетронутая копия английского текста
(«Копировать в мои» старой версии) считается файлом приложения и записывается заново. Пункт «+ →
Вернуть встроенные» дописывает недостающие и не трогает существующие (`restorePlan`). Сброс
настроек записи не стирает: файлы в «Моих» его переживают.
Отвергнуто: наложение «встроенное + правка поверх + Сбросить» (JetBrains) — пока файл не правили,
его нет на диске, и в свой git его не положить.

**Обновления (2А).** Файл, текст которого совпадает с записанным (по отпечатку `textHash`),
обновляется вместе со сборкой, на языке, на котором был записан. Изменённый, переименованный или
удалённый — никогда.

**Язык шапки (3А)** — язык интерфейса в момент записи. Шапка собирается из тех же ключей
`scenarios.builtin.<имя>.*` (имя, описание, подписи и подсказки параметров); у плейбуков —
`scenarios.starter.<имя>.*` (комментарий сверху и имя play). Код не меняется, имена задач —
английские, как вывод рецептов. Смена языка позже файл не переписывает. Показ через `t()` по id
ушёл: список называет рецепт по его шапке, плейбук — по первому play.

**Плейбуки в библиотеке (4А).** Библиотека читает `*.sh`, `*.yml` и `*.yaml` в «Моих» и в
папках-источниках (`LIBRARY_EXTENSIONS`). Плейбук — YAML, документ которого — список play
(`readPlaybook`); YAML с ошибкой синтаксиса показан с причиной, а не пропущен. Другой YAML
(переменные, инвентарь, compose) не показан, но посчитан. YAML папки-источника, которая сама —
проект Ansible, принадлежит проекту. Всё многофайловое (роли, `group_vars`) остаётся проектами.
Описание плейбука — комментарий у него сверху. Новый плейбук — «+ → Новый плейбук…»; импорт берёт
и `.yml`.

**Где запускается плейбук (5А).** «Где запускать» — этот компьютер или сервер каталога; выбор
запоминается (`settings.playbookNode`). «Пробный…» и «Выполнить…» открывают вид плейбука — тот же
`ProjectView` в режиме библиотеки (`EditorDoc.project.library`) — рядом с терминалом этого места,
после подключения, и в нём окно запуска. Серверы — только из каталога (временный инвентарь ADR
0071), инвентаря у одиночного плейбука нет. Здесь плейбук запускается в своей папке
(`cd <папка> && … ansible-playbook файл`). На сервере его текст кладётся во временную папку прогона
вместе со сборщиком событий (`carriedName`), запускается оттуда и удаляется с папкой. Файлы рядом с
ним не едут, и так и сказано. Нет Ansible на узле (или Windows, где он сам не работает) — вид
говорит об этом и предлагает сервер каталога. Прогон — тот же вид «задачи × хосты», первым —
`--check --diff`, прод — красным.
Отвергнуто: только этот компьютер — на Windows плейбук бы не запускался вовсе.

**Стартовые плейбуки (6А)** — три примера рядом с рецептами: Docker, обновление пакетов,
пользователь с ключом (`vars_prompt` — Ansible спросит имя и ключ сам). Только модули
`ansible.builtin`: коллекций они не требуют.
Отвергнуто: плейбук-версии всех десяти — двойная поддержка одного и того же.

**Проекты на виду (7А).** Группа «Проекты» видна всегда, пустая — с подсказкой. «+ → Добавить
папку проекта…» берёт папку этого компьютера и закрепляет её, если это проект (`projectSigns`).
Папка-источник и её подпапки (один уровень, без скрытых, `MAX_FOLDERS_PER_SOURCE`) перечисляются при
чтении библиотеки. Найденные проекты стоят в группе с пометкой «найден в …», пока папку читают, и их
можно закрепить. Проект из панели открывается после подключения вкладки — раньше обзор успевал
прочитать неподключённую сессию.

## Не взято

- **Форма переменных плейбука (`-e`)** — значения в командной строке видны в `ps` и в записи;
  `vars_prompt` спрашивает Ansible в терминале.
- **Поиск WSL на Windows** — Ansible в WSL видит пути Windows иначе; честно сказано «здесь не
  работает», выбор — сервер.
- **Плейбук с файлами рядом на сервере** (`templates/`, `files/`) — это проект, его место — папка.

## Последствия

- Rust: `scenarios.rs` — библиотека читает `.sh`/`.yml`/`.yaml` (`is_library_name`,
  `library_file_name`), перечисляет папки источников (`SourceFolder`); бэкап `scripts/` берёт и
  плейбуки.
- Фронт: `recipelib.ts` — `LibraryItem` (рецепт или плейбук), `libraryItems`, `foundProjects`,
  засев (`SHIPPED_FILES`, `shippedIn`, `seedPlan`, `restorePlan`, `textHash`); `bookmarks.ts` —
  `SeedState`/`sanitizeSeeded`; `recipe.ts` — `headerValue`, `playbookFileName`, `playbookTemplate`;
  `ansibleargv.ts` — `carriedName`; компонент `PlaybookDetail`; `ProjectView` и `AnsibleRunDialog`
  в режиме библиотеки; стор — `restoreShipped`, `loadLibraryPlaybook`, `projectKindOf`; страница —
  `openLibraryPlaybook`, `waitConnected`. Настройки `scenarioSeeded`, `playbookNode`.
- Гейт `scenarios.guard`: файл «Моих» перезаписывает только план засева.
