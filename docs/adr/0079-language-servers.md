# ADR 0079 — Языковые серверы там, где лежит проект

**Статус:** принято (готовится).

## Контекст

Дополнение по смыслу, подсказка по наведению, переход к определению, диагностика компилятора — это
языковые серверы (LSP). VS Code Remote-SSH, JetBrains Gateway и Zed ставят на сервер своего агента.
У vterm нет агента, но есть SSH-сессия и программы пользователя на сервере — тот же путь, что у
форматтеров и линтеров.

## Решение

**1. Сервер пользователя на хосте файла.** Для SFTP-файла — на сервере, через один долгоживущий
exec-канал SSH самого vterm (`cd корень && exec программа`); для локального файла — дочерний процесс
на этом компьютере. Сокетов у приложения не появляется (гейт `app_originated_sockets_…`), канал
открывается через `answered`.

**2. Каталог, а не argv** (`lsp.rs`, `SERVERS`): окно называет сервер по id, программу и аргументы
знает бэкенд. basedpyright → pyright → pylsp, rust-analyzer, gopls, terraform-ls, yaml-language-server,
ansible-language-server, bash-language-server, typescript-language-server, docker-langserver,
helm_ls, clangd. Первый установленный для языка — тот, что запускается; нет ни одного — «Установить…».

**3. Корень проекта** — ближняя папка с маркером языка (`Cargo.toml` — самый внешний: рабочее
пространство, `go.mod`, `pyproject.toml`, `package.json`…), до 8 уровней вверх; нет — папка файла.

**4. Жизнь сервера.** Один на вкладку, папку и сервер, общий для всех её редакторов (`stores/lsp`);
останавливается с последним редактором, с вкладкой (`forgetLsp` в `closeTabFully`) и с сессией
(`end_session` — бэкенд). Сам сервер не запускается: по кнопке в строке состояния или «запускать сам
на этом сервере» (`settings.editor.lspAuto`). На проде — только после вопроса: сервер читает весь проект,
ест память, rust-analyzer собирает проект и выполняет build-скрипты.

**5. Транспорт.** JSON-RPC кадрами `Content-Length` (`Framer`, кадр больше 32 МБ останавливает сервер),
сообщения — событием `lsp://msg/{id}`, конец — `lsp://closed/{id}`, отправка — `lsp_send`. Клиент —
`@codemirror/lsp-client`, грузится при первом запуске.

**6. Недоверенный вывод.** Markdown подсказок клиент превращает в HTML; сервер — программа на хосте,
которым мы не управляем, а окно умеет `invoke()`. HTML проходит `sanitizeLspHtml`: текстовые теги и
классы подсветки, без ссылок, картинок и атрибутов; `script`/`svg`/`iframe` — с содержимым.
`window/logMessage` никуда не идёт, `window/showMessage` — подсказкой у значка.

**7. Диагностика** — старт (сервер, корень), остановка и длительность, самостоятельный конец —
предупреждением; сообщения сервера и содержимое файлов не пишутся.

## Отвергнуто

- **Свой агент на сервере** — установка чужого кода на сервер пользователя.
- **Сервер с автозапуском по умолчанию** — неожиданная нагрузка на прод.
- **Проброс порта к серверу** — сокеты приложения и открытый порт на сервере.

## Последствия

- Команды `lsp_start`, `lsp_send`, `lsp_stop`, канал событий `lsp://`; `SshSession::exec_channel`.
- Принцип 6: «его» форматтеры и языковые серверы на хосте файла — названное исключение.
- Гейты: `a_language_server_is_named_never_given_as_a_command` (Rust), `editorwork.guard` (санитайзер),
  `tabteardown.guard` (`forgetLsp`).
