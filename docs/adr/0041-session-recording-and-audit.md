# ADR 0041 — Запись сессий и аудит: бэкенд пишет, GUI чистый, итог вместо сырья

**Статус:** принято. Записано в 1.25.4 из разборов, которые жили в INVARIANTS. Правила — в
[INVARIANTS](../INVARIANTS.md#логи-поиск-запись-сессий).

## Контекст

Запись сессии — документ о том, что делали на сервере, в том числе для прод-серверов, где она
включается сама. Действия, сделанные кнопками панелей (git, docker, kubectl, SFTP), иначе в неё
не попали бы. При этом запись не должна ни тормозить терминал, ни хранить секреты.

## Решения

**Запись ведёт бэкенд, по сессии.** `Recorder` живёт внутри `SshSession`/`LocalPty`: вывод пишет
ридер, ввод — `write_input`. Формат — asciicast v2 в `data_dir/recordings/*.cast`. Команды
чтения, удаления и меты ограничены каталогом записей (`is_recording_path`) — это граница: иначе
страница читала бы любой файл. Ввод после `password:` маскируется.

**Файловый I/O локальной записи — на своём потоке.** Синхронный `Recorder::output` (flush на
каждое событие) под общим мьютексом прямо на ридере тормозил слив ConPTY на Windows → пайп
включал back-pressure → shell вставал, терминал замирал, а тот же мьютекс держал пути ввода и
остановки. Теперь ридер и `write_input` только шлют байты в неблокирующий канал (`RecMsg`), а
`end_recording` ждёт ограниченный флаш, а не мьютекс поверх I/O.

**Пауза экономит диск, а не теряет данные.** Пока `paused`, вывод отбрасывается, а время паузы
вычитается из таймстемпов — иначе в воспроизведении дыры. Любой `input` возобновляет запись
первым делом, иначе вывод после нажатия потерялся бы. Пишутся вкладки на экране (по одной на
область), остальные на паузе; простой дольше `recordIdlePauseSecs` — у каждой свой.

**Автозапись прода — тем же путём, что REC.** Общий `startSessionRecording` с гардом
`isRecording` делает старт идемпотентным; финализация на `closed` — без диалога сохранения (он
только для ручного стопа); реконнект — новая запись.

**Мета — в заголовке asciicast.** `title` и свои `description`/`server`; `with_updated_meta`
переписывает только первую строку и сохраняет `server`, поэтому имя сервера переживает
переименование записи. Пост-стоп-диалог «Сохранить/Удалить» — исключение из «удаление только с
подтверждением»: он сам и есть явный выбор.

**Аудит — только в запись.** Мутирующий вызов драйвера с флагом `mirror` пишется блоком
`[тег] $ … / [тег] exit N`, в живой терминал не эмитится — GUI остаётся чистым. Чтения и поллинг
не мирроятся: они похоронили бы запись. Секреты не пишутся никогда. Аудит-факты редактора
(`[vterm] правка {path} (+N −M строк)`) идут через `annotate_recording` — видимым `o`-событием,
даже на паузе: событие намеренное и редкое.

**Сетевые утилиты пишут итог, а не сырьё.** В argv HTTP-клиента — значения заголовков
(`Authorization`) и тело запроса, в выводе — тело ответа и `Set-Cookie`; у проверки доступа —
нечитаемый протокол. Поэтому `probe_run`/`netcheck_run` в запись не пишут ничего, а строку и тело
блока собирает фронт из разобранного результата: поля сертификата, метод и URL с маской,
**имена** заголовков, размер тела, статус и тайминги; у проверки доступа — тот же отчёт, что
«Скопировать отчёт». `netprobe::audit_block` вычищает управляющие символы ответа сервера.
Провал записывается провалом (`exit ≠ 0`), а не тишиной.

**SFTP и переносы — сводкой.** Одиночная операция SFTP — строка (`save` — только размер, не
содержимое). Задание переноса — одна строка в запись каждой SSH-сессии, которой оно касается;
копия называет другую сторону, как `scp` (`copy '/etc/x' -> db-01:'/srv/x'`), несколько
объектов — счётом и перечнем до 50 строк. Имя вкладки очищено (`audit_label`): оно приходит из
WebView и не должно ни разбить строку, ни сойти за управляющую последовательность.
Синхронизация — одна запись на прогон с перечнем операций (кап 50 строк и хвост `… and N more`;
`exit 130` при остановке): построчный миррор похоронил бы запись, которую он же документирует.

## Последствия

- Новая мутирующая операция пишется в запись своим тегом; новая массовая — сводкой.
- Новый вход записи на локальной вкладке идёт через канал, а не инлайн под мьютексом.
- Локальная вкладка файловые операции в запись не пишет — у неё нет SSH-сессии.
