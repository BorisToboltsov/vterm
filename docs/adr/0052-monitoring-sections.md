# ADR 0052 — Страница мониторинга разделами: обзор проблем, честные графики, данные по требованию

**Статус:** принято (Готовится, после 1.32).

## Контекст

Страница мониторинга росла блоками: «Система» сверху, под ней сетка карточек CPU, памяти, дисков,
load, сети, температуры и «Дополнительно». Все карточки одного веса, и ответа на вопрос, ради
которого её открывают, — всё ли в порядке и если нет, то где, — на ней не было: health-чипы
перечисляли блоки, а не то, что в них не так.

Графики врали о времени и масштабе:

- **«Гармошка».** Точка стояла на `i / (n − 1)` ширины: пока история набиралась (первые три
  минуты), каждый опрос сжимал всю линию, потом она прыгала влево на шаг.
- **Шкала без подписи.** У CPU и памяти потолка не было — шкала шла от максимума данных: 20 → 35 %
  занимали всю высоту, а уход пика из окна за кадр «раздувал» график. Сеть — так же.
- **Скачки.** Числа, столбики ядер, полосы разделов и составные полосы менялись за кадр; сегмент
  с нулём пропадал из DOM, и соседи дёргались. Цвет TCP-состояния зависел от места в списке.

И часть показаний была неправдой: `dmesg` без прав давал пустой вход, `grep -c` считал по нему
«0 OOM» — значение, которого никто не измерял.

## Решение

**Разделы.** Слева навигация — обзор и девять разделов (CPU, память, диски, сеть, температура,
процессы, контейнеры, GPU, система), у каждого короткое значение и точка уровня; справа раздел.
Раздела для того, чего у хоста нет (GPU, контейнеры), нет. Температура остаётся и без датчиков:
там страница объясняет, почему читать нечего.

**Один список проблем** (`monproblems.ts`). Каждое правило — проблема с уровнем и разделом;
уровень раздела — худшая из его проблем, вердикт — худшая из всех. Числовые правила читают пороги
пользователя, факты (упавший юнит, OOM, вердикт SMART) имеют свой уровень. Счётчик, растущий с
загрузки (ошибки интерфейса, троттлинг), — проблема, только если вырос, пока страница открыта:
тысяча сбросов полугодовой давности — история, а не проблема. Обзор показывает список первым, у
строки — переход в раздел и вопрос ИИ именно про неё; снимок для ИИ несёт проблемы по-английски.

**Честные графики** (`chartgeom.ts`). Точка — слот от правого края окна; край идёт к новому
замеру, и линия вдвигается, а не сжимается. Проценты — против 0–100, скорости — против круглого
потолка (1/2/5 × 10ⁿ), который подписан и к которому шкала идёт плавно. Кривая монотонная
(Fritsch–Carlson): между двумя замерами она не выходит за них, пика, которого не было, не
рисует. Не прочитанное — разрыв линии. Окно — 121 замер, 10 минут при опросе раз в 5 с; история
— одна (`monhistory.ts`), по каждому потоку, интерфейсу, устройству, датчику и процессу из тех же
зондов, без новых запросов.

**Плавность — общая с заставкой** (`ui/tween.ts`): число досчитывает (`RING_MS`), край графика
идёт к замеру (`LINE_MS`), шкала — к потолку (`SCALE_MS`); кадры — только пока что-то движется.
Полосы — CSS `transform`, их гасит общее правило reduced motion; сегмент не исчезает, а сжимается.

**Новые данные — сырые показания, производные в Rust.** Имена упавших юнитов, подкачка
(`/proc/vmstat` × размер страницы), частота и троттлинг CPU, слушающие сокеты с владельцем
(чужие видны только root), занятость и задержка устройств (`/proc/diskstats`), жертвы OOM из
журнала ядра или `dmesg` (не прочитан — `null`), износ SSD и переназначенные секторы, мощность,
частоты и процессы GPU, лимиты контейнеров (`HostConfig`: без лимита доли нет), последние входы.
GPU и контейнеры меняются по секундам — их опрашивает `fetch_live_extras`, только пока открыт их
раздел; процесс читается по клику (`fetch_process_detail`) и никогда в цикле опроса. Обе команды
зовёт один модуль (`vterm/owned-imports`).

**Все процессы — только пока открыт их раздел.** Детальный зонд читает каждый процесс одним `ps` и
тики CPU из `/proc/<pid>/stat`; текущий CPU% — прирост тиков между опросами в Rust. Прежняя шестёрка
брала `%cpu` из `ps`, а на Linux это среднее за жизнь процесса: сервис, работающий неделями, висел
в топе со своим средним, а занятый сейчас процесс мог в него не попасть. Шестёрка теперь из того же
снимка; на страницу весь список (до 3000) уходит, только пока открыт раздел. Хост без `/proc` (BSD,
macOS) отдаёт свой `ps`, где `%cpu` — недавнее среднее. История пишется для 40 самых занятых по CPU и
по памяти: тысячи серий на опрос были бы одним копированием. Список — модель ADR 0050 (поле, фасеты,
порядок), дерево по родителю держит родителей найденного бледными, строки — окно `windowRange`.

**Действия — только чтение и в терминале.** «`systemctl --failed`», список обновлений менеджера,
`top -p` печатаются в терминал вкладки под её оболочку (`renderArgv`); пользователь видит, что
запустилось. Завершать процессы со страницы нельзя.

## Альтернативы

- **Плитки KPI одной страницей с перекрестием.** Меньше переделки, но не масштабируется под
  разделы GPU/Docker/SMART и снова кладёт всё в один скролл.
- **Сглаживание линии сплайном.** Красиво, но сплайн вылетает за замеры и рисует пики, которых
  не было.
- **Доля контейнера от `docker stats`.** Без лимита она считается от памяти хоста — это не
  потолок; доля только при заданном лимите.
- **Кнопка «Завершить процесс».** Разрушительное действие ради удобства; терминал рядом.

## Последствия

- Уровень блока больше не считают функции `*Health` — их место заняли правила `problems`; в
  `monhealth.ts` остались общие примитивы (`worstLevel`, `loadCoreLevel`, `sensorLevel`, `loadHealth`).
- Новый показатель с порогом = ключ порога + дефолт + поле настроек + правило в `problems`.
- `sudo`-история входов не читается: в журнале команд бывают секреты, а читать его можно только с
  правами. Командная строка процесса уходит в ИИ только через обычные маскирование и согласие.
