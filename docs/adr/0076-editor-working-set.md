# ADR 0076 — Редактор как рабочее место: основа, слой DevOps, форматирование

**Статус:** принято (готовится).

## Контекст

Редактор vterm умел подсветку около 75 языков, линт на сервере, сниппеты, превью Markdown,
схему пайплайна и аккуратное сохранение (кодировка, CRLF, хэш, diff, `.bak`, sudo). Остальное было
минимальным, и часть пробелов была дефектами:

- Tab и Enter всегда ставили два пробела: в Python-файле с отступом 4 новый блок получал 2, Makefile —
  пробелы вместо табов. Отступ файла не определялся, `.editorconfig` не читался.
- `⌘D` был назначен, но несколько выделений в состоянии были выключены — следующее вхождение не
  добавлялось.
- Кодировка и конец строки хранились, но нигде не показывались; сворачивания, автодополнения,
  автозакрытия скобок не было; перенос строк был всегда включён.

Как у других: в Termius своего редактора нет; MobaTextEditor и WinSCP — подсветка и поиск; VS Code
Remote-SSH, JetBrains Gateway и Zed — уровень IDE: сворачивание, курсоры, строка состояния,
форматирование, символы файла. Владелец посмотрел рендеры и взял всё: основу, слой DevOps и
форматирование.

## Решение

**1. Основа — модули CodeMirror, подключённые в `editorbase.ts`.** Сворачивание (по дереву грамматики,
а у StreamLanguage-языков — по отступам, `foldsByIndent`), несколько курсоров (`allowMultipleSelections`,
`⌥`-выделение столбцом), автозакрытие скобок, автодополнение словами файла и сниппетами языка (через
`languageData`, чтобы языковой сервер добавлял свои, а не заменял), направляющие отступов (классы на
ширину уровня — инлайн-стиль срезал бы CSP упакованной сборки), подсветка хвостовых пробелов,
переключатель переноса. Каждая часть — в своём `Compartment`, переключатели живые.

**2. Отступ файла — `.editorconfig`, затем сам файл, затем язык** (`indent.ts`, `editorconfig.ts`).
`.editorconfig` читаются вверх от папки файла до `root = true` (до 12 уровней) через соединение файла;
глобы — по спецификации (`*`, `**`, `?`, `[..]`, `{a,b}`, `{1..3}`), ближний файл перекрывает дальний.
Файл говорит шаг (2/3/4/8 или табы), а не глубину. Язык: Python, Rust, Java, C — 4; Go и Makefile — табы.

**3. Строка состояния** (`EditorStatusBar`): строка и столбец, число выделений, отступ и откуда он
(меню: другой шаг, «перевести отступы файла»), кодировка и концы строк (сохраняются при записи),
перенос, миникарта, язык. Язык выбирается вручную и запоминается для пути (`settings.editor.langOverrides`,
до 300 записей); «Вернуть определённый» убирает выбор.

**4. Слой DevOps.**
- Jinja2 поверх языка: `{{ }}`, `{% %}`, `{# #}` — разметкой поверх подсветки (`jinja.ts`), в Ansible, в
  `*.j2` (`nginx.conf.j2` — nginx с Jinja) и в `templates/` чарта Helm.
- Ansible Vault: зашифрованный файл — плашка вместо попытки читать hex, кнопки печатают
  `ansible-vault view|edit` в терминал соединения; пароль vault приложение не держит.
- Путь в документе над кодом (`breadcrumbs`) и список символов `⌘⇧O` (`outline.ts`): плеи и задачи,
  сервисы Compose, задания Actions, документы k8s, ресурсы Terraform, функции и типы, заголовки,
  блоки nginx, стадии Dockerfile, цели Makefile — по форме текста, без грамматики.
- Распознавание: shebang, vim/emacs-modeline, `.j2`, `.hcl`, `Jenkinsfile` (`editorLangFromContent`).

**5. Форматирование — инструмент проекта там, где лежит файл.** Буфер уходит на stdin, ответ — со
stdout, запуск — в папке файла, чтобы применились `pyproject.toml`, `rustfmt.toml`, `.prettierrc`,
`.yamlfmt`. На SFTP-файле — на сервере, на локальном — на этом компьютере (`format_run` с сессией или
без). Цепочки по языку, первый установленный побеждает (`format.ts`): ruff → black, terraform → tofu,
rustfmt, gofmt, shfmt, yamlfmt → prettier, prettier, xmllint, clang-format; в конце любой цепочки —
встроенный «только пробелы». JSON — встроенный, значения и порядок ключей как написаны (`JSON.parse`
переставил бы числовые ключи и округлил бы большие числа). Результат ложится одной правкой
(`minimalChange`), одной отменой; изменённые строки подсвечиваются на мгновение; если буфер поменялся,
пока работал инструмент, ответ отбрасывается. Нет инструмента — «Установить…» тем же установщиком.
«Форматировать при сохранении» — настройка, по умолчанию выключена; работает до diff перед записью,
отсутствие инструмента запись не останавливает. `ansible-lint --fix` меняет больше раскладки (FQCN,
`yes` → `true`, free-form) — это отдельная команда «Исправить», а не форматтер: он правит копию
`.vterm-fix-*` рядом с файлом, ответ — содержимое копии, копия удаляется.

**6. Политика argv в Rust** (`format::check_args`): только формы, которые строит `format.ts` — нет
другой программы, нет опции, читающей или пишущей свой файл (`-w`, `--write`, `--config`); имя файла —
одна компонента, путь prettier — абсолютный, папка — абсолютная.

**7. Миникарта** — `@replit/codemirror-minimap`, грузится при первом включении, по умолчанию выключена.

## Отвергнуто

- **WASM-форматтеры в окне.** Для rustfmt и `terraform fmt` их нет, нужен `'wasm-unsafe-eval'` в CSP, а
  версия расходится с проектом.
- **Форматирование `ansible-lint --fix` по умолчанию** — меняет смысл, а не только вид.
- **Отступ из настроек приложения** — у файла свой, и он важнее.

## Последствия

- Новые модули `editor/`: `editorbase.ts`, `indent.ts`, `editorconfig.ts`, `jinja.ts`, `vault.ts`,
  `outline.ts`, `format.ts`, `flash.ts`, `minimap.ts`, `editorprefs.ts`; компоненты `EditorStatusBar`,
  `OutlinePalette`. Команда `format_run`, модуль `format.rs`; у `exec::Local` появилась папка запуска.
- Гейт `editorwork.guard`: форматирование — одна правка на тексте, для которого сделано.
