# ADR 0009 — Честный интерфейс: заглушке предпочитается пустота

**Статус:** принято (Фазы 21 · 39 · 40 · 43 · 44.1).

## Контекст

Правило выведено не из вкуса, а из повторяющегося класса дефектов. Инструмент отладки
показывает данные о чужой системе, и правдоподобное число там опаснее прочерка: его нельзя
отличить от измеренного, и увидят его ровно в тот момент, когда что-то сломалось.

Случаи, каждый из которых чинился отдельно:

- фейковые подстадии подключения (нарисованный прогресс вместо реальных событий);
- load average на Windows из прочерков — такого понятия там нет вовсе;
- шкала «доля от лимита» у контейнера без лимита (проценты `docker stats` считаются от памяти
  хоста и выглядят неотличимо);
- выдуманный ноль в счётчике токенов, о котором эндпоинт промолчал;
- «данные спасены» вместо «данные всё ещё под угрозой» при неудавшемся карантине;
- значок битой картинки вместо «недостижима» — утверждение «файл повреждён» там, где файл
  просто не грузился.

## Решение

- Неизвестное — `None`, «—» или явная пометка. Правдоподобная заглушка запрещена.
- **«Нет данных» и «здесь невозможно» — разные сообщения.** Первое значит «ещё не опрошено»,
  второе — «на этом хосте не существует»; гейт по данным, а не по ОС приложения
  (`hostcaps.ts` поверх `Metrics.os`, то есть ОС **хоста сессии**).
- Показатель, у которого нет честного источника, не рисуется вовсе — вместо приблизительного.
- Потолок берётся из спека (`resources.limits`, `HostConfig`), а не выводится из процентов.
- Стадии и прогресс — только из реальных событий бэкенда.

## Последствия

- Часть интерфейса выглядит «беднее»: на Windows нет карточки load average, у безлимитного
  контейнера нет шкалы, у части ответов ИИ нет счётчика токенов. Это правильный вид.
- Новый «недоступный здесь» показатель добавляется предикатом с тестом, а не проверкой ОС по
  месту в компоненте.
- Честное разбиение стадий иногда стоит работы (для SOCKS5 пришлось перейти на socket-вариант
  `tokio-socks`, чтобы отдельно эмитить connect и негоциацию) — эта цена принимается.
