# ADR 0003 — Состояние UI в runes-сторах, чистая логика в `.ts`

**Статус:** принято (Фаза 5.8 + 6.3).

## Контекст

`+page.svelte` разросся (~1500 строк): держал состояние панелей, вкладок, дерева,
драг-н-дропа и кучу модалок. Это мешало тестированию и переиспользованию.

## Решение

- **Чистую логику** вынести в `.ts`-модули и тестировать без DOM: `tree.ts`
  (дерево/фильтр/drop), `format.ts` (форматтеры статус-бара), `util.ts`
  (`debounce`, `isHidden`), `actions/drag.ts` (pointer-drag хелперы + экшен).
- **Состояние UI** — в runes-сторах `src/lib/stores/*.svelte.ts` (по образцу
  `settings.svelte.ts`): `layout` (ширины/сворачивание панелей + persist) и
  `tabs` (список вкладок, активная, операции, чистые `statusLabel`/`dotClass`).
- **Компоненты** декомпозировать: `TopBar`, `ServerTree` и переиспользуемые
  примитивы `Modal`, `ConfirmDialog`, `Icon` (реестр SVG вместо эмодзи).

## Последствия

- `+page.svelte` сократился примерно вдвое и стал оркестратором.
- Логика дерева/вкладок/layout покрыта юнит-тестами; компоненты — компонентными.
- Новое состояние добавляется как стор; новые иконки — ключ в `icons.ts`.
