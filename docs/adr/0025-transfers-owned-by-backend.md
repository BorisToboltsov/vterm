# ADR 0025 — Перенос файлов — задание бэкенда: окно его показывает, а не ждёт

**Статус:** принято (v1.12.0). Закрывает часть долга из
[ADR 0017](0017-detached-windows.md): «вкладка с переносом файла ждёт его конца, потому что
ожидание живёт в памяти исходного окна».

## Контекст

До 1.12 перенос файла принадлежал окну, которое его запустило:

- **Пачка загрузки была циклом в JavaScript панели** — файл за файлом через
  `await sftpUpload(…)`. Панель файлов пересоздаётся при каждой смене вкладки терминала, и цикл
  доживал в замыкании уничтоженного компонента.
- **Чей это перенос, знало только окно.** Событие прогресса не называло сессию; принадлежность
  держала карта в сторе окна, а само событие шло окну, вызвавшему команду (`WindowSink`).
- **Поэтому вкладку с переносом нельзя было вынести в другое окно** (`detachBlocker`), а
  закрытие вкладки и вопрос о выходе считали переносы по памяти окна.

Следующая задача — копировать файл с одного сервера на другой — в эту схему не помещается
вовсе: у такого переноса две сессии, и их вкладки могут стоять в двух окнах. Окну-инициатору
пришлось бы знать о сессии, которой у него нет, а второе окно не знало бы, что его сессия
занята, и могло бы её закрыть.

Варианты:

1. **Оставить перенос окну и запретить больше.** Копия между сессиями — только пока обе вкладки
   в одном окне, и обе нельзя выносить. Запрет растёт с каждой новой возможностью.
2. **Передавать перенос вместе с вкладкой** — как терминал: придержать, снять, отпустить в
   принимающем окне. Поток байтов нельзя «снять» посреди файла; у копии между сессиями две
   вкладки, и уйти может любая.
3. **Перенос — задание бэкенда.** Окно просит о нём одной командой и ничего не ждёт; что
   происходит с заданием, бэкенд говорит окну, которое показывает вкладку сессии **в момент
   события**.

## Решение

Вариант 3. Реестр заданий — [transfers.rs](../../src-tauri/src/transfers.rs).

- **Одно задание — список файлов и папок с одной стороны на другую.** Сторона — сервер сессии
  (по её SFTP) или эта машина. Из одного цикла получаются четыре вида: загрузка, скачивание,
  копия между двумя серверами и локальная копия. Локальная вкладка — такая же сторона, как
  серверная, только её файлы здесь.
- **Команда `transfer_start` возвращается сразу**, с id задания; `transfer_list` отдаёт задания,
  которые окно показывает сейчас. Отдельной команды отмены нет: флаг задания лежит в общей
  карте отмен под его id, и его снимает тот же `sftp_cancel`, что останавливает прогон
  синхронизации.
- **Событие `sftp://job` идёт владельцу сессии на момент события** (`audience`): окну, которое
  показывает вкладку каждой сессии задания. Две сессии в двух окнах — слышат оба. Ни одна
  сессия не имеет вкладки — последнее слово получает окно, запустившее задание.
- **Окно — вид.** Стор переносов хранит то, что бэкенд последним сказал о заданиях сессий этого
  окна; он не запускает задания и не ведёт карту «чей перенос». Панель не держит цикла по
  файлам. Окно сперва слушает, потом спрашивает список — и при запуске, и приняв вкладку.
- **Вкладка уходит в другое окно с переносом в полёте.** Из `DetachState` поле о переносах
  убрано: заданию всё равно, какое окно показывает вкладку.
- **Конец сессии отменяет её задания** (`end_session` → `cancel_session`). Задание держит
  сессию открытой, пока не заметит флаг; временный файл на другой стороне убирает его же выход.
- **Копия между серверами идёт через этот процесс и только через него** (`relay_staged`):
  читается с одного сервера, пишется во временный сосед на другом, переименовывается поверх
  цели. На диск этой машины не попадает ни байта — под большой файл не нужно место, файл
  прод-сервера не остаётся на ноутбуке. Серверы могут не доставать друг до друга: каждый
  говорит только с приложением.
- **Новый файл на другом сервере получает биты прав источника**, как у `scp`: приватный ключ,
  скопированный с `0600`, не должен стать `0644`. Заменяемый файл сохраняет свои. Загрузка и
  скачивание ведут себя как раньше — новый файл получает права по умолчанию у назначения.
- **Один файл не останавливает остальные.** Задание идёт до конца, считает не дошедшие и
  называет первую причину. Имя из листинга, которое вывело бы путь за папку назначения,
  останавливает задание **до первой записи** — обход дерева ничего не пишет.
- **Один путь запуска** — `startTransfer` в [transferflow.ts](../../src/lib/transferflow.ts): у
  назначения спрашивают, какие имена заняты, пользователя — один раз на пачку, и право заменить
  получает только то, о чём спросили (правило 1.11.3 — теперь для всех видов переноса).
  Диалог вопроса — один на окно, вопросы встают в очередь.
- **Запись сессии получает одну строку на задание**, а не на файл: одиночный файл пишется как
  раньше (`put '…' -> '…'`, `get '…' -> '…'`), копия называет другую сторону по-`scp`-шному
  (`copy '/etc/x' -> db-01:'/srv/x'`). Имя вкладки идёт в запись очищенным.
- **Синхронизация в реестр не входит.** Её прогон — уже цикл в бэкенде, но ждёт его и
  отчитывается о нём окно; файлы прогона по-прежнему идут в `sftp://progress` окну, которое
  прогон запустило. Это следующий шаг того же долга.

## Последствия

- Строки переносов в панели — задания: у пачки одна строка с «какой файл из скольких» и общим
  числом байт, а не строка на файл. Прогресс папки считается в байтах, а не в файлах, — у неё
  появились скорость и оставшееся время.
- Папка назначения перечитывается один раз, когда бэкенд сказал, что задание кончилось, —
  чем бы оно ни кончилось: часть файлов могла дойти.
- Задания идут одновременно, файлы внутри задания — по одному. Строгой очереди на сессию нет.
- Команды `sftp_upload` и `sftp_download` убраны; у события `sftp://progress` больше нет
  признака папки. Их функции в `sftp.rs` остались для синхронизации.
- Имя, которое назвал один сервер, не доверяется и на другом сервере — не только на диске
  (`sftp::safe_child`).
- Вкладка с идущим сравнением, синхронизацией, ответом ИИ или сохранением файла по-прежнему
  ждёт: эта работа всё ещё в памяти окна.

## Что не сделано

- Перетаскивание файла мышью — на вкладку, в панель другой сессии, в другое окно (1.13) и на
  рабочий стол (1.14). В 1.12 копия между сессиями — из меню файла и из ⌘K.
- В меню «Копировать в сессию» — только сессии своего окна; две вкладки одного сервера
  предлагаются обе, под одним именем.
- Возобновления прерванного переноса нет, как и раньше.
- На настоящем приложении не запускалось: проверено тестами, живыми тестами против sshd в
  Docker и в браузерном превью с подставным бэкендом.
