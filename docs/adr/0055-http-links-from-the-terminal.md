# ADR 0055 — Ссылки `http` открываются, как `https`: opener пускает обе схемы

**Статус:** принято (v1.33.0).

## Контекст

С 1.20 ссылка из вывода терминала открывалась только по `https`: scope opener —
`https://*`, а `http`-ссылку окно предлагало лишь скопировать. Чаще всего такая ссылка — свой
dev-сервер (`http://localhost:5173`), страница статуса внутри сети, Grafana на внутреннем
адресе. Каждую приходилось копировать в браузер руками. Ссылки `http` из markdown (ответ ИИ,
превью `.md`) `mdLinks` отдавал opener'у, и тот молча отказывал.

Защита ссылок из вывода стоит не на схеме: что делает клик, решает `linkClick` — вопрос по
умолчанию, хост в нём крупно (punycode для нелатинского имени, `user@` отделён), ссылка,
текст которой называет другой сайт, спрашивает в любом режиме и не замолкает (ADR 0008,
инвариант «Ссылка из вывода открывается одним путём»).

## Решение

- **Scope opener — `https://*` и `http://*`, и ничего больше** (`capabilities/default.json`):
  ни `file:`, ни других схем, ни открытия путей. Держит гейт `tauri-security.guard`
  (`webOnly`, с живыми нарушениями).
- **`http`-ссылка из вывода открывается так же, как `https`**: по режиму «Ссылки в выводе», с
  той же проверкой обманчивого текста. В вопросе — пометка «без шифрования» (`LinkTarget.secure`).
  Окна «только скопировать» больше нет.
- Ссылки `http` из markdown начинают открываться тем же opener'ом — `safeUrl` и `mdLinks` их
  и раньше пускали.

## Почему не «http — всегда с вопросом»

Схема — свойство сайта, а не клика. Взломанный хост, который хочет увести на свой сайт,
напечатает `https`-ссылку так же легко; от подмены текста защищает `misleadingHost`, а не схема.
Без шифрования страницу могут прочитать или подменить по пути — это и говорит пометка, но
решение, доверять ли сети, — пользователя. Вопрос на каждую `http`-ссылку в режиме «Открывать
сразу» был бы лишним трением ровно там, где ссылок больше всего, — на своём dev-сервере.

## Последствия

- Браузер получает и незашифрованные адреса; что открывать — по-прежнему решает клик и режим.
- Инвариант «Ссылка из вывода…» и SECURITY обновлены; `link.copyTitle`/`link.httpOnlyCopy` сняты.
- Не сделано: URL с нелатинскими буквами в тексте вывода xterm ссылкой не распознаёт — это
  распознавание аддона, а не схема.
