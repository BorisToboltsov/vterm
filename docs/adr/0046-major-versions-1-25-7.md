# ADR 0046 — Мажорные версии 1.25.7: SvelteKit 3, vitest 5, russh 0.65; TypeScript 7 отложен

**Статус:** принято (1.25.7). Стек — в [ARCHITECTURE](../ARCHITECTURE.md#стек), остаточные
advisory — в [SECURITY](../../SECURITY.md).

## Контекст

Этап H рефакторинга 1.25 — мажорные версии, которые Dependabot приносит поштучно и которые
копились: `russh` 0.65 / `russh-sftp` 3, SvelteKit 3 (у Kit < 3 два low advisory), TypeScript 7,
vitest 5. Этап не добавляет возможностей: поведение приложения остаётся прежним, а то, что
меняют сами мажоры, либо возвращено к прежнему, либо записано здесь.

## Решение

**SvelteKit 3: конфигурация — в плагине Vite.** `svelte.config.js` Kit 3 не читает: адаптер
(`adapter-static` с фолбэком `index.html`) и `vitePreprocess` переданы `sveltekit()` в
[vite.config.js](../../vite.config.js). Vitest собирает компоненты без Kit, плагином
`svelte()`, и общего файла конфигурации у них больше нет — тот же препроцессор передан ему
явно. `tsconfig.json` наследует `$app/tsconfig` (его пишет `svelte-kit sync` в
`node_modules`) и сам называет `include` — `src` и `vite.config.js`, ровно то, что генерировал
Kit 2.

**`$lib` → `#lib/…` с расширением файла.** Алиас `$lib` Kit 3 не создаёт; его место занял
subpath import `"#lib/*": "./src/lib/*"` в `package.json`, который Vite, TypeScript и vitest
разрешают сами. Subpath import не дописывает расширение, поэтому импорт называет файл целиком:
`#lib/stores/tabs.svelte.ts`, `#lib/api/index.ts`. `$app/tsconfig` включает
`allowImportingTsExtensions`, так что это настоящее имя файла: его находит поиск, и резолвер
правила `vterm/layers` (`target()` в [lint/vterm.js](../../lint/vterm.js)) берёт путь как есть.
`#lib` пользуется только страница (`src/routes/`); внутри `src/lib` импорты относительные, как
и были.

**Опрос версии выключен.** Kit 3 по умолчанию раз в час запрашивает `_app/version.json`, чтобы
узнать о новом деплое (`version.pollInterval`). Бандл vterm зашит в бинарь и не меняется, пока
приложение работает, поэтому таймер выключен (`pollInterval: 0`) — как по умолчанию было в
Kit 2. Проверку при фокусе и смене видимости окна конфигурацией не выключить: это `fetch` того
же файла с origin приложения — встроенные ассеты Tauri, а не сеть (`connect-src 'self'`), и
ответ всегда совпадает с запущенной версией.

**vitest 5 — с новыми умолчаниями.** `clearMocks` теперь включён: история вызовов мока
чистится перед каждым тестом, набор от прежней не зависел. `coverage.include`/`exclude`
сопоставляются точнее; набор покрываемых файлов сверен с прогоном на vitest 4 — те же 270
файлов, проценты расходятся не больше чем на сотую.

**russh 0.65 и russh-sftp 3 — без правок кода.** Ломающее в russh 0.65 — серверный `Handler` и
снятый `async-trait`; vterm — клиент и не пользуется ни тем, ни другим. russh-sftp 3
конвейеризует чтение и запись (до 16 запросов в полёте), а его `read`/`write` теперь сами
закрывают файл; запись vterm идёт своим путём (`sftp::write_bytes`), и разговор с сервером
закрепляют живые тесты `live_sftp`, `live_exec`, `live_kbdint` — они зелёные.

**TypeScript 7 отложен.** TS 7 — компилятор на Go без JS API: пакет экспортирует только
`version` и `unstable/*`, API обещан в 7.1. На API TS 6 стоят все, кто проверяет типы в
vterm: `svelte-kit sync` (сверяет tsconfig через `ts.parseJsonConfigFileContent`), svelte-check
и svelte2tsx (peer `^6`), typescript-eslint (peer `<6.1`, на 7.0 отказывает прямым
сообщением). Проверено установкой `typescript@7.0.2`: `pnpm check` и `pnpm lint` падают.
Переход — когда эти инструменты примут TS 7.

## Последствия

- `svelte.config.js` удалён; `vite.config.js` — единственная конфигурация Kit.
- Override `cookie` `^0.7` снят из `pnpm-workspace.yaml`: он закрывал advisory `cookie` < 0.7 у
  Kit 2, а Kit 3 сам зависит от `cookie` 2 — override откатил бы его на API, которого он не знает.
- `svelte-kit sync` в `deep.yml` по-прежнему обязателен до тестов: без `$app/tsconfig`
  dep-оптимизатор vitest падает на старте («Tsconfig not found»).
- Low advisory `deepmerge` ≤ 4.3.1 (сборочная зависимость `vite-plugin-svelte`) остаётся:
  исправленной версии в npm нет.

## Отвергнутые варианты

- **`.js` в импортах `#lib`, как в примере гайда миграции.** Работает — TypeScript подменяет
  `.js` на `.ts`, — но имя в импорте не совпадает с файлом: `tabs.svelte.js` не находится
  поиском, а резолверу линтера пришлось бы угадывать настоящее имя.
- **Относительные пути со страницы (`../lib/…`)**, как внутри `src/lib`. Обошлись бы без
  расширений, но страница импортирует 130 модулей из 25 папок, и `#lib/` — то, что предлагает
  сам Kit, — читается как «из библиотеки» без подсчёта уровней.
- **TS 7 рядом с TS 6** — `typescript` алиасом на `@typescript/typescript6`, TS 7 отдельным
  пакетом ради `tsc`, как советует Microsoft. Все потребители типов остались бы на TS 6, а
  запускать `tsc` 7 в vterm нечем: `.svelte` он не читает, типы проверяет svelte-check. Сменилась
  бы версия в манифесте, но не проверка.
