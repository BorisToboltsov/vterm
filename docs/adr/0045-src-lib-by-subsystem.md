# ADR 0045 — `src/lib` по папкам подсистем

**Статус:** принято (1.25.6). Правило — в [INVARIANTS](../INVARIANTS.md#ui-и-оформление), карта
папок — в [ARCHITECTURE](../ARCHITECTURE.md#структура-каталогов).

## Контекст

К 1.25 в корне `src/lib` лежало около 540 файлов: 270 модулей и их тесты рядом. Папки были
только у слоёв — `api/`, `stores/`, `page/`, `actions/`, `i18n/`. Файлы одной подсистемы
находились по префиксу имени там, где он был (`Docker*`, `K8s*`, `term*`), а где не было — только
по памяти: `format.ts` — статус-бар, `tree.ts` — дерево серверов, `transfer.ts` — скорость
переноса. Правило линтера `vterm/layers` отличало чистую логику по глубине: `.ts` в корне —
чистый, в подпапке — нет.

## Решение

**Компоненты, чистая логика и их тесты — в папке подсистемы.** Папка — вертикальный срез:
`terminal/`, `files/`, `docker/`, `netcheck/`… Кто ищет всё о Docker, открывает `docker/`; зависимость
одной подсистемы от другой видна в пути импорта (`../ui/Modal.svelte`). Тест лежит рядом со
своим модулем, гейт — в папке подсистемы, чей контракт он держит.

**Слои остаются своими папками, поперёк подсистем.** Сторы, контроллеры страницы, обёртки
бэкенда, экшены и словари в подсистемы не переехали. Слой узнаётся по папке — на этом стоят
`vterm/layers`, `owned-imports` и `forbidden-imports`; контроллер страницы связывает несколько
подсистем сразу; `api/` — один нижний слой, зеркало доменов Rust. Разнести их по подсистемам
значило бы сменить две оси за один перенос и спрятать слой из пути.

**`types.ts` — единственный файл в корне.** Это зеркало моделей Rust, его импортирует каждый
слой, включая `api/`. В `api/` он стал бы для линтера бэкендом, и каждый чистый модуль,
берущий из него значение, нарушал бы `vterm/layers`.

**Чистота — по папке, а не по глубине.** `LAYER_DIRS` в [lint/vterm.js](../../lint/vterm.js)
называет папки-слои; `.ts` любой другой папки (и `types.ts`) — чистая логика. Переименованная
папка-слой иначе молча сделала бы свои модули «чистыми».

**Где что лежит, решает подсистема, а не вид файла.** Секция настроек — у своей подсистемы
(`docker/DockerSettings.svelte`); в `settings/` — окно настроек, его навигация и стор. Общие
примитивы, которыми пользуются несколько подсистем, — в `ui/`; компонент одной подсистемы,
который где-то ещё вызван один раз, остаётся у неё (`utilities/KeyGenModal.svelte` открывает и
форма сервера). Гейты репозитория целиком — документация, CI, линтер, версия, релиз — в `repo/`:
у них нет подсистемы.

**Новый модуль — в папку той подсистемы, чьё правило INVARIANTS он обслуживает.** Новая
папка — строка в дереве ARCHITECTURE: гейт `liblayout.guard` сверяет папки с деревом в обе
стороны и не пускает файлы в корень.

## Последствия

- Перенос — `git mv` каждого файла: история идёт за файлом (`git log --follow`).
- Пути в документации, конфигах (`eslint.config.js`, `vitest.config.ts`), гейтах и
  комментариях Rust переписаны вместе с импортами; ссылки ADR — тоже, чтобы вели на файл.
- Гейты, которые читают исходник по пути, называют папку (`read("k8s/K8sPanel.svelte")`); гейт,
  перебирающий дерево, обходит его рекурсивно.

## Отвергнутые варианты

- **Папки по виду файла** (`components/`, `logic/`). Два плоских списка вместо одного: файлы
  Docker всё так же искались бы по имени, теперь в двух местах.
- **Полные вертикальные срезы со сторами и контроллерами.** См. выше: слой перестал бы читаться
  из пути, а правила линтера — узнавать его.
- **Оставить плоско, добавить префиксы.** Переименований не меньше, чем переносов, а подсистему
  без естественного префикса (`format.ts`, `tree.ts`) префикс не спасает.
