# ADR 0042 — Файлы на сервере: запись, кодировка, синхронизация

**Статус:** принято. Записано в 1.25.4 из разборов, которые жили в INVARIANTS; дополняет
ADR 0025 и 0026. Правила — в [INVARIANTS](../INVARIANTS.md#файлы-пути-текст).

## Контекст

Редактор правит конфиги на серверах пользователя, панель файлов переносит их, синхронизация
сравнивает деревья. Цена ошибки здесь — уничтоженный или молча испорченный чужой файл, и
несколько правил ниже появились именно после такого: зелёный тост над обнулённым конфигом.

## Решения: запись

**`SETSTAT` — только запрошенные атрибуты.** Флаг атрибута поднимается на каждое `Some`, а
`size: Some(0)` — это truncate. Шаг «сохранить права» строил атрибуты из шаблона «новый каталог»
(`size`/`uid`/`gid`/`atime`/`mtime: Some(0)`), уходил `ATTR_SIZE = 0`, и сервер обнулял
пользовательский конфиг перед переименованием на место. В russh-sftp ≤ 2.3.0 этот шаблон был
самим `Default`; 2.4.0 сделал `Default` пустым и перенёс шаблон в отдельный конструктор — payload
тот же, поэтому гейт держит оба написания: откат версии снова взвёл бы старое.

**Запись — только через `create`, через соседний temp.** `SftpSession::write` открывает файл
флагами `WRITE` без `CREATE` — «No such file» на новом пути. Форма: temp рядом с целью →
`set_metadata` (сохранить mode) → `remove_file` → `rename`. `remove_file` нужен, потому что
`SSH_FXP_RENAME` у OpenSSH падает на существующей цели; это единственное неатомарное окно, но
полный контент уже в temp. Упавшая запись не обрезает оригинал.

**Расписка — по тому, что подтвердил сервер.** Ошибку `set_metadata` глушить `let _ =` нельзя.
Добавляя шаг в путь записи, спроси, что увидит пользователь, если шаг молча провалится: зелёный
тост над уничтоженным конфигом хуже любой ошибки. Поведение сервера держат живые тесты
`live_sftp`.

**Конфликт — по хэшу открытия.** Время изменения не надёжно; `expectedSha256` — хэш, с которым
редактор открыл файл, и бэкенд сверяет его перед записью.

**Кодировка определяется и сохраняется.** Молча переписать чужой UTF-16 или CP1251-конфиг в
UTF-8 нельзя, поэтому метка кодировки едет от чтения до записи. Проверка бинарности идёт после
распознавания UTF-16 — иначе перемежающиеся NUL читаются как бинарь (так `.ini` «не
открывался»). Только `chardetng` — догадка. `sha256` считается по сырым байтам, иначе
перекодирование ломало бы проверку конфликтов.

**Права записи — по пути сохранения.** Staged-temp создаётся в родительском каталоге, поэтому
режим исходного файла сам по себе не делает буфер `readOnly`. `sftp_write_access` проверяет
каталог через удалённый shell и даёт лишь предварительный статус. sudo-правка подаёт пароль
через stdin (не argv, не `ps`, не history, не keychain); успех — маркер `__VTERM_OK__`, потому что
exit-статус по exec не виден. Часть SFTP-серверов при незаписываемом каталоге отвечает «no such
file» вместо «permission denied» — файл точно есть, он был в листинге, поэтому оба читаются как
отказ доступа.

**Каретка после вставки — из применённого изменения.** CodeMirror нормализует переводы строк, а
`<textarea>.value` по HTML приводит CRLF к LF: текст из Windows-приложения ложился в документ
короче строки, из которой пришёл, вычисленный якорь уезжал за конец, и `state.update()` кидал
`RangeError` до применения — внутри `.then()`, поэтому вставка проваливалась молча и только не на
macOS.

## Решения: перенос и панель

**Перенос не заменяет без согласия.** Файл, брошенный в окно, молча заменял одноимённый на
сервере, а бросок — жест, который проще всего сделать случайно. Занятые имена спрашивают у
**назначения** (листинг панели мог устареть), один вопрос на пачку; право заменить — только у
файлов, о которых спросили. Непрочитанная папка — не пустая: вопрос другой.

**Список после переноса обновляет стор.** Док пересоздаётся на каждой смене вкладки терминала,
и новая панель читает папку до конца переноса, а «обновить по завершении» доставалось
уничтоженному экземпляру. Ответы листинга приходят не по порядку — принимается последний
запрошенный (`loadSeq`).

**Таблица файлов держит 28 px строки.** На этой высоте стоит виртуальное окно; закреплённая
шапка вычитается при прокрутке к курсору, иначе строка уходит под неё. Блок действий
фиксированной ширины: у каталога кнопок меньше, и ячейки сжимались бы в каждой строке по-своему.

**Порядок один на таблицу и список.** Панель, ставшая шире, не должна показать ту же папку в
другом порядке. Неизвестное время — не самое старое и не самое новое, поэтому в конце при обоих
направлениях; равные — по имени, чтобы порядок был полным.

**Диски не трогаем.** Обращение к отвалившейся сетевой шаре блокируется на SMB-таймаут;
`GetLogicalDrives` даёт буквы мгновенно. Перебор `A:\…Z:\` через `fs::metadata` — та же
ловушка. Синтетический уровень дисков — явный сентинел `"::drives"`, а не пустая строка: `cwd`
кратко пуст при монтировании.

## Решения: синхронизация

**Нечитаемое дерево — ошибка.** Пустой список хэшей планирует «залить всё», а с «удалять
лишнее» — «стереть всё на другой стороне». Удалённый скрипт проговаривает каждый отказ маркером
(нет папки или доступа, нет `sha256sum`/`shasum`, строка на непрочитанный объект, маркер
завершения), потому что exec-канал собирает только stdout.

**Исключения режутся при обходе — но не больше, чем отфильтрует `diffTrees`.** Шаблон с `*` и `/`
остаётся фронту: `find -path` пускает `*` через `/`. Отрезанное сверх фильтра выглядело бы «нет на
этой стороне» — заливкой или удалением.

**Синхронизацией владеет стор.** «В фоне» закрывает окно, а панель SFTP перемонтируется на смене
вкладки — компонентное состояние потеряло бы результат. Прогон один на приложение: id прогресса
`sync:<путь>` без сессии, и два прогона рисовали бы полосы друг друга. Закрыть окно посреди
работы молча нельзя: следование за терминалом переносило бы сравнённый план на папку, с которой
его не сравнивали.

**Прогресс — по детерминированному id.** Поле `name` — базовое имя и коллизирует между
каталогами. Удаления шлют финальный `emit_done`, иначе строка висит «в очереди» над удалённым
файлом. Список ведёт свой стор: общий `transfers` выбрасывает завершённое через
`DONE_LINGER_MS`, и отчёт растворился бы на глазах. Остановка проверяется между файлами: разрыв
копирования оставил бы обрезанный файл поверх рабочего.

**Большой план не стоит квадратично.** Пересуммировать план или копировать карту прогресса на
каждое событие нельзя: виртуальный список, правка на месте, итоги инкрементально.

## Последствия

- Новый шаг записи на сервер отвечает правдой о результате.
- Новый источник текста — через `textenc`; новая запись атрибутов — с выписанными полями.
- Новое направление синхронизации — в `diffTrees`/`apply`, без второго обхода.
