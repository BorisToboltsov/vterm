# ADR 0032 — Проверка доступа: заявка как есть, источник выбирает сервер, подсети и остановка

**Статус:** принято (v1.21.0). Дополняет [ADR 0012](0012-local-access-check.md): поднимает предел
проверок и разрешает подсеть как цель. Куда идёт правило без источника, пересмотрено в
[ADR 0033](0033-access-check-picked-servers-local-tools.md): на отмеченные серверы, а не на
вкладку инструмента.

## Контекст

«Проверка доступа» принимала правила одного синтаксиса — `src -> host:[ports]/tcp`, по строке.
Заявки на доступ приходят иначе: таблицей из Excel или Confluence, формой тикета
(«Источник: …» отдельной строкой), фразой из чата. Каждую приходилось переписывать руками.
Источник в правиле был только подписью для сверки: проверка всегда шла с хоста активной
вкладки, а несовпадение давало жёлтое предупреждение. Проверить один и тот же доступ с
нескольких серверов было нельзя. Черновик правил был один на приложение — на вкладке другого
сервера оставались правила прошлого, с чужим источником. Подсеть как цель не принималась, а
запущенную проверку нельзя было остановить.

## Решение

1. **Заявка вставляется как есть.** Чистая функция `recognize`
   ([netcheckpaste.ts](../../src/lib/netcheck/netcheckpaste.ts)) читает таблицы с шапкой (TSV, Markdown,
   CSV; столбцы по названиям на русском и английском), поля формы, строки со стрелками (через
   прежний `parseRules`) и фразы с «с/from», «на/to», «порт/port». Результат — строки таблицы
   правил, а не текст. Ничего не добавляется само: под полем — сводка, по кнопке — исходный текст с
   отмеченным, у каждой строки — что взято, что пропущено и что угадано («первый адрес — источник»,
   «порт по имени сервиса»). Добавляет только кнопка или ⌘/Ctrl+Enter.
2. **Таблица — ячейки текста, правило решает парсер.** Строка таблицы собирается в каноническую
   строку и уходит в `parseRules`; своего понятия о правиле у таблицы нет. Синтаксис расширен:
   несколько источников (правило на каждый), подсеть в источнике и в цели, имена сервисов вместо
   номеров.
3. **Источник выбирает сервер.** `sourceHosts` ([netroute.ts](../../src/lib/netcheck/netroute.ts))
   сопоставляет источник с каталогом серверов: по имени, адресу профиля, адресам, которые сообщила
   открытая сессия (многоадресные хосты), имени хоста; подсеть — со всеми серверами внутри неё.
   Правило без источника — с вкладки, на которой открыт инструмент; источник, которого нет ни у
   одного сервера, — тоже оттуда, и строка говорит об этом. Сервер можно выбрать у строки вручную.
   Сервер без открытой сессии подключается кнопкой обычным путём (пароль, прод).
4. **Прогон — по серверам сразу.** План (`planRun`) раскладывает правила по серверам; каждый сервер
   получает свой вызов `netcheck_run` по своей сессии, параллельно. Ответ — матрица
   «цель:порт × сервер»; «—» — с этого сервера не спрашивали. Подсеть в матрице — сводка по порту.
5. **Подсеть — каждый адрес хоста, с вопросом и пределом.** Цель-подсеть разворачивается в адреса
   хостов (без адреса сети и широковещательного, кроме /31 и /32). Предел — 2048 соединений с
   одного сервера за прогон (/24 на восемь портов), а не 512 на весь прогон: правила одной заявки
   идут с разных серверов. Перед прогоном с подсетью — подтверждение с числом соединений по
   серверам; для прод-сервера — красное предупреждение (обход подсети может сработать на систему
   обнаружения вторжений). Скрипт сервера пишет строку на хост, а не на порт: весь скрипт идёт
   одним аргументом, а Linux ограничивает его 128 КиБ.
6. **Остановка — общая карта отмен.** `netcheck_run` регистрирует флаг под `cancel_id`, `sftp_cancel`
   его ставит. На SSH-вкладке команда получает `SIGTERM`, канал закрывается — обход подсети не
   продолжается на сервере после «Остановить»; на локальной — соединения в полёте сбрасываются.
   Остановленный сервер — «остановлено», а не «не ответил»; в записи сессии — `exit 130`.
7. **Правила и последний ответ — по серверу вкладки.** Стор держит их по ключу хоста вкладки, на
   которой открыт инструмент; другая вкладка показывает свои. Прогон живёт в сторе: закрытое окно
   «Утилит» его не обрывает.

Рассматривались:

- **Только расширить синтаксис** (разрешить больше форм в одном текстовом поле). Не решает
  главного: таблица из Excel — это табы и шапка, а не строка правила; и нет места, где показать,
  что из вставки взято.
- **Отдельный режим «откуда × куда × порты»** (три поля, как у nmap). Удобен для одних портов на
  многих хостах, но заявку с разными парами им не описать; в таблице это одна строка с
  несколькими значениями в ячейках.
- **Источник как раньше — подпись.** Тогда «несколько серверов» потребовали бы второго способа их
  выбирать, а заявка всё равно называет источник — тот сервер, с которого и нужен ответ.
- **Перебор подсети без вопроса, с прежним пределом 512.** /24 на три порта уже не помещается, а
  тихий обход сети с прод-сервера — ровно то, о чём надо спросить.

## Последствия

- `recognize` — эвристика, поэтому предпросмотр обязателен, а догадки помечены. Адрес с опечаткой
  (`10.70.39.300`) берётся, чтобы таблица назвала ошибку, а не потеряла строку.
- Опрос «кто это» (`netcheckArgs([])`) идёт только к серверам, которые нужны: вкладка инструмента,
  серверы плана и — пока источник не найден — остальные открытые сессии.
- `ssh::exec_on` теперь ждёт код выхода после EOF (OpenSSH шлёт EOF, затем код, затем CLOSE):
  прежний выход на EOF терял код примерно в половине случаев — это касалось и Git, и Docker, и k8s.
  Живые тесты `live_exec`.
- Гейты: `netcheck.guard.test.ts` (прогон только через стор и с ручкой остановки, подсеть — после
  вопроса, вставка — только по действию, ключ — хост вкладки, предел и пачка одни на обе стороны) и
  Rust `a_netcheck_run_can_always_be_stopped`.
- UDP по-прежнему не проверяется; Gateway API, баннеры и HTTP — за пределами этого решения, как и в
  ADR 0012.
