# ADR 0020 — Широкий вид панелей: раскладку решает CSS, поведение читает тот же порог

**Статус:** принято (v1.7.0). Дополняет [ADR 0015](0015-dock-layout.md): там панель
«подстраивается под свой размер», и широкий вид получили Docker и k8s; здесь — Git, файлы и
то, что в узком доке вынуждено быть окном.

## Контекст

В 1.1 панель научилась раскладываться по собственной ширине: `@container` на корне и
варианты `@wide:` в той же разметке. Git, файлы и чат ИИ в нижнем доке работали, но
раскладку не меняли; логи, inspect и подробности контейнера или пода открывались окном
поверх всего — потому что в доке шириной 384 px им негде встать, а в нижнем доке на всю
ширину окна — есть где.

Расширить тот же приём мешали две вещи.

1. **CSS не решает поведение.** «Открыть подробности рядом со списком или окном» — не
   раскладка одной разметки, а выбор, что смонтировать. Контейнерный запрос его не сделает.
2. **Диалог внутри контейнера.** Элемент с `container-type` в части движков становится
   containing block для `position: fixed` потомков — и приложение работает на системном
   WebView, возраст которого выбирает не оно. У Docker и k8s это обошли расположением:
   диалоги стоят рядом с корнем панели. У Git диалоги и меню живут в подкомпонентах
   (изменения, ветки, граф) — поставить контейнер над ними нельзя. А «подробности рядом со
   списком» — это по определению содержимое диалога **внутри** корня панели.

Варианты для второго:

1. **Портал: `Modal` и `ContextMenu` переносят себя в `<body>`.** Снимает ограничение
   целиком. Но диалог перестаёт наследовать стили предков — у большинства из ~50 диалогов
   размер шрифта приходит от корня панели (`text-xs`), — и меняется всплытие событий. Правка
   общего примитива с риском тихой визуальной регрессии в каждом окне.
2. **Поднять диалоги из подкомпонентов Git в панель.** Три компонента, каждый со своим
   состоянием диалога; перестройка ради класса на корне.
3. **Не делать панель контейнером там, где нельзя, и мерить её в JS** тем же порогом.
4. **Разделить «содержимое» и «диалог»**: то, что показывается рядом со списком, — компонент
   без диалога внутри, а окно — тонкая обёртка вокруг него.

## Решение

- **Порог один, читателей два.** Раскладку по-прежнему решает CSS (`@wide:`,
  `--container-wide`). То, чего CSS решить не может, читает тот же порог из
  [panelwide.ts](../../src/lib/panelwide.ts) действием `wideWhen` (`ResizeObserver`,
  сообщает только о переходе через порог): выбор «рядом или окном» в Docker и k8s — и
  раскладка Git, который контейнером быть не может. Константу и CSS-переменную держит вместе
  тест.
- **Рядом со списком стоит содержимое, а не диалог.** Четыре окна разделены на содержимое
  (`DockerDetail`, `DockerText`, `K8sDetail`, `K8sText`) и обёртку-диалог (`*Modal`). В
  широкой панели содержимое встаёт в [SidePane](../../src/lib/SidePane.svelte) справа от
  списка, в узкой — в `Modal`. Содержимое не знает, где оно: ему говорят, занимать ли высоту
  места (`fill`) и закрываться ли после вопроса к ИИ (`closeOnAsk` — окно закрывает собой
  чат, панель нет).
- **Правило стало проверяемым.** `panelcontainer.guard` обходит импорты: в поддереве
  элемента с `@container` нет ни класса `fixed`, ни компонента, который приносит такой
  элемент сам или через вложенный. Первым же прогоном он нашёл нарушение, которого никто не
  видел: корень терминала с фазы 22 оставался контейнером (под переключатель вида, давно
  переехавший в панель сессии), и под ним стояли меню правого клика и диалог структурного
  вида. Запрос с корня снят.
- **Git — два вида рядом.** В широкой панели история стоит справа от изменений или веток.
  Запомненная подвкладка при этом не переписывается: в узком доке панель покажет то, что
  показывала там.
- **Файлы — таблица той же разметкой.** Контейнер — сам скроллер списка (в нём нет
  `fixed`-потомков); шапка закреплена внутри него, строка остаётся 28 px, потому что на этом
  стоит виртуальное окно.

Отклонено: портал (риск для всех диалогов ради трёх панелей), подъём диалогов Git (объём
без выигрыша), отдельный «широкий» компонент панели (запрещён ADR 0015).

## Последствия

- Подробности, открытые при переходе панели через порог, пересоздаются: окно и боковая
  панель — два экземпляра одного содержимого. Выбранная вкладка «Логи» при этом сбрасывается
  на «Обзор», загруженный текст запрашивается заново.
- Панель с диалогами в подкомпонентах меряет себя в JS; панель без них — контейнер. Какая
  из двух, решает не вкус: гейт не даст поставить контейнер над диалогом.
- Боковая панель делит место со списком пополам, граница не тянется. (С 1.10.1 тянется:
  `PanelDivider`, доля первой части — в сторе `panelsplit`, одна на вид панели.)
- Не сделано: сортировка таблицы файлов по колонке; результаты поиска по содержимому и
  переносы рядом со списком; широкий вид чата ИИ.
- Проверка. Логика и разметка покрыты тестами (шапка таблицы совпадает со строкой ячейка в
  ячейку; панель меняет вид при переходе порога и ничего не перезапрашивает; подробности
  открываются рядом или окном). Вживую проверено в браузере на подставном IPC: таблица
  файлов, Git и Docker в нижнем доке, узкий вид в правом. На движке, где контейнер становится
  containing block для `fixed`, не запускалось — там правило держит только гейт.
