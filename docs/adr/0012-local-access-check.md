# ADR 0012 — Проверка доступа с локальной вкладки: узкое исключение из офлайна

**Статус:** принято (v1.0.36).

## Контекст

Утилита «Проверка доступа» отвечает на вопрос «есть ли с этого хоста доступ до таких-то
портов» — обычно его задают, открывая `telnet` на сервере. На SSH-вкладке проверку делает
сам сервер: скрипт идёт по exec-каналу, трафик исходит с хоста пользователя, и
[ADR 0004](0004-offline-first.md) не затронут. На локальной вкладке «этот хост» — машина
пользователя. Прежнее правило сетевых утилит (Фаза 34) отдавало такие команды в PTY
текстом, но для этой утилиты нужен **структурный** ответ: открыт / отказ / таймаут, время,
исходящий адрес.

Рассматривались:

1. **Команда в PTY** (как TLS/HTTP). Ответ — текст в терминале: ни сводки, ни «повторить
   недоступные», ни сверки источника. Не решает задачу.
2. **Локальный процесс-шелл** через `localenv` (как локальный `kubectl`): `sh` + `nc` или
   `bash /dev/tcp` на macOS/Linux и PowerShell `TcpClient` на Windows. Формально ближе к
   правилу «диагностика исполняется на хосте сессии», но это два диалекта скрипта. На macOS
   нет GNU `timeout`, а `nc -w` там не ограничивает сам connect (проверено: таймаут
   растягивался до 75 с). Трафик при этом тот же самый — процесс лишь переносит его на шаг
   дальше от приложения.
3. **TCP connect из Rust.** Один код на трёх ОС, вердикт прямо по ошибке сокета
   (`ConnectionRefused` / таймаут / `HostUnreachable`), время в мс. Исходящий адрес — через
   *подключённый UDP-сокет*: ядро сообщает адрес маршрута, не отправив ни пакета.

## Решение

Вариант 3, как **узкое** исключение из ADR 0004:

- соединения открываются только по явному нажатию «Проверить»;
- только к хостам и портам, которые пользователь ввёл сам (кап — 512 проверок за запуск);
- только TCP-рукопожатие, соединение сразу закрывается, полезной нагрузки нет;
- резолв имени — системным резолвером, как у любой программы на машине.

Транспорт выбирается по наличию сессии (принцип 3): одна команда `netcheck_run`. SSH —
скрипт с сервера, локальная вкладка — `netcheck::run_native`. Обе стороны отвечают одним
построчным протоколом, фронт разбирает его одной функцией. Прогон пишется в запись сессии
как `[util] $ netcheck …`.

## Последствия

- Сокеты приложения живут только в `ssh.rs` и `netcheck.rs`. Это держит Rust-гейт
  `app_originated_sockets_live_only_in_ssh_and_netcheck`: любой новый `TcpStream::connect` /
  `UdpSocket` / `lookup_host` в другом модуле роняет тесты.
- UDP не проверяется ни на одном транспорте: у него нет рукопожатия, тишина ничего не
  значит, а «открыт» был бы выдумкой ([ADR 0009](0009-honest-ui.md)).
- Расширять исключение (UDP-пробы, баннеры, HTTP) — значит снова пересматривать этот ADR и
  гейт, а не дописывать ветку в `netcheck.rs`.
