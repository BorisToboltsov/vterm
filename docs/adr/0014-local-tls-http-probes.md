# ADR 0014 — TLS-инспектор и HTTP-клиент с локальной вкладки: свои curl/openssl пользователя

**Статус:** принято (v1.0.41).

## Контекст

TLS-инспектор и HTTP-клиент (Фаза 34) на SSH-вкладке выполняются сервером через
`probe_run`, и результат разбирается в карточку: срок сертификата, SAN, статус, заголовки,
тайминги. На локальной вкладке они печатали команду в PTY (кнопка «Выполнить в терминале»):
структурного ответа не было, а на Windows команда падала. Строка собиралась под POSIX —
`sh -c '…'`, одинарные кавычки, `2>/dev/null`; в `cmd.exe` и PowerShell она разваливалась,
а `curl` в Windows PowerShell 5.1 — это алиас `Invoke-WebRequest`.

Рассматривались:

1. **Только чинить печать в терминал** — собирать строку под реальный шелл вкладки
   (`renderArgv`, как `cdCommand`). Windows перестаёт падать, но разобранного ответа
   локально по-прежнему нет: одна и та же утилита умеет разное в зависимости от вида
   вкладки.
2. **TLS/HTTP из Rust** (`rustls`/`reqwest`) — как TCP-рукопожатие в ADR 0012. Это новые
   сокеты приложения и вторая реализация того, что уже умеют `curl`/`openssl`, с другим
   поведением (прокси, доверенные CA, SNI), чем у инструментов, которыми пользователь
   проверяет то же самое руками.
3. **Запустить `curl`/`openssl` пользователя локально** через `localenv`, без шелла, и
   разобрать вывод тем же парсером, что на SSH.

## Решение

Вариант 3 плюс вариант 1 как вторая кнопка — **узкое** расширение ADR 0004, по образцу
ADR 0012:

- `probe_run` выбирает транспорт по сессии (принцип 3): SSH — exec на сервере, локальная
  вкладка — `container::run_local` (`localenv`, `no_console_window`, без шелла, аргументы
  verbatim);
- локально запускаются **только** `curl` и `openssl` (`netprobe::local_program_allowed`,
  по имени программы, с `.exe` и путём); `sh`/`cmd`/`powershell` отклоняются — иначе
  команда превратилась бы в произвольный локальный процесс;
- только по нажатию «Запустить», только на адрес, введённый пользователем;
- конвейер без шелла: TLS — два шага (`s_client` → `x509`), stdout первого подаётся на stdin
  второго (`stdin` у `probe_run`); при сбое шага цепочка останавливается с его сообщением;
- «Выполнить в терминале» остаётся: строку собирает чистая логика под **реально запущенную**
  оболочку вкладки (`tlsTerminalCommand`, `httpTerminalArgv` + `renderArgv`, `curl.exe` вне
  POSIX). Невыразимое в этой оболочке (многострочное тело, `"` в `cmd.exe`) даёт `null` —
  кнопка неактивна с причиной, в терминал не уходит ничего.

## Последствия

- Приложение по-прежнему не открывает сокетов для этих утилит: трафик делают процессы
  пользователя, Rust-гейт `app_originated_sockets_live_only_in_ssh_and_netcheck` не меняется.
- Нет `openssl` на машине (обычно на Windows) — честное «openssl не найден на этом
  компьютере», а не правдоподобная заглушка (ADR 0009).
- Прогон пишется в запись сессии как `[util] $ …` на обоих транспортах.
- Добавить локальной вкладке ещё одну программу — значит пересмотреть этот ADR и allowlist,
  а не дописать имя в список.
