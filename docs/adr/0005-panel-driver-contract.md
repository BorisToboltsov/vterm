# ADR 0005 — Единый контракт исполнения для панелей-драйверов

**Статус:** принято (Фазы 29 · 34 · 35 · 37 · 38).

## Контекст

За пять фаз к приложению добавились git-панель, Docker, Kubernetes, сетевые пробы и
локальные метрики. Каждая из них делает одно и то же: выполняет программу на хосте
активной сессии и показывает разобранный вывод. Наивная реализация дала бы по
бэкенд-команде на операцию (`git_status`, `git_log`, `docker_ps`, …) — десятки команд,
в каждой свой квотинг и свой разбор вывода, и каждая заново решает, куда идти на
локальной вкладке.

## Решение

**Одна бэкенд-команда на драйвер** (`git_run`, `container_run`, `kubectl_run`,
`probe_run`, `fetch_metrics*`), принимающая `session_id` + вектор argv.

- **Транспорт выбирается по наличию сессии, а не по ОС:** есть SSH-сессия →
  `exec_captured`; есть локальный PTY → `tokio::process` (через `localenv::resolved_local`,
  потому что упакованное macOS-приложение наследует от launchd минимальный `PATH`).
- **Бэкенд — дамповый исполнитель:** шелл-квотит каждый токен (`git::shell_quote`) и
  возвращает stdout/stderr/код. Никакой логики драйвера в Rust.
- **Сборка argv и разбор вывода — чистые функции в `.ts`** (`git.ts`, `docker.ts`,
  `k8s.ts`, `probe.ts`) с тестами; вид — тонкие `.svelte`.
- **Расширение — новым билдером или парсером**, а не новой командой.

## Последствия

- Новая операция драйвера стоит одной чистой функции с тестом и не трогает Rust.
- Общие правила (аудит `[тег] $ …` в записи, `needsConfirm` → `ConfirmDialog`, снимок
  раз в N секунд вместо потока, сетевые операции только по явной кнопке) формулируются
  один раз для всех драйверов.
- Офлайн-инвариант держится сам собой: трафик идёт с хоста сессии, WebView в сеть не ходит.
- Цена — драйверы не могут иметь принципиально разный протокол исполнения; k8s
  осознанно отличается **данными** (`-o json` вместо `--format`), но не контрактом.
