# ADR 0034 — Как включается синхронизация пути — выбор сервера: три исхода, ответ в профиле

**Статус:** принято (v1.23.0).

## Контекст

Синхронизация пути (панели файлов и Git следуют за каталогом терминала) включалась
кнопкой в каждой сессии заново. На SSH-сервере, который сам не сообщает каталог, каждое
включение открывало окно с командой настройки (OSC 7), и согласие действовало до конца
сессии. Тот, кто работает с сервером каждый день, отвечал на один и тот же вопрос при
каждом подключении.

Нужно было запомнить ответ. Решить пришлось три вещи: где он хранится, каким он бывает и
что приложение делает с ним само.

**Где хранится.**

1. *В настройках приложения — список «сервер → ответ».* Так задумывалось сначала. Но
   ответ — свойство сервера, как «Прод-сервер» и «Автозапись»: в настройках остались бы
   записи удалённых серверов, копия сервера не получила бы ответ, а увидеть его там, где
   сервер настраивают, было бы нельзя.
2. *В профиле сервера.* Удаляется вместе с сервером, переходит в копию и в бэкап, между
   окнами расходится той же рассылкой `window://catalog`, виден и меняется в карточке.
   У локальной вкладки профиля нет — её ответ лежит в настройках, раздел «Терминал».

**Каким бывает ответ.** В первом наброске было два флажка: «включать автоматически» и
«больше не спрашивать». Два флажка — четыре сочетания, а исходов три: всегда, только
сейчас, вручную без вопроса. «Включать автоматически» вместе с «не спрашивать» ничего не
добавляет — вопрос и так не возникнет. Поэтому ответ — один из трёх: в вопросе — три
плитки и одна кнопка, в карточке — сегментный переключатель «Спрашивать / Всегда /
Вручную». По умолчанию в вопросе выбрано «Только сейчас»: долгий ответ — выбор, а не
умолчание.

**Что приложение делает само.** «Всегда» включает синхронизацию на каждом подключении, и
на SSH это значит вписать команду настройки в свежий шелл.

1. *Подождать, не сообщит ли шелл каталог сам, и вписывать только тогда.* Ждать — значит
   угадывать паузу; угаданная пауза на медленном сервере неверна.
2. *Вписывать всегда.* Лишняя строка там, где шелл справился бы сам, — но предсказуемо.
   Принято. Поэтому вопрос показывает команду при каждом долгом ответе, даже если этот
   шелл в ней не нуждается: то, что приложение впишет само, пользователь видит до
   согласия.

Не вписывается команда во вкладку, где шелл занят своей программой (контейнер, под,
`port-forward`), — строка ушла бы в неё. На прод-сервере «Всегда» разрешено, но вопрос и
карточка предупреждают: команда будет вписываться при каждом входе и попадёт в запись.

## Решение

- Режим в профиле — `ServerProfile.pathSync` (`auto`/`manual`, нет — спрашивать), строкой,
  а не enum Rust: незнакомое значение из новой сборки не делает `servers.json`
  нечитаемым для старой. Читается только через `pathSyncMode`: незнакомое — «спрашивать».
- Ответ на вопрос пишет отдельная команда `set_server_path_sync` (как заметки): окно
  вопроса не держит свежей копии профиля, и полный `update_server` мог бы затереть правку
  из открытой формы. Память меняется после записи файла.
- Синхронизацию включает одна функция страницы (`startFollowing`) — кнопкой, из вопроса и
  при подключении. Конец сессии её выключает: шелл, в который вписали команду, умер, и
  после переподключения синхронизацию снова включает только «Всегда».

## Последствия

- На SSH-сервере с «Всегда» при каждом подключении в терминале видна строка настройки.
  Кто не хочет её видеть, добавляет OSC 7 в `~/.bashrc` на сервере (руководство) и
  выбирает «Вручную».
- Переподключение больше не оставляет синхронизацию «включённой» над шеллом, который не
  сообщает каталог, — раньше панель молча переставала следовать.
- Общего «включать везде» нет: каждый сервер отвечает сам.
