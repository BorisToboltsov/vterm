# ADR 0050 — Шапка списка: поле, фасеты, «Вид» и заголовок группы — один набор

**Статус:** принято (v1.29.0).

## Контекст

Сортировка, группировка и фильтрация появлялись в списках по одной, и у каждой — своя форма.

- **Сортировка.** В записях сессий — ряд чипов с несколькими ключами и шевронами, в файлах —
  `SortTitle` со стрелками в шапке и меню в узкой панели. У Docker и k8s колонки есть, но не
  сортируют: `ColumnHead` принимает `onsort`, его не подключили.
- **Группировка.** В записях выбор одного из трёх способов нарисован чипами, как мультивыбор,
  хотя для 2–4 вариантов в языке есть сегменты. Docker и k8s группируют всегда одним способом и
  не сворачивают. Заголовков групп не меньше пяти видов: шевроны 11–14 px, счётчик «N», «(N)» и
  «N» с `opacity-70`. Заголовок раздела записей (`text-meta font-medium uppercase tracking-wide`)
  нарушает правило микро-метки, а `vterm/micro-label` его не видит: регулярное выражение ищет
  классы подряд.
- **Фильтрация.** Поле нарисовано четырьмя способами (с лупой и без, 22 и 28 px, с крестиком и
  без), отбор по признаку — ещё четырьмя: чипы уровней логов, кнопки-фасеты истории Git, чипы
  событий k8s, слитые сегменты плана синхронизации. В Docker, подах и нагрузках k8s, изменениях
  Git и в файлах по имени фильтра нет совсем.

В истории Git (1.27) набор уже собран так, как его делают окна инструментов IDE: поле, фасеты —
кнопками со значением в широкой панели и воронкой в узкой, меню «Вид». Его и берём для всех.

## Решение

**Шапка списка — одна строка под заголовком панели** (`border-b border-edge px-2 py-1 text-meta
text-muted`). Слева направо: поле, фасеты, сброс, меню «Вид». Что показать, решают поле и фасеты;
как разложить и в каком порядке — «Вид».

**Поле — как в истории Git.** 22 px, рамка `edge`, фон `panel`, лупа 12, в фокусе рамка `accent`;
крестик и Esc очищают. Пока список отфильтрован, справа — «N из M» (`tabular-nums`). В окнах
(настройки, «Утилиты», known hosts) — тот же элемент размером 28 px и `text-sm`. Горячей клавиши
нет: ⌘F принадлежит терминалу.

**Фасет — признак со значением.** В широкой панели — кнопка «Признак ▾»: выбранное значение
заменяет подпись, кнопка становится `text-accent`. В узкой — воронка: `text-accent` и число
активных отборов, признаки — подменю со значением в подписи, как у фильтров истории Git. У
каждого значения в меню — число объектов. Сброс — крестик за фасетами и пункт «Сбросить фильтры»
в меню воронки. Порог широкой раскладки — общий (`wideWhen`).

**«Вид» — меню на глазе.** «Группировать ›» и «Упорядочить ›» с текущим значением в подписи, в
подменю — отмеченные строки; «Свернуть все / Развернуть все», пока групп больше одной; галочки
вида списка (теги в истории Git, скрытые файлы). Меню — общий `ContextMenu`: новых видов меню и
поповеров нет.

**Сортировка — один ключ и направление.** Равные — по имени, как в файлах (там же папки над
файлами и неизвестное в конце). Направление по умолчанию у ключа своё: текст — по возрастанию,
числа, размер и время — по убыванию. В широкой панели с колонками тот же порядок меняет
`SortTitle` в шапке: стрелка только у активной колонки.

**Заголовок группы — один компонент.** Строка `bg-panel px-2.5 py-1.5 border-b border-edge`:
шеврон 12, иконка группы 13 `text-accent` (если у группы есть вид), имя `font-medium
text-text/85`, счётчик `text-caption text-muted`; справа — место под сводку (CPU и память стека) и
действия группы. Группа без ключа («Отдельные», «Без сервера») подписана микро-меткой и стоит
последней. Сворачивается любая группа. Группа без совпадений не рисуется; свёрнутая остаётся
свёрнутой, её счётчик — найденное в ней.

**Пустой результат** — `EmptyState`: «Под фильтр ничего не подходит», что именно отфильтровано и
«Сбросить фильтры». Пустой список без фильтра — прежнее пустое состояние: это разные сообщения
(ADR 0009).

**Что фильтрует, решает список.** Шапка — вид, модель — у списка. Docker, k8s, файлы и записи
фильтруют загруженное; история Git — запросом к git (ADR 0048); контекст и
namespace k8s остаются выбором, вшитым в argv, — это не фильтр. Фильтр файлов — по имени в
текущей папке, не рекурсивно: глубже ищет поиск по содержимому. Курсор и выделение ходят по
показанным строкам (`shownEntries`).

**Модель — чистая и одна.** `listview.ts` в `ui/`: схема списка (текст для поля, фасеты с
подсчётом, ключи порядка, способы группировки) и `applyView(items, schema, state)` → группы,
показанное и всего. Правила прежних функций переходят в схемы: группы `groupByCompose` и
`groupByOwner` — группировки схем с теми же правилами, `sortEntries` сортирует моделью;
`sectionRecordings` остаётся разделами записей — он не разбивает групповую запись. Меню «Вид»
собирает `viewMenu`, меню воронки — `facetMenu`; оба отдают `MenuItem[]`.

**Где хранится.** Группировка и порядок — на приложение, по списку: `vterm.listview`, как сейчас
`vterm.filesort`; порядок файлов переезжает туда с чтением старого ключа. Фильтры и свёрнутые
группы — по сессии в `dockstate`: переживают смену вкладки, чистятся в `closeTabFully` и уезжают с
вкладкой в другое окно. У записей, списка в окне, — пока окно открыто.

**Меню рисует не шапка.** Docker, k8s и файлы — контейнеры `@container`, а `ContextMenu` —
`fixed`: шапка отдаёт пункты наружу, и меню показывает то же место, что меню строк (`showMenu`).
Иначе меню встанет не там, где его открыли (гейт `panelcontainer.guard`).

### По спискам

| Список | Поле | Фасеты | «Вид» |
|--------|------|--------|-------|
| Docker · контейнеры | имя, образ, порт | статус, compose | группы: compose / статус / без групп; порядок: имя, статус, CPU, память |
| Docker · образы | репозиторий, тег, id | вид: с тегом / висячие | группы: репозиторий / без групп; порядок: имя, размер, создан |
| Docker · сети и тома | имя | драйвер | — (разделы — заголовками групп) |
| k8s · поды | имя | статус, узел | группы: владелец / узел / namespace / без групп; порядок: имя, рестарты, CPU, память, возраст |
| k8s · нагрузки | имя | вид | группы: вид / namespace |
| k8s · события | причина, объект, сообщение | тип (вместо чипов) | порядок: время, число |
| Файлы | имя в папке | — | порядок (вместо меню-шеврона), скрытые файлы; кнопка в тулбаре остаётся |
| Git · изменения | путь | статус | — (стадии — заголовками групп) |
| Git · ветки | ветка, с крестиком и «N из M» | — | — (свернуть и развернуть всё — в тулбаре веток) |
| Git · история | как есть | как есть | как есть |
| Логи | текст | уровень (вместо чипов) | — (выбор колонок — кнопкой в строке) |
| Записи сессий | название, сервер, описание | сервер, дата | группы: дата / сервер / без групп; порядок: дата, сервер, размер |
| Серверы, настройки, «Утилиты», known hosts | общее поле | — | — |

Не меняются: палитра ⌘K, поиск в терминале и поиск по содержимому — это поиск, а не фильтр
списка; дерево серверов и дерево веток — деревья, их разделы не режим группировки. **План
синхронизации — исключение:** его слитые сегменты со счётчиками остаются. Это обзор плана перед
применением, и все числа нужны на виду сразу, а не в меню; новый список эти сегменты не копирует.

### Что разошлось с планом при реализации

- **«Используются» у образов** не сделано: узнать, чем занят образ, — значит на каждом опросе
  образов звать ещё `docker ps`. Остался фасет «вид» (с тегом / висячие).
- **Колонки логов** остались кнопкой в строке фильтра: строка меню закрывает его по клику, а
  колонки включают по несколько подряд.
- **Группы по папке в изменениях Git** не сделаны, и «Вида» там нет: стадии — уже разделы, а
  выделение и действия стадий устроены вокруг них.
- **Свернуть и развернуть всё у веток** остались в их тулбаре: в широкой панели это вертикальная
  полоса инструментов, перенос перекроил бы её.

## Отвергнутые варианты

- **Чипы, как в записях.** Две строки высоты в каждом списке; чип читается как мультивыбор, а
  способ группировки — один из трёх.
- **Фраза «Группы: … · Порядок: …».** Компактно, но значения — текстовые кнопки без рамки, их не
  отличить от подписей; в узком доке строка переносится.
- **Поповер «Вид» с выпадающими списками** (Display в Linear, ⌘J в Finder). Такого примитива нет,
  `fixed` внутри контейнера запрещён, а поповер с селектами шире дока в 340 px.
- **Токены условий и язык запросов** (Notion, Datadog, k9s). Нужны ширина и знание синтаксиса;
  в доке строка токенов растёт в высоту.
- **Две иконки ⇅ и ▦ без подписей.** Экономно, но состояние видно только точкой, а воронка и
  глаз уже есть в истории Git и узнаются.
- **Только шапка колонок.** В узком доке колонок нет; группировку из шапки без меню не выбрать.
- **Несколько ключей сортировки.** В меню ложатся неудобно, а были только в записях; один ключ с
  добором по имени уже даёт устойчивый порядок.
- **Фасет «Действие» в плане синхронизации.** Один способ отбора на всё приложение, но числа по
  действиям ушли бы в меню, а при разборе плана их смотрят все сразу.

## Последствия

- Новый список с поиском, отбором, группами или порядком собирается из этих частей; своего поля,
  чипов и заголовка группы он не заводит. Правило — в INVARIANTS, вместе с гейтами: правило
  линтера `vterm/filter-field` не пускает поле поиска мимо общего элемента (исключения с
  причиной — поиск в терминале, поиск по содержимому, путь в фильтре истории), `listview.guard`
  проверяет, что списки этого ADR рисуют общую шапку и общий заголовок группы, модель держат
  тесты `listview.test.ts`.
- `vterm/micro-label` ловит микро-метку, у которой классы стоят не подряд.
- Классы набора — в DESIGN.md, раздел «Списки: фильтр, группы, порядок».
- Записи теряют сортировку по нескольким ключам. Переносить нечего: порядок записей не хранился.
- Чипы уровней логов и событий k8s и строки чипов записей уходят: в широкой панели отбор — одна
  кнопка вместо ряда, состояние видно по подписи.
- Docker и k8s получают сортировку колонок без новой разметки: `ColumnHead` уже принимает `onsort`.
- Фильтры по сессии — новые поля `DockSessionState`: очистка и перенос в другое окно идут
  существующим путём (`removeDockState`, `packTab`/`unpackTab`).
