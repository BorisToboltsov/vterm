# ADR 0013 — Portable с вшитым WebView2 для Windows без него

**Статус:** принято (v1.1.0).

## Контекст

Окно vterm рисует системный **WebView2**. На Windows 11 он есть всегда, на Windows 10 —
обычно, но на LTSC/LTSB, урезанных корпоративных образах и машинах без обновлений его нет.
Именно там нечем его поставить: Microsoft Store отсутствует, winget приходит только с
пакетом App Installer из того же Store, интернета часто нет. Portable-файл на такой машине
просто не стартует, а установщики `-setup.exe`/`.msi` качают загрузчик WebView2 из сети.

Рассматривались:

1. **Офлайн-установщики** (`bundle.windows.webviewInstallMode: offlineInstaller`). Одна
   строка конфига, но +~130 МБ к установщику у всех, включая тех, у кого WebView2 уже
   есть, и системная установка обычно требует администратора. Portable не решает.
2. **Положить Standalone Installer рядом** с portable отдельным ассетом. Кода нет, но
   пользователь ставит runtime сам и с правами администратора — это просто инструкция,
   упакованная в файл.
3. **Zip: `vterm.exe` + папка Fixed Version runtime** и переменная окружения на неё.
   Работает без администратора и без сети, но это два артефакта: распаковать, не
   перепутать, держать рядом.
4. **Один exe с runtime в хвосте.** К концу собранного `vterm.exe` дописывается `.cab`
   Fixed Version runtime и 64-байтовый хвост-описание (версия, sha256, длина, сигнатура).
   Windows дописанные байты не исполняет. На старте vterm сам распаковывает runtime в
   кэш и указывает на него штатной переменной `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER`.

## Решение

Вариант 4 — **вторым** portable-файлом `vterm-portable-<v>-x86_64-webview2.exe`. Лёгкий
portable и установщики не меняются: большинству он не нужен.

- **Системный runtime всегда побеждает вшитый** (`webview2::decide`): установленный
  WebView2 обновляется Windows Update, вшитый — никогда. Явно заданная пользователем
  переменная тоже побеждает. Наличие runtime проверяется тремя ключами реестра EdgeUpdate
  — ровно так, как это описывает Microsoft.
- **`.cab` вшивается как есть**, без пережатия: это файл, подписанный Microsoft, и CI
  проверяет подпись Authenticode до вшивания. Распаковывает его встроенный `expand.exe` —
  тот же способ, что Microsoft описывает для Fixed Version. Крейт `cab` отклонён: он читает
  каждый файл солидного LZX-архива с начала папки, на 300 МБ это квадратичное время.
- **Распаковка атомарна** — та же форма, что у `store::write_atomic`: `.cab` копируется из
  exe с проверкой sha256 из хвоста, разворачивается во временную папку, и только целиком
  готовая папка переименовывается в `<версия>`. Права для песочницы WebView2
  (`ALL APPLICATION PACKAGES`) выдаются на пустую папку до распаковки — файлы наследуют.
- **Версия runtime не пинится в репозитории.** Microsoft держит на странице загрузки только
  две последние мажорные версии, и старые `.cab` с сервера пропадают: пин протух бы за пару
  месяцев. CI берёт самую свежую x64-сборку со страницы в момент сборки
  (`scripts/webview2-runtime.mjs resolve`); подлинность держит подпись, а не хэш в репо.
- На время первой распаковки показывается нативное окно «Подготовка…» — WebView ещё нет,
  `t()` недоступна, поэтому его тексты (en/ru, по языку интерфейса Windows) живут в
  `webview2.rs`. Сбой распаковки — окно ошибки с причиной и путём, а не белый экран.

## Последствия

- Файл весит ~330 МБ (сам `.cab` ~300 МБ), первый запуск на машине без WebView2
  распаковывает runtime в `%LOCALAPPDATA%\vcore\vterm\data\webview2\<версия>` (сотни МБ)
  и занимает до пары минут; дальше запуск обычный. Прежние версии кэш убирает сам.
- **Вшитый движок не обновляется.** Его свежесть привязана к релизам vterm: каждый релиз
  берёт текущую сборку Microsoft. Это принятый риск ([SECURITY.md](../../SECURITY.md)).
- Офлайн-инвариант ([ADR 0004](0004-offline-first.md)) не затронут: в сеть ходит только CI
  при сборке, приложение — нет.
- Сборка релиза зависит от разметки страницы Microsoft. Если ссылки перестанут находиться,
  шаг падает с понятной ошибкой, а не выпускает файл без runtime; обход — переменные
  `WEBVIEW2_CAB_URL`/`WEBVIEW2_VERSION`.
- Неподписанный exe с большим сжатым хвостом — вероятный повод для ложных срабатываний
  антивирусов; проверяется существующим opt-in шагом VirusTotal.
- Формат хвоста описан дважды (Rust и скрипт CI) — их держит вместе гейт
  `webview2runtime.test.ts`.
