# ADR 0028 — Коммит в истории Git: панель по выбору, рядом — по правилу, которое уже есть

**Статус:** принято (v1.15.0). Дополняет [ADR 0020](0020-wide-panels.md): там «подробности
рядом со списком» получили Docker и k8s, а у Git история встала рядом с изменениями; здесь —
подробности коммита.

## Контекст

Клик по коммиту открывал под историей полоску: короткий хэш, тема и плоский список файлов.
Автор и тело сообщения жили только в подсказке строки, почты не было нигде. В нижнем доке на
всю ширину окна панель Git показывает две колонки — изменения и историю — и справа от
истории остаётся место, которого полоска высотой в четыре строки не использует. Образец —
журнал IDE: справа от списка коммитов стоят файлы выбранного коммита и сведения о нём.

Решить нужно было три вещи.

**Постоянная колонка или панель по выбору.**

1. *Третья колонка всегда на экране*, как в IDE. Но у IDE под журнал отдано окно целиком, а
   у нас панель Git делит док с изменениями: постоянная колонка забирает треть строки у
   истории и у изменений и тогда, когда коммит не выбран и показывать в ней нечего.
2. *Панель, которая открывается выбором коммита и закрывается.* Так уже устроены
   подробности контейнера и пода (ADR 0020): место занимает то, что открыли.

**Когда панель встаёт рядом.** Порог широкого вида один (`WIDE_REM`, 768 px), и на нём три
части по `PART_MIN` (240 px) помещаются впритык: история в 256 px перестаёт читаться.

1. *Второй порог* — «очень широкая панель». Второе число — второй ответ на вопрос «широкая
   ли панель», и они разойдутся: ADR 0020 оставил один порог именно поэтому.
2. *Рядом всегда, когда панель широкая.* В строке, которая не держит две части, граница
   встаёт пополам и обе части уже минимума.
3. *Рядом, когда панель широкая и строка истории держит две части* — то есть по минимуму,
   который у части и так есть. Иначе — полоска под списком, как в узком доке.

**Что считать файлами слияния.** `git show --name-status` перечисляет у слияния только
файлы, где результат отличается от *обоих* родителей: для слияния без конфликтов — ничего.
«В коммите нет файлов» под слиянием сорока коммитов — неправда. Что делают с этим `-m` и
`--first-parent`, менялось между версиями git, а версия на сервере — не наша.

## Решение

- **Панель по выбору.** Выбранный коммит показывает `GitCommitDetail`: файлы деревом по
  каталогам (цепочка каталогов с одним вложенным сворачивается в строку, каталог
  складывается), под ними — сообщение целиком, хэш, автор с почтой, момент и возраст,
  коммиттер, если он или его время отличаются от авторских, родители (ссылкой на коммит,
  если он есть в истории), ветки и теги на коммите. Повторный клик по коммиту или крестик
  панели закрывает её.
- **Одно содержимое, два места.** В широкой панели — `SidePane` рядом со списком, за
  границей `gitCommit` (своя доля в сторе, 55/45); иначе — полоска под списком, не выше 55 %
  его колонки. Диалога и меню в содержимом нет: diff файла оно просит у панели. Файлы стоят
  первыми — там, где их показывала прежняя полоска; в панели файлы и сведения прокручиваются
  порознь, чтобы коммит на триста файлов не уводил автора за край.
- **Рядом — `wide && fitsBeside(rowWidth)`.** `fitsBeside` — чистая функция от `PART_MIN`;
  своей ширины и своего `isWide` у истории нет. Пока строка не держит две части, остаётся
  полоска; стоит отдать истории место (граница с изменениями тянется) — тот же коммит
  переезжает рядом, без нового запроса к git.
- **Список истории — сам контейнер.** Его строка раскладывается по ширине списка, а не
  панели: в широком списке — автор и момент коммита колонками, в узком — возраст. Открытая
  рядом панель сужает список, и колонки уходят сами. Внутри списка нет ни диалога, ни меню
  — они стоят рядом с корнем компонента, как требует ADR 0020.
- **Один вызов на коммит.** `git show -z --name-status` с заголовком в ограде RS: автор,
  коммиттер и файлы приходят вместе, имя файла — как есть (без `-z` git экранирует
  не-ASCII в восьмеричные последовательности). Формат снят с ответа настоящего git
  (2.54), а не написан по памяти.
- **Файлы слияния — его diff с первым родителем, названным по имени**
  (`git diff <hash>^1 <hash>`): diff двух коммитов читается одинаково в любой версии. Панель
  подписывает список — «изменения относительно первого родителя»; тот же diff открывается
  по клику на файл.
- **Ответ, который не разобрался, — ошибка**, а не коммит без автора и файлов; ответ на
  коммит, с которого уже ушли, отбрасывается.

## Последствия

- У вида Git две границы, и у каждой своя доля (`git`, `gitCommit`) — «одна доля на вид
  панели» из 1.10.1 стало «одна на границу».
- Переход панели между «рядом» и «под списком» пересоздаёт содержимое: прокрутка дерева
  файлов сбрасывается. Выбор, ответ git и сложенные каталоги живут в истории и переживают
  переход.
- В строке истории появилось абсолютное время. Правило «возраст — один формат» не
  ослаблено: возраст по-прежнему `compactAge` (Git перешёл на него с собственного
  `now`/`4w`/`1y`), а время коммита в широком списке — момент, в том же виде, что время
  изменения файла.

## Что не сделано

- «В каких ветках содержится коммит» (`git branch --contains`) — показаны только ветки и
  теги, которые стоят на самом коммите.
- У слияния показан diff с первым родителем; изменения относительно второго не показаны.
- Число добавленных и удалённых строк по файлам (`--numstat`) не читается.
- Переименованный файл открывается как diff нового пути; откуда он пришёл — в подсказке.
- Фильтров журнала (ветка, автор, текст) нет; история по-прежнему — последние 200 коммитов.
- Рисуется первая тысяча файлов коммита, остальные только считаются.
