# ADR 0043 — Вход по SSH и хранение: секрет туда, где его спросили, данные — только подтверждённые

**Статус:** принято. Записано в 1.25.4 из разборов, которые жили в INVARIANTS; дополняет
ADR 0007. Правила — в [INVARIANTS](../INVARIANTS.md#хранение-и-секреты).

## Контекст

Вход на сервер и хранение каталога — места, где ошибка либо отдаёт секрет не тому, кто
спрашивает, либо показывает данные, которых нет: сервер, исчезающий после перезапуска, пароль,
который «сохранён», но не здесь.

## Решения

**`keyboard-interactive` получает пароль только в вопрос о пароле и один раз.** Часть серверов
(UniFi, PAM) не принимает метод `password`; тот же пароль даётся ответом на **скрытый** вопрос,
похожий на запрос пароля (`plan`). Тот же вопрос снова значит «неверный» — вход отклоняется, а не
переспрашивает. Одноразовые коды («Verification code», Duo «Passcode», pam_oath «One-time
password») паролем не заполняются никогда; после частичного успеха (ключ или пароль + код) пароль
не отправляется повторно. Остальное спрашивает окно; текст вопросов — от сервера и показывается
как текст. Ожидание ответа без таймаута, поэтому конец сессии (`disconnect` и новый
`connect_session` той же сессии) снимает ожидающий вопрос. Сервер без пригодных методов —
`AuthMethodsUnsupported` со списком его методов, а не «неверный пароль».

**Сертификат хоста отклоняется.** Доверенных CA у приложения нет, а пин ключа, вложенного в
сертификат, молча пропустил бы подпись, срок и principals. Алгоритмы `*-cert-v01` не
рекламируем. Поддержка сертификатов — это явный список CA и проверка сертификата.

**После входа подключение не проваливается.** `?` после успешного `ssh::connect` выбрасывал
аутентифицированное подключение из-за сбоя keychain: на Linux без Secret Service подключиться с
«запомнить» было нельзя вовсе, а человек видел ошибку вместо шелла. Сохранение секрета — совет.

**Профиль публикуется после записи.** Иначе окно видит сервер, который исчезнет после
перезапуска. Форма закрывается до ожидания keychain: запись секрета медленная и от сохранения
профиля не зависит.

**Секрет proxy — под своим id.** `{id}::proxy`, чтобы не конфликтовать с секретом самой цели.

**Хардкодных путей во фронте нет.** Отладочный блок с `/tmp/vterm-realtest.conf` однажды уехал в
main и на каждом запуске показывал тост об отсутствующем пути (на Windows `/tmp` нет вовсе) и
открывал локальную вкладку без спроса.

**Карантин различает три случая.** Атомарная запись (ADR 0007) не спасает от **успешной** записи
пустоты поверх единственной копии, поэтому «файла нет», «файл не парсится» и «прочитан» не
склеиваются. Метка времени в имени карантина — чтобы вторая порча не затёрла улику от первой;
неудавшийся карантин — отдельное, более тревожное сообщение, а не смягчённая версия первого.

**Импорт бэкапа пишет то, что показал предпросмотр.** Бэкап, сделанный другим, несёт его логины и
домашний каталог в путях ключей — поэтому они меняются по значению на всех серверах и jump host.
Сервер, который уже есть (тот же id или хост, порт и логин), не трогается: у него свой секрет.
Секреты с бэкапом не переезжают, и флаг «пароль сохранён» из чужого бэкапа обещал бы пароль,
которого здесь нет. Каталог проверяется до записи (`check_catalog`: без пустых и повторяющихся
id — секреты в keychain лежат по id). Замена удаляет, поэтому по умолчанию — «Добавить к моим».

## Последствия

- Новый ответ серверу при входе проходит `kbdauth::merge`.
- Новый шаг после входа — совет с тостом, а не `?`.
- Новый store-файл — через `read_store`/`write_atomic`.
