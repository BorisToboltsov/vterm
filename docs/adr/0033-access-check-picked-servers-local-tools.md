# ADR 0033 — Проверка доступа: отмеченные серверы и метод проверки на этом компьютере

**Статус:** принято (v1.22.0). Дополняет [ADR 0032](0032-access-check-requests.md) (куда идёт
правило без источника) и [ADR 0012](0012-local-access-check.md) (чем проверяет локальная
вкладка).

## Контекст

В 1.21 правило без источника проверялось с вкладки, на которой открыт инструмент. Проверить
список целей с трёх серверов сразу можно было только так: вписать в источник каждой строки
три имени. Выбор метода проверки (bash, nc, telnet, curl) остался, но стоял под чипом сервера
и показывал плитки только для чипа, на который нажали. Открыв инструмент с локальной вкладки,
плиток не было видно вовсе, и по ощущению пользователя выбор метода пропал.

На локальной вкладке метода не было никогда: соединялся сам vterm (ADR 0012). Этого хватает
для ответа «открыт ли порт», но не для сверки: «vterm говорит таймаут, а `nc` из терминала
подключается» — то, что администратор хочет проверить тем же инструментом. ADR 0012 отказался
запускать на этой машине `sh` с инструментами, потому что на macOS нет GNU `timeout`, а
`nc -w` там не ограничивает сам connect.

## Решение

1. **Плашка на каждый сервер с открытой вкладкой — и клик её отмечает.** Под «Проверять с» —
   по плашке на сервер, к которому открыта вкладка (живая, подключающаяся или оборванная),
   одна на адрес; все локальные вкладки — одна «Этот компьютер». Рядом — серверы, которые
   назвали источники правил. Отмеченные плашки проверяют **правила без источника** и
   правила, чей источник не нашёлся ни у одного сервера. По умолчанию отмечена вкладка, с
   которой открыт инструмент. Отметки хранятся в сторе по хосту вкладки, как правила.
2. **Отметка не перебивает источник.** Правило, чей источник называет сервер, проверяется с
   него, отмечен он или нет: заявка просит доступ именно оттуда, и «открыт» с другого адреса
   был бы ответом не на тот вопрос. Ручной выбор у строки («⋯ → Проверять с») остаётся.
3. **«Откуда» — список, а не поле для текста.** Ячейка показывает одно из трёх
   (`sourceChoice`, [netcheckform.ts](../../src/lib/netcheckform.ts)): «Все отмеченные» — по
   умолчанию, источника нет; отмеченный сервер — выбран вручную (`via`); адрес текстом — из
   заявки или введённый через «Ввести адрес или подсеть…». Выбор сервера заменяет адрес заявки,
   ввод адреса снимает ручной выбор (`withSource`): ячейка, показывающая одно, а проверяющая по
   другому, обманывала бы. Цена — у строки, где адрес заявки заменили сервером, в отчёте нет
   пометки «в правиле: …». Ручной ввод оставлен: заявки называют адреса и подсети, которых нет
   среди плашек.
4. **Ничего не отмечено — не запускается.** Правило без источника, которому некуда идти,
   не выпадает из прогона молча: строка говорит «не с чего проверять», кнопка запуска
   недоступна, причина названа (`RunPlan.unrouted`).
5. **Метод — один блок, ряд на сервер.** Под плашками — по ряду плиток на каждый сервер,
   который что-то проверяет (отмечен или назван источником). Чип больше не выбирают ради
   плиток: их видно все сразу. У неподключённого сервера вместо плиток — «подключите».
6. **У «Этот компьютер» тот же ряд.** Плитки: `vterm` (по умолчанию — соединяется само
   приложение, как раньше), `bash`, `nc`, `telnet`, `curl` — программы пользователя.
   - **Аргументы зашиты в Rust, страница называет только инструмент.** `netcheck_run`
     получает имя (`localTool`), `LocalTool::parse` принимает одно из четырёх, а argv строит
     `LocalTool::argv`. `bash` — это шелл: страница, способная передать ему argv, могла бы
     запустить что угодно. Это граница, поэтому argv здесь — в Rust, а не в `.ts`
     (исключение из принципа 2 по принципу 7).
   - **Хост — аргумент, а не текст команды.** `bash -c 'exec 3<>"/dev/tcp/$0/$1"' host port`,
     у остальных хост — отдельный аргумент. Бэкенд не пускает хост, который начинается с `-`
     или содержит что-то, кроме букв, цифр, `.`, `-`, `_`: иначе `-e…` стало бы опцией `nc`, а
     `a@b` — другим адресом у `curl`.
   - **Ожидание ограничивает приложение.** Инструмент, который ждёт дольше таймаута, убивается
     и читается как код 124 — тот, что даёт GNU `timeout`. Поэтому локально `timeout` не
     нужен никому, и macOS проверяет `bash` и `telnet` так же, как Linux.
   - **Ответ — сырые показания, вердикт — на фронте.** Строки `R` того же протокола, что у
     скрипта сервера; открыт/отказ/таймаут решает `classifyAttempt` и для сервера, и для этой
     машины.
   - **На Windows — только `vterm` и `curl`.** `bash` в System32 — это WSL, другая машина для
     правила файрвола; `telnet` Windows ничего не печатает при соединении — открытый порт
     читался бы как таймаут; сборки `nc` расходятся в `-z`. Такие плитки зачёркнуты с причиной
     «на Windows не поддерживается» (`unsupported`), а не «не установлен».
   - Установить инструмент на эту машину vterm не предлагает: менеджер пакетов — сервера.

Рассматривались:

- **Отметка решает всё, и правило с источником тоже.** Проще объяснить, но тогда источник из
  заявки снова становится подписью, а «проверить с отмеченных» отвечает не на тот вопрос —
  ровно то, от чего уходили в ADR 0032.
- **Плитки только у выбранного чипа, как в 1.21.** Отметка и выбор «чьи плитки показать» —
  два разных значения одного клика; совместить их нельзя, а скрытые плитки и вызвали вопрос.
- **Локальный скрипт через `sh`** (как на сервере). Второй диалект: на macOS нет `timeout` и
  `date +%N`, на Windows нет `sh`; и шелл с текстом от страницы — та самая поверхность,
  которую закрывает фиксированный argv.
- **argv собирает `.ts`, бэкенд сверяет по списку программ** (как `curl`/`openssl` в ADR 0014).
  Для `curl` это принятый риск, для `bash` — нет: allowlist программы без проверки аргументов
  пропустил бы `bash -c '<что угодно>'`.

## Последствия

- Это расширение исключения из офлайна (ADR 0004, 0012): на этой машине по кнопке теперь
  запускаются и программы пользователя — к тем же введённым адресам, с тем же пределом и той
  же остановкой (`kill_on_drop`). Сокетов приложения не добавилось.
- Локальный опрос «кто это» сообщает и инструменты (`C`): поиск по `PATH` пользователя
  (`localenv`) — один раз на открытие, без запуска самих инструментов. `curl -V` спрашивается
  только перед прогоном с `curl`.
- Гейты: Rust `a_local_tool_runs_only_its_fixed_argv` (два спавна в `netcheck.rs`, argv
  проверки только из `LocalTool::argv`, команда берёт имя через `LocalTool::parse`, локальная
  ветка не передаёт `args` страницы); `every_local_cli_spawn_hides_the_console_window` теперь
  считает и `netcheck.rs`; `netcheck.guard` — отметки по хосту вкладки, маршрут правил без
  источника только из отметок.
