# vterm

**vterm** — **кроссплатформенный (macOS + Windows) инструмент для работы системных
администраторов, devops и sre**: SSH-терминал и SFTP-клиент с графическим
интерфейсом, написанный на Rust поверх **Tauri 2** и **SvelteKit**.
По духу — аналог [iTerm2](https://iterm2.com/) и
[MobaXterm](https://mobaxterm.mobatek.net/): слева список сохранённых серверов,
справа живой терминал подключения, плюс передача файлов по SFTP и безопасное
хранение паролей в системном хранилище ключей.

> ⚙️ **Текущий статус: Фазы 0–11 реализованы.** SSH-терминал
> (пароль/ключ, дефолтный ключ из `~/.ssh/`), вкладки, секреты в системном keychain,
> профили в JSON и **SFTP-менеджер файлов** (просмотр, навигация, upload/download,
> drag-and-drop, прогресс). **Фаза 4:** регулируемые/сворачиваемые панели, **темы
> оформления** (xterm + UI), настройки шрифта/курсора, панель **⚙ Settings**,
> **нижний статус-бар** с метриками, копирование/вставка, переподключение, группы/
> поиск/теги серверов, проверка отпечатка хоста, окно Help & About. **Фаза 5:**
> тесты и покрытие (Rust-юниты, Vitest, E2E) с гейтами в CI. **Фаза 6:**
> безопасность/SAST, офлайн-автономность, рефакторинг архитектуры, оптимизация.
> **Фаза 7 (дизайн/UX):** единая иконография, тосты, командная палитра **⌘K**,
> доступность (a11y), пустые состояния, анимации, светлые темы, расширенный
> статус-бар. **Фаза 8 (документация):** этот README, **встроенная инструкция**
> (Help → «Инструкция»), контакты автора. **Фаза 9 (мониторинг):** страница метрик с
> графиками. **Фаза 10 (логи и текст):** поиск по буферу, regex-подсветка, структурный
> вид логов. **Фаза 11 (запись сессий):** запись/воспроизведение asciicast, библиотека,
> ИИ-экспорт, автозапись прод-серверов. Полный план — в [ROADMAP.md](ROADMAP.md).

## Возможности

### Реализовано (Фазы 0–7)

**Подключение и терминал**
- 🪟 Двухпанельное окно: слева — список сохранённых серверов, справа — терминал.
- 📋 Добавление сервера — кнопкой в тулбаре списка серверов (иконка «лист с +»,
  рядом с кнопкой «Новая папка»); подключение кнопкой **Connect** в центре окна
  или двойным кликом по серверу. При наведении на строку появляются значки: ✎ —
  редактировать сервер / переименовать папку, × — удалить.
- 🍎 **Нативное меню приложения**: **Settings** и **About** вынесены в системное меню.
  На macOS — в меню **vterm** (Settings с ⌘,) и **Help**; на Windows/Linux — в
  меню-баре окна (**File → Settings…**, **Help → About**).
- 🔌 **SSH-подключение** (russh) по **паролю и SSH-ключу**: выбор метода в форме,
  путь к ключу через нативный диалог, passphrase для зашифрованных ключей. Если
  путь к ключу не задан — используется дефолтный ключ из `~/.ssh/`
  (`id_ed25519` → `id_ecdsa` → `id_rsa` → …, в порядке предпочтения OpenSSH).
- 🖥️ **Живой терминал** на xterm.js: PTY, ANSI-цвета, ввод/вывод, авто-resize.
- 🗂️ **Вкладки**: несколько одновременных соединений (в т.ч. к одному серверу),
  **перетаскивание** для изменения порядка, индикатор статуса на каждой.
- ➕ **Локальный терминал**: кнопка **«+»** в списке вкладок открывает вкладку с
  shell **локальной машины** (на которой запущен vterm) — реальный PTY через
  `portable-pty` (forkpty на Unix, ConPTY на Windows). Удобно, чтобы быстро
  выполнить локальную команду, не покидая приложение.
- 🔄 Индикатор статуса (Connecting / Connected / Disconnected / Error) и
  **переподключение** при обрыве (кнопка Reconnect + опциональный авто-reconnect).
- ⏳ **Окно ожидания подключения**: пока идёт connect, в центре показывается
  анимированный оверлей (орбита-комета вокруг иконки сервера) с именем сервера,
  `user@host:port` и **чек-листом реальных фаз** соединения — Соединение →
  Аутентификация → Сессия (подсветка идёт по фактическим событиям бэкенда, а не
  по таймеру), чтобы было видно, на каком этапе подключение.
- ⛔ **Экран ошибки/обрыва** в том же стиле: при неудаче иконка сервера получает
  **красный крест**, а чек-лист **замирает на упавшем шаге** (например, «Соединение —
  отказано» с причиной от сервера) — сразу видно, где оборвалось; ниже — кнопка
  **Переподключиться**. При **провале аутентификации** вкладка остаётся с экраном
  «Аутентификация отклонена», а ввод пароля заново — по кнопке (модалка больше не
  выскакивает сама).
- ⏱️ Таймаут подключения и keepalive (настраиваются) — «мёртвое» соединение
  детектируется автоматически.
- 🔑 **Сохранение секретов в системный keychain** (macOS Keychain / Windows
  Credential Manager) — чекбокс «Сохранить» при подключении, автоподключение.
- 🛡️ **Проверка отпечатка хоста** (vterm-managed `known_hosts.json`, SHA256):
  политики strict / trust-on-first-use / accept-any.

**Список серверов**
- 🗂️ Профили серверов сохраняются в **JSON** в конфиг-каталоге ОС.
- ➕ Модальное окно добавления/редактирования: псевдоним, host/IP, порт, логин,
  метод аутентификации и **теги**. Кнопка «Добавить сервер» (иконка «лист с +») —
  в тулбаре списка серверов, рядом с «Новая папка».
- 📂 **Иерархические папки** (любая вложенность, пустые папки сохраняются):
  создание/удаление/переименование, **перетаскивание сервера в папку мышью**
  (распределение по папкам — только так), сворачивание пиктограммой +/−;
  **поиск** по списку (alias/host/логин/папка/теги).

**SFTP**
- 📁 **SFTP-менеджер файлов** (правая панель, по умолчанию свёрнута в полоску;
  разворачивается и подключается кнопкой **Connect** внутри панели): просмотр и навигация,
  создание/удаление папок, **создание пустого файла** (иконка «лист с +» рядом с
  «Новая папка»), **upload/download** через нативный диалог, **drag-and-drop**
  загрузка, индикатор прогресса.

**Интерфейс и UX (Фаза 4)**
- 🎨 **Темы оформления** терминала и UI (применяются в реальном времени): Catppuccin,
  Dracula, Nord, Gruvbox, Solarized, One Dark, Tokyo Night и ретро — Fallout (зелёный
  фосфор), Amber CRT, IBM 3270, Commodore C64; плюс **пользовательская тема**
  (свои цвета фона/текста/курсора и 16-цветной ANSI-палитры).
- ⚙ **Панель настроек**: язык интерфейса, тема, шрифт (семейство/размер/интервал),
  курсор, scrollback, bell, копирование по выделению, параметры соединения,
  host-key-политика и др.
- 🌐 **Язык интерфейса** (English / Русский, переключается в **Настройки → Язык**,
  применяется мгновенно). Перевод покрывает весь UI **и нативное меню** приложения;
  добавление нового языка —
  одна запись в реестре языков плюс словарь (см. `src/lib/i18n/`). Доменные/технические
  термины (`CPU`, `RAM`, `Load average`, `Disk I/O`, `IP`, `SFTP`, `SSH`, `keychain`,
  `passphrase` и т.п.) намеренно **не переводятся**. По умолчанию — English.

  > **Что такое bell.** «Bell» — реакция терминала на управляющий символ BEL
  > (ASCII `0x07`, он же `\a`). Его шлёт удалённая программа, чтобы привлечь внимание:
  > неоднозначное автодополнение по Tab, ошибка ввода в shell, уведомления из
  > `tmux`/`vim` и т.п. (проверить можно командой `printf '\a'`). В настройках
  > выбирается реакция: **None** — игнорировать, **Sound** — короткий звуковой сигнал,
  > **Visual** — кратковременная подсветка терминала акцентным цветом (когда звук
  > нежелателен). По умолчанию — None.
- 💾 **Бэкап настроек** (в панели ⚙ Settings): **Export backup…** сохраняет список
  серверов, их настройки, структуру папок и параметры приложения в один JSON-файл;
  **Import backup…** восстанавливает их (с подтверждением, т.к. заменяет текущие).
  Пароли/passphrase **не** попадают в файл — они остаются в системном keychain.
- 📊 **Нижний статус-бар** (как в MobaXterm): иконка ОС, hostname/пользователь,
  **график загрузки ЦП** + проценты, ОЗУ и свободное место на диске — метрики
  собираются отдельным exec-каналом раз в N секунд.
- 🧩 **Регулируемые и сворачиваемые панели**: ширину левой панели и SFTP можно тянуть
  мышью, каждую можно свернуть в тонкую полоску (состояние запоминается).
- 📋 **Копирование/вставка** (copy-on-select, ⌘/Ctrl-сочетания, средняя кнопка),
  **подтверждение закрытия вкладки** с активной сессией, окно **Help & About**.
  Во **всех** полях ввода (пароль, host/порт/логин в форме сервера, имена папок,
  поиск, ⌘K) работают **⌘V/Ctrl+V** (вставка), а также копирование/вырезание/
  выделение (⌘/Ctrl + C/X/A) — через единый глобальный обработчик; чтение буфера
  идёт нативно через бэкенд, поэтому WebKit не показывает запрос «Paste».

**Качество и безопасность (Фазы 5–6)**
- 🧪 **Тесты и покрытие**: Rust-юниты (`cargo test`), Vitest (юнит + компонентные),
  E2E (WebdriverIO + tauri-driver) против тестового SSH; гейты покрытия в CI
  (≥ 90 % чистой логики, ≥ 80 % в целом). Подробно — в [TESTS.md](TESTS.md).
- 🔒 **Безопасность и автономность**: строгий CSP, минимальные capabilities,
  SAST-гейты (`cargo audit`/`deny`, `pnpm audit`, Semgrep, Trivy), секреты только в
  keychain (`zeroize`). Приложение **полностью офлайн**, кроме исходящего SSH —
  закреплено тест-гейтами. Модель — в [SECURITY.md](SECURITY.md).

**Дизайн и UX (Фаза 7)**
- 🎨 Единая **иконография** (line-SVG реестр вместо эмодзи), **светлые темы** +
  визуальный пикер с образцами, превью шрифта, **поиск по настройкам**.
- ⌨️ **Командная палитра ⌘K / Ctrl+K**: быстрый доступ к серверам, папкам, действиям
  и настройкам с клавиатурной навигацией.
- 🔔 **Тосты/уведомления** для ошибок и статусов операций (неблокирующие).
- ♿ **Доступность (a11y)**: фокус-трап и семантика диалогов, роуминг-навигация по
  вкладкам, дерево серверов `role="tree"`, ARIA на интерактивных элементах.
- ✨ **Пустые состояния/онбординг**, плавные **анимации/переходы** (с уважением к
  `prefers-reduced-motion`), **расширенный статус-бар** (uptime, swap, disk I/O,
  сеть, соединения, температура, top-процесс, индикатор передач SFTP и др.).

**Документация (Фаза 8)**
- 📖 **Встроенная инструкция**: вкладка **«Инструкция»** в окне Help (рендер
  README) и пункт меню **Help → Инструкция**; команда в палитре ⌘K.
- 🆔 Контакты автора в **About**; пошаговая установка на Windows (см. ниже).

**Расширенный мониторинг (Фаза 9)**
- 📈 **Страница подробного мониторинга** — полноэкранный оверлей с **графиками**
  (ЦП/load/ОЗУ/swap), **загрузкой по ядрам**, детализацией памяти, **полным
  списком файловых систем** (место + **inodes**), сетью и состояниями TCP. Открыть:
  кнопкой в статус-баре (иконка-график), командой **⌘K → «Мониторинг сервера»** или
  пунктом меню **Мониторинг** (⌘/Ctrl+Shift+M). **Данные тянутся только пока
  страница открыта.**
- 🚦 **Пороги с цветовой индикацией**: для числовых метрик (ЦП, ОЗУ, swap, диск,
  inodes, дескрипторы, load, температура) задаются «средний» и «предельный» уровни;
  превышение среднего — **жёлтый** текст, предельного — **красный**. Работает и в
  статус-баре, и на странице. Настройки → Status bar → «Пороги».
- 🧮 **Дескрипторы и inodes** — чтобы заранее видеть исчерпание ресурсов
  («невозможно создать файл»): системные FD (`/proc/sys/fs/file-nr`), `ulimit -n`,
  inodes по каждому разделу.
- 📦 **Pending updates** (apt/dnf/yum/pacman/zypper/apk) и флаг «требуется
  перезагрузка» — подгружаются **лениво**, только на странице.
- 🛑 **Полное отключение статус-бара** в настройках: бар перестаёт **опрашивать
  сервер**, при этом страница мониторинга остаётся доступной (⌘K/меню).

**Логи и текст (Фаза 10)**
- 🔎 **Поиск по всему буферу терминала** — не только по видимому экрану, а по всему
  scrollback (десятки тысяч строк). Открыть: **⌘F** (macOS) / **Ctrl+Shift+F**
  (Windows/Linux). Поле поиска с **счётчиком совпадений**, тумблерами **«учитывать
  регистр / слово целиком / regex»**, навигацией **Enter / Shift+Enter** (и кнопками
  ↑/↓) и кнопкой **«копировать совпадение с контекстом»** (строка ±5). Опции
  регистр/слово/regex **запоминаются**, при ошибке в regex — подсказка. Совпадения
  подсвечиваются цветами активной темы, активное — плавно «нарастает» при переходе.
- 🎨 **Подсветка логов по правилам (regex):** настраивается в настройках («Логи и
  текст») — имя, регулярное выражение, цвет (из палитры темы), вкл/выкл, учёт
  регистра, **стили** (жирный / фон / **подсветка всей строки**) и **порядок**
  правил (↑/↓ — приоритет). Из коробки: `ERROR/FATAL` — красным жирным, `WARNING` —
  жёлтым, `SUCCESS/OK` — зелёным, IP-адреса — синим. Подсветка идёт **цветами текущей
  темы** и **только в обычном выводе** (полноэкранные программы вроде `vim`/`htop` не
  затрагиваются).
- 🔗 **Кликабельные ссылки:** `http(s)`-ссылки в выводе открываются во внешнем
  браузере по клику (через системный опенер; офлайн-инвариант сохранён).
- 🧱 **Структурный просмотр логов (мультиформатный):** тумблер **raw↔structured**
  (иконка-таблица в углу терминала). В structured-режиме строки распознаются на лету с
  **авто-определением формата**: **JSON** (NDJSON), **logfmt** (`key=value`), **syslog**
  (`/var/log/syslog`, `journalctl`), **nginx/apache** access-логи и **dmesg** — всё в
  единую **таблицу** (Время / Уровень / Сообщение) с цветом уровня — локальный мини-аналог
  Kibana/Loki. Можно **добавлять колонки по любым полям** (пикер колонок), фильтровать
  **чипами по уровню** (error/warn/info/debug) и текстом, **разворачивать строку** (детали
  + **копирование**), а **ширину любой колонки можно менять мышью** — потяните за правый
  край заголовка (курсор-стрелка ↔; при переполнении таблица прокручивается по горизонтали).
  Таблица **автопрокручивается** в режиме `tail -f`, а **время
  приводится** к локальному виду (epoch/ISO/syslog). Кнопка **«Clear»** (с подтверждением)
  даёт чистый старт перед просмотром другого лога. Имена полей понимаются **без учёта
  регистра** — `journalctl -o json` (`MESSAGE`/`PRIORITY`/`SYSLOG_TIMESTAMP`) работает из коробки.
- ⚙️ **Раздел настроек «Логи и текст»** с **мастер-переключателем**: один чекбокс
  полностью отключает все доработки этой фазы — терминал ведёт себя как раньше
  (плюс отдельные тумблеры по фичам: поиск, подсветка, JSON-вид).

**Запись сессий (Фаза 11) ✅**
- ⏺️ **Запись сессий** в формате **asciicast v2**: кнопка **REC** в полосе вкладок —
  **по сессии** (каждая вкладка пишется отдельно), красный индикатор на вкладке, старт/стоп
  также из ⌘K. Пишется весь ввод-вывод с таймингами **на бэкенде**; файлы — в каталоге
  `recordings/` приложения. В начало записи подставляется **текущая строка приглашения**
  (например `root@host:~#`), чтобы первая команда тоже шла с приглашением.
- 🎚️ **Режим записи** (Settings → «Запись сессий»): полный с таймингами (как видео),
  полный без таймингов, или **только команды** (по одной строке на Enter — без лишних
  нажатий и правок; пустые нажатия Enter не записываются). В режимах **без таймингов** команда в плеере **«печатается»** с
  постоянной скоростью, а **вывод появляется сразу целиком** (не построчно); оба таких режима
  («только команды» и «полностью без таймингов») играются **одинаково и на одной замедленной
  шкале** скоростей (см. плеер).
- 🔒 **Приватность:** ввод после промптов `password:` **маскируется** (настройка
  **Settings → «Запись сессий»**, по умолчанию вкл); SSH-пароль в запись не попадает.
- 💾 **Сохранение после остановки:** при остановке записи всплывает окно — задать **заголовок**
  и **краткое описание** и **Сохранить** либо **Удалить** запись. Заголовок и описание потом
  можно **отредактировать** карандашом в библиотеке.
- 📚 **Библиотека записей** (⌘K → «Записи» или кнопка в полосе вкладок): список с **заголовком,
  описанием и сервером** (имя сервера сохраняется даже после переименования заголовка), датой и
  размером, **поиск** (по серверу / описанию / дате) и **многоуровневую сортировку** (дата/сервер/
  размер — цепочкой приоритетов), **редактирование** (карандаш), удаление **с подтверждением**,
  воспроизведение и **экспорт** в 4 формата (выбор формата — окно **поверх** библиотеки):
  **Markdown-«ранбук»** (шапка с метаданными → нумерованные команды + вывод в блоках; лучший
  для ИИ), **только команды**, **транскрипт** (чистый текст, ANSI снят) и **сырой `.cast`**.
  **Во все экспорты добавляется блок метаданных сессии:** сервер, hostname, IP, пользователь,
  версия ОС и ядра, время старта/окончания и длительность, режим записи, версия приложения
  (для удобного анализа). Чтобы скормить ИИ — снаружи; приложение остаётся **офлайн** (ИИ-вызовов внутри нет).
- ▶️ **Встроенный плеер:** открой запись из библиотеки и проиграй её как «видео» —
  **play/pause**, **перемотка** (слайдер) и **скорость**, время `M:SS`. Скорости зависят
  от записи: с реальными таймингами — `0.5/1/2/4×` (старт `1×`); без таймингов («команды +
  вывод») — **вся шкала на ступень медленнее** `0.25/0.5/1/2×` (старт `0.5×`), чтобы
  «печатание» команд читалось спокойнее. Терминал **сам следит за низом** вывода и
  **прокручивается колесом/полосой назад** по истории (без лишней внешней полосы).
  Воспроизведение в read-only терминале, офлайн.
- 🤖 **Автозапись для прод-серверов:** в форме сервера — флажок **«Автозапись сессий»**. Для
  таких серверов запись **начинается автоматически** при подключении (аудит-след каждой
  сессии) и финализируется при отключении; реконнект создаёт новую запись.
- ⏸️ **Пауза для экономии диска:** запись **не пишет фоновые потоки** (`tail -f`, `top`), когда
  вкладка не на виду. Переключение на другую вкладку **ставит запись на паузу**; простой
  активной вкладки дольше N секунд (поле **«Пауза записи при простое»** в настройках, по
  умолчанию 20с, `0` = выкл) тоже паузит — а любое нажатие в консоли мгновенно **возобновляет**.

## Доступность и горячие клавиши

vterm управляется с клавиатуры и предоставляет доступную семантику для скринридеров
(результат UX-ревизии Фазы 7).

### Горячие клавиши

| Действие | Сочетание |
|----------|-----------|
| **Командная палитра** | `⌘K` / `Ctrl+K` |
| **Поиск по буферу терминала** | `⌘F` / `Ctrl+Shift+F` |
| Навигация по совпадениям поиска | `Enter` / `Shift+Enter` |
| Копировать выделение | `⌘C` / `Ctrl+Shift+C` |
| Вставить | `⌘V` / `Ctrl+Shift+V` |
| Прерывание (SIGINT) | `Ctrl+C` |
| Закрыть диалог / палитру | `Esc` |
| Переключение вкладок | `←` / `→` (по кругу), `Home` / `End` |
| Активировать вкладку под фокусом | `Enter` / `Space` |
| Подключиться к выбранному серверу | двойной клик по серверу |

### Командная палитра (⌘K)

`⌘K` / `Ctrl+K` открывает палитру с быстрым поиском по **серверам** (подключение),
**папкам** (добавить сервер в папку), **действиям** и **настройкам**. Навигация:
`↑` / `↓` — выбор, `Enter` — выполнить, `Esc` — закрыть.

### Доступность диалогов

Все модальные окна (форма сервера, ввод пароля **Connect**, создание/переименование
папки, диалоги подтверждения) построены на общем компоненте `Modal` и обеспечивают:

- **автофокус** первого поля при открытии;
- **фокус-трап** — `Tab` / `Shift+Tab` ходят по кругу внутри окна и не уходят на фон;
- **возврат фокуса** на элемент, открывший окно, после закрытия;
- закрытие по `Esc` и семантику `role="dialog"` / `aria-modal` / `aria-label`.

### Навигация по вкладкам терминалов

Ряд вкладок реализует ARIA-паттерн *tablist* с роуминг-фокусом: в общий порядок `Tab`
включена только активная вкладка, а `←` / `→` (с заворотом), `Home` / `End`
переключают вкладки; `Enter` / `Space` активируют вкладку под фокусом. Список серверов
слева — дерево (`role="tree"`).

### macOS: полный доступ с клавиатуры

Если в диалоге `Tab` перескакивает только между текстовыми полями и **не попадает на
кнопки**, включите системную опцию: **Системные настройки → Клавиатура → «Навигация с
помощью клавиатуры»** (Full Keyboard Access). Это ограничение macOS, а не приложения.

## Архитектура

Главный принцип: **вся «тяжёлая» логика живёт в Rust-бэкенде**, а фронтенд —
тонкий UI. Граница между ними проходит по двум каналам Tauri:

```
┌───────────────────────────────┐         ┌──────────────────────────────┐
│        Фронтенд (WebView)      │         │        Бэкенд (Rust)         │
│  SvelteKit + Tailwind + (xterm)│         │           Tauri 2            │
│                                │         │                              │
│  +page.svelte ── UI            │         │  lib.rs ── #[tauri::command] │
│        │                       │         │     ├─ list_servers          │
│  lib/api.ts ──invoke()────────────────▶  │     ├─ add_server            │
│        ▲                       │ команды │     ├─ delete_server         │
│        │                       │         │     └─ connect_session       │
│  xterm.js ◀───event()──────────────────  │  model.rs ── ServerProfile   │
│   (поток терминала, Фаза 1)    │ события │  AppState (Mutex<…>)         │
└───────────────────────────────┘         └──────────────────────────────┘
```

- **Команды** (`invoke`) — запрос/ответ: фронтенд вызывает функции Rust
  (`list_servers`, `add_server`, …). Все вызовы инкапсулированы в
  [src/lib/api.ts](src/lib/api.ts), UI не работает со строками-именами команд
  напрямую.
- **События** (`event`) — поток данных от бэкенда к фронту. В Фазе 1 по этому
  каналу пойдёт вывод PTY с удалённого сервера прямо в xterm.js, а нажатия клавиш
  пойдут обратно командой.
- **Модель данных** ([src-tauri/src/model.rs](src-tauri/src/model.rs)) сериализуется
  через `serde` с `rename_all = "camelCase"`, чтобы поля совпадали с TypeScript-типами
  ([src/lib/types.ts](src/lib/types.ts)). Пароли в модели **не хранятся** — они
  пойдут в системный keychain (Фаза 2).

## Установка и запуск (разработка)

```bash
# 1. Установить JS-зависимости
pnpm install

# 2. Запустить приложение в режиме разработки
pnpm tauri dev
```

`pnpm tauri dev` поднимает Vite на `http://localhost:1420`, компилирует Rust-бэкенд
(первая сборка — 1–2 минуты, дальше быстрее за счёт кэша) и открывает нативное окно
с горячей перезагрузкой фронтенда.

> **Если `pnpm` или `cargo` не находятся** (`command not found`) — инструменты стоят
> в нестандартных путях. Откройте новую вкладку терминала (профиль перечитается) или
> выполните в текущей сессии:
>
> ```bash
> export PATH="$HOME/Library/pnpm/bin:$PATH"   # pnpm
> source "$HOME/.cargo/env"                     # cargo
> ```

## Установка на Windows (с нуля)

Пошагово для **чистой Windows-машины** после того, как репозиторий уже скопирован
(`git clone` или распакованный архив). Все команды выполняются в **PowerShell**.

### 1. Системные компоненты

Проще всего поставить зависимости через **winget** (встроен в Windows 10 1709+ /
Windows 11). Открой PowerShell и выполни:

```powershell
# Rust (компилятор + cargo) через rustup
winget install --id Rustlang.Rustup -e

# Node.js LTS (даёт node + npm; pnpm включим ниже через corepack)
winget install --id OpenJS.NodeJS.LTS -e

# Microsoft C++ Build Tools — нужен линковщик MSVC для сборки Rust
winget install --id Microsoft.VisualStudio.2022.BuildTools -e `
  --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"

# WebView2 Runtime — движок окна Tauri (на Windows 11 обычно уже стоит)
winget install --id Microsoft.EdgeWebView2Runtime -e
```

> Если `winget` недоступен — поставь те же компоненты вручную:
> [rustup](https://rustup.rs/) · [Node.js LTS](https://nodejs.org/) ·
> [Build Tools for Visual Studio](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
> (отметь рабочую нагрузку **«Разработка классических приложений на C++»**) ·
> [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/).

**Закрой и открой PowerShell заново** (или перелогинься), чтобы обновился `PATH`
и стали видны `cargo`, `node`, `corepack`.

### 2. Активировать pnpm

```powershell
corepack enable
corepack prepare pnpm@latest --activate
```

Проверка, что всё на месте:

```powershell
rustc --version    # напр. rustc 1.9x.x
node  --version    # напр. v20.x
pnpm  --version    # напр. 9.x
```

### 3. Установить зависимости и запустить

Из корня репозитория:

```powershell
# JS-зависимости
pnpm install

# Запуск в режиме разработки (первая Rust-сборка — 1–2 минуты)
pnpm tauri dev
```

### 4. Собрать дистрибутив (опционально)

```powershell
pnpm tauri build
```

Готовые файлы появятся в `src-tauri\target\release\bundle\` — установщики `.msi`
(в `msi\`) и/или NSIS `.exe` (в `nsis\`); портативный `vterm.exe` —
в `src-tauri\target\release\`.

> **Возможные проблемы (Windows).**
> - *`link.exe` not found* / ошибка линковки — не доустановлены **C++ Build Tools**
>   (шаг 1) или не перезапущен терминал.
> - *Окно не открывается / белый экран* — не установлен **WebView2 Runtime**.
> - *`pnpm` не распознан* — не выполнен `corepack enable` (шаг 2) или не перезапущен
>   терминал.

## Сборка дистрибутивов

```bash
pnpm tauri build
```

Команда собирает фронтенд, компилирует Rust в release и упаковывает нативный
дистрибутив **только для текущей ОС**.

⚠️ **Важно: один файл, работающий и на Windows, и на macOS, невозможен** — у систем
разные форматы исполняемых файлов (PE/`.exe` vs Mach-O). Поэтому на каждом этапе
собираются **два отдельных артефакта**, по одному на ОС. Кросс-компиляция между
macOS и Windows на одной машине для Tauri-приложения нерабочая (нужны системный
WebView и линковщик целевой ОС), поэтому **оба файла собираются в CI** — см. ниже.

Результат локальной сборки появляется в `src-tauri/target/release/bundle/`:

- **macOS** — `.app` (портативный бандл, можно перетащить куда угодно) и `.dmg`
  в подкаталогах `macos/` и `dmg/`.
- **Windows** — `.msi` (WiX) и/или установщик NSIS (`.exe`) в `msi/` и `nsis/`.
  Сам `vterm.exe` из `target/release/` — это портативный файл (нужен лишь системный
  WebView2 Runtime).

> Для распространения без предупреждений ОС потребуется подпись кода: Apple
> Developer ID + нотаризация на macOS и code-signing сертификат на Windows. Это
> вынесено в Фазу 13 (см. [ROADMAP.md](ROADMAP.md)).

## Непрерывная сборка (CI): два файла на каждом этапе

Чтобы на каждом этапе гарантированно получать **оба** дистрибутива, настроен
**GitLab CI** [.gitlab-ci.yml](.gitlab-ci.yml) с двумя задачами сборки — на
macOS- и Windows-раннерах:

| Событие | Что происходит |
|---------|----------------|
| push в дефолтную ветку, Merge Request, ручной запуск | Сборка обеих ОС, файлы — в **артефактах пайплайна** (`vterm-macos`, `vterm-windows`) |
| push тега вида `v1.2.3` | Дополнительно создаётся **GitLab Release** для обеих ОС |

macOS собирается как **universal** (Intel + Apple Silicon). Конфиг рассчитан на
**self-hosted раннеры**: в [.gitlab-ci.yml](.gitlab-ci.yml) указаны теги-плейсхолдеры
`macos` / `windows` / `linux` — замените их на теги своих раннеров
(*GitLab → Settings → CI/CD → Runners*). Раннер macOS должен иметь Xcode CLT, раннер
Windows — VS C++ Build Tools и WebView2 Runtime; Rust и pnpm CI ставит сам
(идемпотентно). Сборка активируется после публикации репозитория в GitLab; локально
по-прежнему доступна сборка только под текущую ОС через `pnpm tauri build`.

## Тестирование

Проект покрыт многослойным набором тестов (Фаза 5): Rust-юниты (`cargo test`),
фронтенд-юниты и компонентные тесты на **Vitest**, а также E2E на
**WebdriverIO + tauri-driver** против тестового SSH-сервера. CI блокирует сборку
дистрибутивов, пока линтеры, тесты и гейты покрытия (≥ 90 % для чистой логики,
≥ 80 % в целом) не пройдут.

```sh
cargo test --manifest-path src-tauri/Cargo.toml   # Rust-юниты
pnpm test            # фронтенд: юнит + компонентные тесты
pnpm test:coverage   # то же + покрытие и гейты
```

📖 **Полная документация по тестам — в [TESTS.md](TESTS.md):** слои, как
запускать каждый вид, тестовый SSH-сервер, покрытие, структура CI и как добавить
свой тест.

## Сеть и автономность

vterm работает **полностью офлайн**. Единственный сетевой доступ — исходящие
**SSH-подключения к серверам, которые вы сами добавили** (порт 22 или указанный в
профиле). Приложению **не нужен** доступ в интернет для работы.

- Нет CDN, Google Fonts, телеметрии и аналитики: моноширинные шрифты встроены в
  бандл (`@fontsource`, копируются при сборке), цвета/темы — локальные.
- Нет runtime-запросов `fetch`/WebSocket к внешним сервисам. Это закреплено
  тестом-гейтом [autonomy.guard.test.ts](src/lib/autonomy.guard.test.ts), который
  падает в CI, если в исходниках появится сетевой вызов.
- Внешние ссылки в окне **About** открываются в системном браузере **только по
  явному клику** пользователя (через `tauri-plugin-opener`).
- Секреты хранятся локально в системном keychain; профили/папки — в JSON в
  конфиг-каталоге. Ничего не синхронизируется в облако.

Воспроизводимость сборки: lock-файлы (`pnpm-lock.yaml`, `Cargo.lock`) закоммичены;
CI ставит зависимости через `pnpm install --frozen-lockfile`.

## Запуск готового приложения

### macOS
1. Открыть `.dmg`, перетащить **vterm.app** в `/Applications`.
2. Запустить. Если сборка не подписана, при первом запуске:
   правый клик по приложению → **«Открыть»** → подтвердить
   (либо разрешить в *Системные настройки → Конфиденциальность и безопасность*).

### Windows
1. Запустить `.msi` или NSIS-`.exe` и пройти установку.
2. Запустить **vterm** из меню «Пуск». Если установщик не подписан, SmartScreen
   может показать предупреждение — *«Подробнее» → «Выполнить в любом случае»*.

## Возможные проблемы

- **`cargo` не найден после установки rustup** — добавьте Cargo в `PATH`
  (`source "$HOME/.cargo/env"` или перезапустите терминал).
- **pnpm блокирует сборку нативных пакетов** (`Ignored build scripts: esbuild`) —
  разрешение уже прописано в [pnpm-workspace.yaml](pnpm-workspace.yaml)
  (`allowBuilds: { esbuild: true }`); достаточно выполнить `pnpm install` повторно.
- **Долгая первая сборка Rust** — это нормально: компилируется всё дерево
  зависимостей Tauri. Последующие сборки используют кэш в `src-tauri/target/`.
