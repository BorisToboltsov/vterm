# AGENTS.md — правила разработки vterm

Свод **обязательных правил** для любой работы в этом репозитории — единственный файл правил
процесса: `CLAUDE.md` только подключает его импортом `@AGENTS.md`, своей копии правил у него
нет. Файл загружается в начале каждой сессии — держи его компактным: сюда только то, что нужно
соблюдать, подробности живут в `docs/`.

## Definition of Done (каждая задача)

1. **Тесты обязательны.** На каждую фичу и фикс — тесты. Новый контракт закрепляй гейтом
   и **проверяй его на живом нарушении**, а не только на зелёном коде. Контракт, который виден
   в одном месте кода (импорт, вызов, атрибут), — правило линтера в [lint/vterm.js](lint/vterm.js)
   с кейсами в `lint.guard.test.ts`; связь нескольких мест — `*.guard.test.ts`, а поведение —
   тест контроллера.
   **Гейт читает исходник сканером, а не регуляркой по разметке** — CodeQL гоняется только в
   CI и роняет PR на этом и в тестах: `<!-- … -->`, `<style>` и прочие блоки снимай сканером
   (`stripBlocks`, как в [panelcontainer.guard](src/lib/layout/panelcontainer.guard.test.ts)), а не
   `.replace(/<!--…-->/, "")` (`js/incomplete-multi-character-sanitization`); разметку отделяй по
   `lastIndexOf("</script>")`, регулярок с `<script` не пиши (`js/bad-tag-filter`); строку для
   `RegExp` экранируй полным набором, обратную косую черту тоже — `/[.*+?^${}()|[\]\\]/g`
   (`js/incomplete-sanitization`).
   Держит правило `vterm/scan-blocks`: `pnpm lint` ловит это до пуша.
   **Переводы строк — LF на всех ОС, и Windows тоже:** так велит `.gitattributes`
   (`* text=auto eol=lf`, гейт `ci.guard`). Без него Windows-раннер выкачивал исходники с CRLF,
   и гейт, искавший маркер с `\n`, проходил на macOS и Linux, а падал только в Rust (Windows) —
   четыре раза (#85, #168, #175, #182), и каждый раз чинили один тест. `.gitattributes` не
   убирай и не выводи из LF ни одного шаблона; понадобится CRLF (`.bat`) — сперва решение и
   правка гейта, а не тихое исключение.
2. **Гейты зелёные.** По ходу работы гоняй затронутые (команды ниже); **перед слиянием в
   `main` и перед хотфиксом — полный прогон целиком**. Красное — чини, не обходи.
3. **Документация наравне с кодом.** Пройди по «Карте документации» выше и обнови **каждый**
   файл, чей жанр задет: минимум — CHANGELOG (что изменилось — в «Готовится») и ROADMAP, плюс
   INVARIANTS, если появился контракт. Фича без отражения в доках — **незавершённая**.
4. **Перевод наравне с кодом.** Любой видимый текст — только через `t()` и **сразу на всех**
   языках (см. ниже). Частичный перевод не компилируется.
5. **Версию не трогаем** — её поднимает выпуск (см. «Версионирование»).
6. **Диагностика наравне с кодом** (ADR 0063). Новая операция с побочным эффектом — событие
   `info` её начала и итога; новый путь отказа — `warn`/`error` с причиной и тест на это
   (`captureDiag()` во фронте, `diag::Capture` в Rust); новый источник — в общий список
   (`DIAG_SOURCES` ↔ `diag::SOURCES`); событие, которое прочтёт человек, — с кодом из
   `DIAG_CODES` и заголовком `diag.code.*` на всех языках. Секреты и содержимое — никогда. Ошибку
   не глушат молча: обработать или записать (`.log_debug`/`.log_warn` в Rust, `swallow()` во
   фронте, отказ `call()` — `writtenByCall`), и описание — словами: что не случилось и чем это
   грозит. Сколько писать, гейт не решит — это решение задачи, как и тесты.

### Полный прогон

```sh
source "$HOME/.cargo/env"                       # cargo не в PATH свежей сессии
export PATH="$HOME/Library/pnpm/bin:$PATH"      # standalone pnpm

cargo fmt    --manifest-path src-tauri/Cargo.toml --all --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test   --manifest-path src-tauri/Cargo.toml
pnpm check
pnpm lint
pnpm test:coverage
pnpm build
```

Все семь должны быть зелёными. `pnpm lint` — ESLint с правилами проекта: исключение из
правила — комментарий `eslint-disable … -- причина`, и исключение, которому нечего
подавлять, роняет прогон. Гейты покрытия (≥ 90 % чистая логика, ≥ 80 % в целом)
настроены в [vitest.config.ts](vitest.config.ts) и **роняют** прогон. `pnpm build` нужен
отдельно от `pnpm check`: `check` — это только типы (`svelte-check`), а `vite build` ловит
поломки production-сборки, которые типы пропускают (`pnpm tauri build` собирает тот же бандл).

### Свежие lockfile раз в месяц

```sh
cargo update --manifest-path src-tauri/Cargo.toml   # в пределах диапазонов Cargo.toml
pnpm update                                          # в пределах диапазонов package.json
```

Dependabot двигает только **прямые** зависимости; исправления транзитивных (так ушли `unic-*`
вместе с пятью исключениями advisory) приходят только так. Тогда же — версия Rust: `channel`
в [rust-toolchain.toml](rust-toolchain.toml) и `FROM rust:…` в
[e2e/linux/Dockerfile](e2e/linux/Dockerfile) на текущий stable, обе разом (гейт `ci.guard`):
Dependabot её не двигает. После — полный прогон: `cargo deny` упадёт на исключении, которому
стало нечего исключать, — сними его из `deny.toml`; новый clippy — чини код.

### Очистка после зелёного прогона

```sh
rm -rf src-tauri/target/release/bundle    # .app/.dmg/.msi/.exe
./scripts/clean-launchservices.sh         # macOS: снять мёртвые регистрации vterm.app
```

**Порядок важен** — сперва `rm`, потом скрипт. Каждый `tauri build` регистрирует свой
`vterm.app` в LaunchServices; после удаления бандла запись становится фантомной, и за
десятки пересборок Finder начинает резолвить `su.vcore.vterm` в мёртвый путь — приложение
молча не открывается. Скрипт идемпотентен и чистит только несуществующие пути `vterm.app`.
Это дефект машины разработчика, а не код. Инкрементальный кэш Rust (`target/debug`,
`release/deps`) **не трогаем** — он держит следующую сборку быстрой.

## i18n — ЗАКРЕПЛЕНО

- **Главное правило.** Весь видимый текст — на **всех** языках, через `t()`. Хардкод строк
  запрещён (надписи, кнопки, `title`/`aria-label`, тосты, тексты ошибок). Ключ добавляется
  **сразу во все** словари — иначе `pnpm check` падает.
- **Где живёт.** [src/lib/i18n/](src/lib/i18n/): `locales.ts` (реестр, `DEFAULT_LOCALE=en`),
  словарь на язык — `en.ts` (канонический набор ключей) и `ru.ts`, `messages.ts` (сборка
  словарей), `translate.ts` (чистые resolve/interpolate), `index.ts` (`t()` реактивен от
  `settings.language`). Новый язык — свой файл и запись в `LOCALES`.
- **Не переводим** доменные термины (`CPU`/`RAM`/`SSH`/`SFTP`/`IP`/`PSI`/`inodes`, имена тем).
- **Логику не завязывай на перевод:** храни канонический английский в состоянии, локализуй
  при выводе. Поиск по настройкам — двуязычный (EN+RU в одной строке).
- **Язык интерфейса меняется только через `setLocale()`** — двусторонний бинд к
  `settings.language` пишет мимо пересева промптов ИИ (правило `vterm/locale-binding`).
- **Нативное меню** — только на macOS (строится в Rust, метки пушатся с фронта через
  `set_menu_language`). На Windows/Linux окно безрамочное и меню Файл/Справка рисует
  `TitleBar.svelte` — те же `menu.*`-ключи (ADR 0011, инвариант «UI и оформление»).
- Переменную `{#each … as t}` не называй `t`: она закрывает функцию перевода (`vterm/each-as-t`).
- **Текст события диагностики — не интерфейс** (ADR 0063): технический английский, мимо `t()` —
  его ищут в коде и пересылают. Всё вокруг него на экране (уровни, источники, кнопки, заголовок
  события с кодом — `diag.code.*`) — через `t()`.
- **Мёртвых ключей нет.** Убрал последнее использование ключа — убери ключ из всех словарей
  (гейт `i18nkeys.guard`): тип `t()` проверяет, что ключ есть, а не что его кто-то спрашивает.

## Версионирование

Схема `<major>.<minor>.<patch>`:

- **major** — публичный рубеж; поднимается только на нём. `1.0.0` был первым.
- **minor** — плановый выпуск, в «Готовится» которого есть «Новое»; `patch` сбрасывается в 0.
- **patch** — плановый выпуск из одних исправлений или хотфикс.

Номер даёт выпуск, а не PR — правила в INVARIANTS «Выпуски», шаги в [docs/CI.md](docs/CI.md#как-выкатить-релиз).

До `1.0.0` вторая цифра называлась «фазой» и совпадала с её номером в ROADMAP
(`0.<фаза>.<фикс>`) — так подписаны старые записи CHANGELOG и ROADMAP; новые называй
minor и patch. Пререлизных суффиксов нет: Tauri их не бандлит.

**Версия лежит в одном месте — [package.json](package.json)**, и правится одной командой (её
зовут поезд и хотфикс):

```sh
pnpm version:set 1.1.0
```

[scripts/set-version.mjs](scripts/set-version.mjs) разносит её в `Cargo.toml`, `Cargo.lock`
(cargo не умеет ссылок, нужен литерал) и в плашку версии `README.md` (статичный бейдж
shields.io, ничем не резолвится). `tauri.conf.json` ничего не хранит — там стоит
ссылка `"version": "../package.json"`, которую Tauri резолвит сам; приложение читает версию
через `getVersion()`, то есть из того же источника. CI берёт её тоже из `package.json` —
достать `.version` из `tauri.conf.json` теперь значит получить строку `"../package.json"`
и собрать файл с таким именем. Расхождение и откат к литералу ловит гейт
`version.guard.test.ts`. Руками эти файлы не правь.

## Сборка: три артефакта

Каждая версия даёт три дистрибутива — macOS, Windows, Linux. Единый кросс-ОС файл невозможен,
кросс-компиляция Tauri между ОС нерабочая, поэтому собирает CI:
[release.yml](.github/workflows/release.yml) на раннерах GitHub по тегу `v*` — его ставит поезд или
человек для хотфикса. Локально доступна
сборка только под текущую ОС. Подробности — [docs/CI.md](docs/CI.md).

**Тег не собирает релиз из красного дерева:** `release.yml` первой джобой сверяет тег с
версией из `package.json` (чужой тег не собирает ничего), затем вызывает
[ci.yml](.github/workflows/ci.yml) целиком, матрица стоит под `needs`. Раскладка всех
workflow — [docs/CI.md](docs/CI.md); свойства цепочки поставки —
[SECURITY.md](SECURITY.md). Правя workflow, помни: экшены пинятся **по коммит-SHA** с
комментарием версии, а `${{ … }}` в `run:` не подставляется (только через `env`) — оба
правила держит гейт. Общие шаги — pnpm, Node, Rust, пакеты Tauri, кэш — только экшены
[.github/actions/](.github/actions/), в workflow их не копируют; у публикующего `release.yml`
кэша нет (гейт `ci.guard`). Изменил workflow — пересобери схемы (`pnpm ci:diagrams`) и опиши новую
джобу в [docs/CI.md](docs/CI.md): гейт `cidoc.guard`.

## Toolchain (нестандартный на этой машине)

- `cargo`/`rustc` через rustup, **не в PATH** свежей сессии → `source "$HOME/.cargo/env"`.
  Версия — из [rust-toolchain.toml](rust-toolchain.toml), та же, что в CI: rustup ставит её сам
  при первом `cargo` в репозитории, `stable` машины не используется.
- `pnpm` — standalone в `$HOME/Library/pnpm/bin` (corepack-шим сломан под Node 25) →
  `export PATH="$HOME/Library/pnpm/bin:$PATH"`.
- pnpm гейтит нативные build-скрипты; esbuild разрешён через `allowBuilds: { esbuild: true }`
  в [pnpm-workspace.yaml](pnpm-workspace.yaml) (**не** `onlyBuiltDependencies` в package.json).
- Запуск: `pnpm tauri dev` (первая Rust-сборка ~1–2 мин).
- `tauri-driver` (E2E) — только Linux/Windows. На macOS E2E и всё, что стоит под
  `cfg(target_os = "linux")`, собирается и гоняется в Linux-контейнере (нужен Docker):
  `pnpm e2e:linux`, `scripts/linux-box.sh <команда>` —
  [docs/TESTS.md](docs/TESTS.md#linux-в-контейнере).
