## 🔁 Принцип сборки: два файла на каждом этапе

Один файл, работающий и на Windows, и на macOS, **невозможен** (разные форматы
исполняемых файлов). Поэтому **на каждой фазе собираются два артефакта**:

- **macOS** — `.app` (портативный бандл) + `.dmg`;
- **Windows** — `.msi` / NSIS `.exe` (+ портативный `vterm.exe`).

**Definition of Done каждой фазы** включает зелёную CI-сборку обеих ОС. Механизм —
**GitLab CI** [.gitlab-ci.yml](.gitlab-ci.yml) (задачи `build:macos` + `build:windows`):
push в дефолтную ветку/MR/ручной запуск → артефакты пайплайна; push тега `v*` →
GitLab Release для обеих ОС.

> Локально доступна сборка только под текущую ОС (`pnpm tauri build`). Windows-файл
> на macOS не собрать — для него нужен Windows-раннер из CI.

## ✅ Фаза 1 — MVP: SSH-подключение и живой терминал

**Цель:** выбрал сервер → ввёл пароль → работаешь в живом shell (vim, htop, цвета).
Это ядро продукта и самая технически нетривиальная часть.

> **Статус:** завершено и проверено на реальном SSH-сервере (подключение, ввод/вывод,
> цвета работают).

Реализовано на `russh` **0.61** (используется `Channel::split()` —
read-half читает вывод, write-half шлёт ввод/resize, что снимает конфликт
заимствований).

### Бэкенд (Rust) — [src-tauri/src/ssh.rs](src-tauri/src/ssh.rs), [store.rs](src-tauri/src/store.rs), [lib.rs](src-tauri/src/lib.rs)
- [x] `russh` + `tokio`; SSH-сессия, аутентификация по паролю.
- [x] Удалённый PTY (`request_pty`) и shell (`request_shell`).
- [x] Мост PTY ↔ фронт:
  - [x] входящие байты с сервера → Tauri-событие `term://out/{id}`;
  - [x] нажатия клавиш из xterm.js → команда `write_to_terminal`;
  - [x] команда `resize_pty(cols, rows)` при изменении размера окна.
- [x] Управление сессиями: `HashMap<id, SshSession>` в `tauri::State` (+ команда `disconnect`).
- [x] **Персистентность профилей**: JSON в конфиг-каталоге (`directories` + `serde_json`).
- [x] Базовая обработка ошибок (отказ аутентификации, недоступность, закрытие сессии
      → событие `term://closed/{id}`).
- [x] Таймаут подключения (10 с вместо ~75 с системного TCP) и keepalive
      (15 с × 3 — обрыв «мёртвого» соединения детектируется за ~45 с).

### Фронтенд (Svelte) — [src/lib/Terminal.svelte](src/lib/Terminal.svelte), [+page.svelte](src/routes/+page.svelte)
- [x] `@xterm/xterm` 6 + `@xterm/addon-fit`, монтирование в правую панель.
- [x] Подписка на поток вывода (событие) и отправка ввода (команда).
- [x] Диалог ввода пароля при подключении.
- [x] Индикатор статуса соединения (Connecting/Connected/Disconnected/Error).

**Артефакт:** полноценная работа в удалённом shell. Это уже рабочий продукт.

**Сборка:** оба дистрибутива (macOS `.app`/`.dmg` + Windows `.msi`/`.exe`) — зелёная
CI-сборка на этом этапе.

## ✅ Фаза 2 — Безопасное хранение паролей и SSH-ключей

**Цель:** не вводить пароль при каждом подключении; поддержать вход по SSH-ключу.

> **Статус:** код реализован, бэкенд/фронтенд собираются без ошибок, приложение
> запускается. На `keyring` **3.6** (macOS Keychain / Windows Credential Manager).
> Осталась функциональная проверка на реальном сервере (сохранение в keychain,
> вход по ключу).

### Пароли — [secrets.rs](src-tauri/src/secrets.rs), [lib.rs](src-tauri/src/lib.rs)
- [x] Интеграция `keyring`: пароль в Keychain / Credential Manager
      (сервис `vterm:password`, аккаунт = id сервера).
- [x] Чекбокс «Сохранить в keychain» в диалоге подключения; флаг `hasSavedPassword`.
- [x] При подключении — `connect_plan` проверяет keychain; промпт только если секрета нет.
- [x] Команда `forget_secrets` — удаление сохранённых секретов (в т.ч. при удалении сервера).
- [x] **Грейсфул-обработка протухшего секрета:** секрет пишется в keychain только
      **после** успешного входа; при отказе аутентификации (`auth-rejected`) сохранённый
      секрет забывается и снова показывается запрос (сетевые ошибки секрет не трогают);
      кнопка **«Forget saved secret»** в форме редактирования.

### Аутентификация по SSH-ключу — [ssh.rs](src-tauri/src/ssh.rs)
- [x] В форме сервера — выбор **метода аутентификации**: пароль / SSH-ключ
      (поле `authMethod` в `ServerProfile`).
- [x] Поле **«путь к приватному ключу»** с нативным выбором файла
      (`tauri-plugin-dialog`); путь хранится в профиле (`keyPath`).
- [x] **Passphrase** к ключу — хранится в `keyring` (сервис `vterm:passphrase`),
      запрашивается только для зашифрованного ключа (`key_is_encrypted`).
- [x] russh: `authenticate_publickey` + `load_secret_key`, авто-подбор RSA-хэша
      (`best_supported_rsa_hash`); ed25519 / rsa / ecdsa.
- [ ] (Опционально) **встроенное хранилище ключей**: импорт ключа в каталог приложения,
      список ключей и привязка к серверам, копирование публичного ключа в буфер
      (для `ssh-copy-id`), генерация новой пары ключей.

### Опционально
- [ ] Портативное зашифрованное хранилище под мастер-паролем (`chacha20poly1305`) —
      для синхронизации между машинами.

**Артефакт:** пароли и ключи в системном безопасном хранилище; автоподключение по
паролю и по SSH-ключу.

**Сборка:** оба дистрибутива (macOS + Windows) — зелёная CI-сборка на этом этапе.

## ✅ Фаза 4 — Полировка UX

**Цель:** довести до уровня зрелого инструмента.

### Сессии и список серверов
- [x] Несколько одновременных сессий (вкладки терминалов) — **реализовано досрочно**
      как промежуточный этап: имена серверов на вкладках, drag-and-drop переупорядочивание,
      индикатор статуса на каждой вкладке, параллельные сессии (в т.ч. к одному серверу).
- [x] **Сворачивание/разворачивание левой панели** со списком серверов: кнопка-тогл
      в заголовке панели, запоминание состояния и ширины между запусками (localStorage).
- [x] **Регулируемая ширина панелей перетаскиванием границ**: левая панель со списком
      серверов и правая панель SFTP. Захват границы мышью (курсор-ресайз) и
      перетаскивание для изменения ширины каждой из частей; запоминание ширин между
      запусками; минимальная/максимальная ширина (левая 160–560 px, SFTP 240–720 px).
- [x] **Сворачивание левой и правой панелей в тонкую полоску**: у каждой панели своя
      иконка-тогл; клик сворачивает панель в узкую полоску, повторный клик по той же
      иконке — разворачивает. Левая (список серверов) и правая (SFTP) сворачиваются
      независимо, состояние каждой запоминается между запусками.
- [x] Группы/папки серверов, поиск по списку, теги: **иерархические папки**
      (вложенность любой глубины, пустые папки сохраняются), создание папки/подпапки и
      удаление из меню списка, **перетаскивание сервера в папку мышью**, сворачивание
      папки пиктограммой +/−; в форме сервера папка выбирается из списка с поиском
      (datalist); теги-чипы; строка поиска (по alias/host/логину/папке/тегам). Папки
      хранятся в `folders.json`, состояние свёрнутости — в localStorage.
- [x] Переподключение при обрыве: кнопка **Reconnect** в области терминала при
      разрыве/ошибке (переоткрывает сессию с теми же учётными данными); опциональный
      авто-reconnect (тумблер в настройках).
- [x] **Подтверждение закрытия вкладки**: модальное окно «Закрыть вкладку? Сессия
      будет разорвана» с Cancel/Close при закрытии вкладки с активной сессией
      (управляется тумблером в настройках, по умолчанию включено).

### Нижняя строка состояния (как в MobaXterm)
- [x] **Статус-бар внизу окна** для активной вкладки с данными удалённого сервера:
  - **иконка ОС** (Linux-дистрибутив / macOS / *BSD) — определять по `/etc/os-release`
    или `uname`;
  - **hostname** и **пользователь**, под которым подключились (`whoami` / из профиля);
  - **загрузка ЦП** — зелёный мини-график процента + число справа (CPU% считается
    дельтой `/proc/stat` между опросами); пиктограмма-микросхема;
  - **ОЗУ** (использовано/всего — `/proc/meminfo`); пиктограмма-планка памяти;
  - **свободное место на диске** (`df -kP /`); пиктограмма-HDD.
- [x] Сбор метрик — лёгким периодическим one-liner'ом по **отдельному exec-каналу**
      russh (раз в N секунд), чтобы не мешать интерактивному shell. Период опроса — в
      настройках.
- [x] Грейсфул-деградация: если команд нет (ограниченный shell) — показывать прочерки.

## Заметки по архитектурным решениям

- **`portable-pty` не используется.** Он нужен для локального процесса с PTY; для
  SSH удалённый PTY предоставляет канал `russh` напрямую. Может понадобиться позже —
  только если добавлять вкладку с локальным shell.
- **`russh-keys`** в свежих версиях влит в `russh` — проверить актуальность на момент
  начала Фазы 2.
- **`keyring` vs собственное шифрование** — основным выбран `keyring` (системное
  хранилище). `chacha20poly1305` под мастер-пароль — опция для портативного файла.
- **Хранение профилей** — простой JSON-файл на стороне Rust (`serde` + `directories`),
  без `tauri-plugin-store` (это фронтовое хранилище настроек, дублирование не нужно).
- **Tailwind v4** вместо 3.x из исходного плана — интеграция одним плагином Vite,
  без `tailwind.config.js`/PostCSS.
